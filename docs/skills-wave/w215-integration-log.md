## 三、本槽最要紧的一格:W207 的参数面判据被 W210 撞红,而这不是"抬一格了事"

合完第二次之后整跑,`contract` 上红一条:

```
episode.compose 的参数面变了:加了点名子集就得同轮重判空跑分档
期望 "pid,epid,ui",实际 "pid,epid,force,ui"
```

这是两支真正的交汇点。W207 在成片侧钉了一条"**没有第三份 note**"的结论,
其中一层是把 `episode.compose` 的参数面**按全等**钉成 `pid,epid,ui`——
它当年就写明这一格是"第三份派生该不该开的入口":加了**点名子集**(镜头侧的
`shotIds`、主体侧的 `subjectIds` 那种位),空跑分档就得按时间轴段重判一遍。

W210 加的 `force` **不是子集位**:它只决定"这一次要不要照旧重跑",
不改变**哪些段落进合成**,故 W207 那条论证的前提一格没变。处置是三条一起做:

1. 参数面那句期望值按 live 换成 `pid,epid,force,ui`,并在报错句里写明"授权位 `force` 不算子集位";
2. **对照面原样留着**——`episode.generateVideos` 的 `shotIds` 与 `subject.generateImage` 的
   `subjectIds` 两句断言一个字没动,真加子集位照旧当场红;
3. 随之**失真的注释一并改到与实况一致**:那条用例的段头原话是"已合成且指纹未变再点一次是**真跑**",
   合完之后这句只在带 `force`/点名那一路成立,故改写成"这一档后来开了,
   但它回的是结构位 `fresh:true` 而不是第三份就地拼句,故本条结论不变"。

有意**没有**走的两条路:把那句断言改成 `includes('shotIds') === false` 之类的宽判据
(等于把 W207 立的入口废掉),或反过来把 `force` 从注册表摘掉迁就旧字面
(那会让 Agent 侧 `sanitizeCmdArgs` 把它抹掉,六个点名入口全部点了没反应——
W210 的 M9 正是钉这一格)。
