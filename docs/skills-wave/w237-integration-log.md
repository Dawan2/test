## 四、三个棘轮字面同在一个文件,只有一个进了冲突面——而它恰是唯一两侧都错的那个

`tests/unit.js` 里有五个 `FLOOR` 字面,本槽涉及三个。三个的两侧取值与合完 live:

**本槽最值得抄走的一格就在这张表里。** 交接明令「smoke 分母会涨,FLOOR 按 live,禁止抄 113」——
而 113 这个数**根本没进冲突面**:我方那侧没碰它,git 自动取了对侧的 117,恰好就是 live。
单元那格同理。也就是说,两个"抄了会错"的格,**是拓扑替我们躲过去的,不是任何判据保住的**;
只要我方那侧当轮顺手动过 `FLOOR`(比如上一槽那样跟着 live 抬一格),它们就会和记账件那格一样
落进冲突面,而冲突面上我方给的正是旧分母 113。

反过来,记账件那格**因为两侧都写了数字才报的冲突,而冲突恰恰是这一格唯一的报警器**:
`P1` 249、`P2` 248,两个都低于合完 live 的 250。假如我方那侧当轮没抬过它,git 就会静默取对侧的
248——比 live 低 2 格,而 `SLACK` 是 3,一条判据都不会红。

**结论按两条分开记:** 自动取对侧取对了的那两格,靠的是"另一侧没动过"这个偶然;报了冲突的那一格,
靠的是"两侧都动过"这个偶然。两个方向都不是判据兜住的,故三格一律按合完 live 现跑重取,
不看 git 怎么合的、也不看哪一侧的数好看。

### 5.4 记一手:反事实脚本自己会说谎
