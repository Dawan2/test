## 3. 为什么是独立键,不跟别的人设合成

任务明确要求不与 `narration`/`reading`/`concept`/`light`(W71 那四条)合成,判据与 W51 三份多轮人设同形:**合成的前提是角色同一**,而这五步的角色互不相同——

| 步骤 | 角色 | 它要模型干什么 |
|---|---|---|
| 事件图谱拆解 | 剧本结构分析师 | 把一集正文**拆**成时间序事件序列(who/where/what/result),只抽取不改写 |
| 旁白解说体改写 | 解说编剧 | 把剧本**改写**成旁白稿 |
| 剧本围读 | 编剧/导演/制片联合评审会 | **评**节奏钩子与人物动机 |
| 构思导演阐述 | 开拍前定调的导演 | **定**美学主张与影调 |
| 全剧光影总控 | 摄影指导(DP) | **排**场景光影方案 |

把它们并成一个带 `{role}` 变量的键,等于让用户改一处就同时改掉五个角色的定位;而按角色各成一条键,「全局默认值」页上用户改哪一步就只影响那一步(第 5 节的串台断言)。同理也不复用既有键:`split.system`(拆集编辑)、`extract.system`(剧本分析助手)、`und.system`(资深短剧导演)三条的角色都不是"结构分析师",字面也都不同——**没有同字面就谈不上复用**,复用会把这一步的产物从"事件序列"推向别的方向。

也不做 `WfCore` 派生函数:该步只要这一句人设,不接方法论块、不接 `Skills.block`,与 `und.system` / `split.system` 同形直接 `Prompts.get`。事件图谱这一步本来就有意不接方法论——它的任务是**只抽不写**,往 system 半塞六阶段结构或钩子六型会把模型推向改写剧情,与本步"覆盖全部关键节点、不漏转折"的要求冲突。

## 4. JSON 契约不开放:只收人设句

注册表条目里只有那一句人设。该步返回 JSON 的字段面(`{"events":[{"who","where","what","result"}]}`)、事件数区间(3-10 个)、正文截断(`slice(0, 8000)`)与"按剧情时间顺序"这些要求仍在 user 半,不做成可覆盖变量——这半是消费侧的解析契约:

```js
const events = (Array.isArray(out && out.events) ? out.events : []).map(ev => ({
  who: String(ev.who || ''), where: …, what: …, result: …,
})).filter(ev => ev.what);
```

`what` 为空的条目会被丢掉,字段名改一个字这一集就整集拆不出事件(且逐集失败会退费)。所以与 W49/W51 同纪律:人设句开放、契约半不开放,并由一条断言钉住注册表里不得出现 `"events"` / `"result"` / `"where"` 这些字面。

## 5. 缺省逐字节不变靠哪几层钉住

1. **注册表层**:`Prompts.get('graph.system')` 与字面 `'你是短剧剧本结构分析师。'` 直接比对(变异 1 转红);并要求这句字面在 `Prompts.list()` 里**恰好命中一条**(变异 12 反向撞车转红)。
2. **消费层(源级)**:`system: Prompts.get('graph.system')` 必须与该步 user 半锚点 `把该集剧本拆成结构化事件序列` 在 600 字符内配对——键挪到别的步骤上、或那一步被改走别的键都当场红(变异 2、5)。
3. **全仓唯一持有者**:这句字面的持有者扫一遍 `server.js`/`cli.js`/`mcp.js`/`index.html` 与 `js/*.js`,必须**恰好只剩 `js/prompts.js`**(变异 9:在同文件另开一个常量抄第二份,转红)。
4. **不冒充双端**:这条链路没有服务端对端(`/api/wf/*` 里没有事件图谱端点),断言正向要求 `server.js` 不出现该步的 user 半锚点。收编解决的是**可覆盖**,不是可 headless——与 W51 三条多轮键同口径,记账里如实这么写。

`Prompts.get` 对未覆盖键返回 `def`,覆盖表为空对象/`undefined` 同样落 `def`,故没改过提示词的用户看到的 system 半与本槽之前逐字节一样。图谱的手动编辑/增删/`graphRev` 传播、`sourceRev` 记录、逐集失败退费与"先清掉已删除分集旧条目"那段全在取值口之外,一行未碰。
