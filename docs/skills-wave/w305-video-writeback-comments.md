- **「一个 id 收两笔视频钱」是真的**——②里选人闸按行筛出三行、三行都真下发,

## 三、改了哪几句(共两处)

### 3.1 `cli.js` `shots-import` 那道唯一闸的头顶注释

改前(一句里前半真、后半假):

```
 * 但同 id 两行落库后这张表就散了——findShot/shot-set 全按 id 取首行,第二行再也寻不着,
 * 而点名子集是按行筛的(ids.has(s.id)),点名一次两行都跑,一个 id 收两笔视频钱、写回的还是首行。
```

改后(按 §二 那份读数写,不多说一句):

```
 * 但同 id 两行落库后这张表就散了——findShot/shot-set 全按 id 取首行,第二行按 id 再也寻不着,
 * 而点名子集是按行筛的(ids.has(s.id)),点名一次两行都跑、一个 id 收两笔视频钱
 * (那两笔各落各的行:两条批量路径 gen-episode 与 exec episode.generateVideos 都按 nthShot 逐行写回;
 * 按 id 点名单镜的 gen-shot-video / shot.generateVideo 仍走 findShot,写回的只有首行)。
```

顺带把「第二行**再也**寻不着」加了三个字的限定「第二行**按 id** 再也寻不着」:
原句主语是 `findShot`/`shot-set` 这两个取数口,读作全局论断就与紧跟着的那句
「两条批量路径逐行写回」自相矛盾;限定语一加,两句读的是同一件事的两面。

### 3.2 `docs/AI助手接入指南.md` 逃生舱那条

改前:

```
  灌进去的同 id 两镜就在库里(点名一次两行都跑、各收一笔视频钱,而只有首行寻得着)。
```

「只有首行寻得着」挂在**批量**那半句上,是同一句假话的调用方版本。改后:

```
  灌进去的同 id 两镜就在库里(点名一次两行都跑、各收一笔视频钱;`gen-episode` 与 `exec episode.generateVideos`
  两条批量路径按行写回、两行各得一段片,而按 id 点名单镜的 `gen-shot-video`/`shot.generateVideo` 与 `shot-set` 仍只落首行)。
```

这一句挨着 W231 那条三处明写的契约(「镜头 id 唯一性由调用方自己保证」)。
那条契约有一层判据按 ±300 字窗口要求「`shots-import` 得跟着这句话一起说」,
改完现取三处窗口全 `true`(`cli.js` 1 处、`README.md` 2 处、接入指南 1 处),没把它挤出窗口。
