## 1. 病灶:11 条红里没有一条在说"键少了"

`w134-integration-log.md` 交接了一处欠账:摘掉 `gaps()` 的 `G-03` 键确实红 11 条,但没有一条在说键集少了东西。
本槽开工先把这句话现跑复核了一遍(基线 `42b2798`,把 `SK-23` 的 `gaps` 清空、`SK-25` 的 `gaps` 去掉 `G-03`):

| 红在哪 | 条数 | 它到底在判什么 |
| --- | --- | --- |
| 九条源级人设用例(`role-editor` / `episodes` / `sb-board` / `gsettings` / `wf-core` / `proj-upload` / `sb-views` / `experts` / `agent-global`) | 9 | 各自那条用例的**收尾一句**顺带写了 `Object.keys(Skills.gaps()).length === 20`;用例名说的是"某文件零内联人设" |
| `skills · 记账对齐` | 1 | 判的是条目字段 `Skills.byId('review.stage').gaps.includes('G-03')` |
| `skills · 清 pending 的行为面为零` | 1 | 早退在 `validate()` 那句上(`pending` 退回 `infra` 后"有未落地机制面须写明缺口编号"),它自己那两句键集断言**一句都没跑到** |

九条"键数 20"的顺带断言看起来像判据,实际上只判**基数**。三条变异把这层皮撕开了:

- **M2 `G-03` → `G-99`**(摘一个键、同时新登记一个键,基数仍是 20):九条全绿,只剩上表后两条条目级的红,而它们判的是 `SK-23` 这一条的字段,不是键集。
- **M3 `S-06` → `S-99`**(挑一个没有条目级断言护着的编号改名):`unit` **492/492 全绿**、`integration` **130/130 全绿**。
  缺口编号被整个改掉、图谱与记账件里那一路指向全部落空,全仓一条红都没有。
- **M4 摘掉 `S-06` 键**(`SK-28` 的 `gaps` 清空):红的仍是那九条"键数"加一条早退用例,依旧没有一条点名是哪个键没了。

所以 W134 那句交接可以说得更准:**`gaps()` 的键集不是"判据弱",是零判据**;
在场的九句是别人用例的收尾附注,判的是基数,改名这一路它们结构上就看不见。

## 2. 落地:一条 contract 用例,四层判据

新增用例接在 `skill 索引登记面无漏登` 之后(与另两条注册表结构契约同处),**既有断言一字未改**:

```
{ name: 'skill 索引缺口键集:gaps() 20 键逐个点名并与两份缺口图谱双向对账(摘键/改名先红在本条)', fn() { … } }
```

四层各判一件事,失败含义不混:

1. **逐字点名**:`Object.keys(Skills.gaps()).sort().join(',')` 等于就地写死的 20 键字面。
   摘键、改名、私自新登记编号一律先红在这里,报错把期望与实际两串都印出来,差在哪个编号一眼看得见。
2. **只收图谱登记过的编号**:`G-xx` 现取 `w1-pipeline-skill-map.md` 的缺口图谱表(按 `^| G-\d\d |` 取行),
   `S-xx` 现取 `w1-selected-skills.md` 的新登记表。键集里出现图谱没有的编号(错字、私自新编号)即红。
3. **反向对账**:图谱登记过而键集里没有的编号,必须在用例里明写闭合/待登记理由。
   现有三条:`G-06`(注入半与校验半两面都落地,关联能力清账)、`S-02`(自撰条目进 `KB.SECTIONS` 后注入与校验共用一份判据)、
   `S-08`(发布后回写上游仍待登记,短名单里还没有关联能力)。这一层就是**"摘键的唯一正当路径是整条闭合"**那句口径的机器形态。
   反过来,已声明闭合的编号又冒回键集里同样红(闭合理由过期即报)。
4. **落地一面不摘键**:`G-03`(审片升主线一等步骤)、`G-11`(结论按板块回流)、`G-13`(内联提示词逐处收编)
   三条各自都有一面已落地、关联能力也早已无 `pending`,而键与关联索引照旧在案——用例把这三条单独点出来,
   连同"关联能力已无 pending 而键仍在案"一起断言,免得后来者把"某一面落地了"读成摘键的许可。

### 2.1 为什么要第二层与第三层(只写第一层不够)

只有第一层时,把键集字面跟着代码一起改就全绿——这正是本目录反复量到的"改测试迁就代码"那一路。
第二、三层把键集接到两份**不在 `js/` 里、也不在 `tests/` 里**的既有记录上:缺口编号本来就是图谱定义的,
键集只是它的投影。于是摘键这件事需要的不再是"改一个数字",而是"在用例里写下这条缺口为什么闭合了",
而闭合是有事实判据的(关联能力一条不剩)。**这个人工出口有意留着**——闭合是真会发生的事(`G-06`/`S-02` 都发生过),
不能钉死;它换来的是把静默改动变成一处要写理由的显式声明,见 5.7 的 M7。

### 2.2 有意不写的三种恒真句

对着 `js/skills.js` 的 `gaps()` 实现逐句筛过,以下写法一概没进用例——它们从投影的构造上就永远成立:

- 「键集等于 `REG` 各条 `gaps` 字段的并集」:`gaps()` 就是这么拼出来的。
- 「每个键至少挂一条关联能力」:`m[g]` 是 push 出来的,不可能是空数组。
- 「关联索引里的 id 都是短名单条目」:值就是 `s.id`。

第四层那句 `every(id => !Skills.byId(id).pending.length)` 不在此列:`pending` 是条目上另一份独立记账,
清没清与 `gaps` 字段无关(`gaps()` 只投影 `gaps`、不看 `pending`,这一点由 `skills` 套件那条逐字节比对的用例钉着)。

### 2.3 与既有 gaps 相关用例的分工

| 既有用例 | 判的是 | 与本条的关系 |
| --- | --- | --- |
| 九条源级人设用例的收尾句 | 键**数** 20 | 本条判键**集**,严格更强;九句一字未改(它们是各自用例"记账随实况"那一向的附注,不是本条的替身) |
| `skills · 记账对齐` | `SK-03`/`SK-04`/`SK-23` 三条**条目字段**的 `gaps` 与 `note` | 对象不同:条目字段 vs 投影键集。M2 实测两者各红各的 |
| `skills · 清 pending 的行为面为零` | 清 `pending` 不动任何投影(逐字节比对) | 它是"`pending` → 投影"这一向;本条是"键集本身"。它那两句键集断言在 M1/M6 下**早退根本跑不到**,本条不早退 |
| `G-06` 校验半那条的 `Skills.gaps()['G-06'] === undefined` | 单个已闭合编号的清账 | 本条第三层把它一般化成"所有图谱编号的在/不在都要有交代",两条互不覆盖(它还判了那两条的 `checks` 与消费点) |

### 2.4 顺带抬的两个下限字面

按 W121/W132 定的规矩(加了用例/记账件就把那个 `FLOOR` 抬到当轮实况,差额上限 3 格):

- 三套件用例数表里单元那格:`492` → `493`。
- 记账件份数那条的 `const FLOOR`:`149` → `150`(含本文)。

集成与 CLI 冒烟两格未动(本槽没碰那两个套件),四格差额抬完均为 0。

## 4. 不做的事

- **不动 gaps 的产品含义**:`G-03`/`G-11`/`G-13` 一条不清,`REG` 里 `gaps` 字段一个字符没改;
  "落地一面不摘标记"仍是目录口径,本槽只是给它补了机器判据,没有借加判据顺手改口径。
- **不把"落地一面"做成摘键绿灯**:第四层判的正是反方向——三条已落地一面的缺口,键必须仍在。
- **不碰九条源级人设用例**:它们那句"键数 20"看着与本条重复,但它是各自用例"记账随实况"那一向的收尾,
  删了会让那九条各少一个向;本条更强不等于可以替它们交账。
- **不改 `SLACK`、不改任何既有判据的形状**:只按各自写明的规矩抬了两个数字。

M3 是本槽最要紧的一条:它把"零直接判据"从推断变成读数——**一个缺口编号可以被整个改名而全仓不响**,
补判据前后从 0 红变 1 红,且那 1 红就写着键集哪里不对。

M7 如实登记为本条的**已知出口**:第一层字面 + 第三层闭合名单 + 第四层点名清单三处一起改就能转绿。
这不是漏洞而是设计——闭合本来就要允许,只是要求写下理由;真正被封死的是"只改代码不改记录"(M1/M2/M3/M4)
与"只改一处字面迁就代码"(M5/M6)。

## 6. 交接

- 下次有缺口真闭合(关联能力一条不剩)时,改三处:键集字面、闭合名单里加一行带理由的条目、
  若它在第四层三条点名里则一并移走。三处都在同一条用例里,不用翻别的文件。
- 新登记缺口编号(`G-16`/`S-09` 之类)要先进图谱表,否则第二层当场红——这是有意的:
  编号的定义在图谱,注册表只是它的投影。
- 仍未被任何判据覆盖的一路:**键的值(关联能力名单)只有 `G-13` 与 `G-03` 等少数几个编号被逐字钉过**,
  其余编号的名单增减仍只有"键在不在"这一层看得见。本槽不扩到值一级(会与 `skills` 套件多条既有用例撞口径),如实交接。
