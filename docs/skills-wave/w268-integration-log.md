## 九、这一槽学到的

1. **对侧动的是我方那半的「上游」时,关键词点数连必要条件都不够**。前三条快进形里对侧加的都是新取数口,点数"我方那几格没往下走"还算说得过去;本槽 `rowIndexOf` 17 → 23,17 一格没减看起来很干净,但点数量的是**引用还在不在**,量不出**那些引用的行为判据还红不红**。M6 那一手(把 W266 落下的行键退回 `shotId`、看报错句是否与 W266 §四 M1 逐字相同)才是这一格的证据。合入线上凡是"对侧改了我方那半依赖的东西",都该补一手反向变异,而不是多点几个关键词。

2. **复现对侧自称的变异,值钱的是报错句而不是红几条**。M1—M5 每手都红 2,单看数字五手无从分辨;真正把"两处必须一起改""两族取数各有判词""屏幕与导出各咬一句"这三件事分开的,是五手的报错句两两不同。尤其 M2 那句 `"8,8,1,4"` 的末位 `4`——它证明缺失行那一族没被清单行那一族的改动连累,这条读数只有报错句里带得出来。

3. **`B == P1` 提交级相等这一档,连着第二次遇到就该当成常态处理**。W266 把它记成"第一次遇到";本槽再遇一次,处置流程一步没变(树面证据全丢、全靠变异 + live)。值得记的反倒是**它与前几条的差别落在别处**——不在拓扑而在"对侧改的是不是我方那半的上游"。判一条快进形要补几手证据,看的是改动的**依赖方向**,不是拓扑退化到哪一档。
