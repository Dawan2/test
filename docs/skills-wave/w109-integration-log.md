### 5.3 零吃测:多重集双向对照全空,而第一遍的去重口径自己假报了一条

**名集口径**:`w108` 相对自己 `merge-base` 取增量,与基线取并集,与合并后 live 逐条双向 `comm`
(抽名前按 `|` 切掉回执载荷,否则 `cli.smoke`/`integration` 那些带期望/实际串的行会假报差集——W104 记过这一处):

| 套件 | `w108` 增量 | 与基线增量相交 | 期望集 \ live | live \ 期望集 |
|---|---|---|---|---|
| `unit` | +2 / −0 | **0** | **0** | **0** |
| `integration` | +0 / −0 | **0** | **0** | **0** |
| `cli.smoke` | +1 / −0 | **0** | **0** | **0** |

`w108` 的增量与基线自己那三条槽的增量**现查为零相交**(不是默认的——W99 正是在这一步翻的车),
故"增量相加"这条算法这一次成立:

```
unit      469 + 2 = 471   ← 与 live 逐字相等
cli.smoke 101 + 1 = 102   ← 与 live 逐字相等
```

**第一遍的比对脚本自己踩了一次重名盲区,值得单记。** 期望集当时写成 `sort -u 基线 增量`(去重),
而 `live` 那侧是原样排序(不去重),于是 `integration` 假报了一条:

```
live \ 期望集:
项目不存在 404
```

这不是新增用例,是 W64 记过、W96 点名过的那对同名用例——`integration` 130 条只有 129 个不同名字,
去重把期望侧压成一份、live 侧仍是两份,差集就多出一行。改成**两侧都不去重的多重集比对**后三套件双向全空:

```
$ for s in unit int smoke; do sort 基线.$s 增量.$s | sort > 期望.$s; \
    comm -23 期望.$s live.$s | wc -l; comm -13 期望.$s live.$s | wc -l; done
unit  期望\live: 0  live\期望: 0
int   期望\live: 0  live\期望: 0
smoke 期望\live: 0  live\期望: 0
```

W96 记的是"重名会让按名成集比对**吃掉**一条";本槽遇到的是同一盲区的另一面——
**两侧去重口径不一致会凭空多报一条**。两种都不是删测,但两种都会让取证读起来像出了事。
判据是一句话:**比对的两侧必须同口径**;这个套件有重名,就只能用多重集。

```

$ grep -c '注册表全仓持有者名单:每条 def' live/unit.names  → 1
```

`unit` 的条数与不同名字数仍相等(471 / 471);`integration` 仍是 130 条 / 129 个名字
