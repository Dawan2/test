## 1. 欠账是什么:源级判据看得见形状,看不见那个数流没流到回执上

发布门 G4 过期镜 / G5 未确认镜 / G6 失败镜三门共用一次遍历,数从 `Domain.episodeState(...).counts` 逐集累加而来
(`js/release.js` 的 `agg` 段、`js/release-core.js` 的同名段,两端各一份)。

钉住这件事的判据,在本槽动手前只有**源级**那一格:
基线 `4eaea86` 上是 `assert(/aggFail: 0/.test(rel) || /counts/.test(rel), …)`(恒真,由 `w171-tautology-assert.md` 那槽收紧);
W171 收紧后是「取那段的可执行行 → 段头锚点取得到 → 行数 > 10 → 段内有 `Domain.episodeState(` → 有 `agg[k] += … counts`」四格。

源级四格判的是**那段代码长什么样**。它判不出**回执上印的那个数是不是它算出来的**:
加数的形状留着、把三门的数在 `gate(...)` 那一步串位,或把镜数写死成常数,源码形状一个字没变。

这一点是现取实测出来的,不是推的。把同一批变异打在 W171 tip(`6e451ee`)上,只看**全套**颜色:

## 2. 处置:让夹具给出可辨的三组数,断言两端回执上印的正是那三个和

新增用例 `两端 · G4/G5/G6 回执上印的镜数就是 Domain.counts 的和(换加数来源、串位、只取首集都红)`,
落在 `tests/unit.js` release 套件里、紧跟既有那两条「判不出来」用例。**产品门槛一字未动**:0 仍 pass、非 0 仍 fail,只钉数从哪来。

夹具三集,`counts` 彼此可辨:

| 集 | stale | unconfirmed | failed |
| --- | --- | --- | --- |
| ep1 | 0 | 4 | 7 |
| ep2 | 2 | 0 | 11 |
| ep3 | 3 | 13 | 60 |
| **和** | **5** | **17** | **78** |

- 三集都用 `releaseReadyEp()`(齐备镜、`video.status === 'done'`、`confirm: true`),**只把 `counts` 这一项换掉**,其余推导仍走真 `Domain`。
  于是「就地数镜头」这类改法在这份夹具上一律数出 0,回执上出现 5/17/78 只可能是 `counts` 原样流过去的。
- 期望值由夹具表**现算**(`ids.reduce(...)`),不在断言里另写一份字面。
- 夹具先自证有辨识力,两句写在用例开头:三个和两两不等(相等则串位不红)、三个和都不撞任何一集的单集数
  (撞上则「只取首个受累集」不红)。日后有人调夹具数字把辨识力调没了,先红在这两句上。
- 取数只认回执开头那个数(`/^(\d+) 镜/`),不吃措辞:两端文案不同(浏览器 `5 镜素材与当前剧本不一致`、headless `5 镜`),
  且改文案不该红(控制项 M7 守着这一点)。

断言四组:

1. 浏览器 `Release.collect`:三门 `status` 仍 `fail`,回执上的数分别等于 5 / 17 / 78。
2. 浏览器一键处置落到哪一集也由 `counts` 定:ep1 的 stale 是 0,故 G4 的 `fix.epid` 得跳过它落到 `ep2`;
   G5 的跳转 hash 与 G6 的 `fix.epid` 落 `ep1`。挑集时读错字段在这里红。
   (`fix.shotIds` 这一面本条没碰——这份夹具的镜头本身都是齐备的,子集恒空;它另有 `G4 只带过期镜子集` 那条钉着。)
3. 计数全归零这一面:三门仍 pass、回执如实印 `0 镜`、不挂 `fix`。把镜数写死成常数的改法,在这一面与第 1 面里必有一面红。
4. headless `ReleaseCore.gates`:同一份夹具、同样三个和,零计数那一面同样走一遍。一端改了另一端没改也要红。

## 6. 如实登记

- **M1/M4 红在 `status` 那句而不是数那句**:两条断言在用例里是先 `status` 后数,而这两条变异让计数变 0、
  连门的结论都从 fail 翻成 pass,故先撞上前一句。数那句同样接得住(0 ≠ 5),只是报不出来。
  这也意味着:本条第 1 组断言里的 `status` 那句不是摆设,它先接住的是「计数塌成 0」这一类。
- **`fix.shotIds` 这一面本条没覆盖**:夹具只换 `counts`、镜头本身齐备,故 G4/G6 的 `shotIds` 恒空数组。
  子集内容由既有那条 `Release 全脏项目:fix.cmd 均已注册 + 集级命令带真实 epid + shotIds 子集正确` 钉着,本条只钉 `fix` 落到哪一集。
- **headless 那一端的 `fix` 没有可钉的面**:`js/release-core.js` 的 `gate(...)` 不产出 `fix`(那是浏览器那一份的字段),
  故第 4 组只有数与 `status` 两面。
- **不吃措辞是有意的**:回执文案属产品口径,本条只认开头那个数。代价是「把 `5 镜` 印成 `共 5 镜`」这类改法本条会红
  (正则要求数在开头),这是误判方向,如实记着——真要改成这种版式,同轮改这条的取数正则。
- **门槛一字未动**:`agg.stale ? 'fail' : 'pass'` 这套判定、三门的文案、`aggErr` 那两条降级路径、`gaps` 与短名单一律没碰;
  `js/release.js` 对 `Skills` 照旧零引用(contract 套件那条守着)。
- 本槽**没有摘任何缺口标记**,`gaps()` 投影零 diff(注册表五个文件一字未改)。
