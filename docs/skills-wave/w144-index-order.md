> **零产品代码改动**(`js/`、`server.js`、`cli.js`、`mcp.js`、`billing.js` 一行未改),不摘任何 `gaps` 键、不动注册表、**不删任何用例**。
> 基线 `cursor/w139-integration-a7f2` head `2851d97`(开工现取核实相符),本槽不做任何合并。

## 1. 病灶:三条索引契约钉的全是"哪些行在场",一行也不管"排在哪"

`docs/skills-wave/README.md` 的索引表现有三条契约护着(本槽一条都没改):

| 既有条 | 钉的是 |
|---|---|
| 双向集合相等 | 目录里的 `.md` 文件名集合 == 索引行的文件名集合,链接文字须就是文件名 |
| 按份点名 + 相对链接不悬空 | 每份 `wNN-*.md` 各要有自己那行;`./` 开头的相对链接不许指空 |
| 份数三方对齐 + 下限 | 目录份数 == 索引行数 == README 明写份数,且只增不减 |

三条的判据全都是**集合与计数**:一行搬到表尾,集合没变、份数没变、每份仍点得到名——**四条断言(含下限)一条不红**。
于是"新记账件要插回它那个波次的位置"这件事至今零判据,只靠评审记性,而它已经人工排过三次;
最近一次是 `w134-integration-log.md` 记的「索引四行取并集并按波次号把 `w130` 排回 `w129` 与 `w131` 之间(行序仍无断言,人工排的第三次)」——
那句括号里的话就是本槽要收的欠账。集成槽合并索引表时取的是**并集**,并集本身不带次序,
两侧各自往表尾追加、`git` 也不会请你过目,乱序是这条线上一直敞着的静默口。

## 2. 落地:钉「不许倒退」,不是「必须连续」

新增一条用例,接在三条索引契约之后:

```
const numbered = rows.map(f => ({ f, m: f.match(/^w(\d+)-/) })).filter(r => r.m);
…
if (prev && +r.m[1] < +prev.m[1]) bad.push(prev.f + ' 之后排了 ' + r.f);
```

### 2.1 为什么不是「波次号连续」

W105 §2.2 当年立份数那条时**已经否掉过连续性判据**,理由本槽照旧成立:目录里 W96/W98 是如实登记在
`w99-integration-log.md` 里的「剩余未合」槽,号被占了而记账件不在这条线上,连续性会把如实记录判成红;
而"例外名单"要么写死(下一次未合又得改)、要么去解析散文里的剩余未合段(比它要拦的问题更脆)。
本条钉的是**相邻两行的大小关系**,号空着一点不碍事,故不重复踩那个坑。

### 2.2 为什么不是「按 git 时间」或「按文件名排序」

- **按 git 时间**:索引表是按主题查文档的目录,不是提交流水;合并、cherry-pick、补记都会让时间序与波次序对不上,
  而读者要的是"W131 那份在哪",判据跟着提交历史走等于把一件稳定的事挂到一件会变的事上。
- **按文件名字典序**:`w10-` 的字典序排在 `w9-` **前面**,按名排等于要求把表排成人眼看着乱的样子;
  今天这张表恰好是按号递增的,按名排则当场红 —— 判据必须取号的**数值**。

### 2.3 同号内不判先后

`w1-*` 有八份、`w3-*` 有四份,同一波次里哪份在前没有客观标准(现表是按主题排的)。
故判据用的是 `<` 而不是 `<=`:同号相邻两行任意顺序都绿。代价如实记在 §4。

### 2.4 本条自足,并自带取数口守卫

按 W132 立下的规矩,判据自己的取数口不许静默失效:本条先断言

```
assertEq(numbered.length, fs.readdirSync(dir).filter(f => /^w\d+-.+\.md$/.test(f)).length, …)
```

取到的 wNN 行数须等于目录里 `wNN-*.md` 的份数。索引表被挪走、行首那条正则被改坏、
表改成别的形态时,`numbered` 退成 0 或几行,本条会**先红在"取数口失效"这一句**,
而不是拿着一份空名单宣布"次序没问题"。非 `wNN` 前缀的行(索引表今天一份也没有)被 `filter` 摘掉不参与排序判定,
免得将来收进不带波次前缀的文档时误红——这与份数那条"只数 `wNN-*.md`"的口径一致。

M1–M3 是本槽的靶心:**三条在基线上一条都不红,在本槽各红一条**,这就是新增的覆盖面,
而它们对应的正是索引表现实中会出的三种乱序(追加到表尾、插到表首、整体被工具重排)。
M4 是有意留的空白。M5/M6 是回归:既有完备性一处没丢,**尤其 M5——"文件+行一起删"仍然红**,
且本条在这一路上**不掺和**(行数与目录实况一起少一,取数口守卫按设计不响),失败含义没被搅浑。

M6 里本条**会跟着多报一条**:索引行少一而文件还在,取数口那句当场不等。这条多出来的红如实登记在这里——
它报的是"本条的取数口失效"而不是"少了一行"(那三句由既有三条各自报),文案上分得开,
但确实是同一处改动惊动了四条断言。不为消掉这一条而放松取数口守卫:守卫失效的代价(本条静静变恒真)比多报一条大。

## 4. 没纳入的部分(诚实位)

- **同号内的先后不判**(§2.3)。`w1-*` 八行之间怎么调都绿。要判就得再立一套"同号内按什么排"的口径,
  而那个口径今天并不存在(现表按主题排),硬立等于凭空造一条每次加同号记账件都要对照的规矩。
- **只判相邻两行的大小关系,不判"整表是不是按号分好组的"**。若同一个号的几行被拆散到表里两处(如 `w1` 三行、
  `w2` 两行、再回来 `w1` 五行),中间那几行会构成倒退故仍红;但**号严格递增地穿插**这一形态不存在,故不另立判据。
- **不判"这一行该不该在这张表里"**。行序与在场是两件事,后者由既有三条管,本条只管次序,失败含义不许合成一句。
- **`README.md` 里的其它表格不在判据内**。本条只认 `docs/skills-wave/README.md` 里那张「行首竖线 + 文件名自链」的索引表。
- 本条落在 `contract` 套件,与产品行为无关:`node tests/unit.js contract` 单跑即可,不需要服务与网络。
