## 1. 切在哪一刀:只抽人设句

W45 第 9 节把这处余量的两种切法都摆出来了,本槽取**前者**——只把开头那句人设抽成键,`ops` 协议、命令白名单与返回 JSON 约定仍由 `wf-core` 拼。理由是这半不是措辞,是**解析契约**:

```js
// 基线 js/wf-core.js:人设句与协议半写在同一个模板串里
W.buildAgentSystem = function (ctx) {
  return `你是「虎鲸导演助手」,短剧制作智能体(服务端单轮模式:…)。${ctx.kbText || ''}…
返回 JSON {"reply":"中文回复","thinking":"一句话思考摘要","ops":[操作]}。
ops 仅支持统一领域命令:{"op":"run","cmd":"命令名","args":{参数}}(…)。命令白名单与参数面:
${ctx.cmdText || '(无可用命令)'}…`;
};
```

`W.agentNormalize` 正是按这份约定过滤 run 类 ops(`o.op === 'run'` 且 `cmd` 在注册表词表内,`args` 过 `sanitizeCmdArgs`)。把协议半做成可覆盖变量,用户在「全局默认值」页改一个字就可能让整轮回复解析不出 ops——**能改坏的东西不该开成开关**。人设句不同:它只影响语气与角色定位,改了照样解析。所以这一刀切在人设句与 `${ctx.kbText}` 之间,协议半连注释一起留在装配口。

顺带按 W45 的另一问定了口径:**浏览器多轮那几份措辞不并进这个键**。分集面板是「短剧分镜编辑智能体」、全局抽屉与预排模式是「短剧创作智能体」,与服务端单轮的「短剧制作智能体(服务端单轮模式)」不是同一句话的三份拷贝,而是三种运行模式各自的角色定位;合成一个键会让其中几端的语义失真,故它们留在 SK-03 的仍欠段(见第 5 节)。

## 3. 这一处的「两端」与前三槽不是同一个意思

W40 / W42 / W45 收的三处,装配口都有**两个消费点**(浏览器某模块 + `server.js`),所以「两端跟随」指的是同一句话在两个消费点同键取值。`buildAgentSystem` 不是这个形态:它只有 `server.js` 一个消费点(CLI `agent`、MCP `hujing_agent` 都是转发到 `/api/wf/agent`,不自己拼提示词),浏览器工作台面板走的是 `js/agent.js` 自己那条路径。

因此本槽的「两端」落在**取值口**而非消费点上:键登记在双端 UMD 注册表里,`Prompts.get(key, ov)` 在浏览器隐式读 `Store.settings.promptOverrides`、在 Node 读调用方显式传入的那张表;用户在浏览器「偏好学习 → 全局默认值 → 核心提示词 skill」写下的覆盖随 state 树同步到服务端,服务端单轮下一次调用就跟随。这条链路第 7 节按真实请求体实测过。写成「两端各有一个消费点」是不实的,故此处如实记账。

## 4. 缺省逐字节不变靠哪三层钉住

1. **注册表层**:`Prompts.get('agent.system')` 的返回值直接与原模板串开头的字面比对——改 `def` 即红(变异 1);把协议半塞进 `def` 也会撞上这条(变异 6)。
2. **装配口层**:`buildAgentSystem({})` 的整条返回值与一段写死的期望串逐字节比对(人设句 + 四行协议 + `(无可用命令)` 占位 + 风格尾注)——丢掉命令白名单段即红(变异 7)。
3. **覆盖层**:同一个 `ctx` 下,覆盖版与缺省版满足 `ovd === 覆盖值 + def.slice(人设句长度)`——**覆盖只换人设句、协议半逐字节不变**这件事就此成为断言而不是承诺;谁把协议半也拼进注册表取值,这条先红(变异 2 实测首红即此条)。同一用例另钉住注册表里不得有任何条目的 `def` 含 `"reply"`(返回 JSON 约定不做成可覆盖变量)。

消费层照旧钉两条:`server.js` 必须给装配口显式传覆盖表(不传则 Node 静默落回 `def`,覆盖只在浏览器生效,变异 3),`js/wf-core.js` 与 `server.js` 一律不得出现 `短剧制作智能体` 字面(注册表 `def` 是唯一来源)。

## 9. 交接

1. **浏览器多轮的三份人设仍在各自文件里**(SK-03 仍欠的第一处,见第 5 节)。三份措辞对应三种运行模式(分集面板改分镜、全局抽屉贯穿全流程、预排模式),要收编得先定**是三个键还是一个带变量的键**——合成一个键会让其中几端的角色定位失真,拆成三个键则「全局默认值」页会一次多出三条,是产品口径题。它们的 ops 协议面比单轮宽得多(数据类 update/insert/delete/move/batch + goto/select + 按需查询 + 决策选项卡),那半同样不该开成可覆盖变量。
2. **单轮的协议半有意不收**(SK-03 仍欠的第二处):要收也只能连着改 `agentNormalize` 的过滤口径,并给「用户把 JSON 约定改坏」备一条兜底(现在没有——解析不出就是整轮无 ops)。属产品口径题,本槽不动。
3. **注册表之外的内联人设仍是大头**,且不在 SK-03 的 `covers` 口径内:浏览器侧的导演阐述、光影总控、剧本围读、拉片分析、配音导演、节拍拆解、发行文案,以及 `aiScriptDigest` 的四步、`js/plans.js` 的制作计划器,各写一份 system 半(G-13,W1 盘点第 7 条已登记)。本槽不动。
4. 单轮步的 `mockKind: 'agent'`、计费动作 `llm.agent`、`buildAgentUser` 的 user 模板、`agentCmdProtocol` 的命令白名单文本与 `agentNormalize` 的 ops 过滤(run 类 + 词表内 + `sanitizeCmdArgs` + ≤5 条),一字未动。
