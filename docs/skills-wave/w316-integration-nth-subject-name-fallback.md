### 4.1 M1:本槽全部的理由,也是明令点名要核的那一格

明令"委托改成立地抛「主体不存在」在起点绿、合完红",现取逐字相符:

- **P1(起点)721/721 全绿**——那句委托被就地抄成一模一样的错话,起点树上**一条都不红**。
- **M(合完)721/722,红 1**,红句原文:

```
FAIL | commands · subject.generateImage 并发改的是 id 不是人:同 id 一位不剩时按名兜底真取到那一位(不止是报错那一半)
     | 人还在库里、名字没变,这一轮不许报「主体不存在」(委托回 findSubject 那一半断掉就红在这里):
```

### 4.2 M2/M3/M4 各 +1,M5 有意 0

M2(认错人还照报成功)在起点树上只红既有那条"同 id 一位不剩时如实失败",合完另红一条
"末轮那张图得落在名字与点名串对得上的那一位身上(退回库里第一位就是认错人:前两轮的图会被顶掉)"——
**新条钉的是"取到的是谁",不是"有没有报错"**,这正是它与既有那条形状相邻结论相反的地方。

M3/M4 各从红 2 涨到红 3,多出来的那一条同样是新条;两手在 M 上红条数相同(3),
说明**新条把两处兜底一起揽下来的那一半是重合的**——它读的是"按名这一路通不通",不区分是哪一处塌的。

**M5 在两棵树上同为红 2、新条不红,是设计内**:那一手动的是序数越界退回首位那一处,

### 4.3 M-DEL 与 M-REV 连读:快进形槽的固有形状

这一对是本槽最要紧的一格,两手的差别只有"删干净没有":

- **M-DEL(删一半)红 2**,两句各有分工:
  1. `contract · README 数字对账` 报 `单元测试用例数:README.md 与实测不符(实测 721,文档 722)`;
  2. `contract · 三套件用例数只增不减` 报 `单元测试用例数不得少于 722(实测 721)`。
- **M-REV(删干净)721/721 全绿**,同一刻 `git diff M-REV P1` **也是空集**——
  即整槽退回后的树**逐字节等于我方尖**,树上没有任何一条判据说得出"这里本该多一条用例"。

**"删一半会响、删干净不响"就是快进形合入的固有形状**,与 W312 / W314 那两槽逐字同形。
判据面的棘轮守的是「别只删测不改数」,它守不住「整槽一起消失」——后者只有 §三 那三层锚点分得开:
根树 oid 对不上 P2、用例名多重集 `M − P1` 落回 0 条、索引行少一行。故本槽的并集判据一律取 §三 那三层,
不取"跑起来全绿"。

### 4.4 M-IDX:索引行是并集里独立的一层

只摘一行、文件与数字全留,红 4 条,其中一句把合入的失手形态直接说出来了:

故索引行这一层是**真并集里独立的一格**,不被文件在不在场那一层覆盖。

## 八、这一槽可复用的一件事

**"错话相同"不等于"那条路还在"——委托型兜底的合入判据得盯委托本身。**
M1 只把一句委托换成就地抛出一模一样的错话,起点树 721/721 全绿、合完 722 里红 1:
那道差就是这一槽全部的净值。合入槽验收对侧"只加测"那一槽时,别只数条数涨了几条,
得找出**一手能把新条单独打红、又在起点树上全绿**的改法;找不出这一手,就说明这一槽合进来的可能只是文字。

**净新增看守面按"每手两边各跑一遍"的差额读,而"设计内不红"必须当场落笔。**
本槽七手里 M1/M2/M3/M4 各 +1、M5 恰 0。0 那一格要么是漏网、要么是设计内,
两者在读数上长得一模一样,只能靠合入槽自己去问"这一手动的是不是新条该管的那一路"——
