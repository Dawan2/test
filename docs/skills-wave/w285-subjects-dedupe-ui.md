## 一、这一槽收的是哪条缺口

W283/W284 残留第 1 条,原话:

> **浏览器侧没有这条出口的入口。** 两条去重命令都只在 CLI/MCP 上,主体库页面没有按钮;
> 同 id 多位在页面上长得与两个不同主体一样(卡片按 `p.subjects` 逐条渲染),
> 要在页面上发现它,现在只能靠批量补图那句 note。

缺口的形状:`subjects-dedupe` 落地之后,**收拾这批脏数据这件事只有 headless 一条路**。
而脏数据的来路(逃生舱 `state-put --force`、`PUT /api/state` 整树原样落库、跨设备恢复快照)
用户在浏览器里就能走完,收拾却要切到命令行;更要紧的是**发现**这一步:主体库卡片按 `p.subjects`
逐条渲染,同 id 三位在页面上与三个不同主体长得一模一样,页面上没有任何一处读得出"这三张卡共用一个 id"。

本槽只做浏览器这一端的入口,**不发明第二套去重语义**:规则、默认档(预览)、落库口径、单位词、
计费(零)一律与 CLI 那条命令同一份。

## 二、入口在哪、确认闸怎么走

| 面 | 落点(现取) |
|---|---|
| 入口位置 | 主体库页头按钮行,`js/roles.js` 的 `dedupeBtn`,**两处头部行各插一次**(独立页 `#/project/<pid>/roles` 与项目详情里嵌入的那一版 `embedded`) |

| 按钮样式 | 沿用现网 `btn sm`(与「✨ 补齐主体图」「📥 从资产库导入」同一行同一档),`title` 里写清代价与零计费 |

## 三、规则单源:页面这一端只注入发号器与单位词

`js/roles.js` 新增两个函数,加起来只干三件事:

```
dedupeScan(subs)  →  Domain.dupIdScan(subs, taken => 避让已占用 id 的 Store.uid('sj'))
                     再把中性单位 n 换成主体侧的 seats
openDedupe(p, done) → 预览一屏 + 确认那一下按 plan 逐位写 id
```

- 「首次出现留原 id、后面每处撞车各发一个新 id」这套规则**一个字都没抄到页面上**:它只在
  `Domain.dupIdScan` 一份,CLI 两条命令与页面这条入口三处同读。抄一份到页面上行为可以完全一样,
  接得住那一手的只有源级判据(见 §五 M4:行为面全绿、只红源级那一条)。
- 发号器由调用方注入,故派生里照旧零随机源零环境引用(UMD 双端同一份的前提);
  浏览器注入的是 `Store.uid('sj')`,`do…while (taken.has(nid))` 避让本轮已发出的 id,
  与 CLI 侧 `crypto.randomBytes` 那一圈同形。
- 单位词 `seats` 由这一层换上(主体库里没有"行"),`keepOrder` 只透传派生那一份、页面不自己算"留哪一位"。
- **预览与落库同调一个 `dedupeScan`**(两处调用),不各写一份计算:各算一份就会漂,而用户是照预览点头的。
  新 id 有意不复用预览那批(隔着一次重算,库可能已经变了),那句话写在预览屏末尾。

## 八、残留(明令:本文不代修,原话逐条保留)

1. **分镜面没有 `shots-dedupe` 的入口**(本槽明令不做,记账点名给下一槽)。镜头侧那条命令仍只在
   CLI/MCP 上;同 id 多行在分镜表上与两个不同镜头长得一样,页面上要发现它只有批量生成那句 note。
   形状与本槽逐格同形(入口位置在分镜面头部、预览 + 确认闸、规则同读 `Domain.dupIdScan`、
   单位词是"行"、零计费),差别是它要挂在**分集级**而不是项目级(带 epid),
   且要判清挂在四视图哪一处头部、以及 `lastReview.perShot`/`uiSel`/`groupId` 那几处引用面在页面上怎么交代。
2. **入口露出与否只按"有没有重复"分档,没有第二档。** 库里同 id 多位极多时按钮上只报一个总位数
   (`🧹 主体 id 去重(N)`),不按 id 分组报;弹窗里才逐个 id 摊开。有意如此(按钮上信息量有上限),
   但"哪几张卡片是重复的那几位"在卡片本身上仍读不出来——卡片上没有加任何标记,
   页面级的发现仍靠页头那个数。想在卡片上直接标出来是另一问(要判定标在哪一位上:
   同 id 三位里首位与后两位的处境本来就不同)。
3. **note 里那句"页面按钮"没有判据接着。** `Domain.dupSubjectRowsNote` 末句现在同时点名页面按钮与
   CLI 同名命令,而既有判据只钉住"须点名 `subjects-dedupe`"这个名字(以及主体库/删掉或改 id/不许串镜头措辞),
   页面那半被删掉一条不红。有意没加:按钮上那行字面(`🧹 主体 id 去重`)是 UI 文案,
   把它钉进 `domain` 那条判据会让改一个 emoji 都得同轮改判据。
