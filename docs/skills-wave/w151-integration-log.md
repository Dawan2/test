   `expert.evolve` 有意不进任何 playbook 的 `steps`(判据见 5.5 M1),故"跑完主线自动进化"这件事在编排层至今**没有出口也没有口径**——要开它得先定产品口径(什么条件下触发、蒸馏结果无撤回口这一点怎么兜),不是补一行 `steps` 的事。
2. **`js/release.js` 底部那个包着 `Bus.on('*')` 注册的 `catch (_) {}` 仍开着。** W149 收的是自喂自的**病因**(事件名被 `payload` 顶掉,堵在 `js/bus.js`),那个包在订阅注册外面的空 `catch` 是另一件事:
   模块加载时 `Bus` 不在或注册抛错的话,交付门角标从此不再随主线事件刷新,而没有任何一处会说。全仓现取:`js/release.js` 空 `catch` 剩 **1 处**(基线是 2 处),`js/bus.js` **0 处**。
3. **`G-03` 的形态面仍欠(SK-25 的仍欠段现在只剩这一条)。** 浏览器 `autoSmartReview` 把重试嵌在逐镜循环里(一镜连着重抽到达标为止),CLI `produce` 是整集低分子集重抽一轮再复审(集外循环);
   `Domain.reviseRetryLimit` 收的是**次数口径**,而同一份次数在两端数的不是同一件事——两端形态不同构这一面 W150 如实留着,新护栏的仍欠段正钉着它。要合成一份得先定浏览器侧进度面板语义与逐镜计费节奏能否改成分轮,属产品口径。
4. **门槛判定仍有三个消费方、三张投影表形状各不相同**(W147 残留 3 原样未动):判据已收成 `Domain.gateBlockers` 一份,但"某个码该不该投、投成什么危险级/什么文案"仍是三处各自决定,
   且**没有任何一条判据管"新加一档阻塞码时三个消费方要不要跟"**——反向(派生新加一码而某个消费方漏投)零判据。
5. **W147 登记的那条行为余面本槽未收**:`extractDone && !script` 的老项目现在推得出计划,但走到 `project.splitEpisodes` 会回 `blocked / no-script` 并被 `execStep` 记成 `failed`。
6. **W142 残留 1(W135 那句 `assertEq` 与 W137 共享 `fails` 计数器)本槽未动**,耦合照旧:失败含义不混、失败条数会串。
7. **散文那半仍没有判据,而本槽给出了这条的一个新读数。** 三次合并共 15 个冲突块,**全槽零处静默取对侧**;
   但 3.3 那处 W150 在主 `README.md`「智能审片闭环」段末尾的追加**没有进冲突块**——`git` 直接取了对侧,而它取对了。
   与 W142 那次"整段取对侧且取错"的分界这次量清楚了:**取对侧对不对,只看我方那一段这一轮有没有动过**,与那段散文有没有判据无关;
   有判据的仍旧只有数字,而至今没有任何一条用例读那段话。
8. **W144 的行序判据仍不管同号内的先后。** 本槽索引表里没有同号多份的情形,故这一面本槽仍没有实测机会(连续第四槽)。
9. **W140 留的那个人工出口本槽未动,也未收窄。**
10. **本槽是本线第一次有既有用例被改名。** `contract` 那条 SK-25 护栏从"钉两个余面都还欠着"翻面成"钉一面已落地、一面仍欠",覆盖面变大(5.3)。
    由此暴露一件此前没量过的事:**"没删测"的按名成集比对,把"翻面重写"与"真删掉"报成同一种形态**(都是"只在基线里有的 N 条")。
    本槽是靠人工逐条核对新旧两条的断言才判定它没被削弱的,**这一步没有任何机器判据**——下一次遇到既有用例改名,同样要人工比一遍。
