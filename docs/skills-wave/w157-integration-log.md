## 6. 残留与欠账

1. **"两支同 diff 自动收敛"这件事靠的是逐字节相同,不是靠纪律。** 本槽 `w152` 与 `w154` 在占位那一行给出的 hunk 完全相同(连新加那句注释的字都一样),`git` 才把它判成同向、既不给冲突块也不把占位加回来。
   假如两支的注释差一个字、或删除范围差一行,第三次合并就会给出冲突块——那时"按删除收敛"就得靠人手判。**本槽没有任何一条判据管这件事**:全仓 `PLACEHOLDER` 零命中是现取出来的,而不是有用例钉着"这一行不许回来"。
   最接近的是 M2(加回去红 2),但那两条红的是"到手几个文件"与"报错带不带原因",**不是"占位这个字面不许出现"**——即如果有人用别的写法再落一次多余的包,现有判据仍抓得住;而如果有人把占位加回去同时把那两条用例一并改了,没有第三道。
2. **零冲突块 + 两半代码都在,仍可能有既有用例被打穿。** 本槽 W149 那条下载回执用例就是:`js/release.js` 三次合并零冲突块、`storyboardFailed` 六处一处不少,而那条用例在合完 W154 后当场炸在 `Blob is not defined`。
   成因是**它的装配依赖了被删掉的那个兜底**(基线上落地失败被兜底吞掉,故没有 `Blob` 桩也跑得通)。这类"判据依赖旧行为的副作用"**`git` 一个字都不会提醒,冲突块分析也看不出来**——本槽是靠合完就跑全套逮住的。
   W148 那条经验("代码合得上、判据合不上只发生在有断言同时读两边产出的时候")在这里**要补一句**:还有一种是**一侧的行为改动让另一侧用例的装配前提不成立**,它不需要任何断言读两边。
