**周期 5 的实测说明这条演进方向本身需要修正**:本轮功能槽的十次基线选择里,

也就是说,周期 4 认为「『取 head』已经被完全遵守、不足的是没说取哪一支」——**这个前提在周期 5 不再成立**。

更关键的是**为什么会退步**。本槽的判断是:周期 4 末有三条 tip、周期 5 中段并行槽最多时有五支在飞
(`w35` / `w36` / `w37` / `w39` / `w40`),开槽者要在**每一个时点**判断「现在哪一支覆盖最多」,

`w33` 与 `w36` 那两次取中间点,取的都是集成线上「合入某支 head」那种带明显语义的提交——
**在 `git log --oneline` 上看,它们看起来就像一条线的 head**。

因此本轮给出的判据不是再加一条规则,而是**把判断变成查询**:
