```
分集表 p.episodes(集序 + 每集 content)
        ↓  Skills.check('eps', {p, ep}, ctx)                ← 早已存在的分发口,本轮之前 eps 步恒回空数组
  CHECKS['eps.*'](obj) → {pass, level, hits}                 ← 本轮新增的两条实现
```

**判定基面与判定下限**沿用剧本段:一律先去空白(`replace(/\s+/g,'')`),某集去空白正文短于 30 字视为没有正文——不拿"通过"冒充"没判"。

## 3. 两条校验项判据

### SK-14 `eps.stageCoverage` — 六阶段结构覆盖

判据出自 `KB` 条目「六阶段结构」:**开篇期(1-10集)…结局期(86-100集),集数少按比例缩放**,以及开篇期那一句 **前 3 集必须出现第一个大反转**。

段名与集号区间**现取条目正文解析**(`([\u4e00-\u9fa5]{2}期)[((](\d+)-(\d+)`),校验层不写第二份区间数字;条目改写导致字面失配时,契约测试里那条 `assert(/开篇期[((]1-10集[))]/.test(KB.section('六阶段结构')))` 先红,且实现自身在解析不出两段以上时直接不产出结论(不拿默认值冒充条目)。

比例缩放取**累计边界四舍五入**:段 i 覆盖第 `round((from-1)·N/100)+1` 到 `round(to·N/100)` 集,六段不重叠且并起来正好是全表。六集时六段各摊一集,十二集时摊成 1 / 2-4 / 5-6 / 7-8 / 9-10 / 11-12。

| 命中码 | 判据 | 级别 |
|---|---|---|
| `stage-uncovered` | 该段区间内没有一集有判得动的正文;`hits` 带段名、集号区间与该段实际字数 | `warn` |
| `stage-thin` | 该段有正文,但字数不足按集数摊到的份额的三分之一(有集却被压成过场) | `warn` |
| `early-no-reversal` | 开篇期区间内找不到反转信号(反转五式各取其字面可判定的信号) | `warn` |

- **集数少于六段就不判**:按比例缩放必把某段摊成零集,那是算术产物不是剧本缺陷。五集及以下一律不产出结论。
- **份额比的三分之一**是刻意放宽的阈值:分集长度天然不均,宁可漏判也不制造噪音。份额按**集数**摊(该段集数 ÷ 总集数 × 全表字数),不拿条目的百分比宽度当第二把尺子。
- **反转只约束开篇期**:条目只写了"前3集必须出现第一个大反转",后段没写反转不报。
- 条目里的"最少 30 集才有完整弧线"**不判**:平台上的项目普遍不足 30 集,拿它报缺陷等于对每个项目喊一遍,是纯噪音。各段该写什么戏(核心冲突爆发 / 线索汇聚 / 圆满或开放式结局)是语义判断,属审片维度(`G-10`)。

### SK-15 `eps.payoffPlacement` — 付费卡点位置

判据出自 `KB` 条目「付费卡点」:**卡在情绪最高那一拍——反转即将揭晓、爽点即将兑现的前一秒**;**卡点之后第一集立刻兑现承诺的爽点,绝不落空**。

落到分集表上,卡点位置就是**集尾**,兑现位置就是**下一集集首**——这也是本条必须吃集序的原因。

| 命中码 | 判据 | 级别 |
|---|---|---|
| `flat-ending` | 集尾窗口(去空白末 120 字)内一个卡点信号都没有,而本集别处有;`hits` 带分集 id、集号与全文最后一个信号的位置和词面 | `warn` |
| `payoff-not-cashed` | 集尾有卡点信号,下一集开篇窗口(120 字)却找不到兑现信号;`hits` 带该兑现应落在第几集 | `warn` |

- **两组词表都不新写**:卡点信号 = SK-07 的冲突信号词表 + SK-14 的反转信号词表(「情绪最高那一拍」的字面就是冲突顶点或反转前一秒);兑现信号 = 「打脸四步」的**反击 / 释放**两步词表(爽点兑现的字面就是那两步)。判据层不因为多一条校验项就多一份词表。
- **末集不判 `flat-ending`**:全剧收束不需要再卡。
- **全集一个信号都没有的段落不判**:那是"整段没有冲突落点",已经是剧本段 SK-07 的 `no-hook-anchor`,分集段不重复报。
- **下一集正文短于判定下限时不判兑现**:没有正文就没有判定输入(缺剧本本身是问题中心的高危项)。
- 窗口取 120 字与开篇窗口同一口播口径(约 4.5 字/秒,覆盖十余秒),比"前一秒 / 立刻"宽——这是提醒不是门禁。

## 4. 消费点与"只报不拦"

**就绪检查(双端)**:`js/commands.js` 与 `cli.js` 的 `episode.preflight` 各多一段 `.concat(...)`,结论按主线步序拼接:

```
result.checks = Skills.check('script', {p, ep}) ++ Skills.check('subjects', {p, ep}) ++ Skills.check('eps', {p, ep})
              = [钩子锚定, 打脸四步, 台词长度, 引用完备性, 跨镜一致性, 六阶段覆盖, 付费卡点]
```

`episode.preflight` 仍是 `risk: 'read'` / `meter: false` 的零计费命令,`ok`/`status` 仍只由 `Domain.episodeState` 决定。按集调用时**六阶段覆盖仍是整表口径**(单测按 JSON 逐字节断言两种调法给同一份结构结论),付费卡点则只判传入那一集。

**问题中心(低危两条)**:

| 条目 | 粒度 | 为什么是这个粒度 |
|---|---|---|
| `{kind:'eps-structure', sev:'low'}` | **项目级**(挂在主体缺图那条后面,进逐集循环之前) | 判定输入是整张分集表,逐集报会把同一条结论复制 N 遍 |
| `{kind:'eps-payoff', sev:'low'}` | **集级**(与剧本面同在未拆镜等早退分支之前) | 卡点是这一集集尾的事,定位到集才可跳转自查 |

两条都走导航自查(不挂命令,点它不会发起任何生成)。选低危同剧本面:发布门 G2 只数高/中危(`js/release.js` 本轮一行未动),**低危不改任何存量项目的门禁状态**。
