## 一、先 live:递同 id 两镜到底会发生什么

真 `server.js`(临时 `MV_DATA_DIR` / `MV_UPLOADS_DIR` / `MV_CONFIG`)+ 真 `cli.js` 子进程,
四段现跑,读数原样抄下来。

### 1.1 两条路并排:导入过闸,逃生舱不过闸

同一份 `shots.json`(两行都写死 `id: "sh_dup"`):

| 走哪条路 | 回执 | 落库 id | 唯一数 |
|---|---|---|---|
| `shots-import`(W226 闸) | `{"imported":2,"total":2,"replaced":true,"renamedIds":1}` + 一句 `log` | `["sh_dup","sh_mtda8g3e_fc6d7b4f"]` | 2 |
| `state-put --file state.json`(缺 `--force`) | exit 2 `全量覆盖将丢弃服务端当前数据,确认请加 --force` | 未改动 | — |
| `state-put --file state.json --force` | exit 0 `{"rev":5}` | `["sh_dup","sh_dup"]` | **1** |

逃生舱那一路落库后两行内容各是各的(`plot` 为 `["A 行","B 行"]`、`prompt` 为 `["A 提示词","B 提示词"]`),
不是"把同一行写了两遍",是**两行各自完整、却共用一个寻址键**。

### 1.2 落库之后:第二行结构性够不着

- `shot-set p ep sh_dup --patch '{"plot":"改过的剧情"}'` → exit 0,读回 `["改过的剧情","B 行"]`:**改的永远是首行**;
- 点名这一个 id 跑一次批量生成(两行都未确认时,借确认闸把行数如实印出来,零上游零计费):

```
exec episode.generateVideos --args {"pid":…,"epid":…,"shotIds":["sh_dup"]}
→ blocked unconfirmed「2 镜未确认已跳过」
  skipped: [{"shotId":"sh_dup","order":1},{"shotId":"sh_dup","order":2}]
```

一个 id,选人闸按行筛出**两行**;不点名的整集档同样是这两行。

### 1.3 账面:一个 id 点名一次,账本登记两笔

两行都确认、都缺底图,上游换成连不上的假 key(必失败 → 失败退费,零真钱):

```
[2] 点名 1 个 id → total=2
[2] 余额 100 → 100(失败退费)
[3] 账本 operations 逐笔:[{"action":"image.gen","status":"refunded"},{"action":"image.gen","status":"refunded"}]
```

**两笔独立的计费登记**(此处停在补底图那一步,视频那一笔同理逐行各来一笔;
W226 记账件里有换假 key 跑到 `usage` 报 `count:2 charged:10` 的那一档读数)。
且两次上游请求印出来的都是**首行**的提示词(`创建视频任务:A 提示词…` 两遍)——
第二行既跑不到自己,也没有任何产物落到它头上。

### 1.4 「灌进去会长回来」:闸修好的表被逃生舱一把打回

```
再走 import 闸 → {"imported":2,"total":2,"renamedIds":1}   → 唯一数 2
再灌同一份 state.json(--force)→ exit 0                     → ["sh_dup","sh_dup"] 唯一数 1
```

这就是交接点名的那一格:**只迁存量而不判这条路,修完还会长回来**;
反过来只堵这条路而不管存量,老库里躺着的照旧两行都跑。两面是同一件事。

### 1.5 同类全量覆盖 API 一并现取

直打 HTTP(不经 CLI),**增量分桶**那一路同样不校验:

```
PUT /api/state {rev, changes:{projects:{pid: …三行同 id sh_x…}}} → HTTP 200
GET /api/state → 落库 ["sh_x","sh_x","sh_x"] 行数 3
```

故"不校验"不是 `state-put` 一条命令的事,是 `PUT /api/state` 这个端点的契约:
**除服务端权威键(`users`/`creditLogs`/`orders`/`session`,由 `shieldBilling` 剥离回填)外整树原样落库**。

### 1.6 谁调用

| 调用方 | 走哪条 | 现取 |
|---|---|---|
| 人手 CLI `hujing state-put --file f.json --force` | `{rev,state}` 全量 | `cli.js` 里 `CMD['state-put']`,`--force` 才放行 |
| MCP | — | `mcp.js` 里 `state-put` / `state_put` / `hujing_state*` 字面 **0 处**(工具表压根没有这条) |
| 浏览器 | `{rev,state}` 全量 与 `{rev,changes}` 增量 | `js/store.js` `syncPush`:无基线或 409 合并后 `_forceFullPush` 时推整树,平时按桶推增量;`state-put` 字面在 `js/` 下 **0 处** |
| 测试夹具 | 两路都有 | `tests/e2e.js` 与 `tests/live-gen.js` 直推整树种数据,`tests/integration.js` / `tests/cli.smoke.js` 多走增量 |

要点:**浏览器自己的保存路径与逃生舱是同一个端点**。所以"在端点上设闸"不是给一条调试命令加约束,
而是给每一次前端保存加约束;而浏览器那一侧的写入点(`blankShot` / `WfCore.normalizeLLMShot` /
节拍板 / 版本回滚)一律走 `Store.uid`,本来就产生不了重复 id(W226 §1.4 那张表)。

## 二、停工判定:逃生舱的产品意图是不是「原样覆盖、调用方负责」

交接给的判据是:**若产品意图就是原样覆盖、调用方负责 → 只记账 + 钉测试,产品可零 diff;
若它是内部写入且用户可误用 → 与 import 同形设最小闸。**逐条现取:

1. 它不是内部写入,是**面向人的调试出口**:`README.md` 命令总览写「任意复杂操作的逃生舱」,
   `docs/AI助手接入指南.md` 写「仅限调试」,CLI 帮助写「危险操作」,且**多要一个 `--force`**
   才肯发出这一次往返(§1.1 的 exit 2 是现跑的)。
2. 它写的是**整棵树**,不是分镜表。改一个镜头 id,就得连带改所有引用它的地方——
   `lastReview.perShot[].shotId`、`ep.uiSel`、镜头组 `groupId`、审片报告里那些 `shotId`。
   **改得干净的那种改法叫迁移,不叫闸**;只改分镜表那一列的"同形改发新 id",落到这条路上
   会把树改成自相矛盾的样子(镜头改了名,审片记录还挂在老名上)。
3. 另一种同形处置「撞 id 整份拒收」会把逃生舱唯一那件活干掉:
   **照原样恢复一份 `state-get` 存下来的备份**。存量库里本来就有重复 id 的用户,
   恢复自己的备份会被拒——而这条路正是他修那批数据的入口(§三)。
4. 反过来看"用户会不会误用":这条路的三处文字此前都只说了"危险""仅限调试""全量覆盖",
   **没有一处说过"镜头 id 唯一性归你自己保证"**。W226 与 W229 两槽的记账里各留了一段
   "这条路仍开着"的交接,说明它反复被当成疑似漏洞重新捡起来。这一格是真缺的,缺的是**声明**,不是闸。

**故:停工。产品行为零 diff,补齐声明并钉住判据。**

另有交接给的例外条款——「除非现跑证明不迁则每次选人都双扣费**且没有别的入口可修**」:
双扣费那一半属实(§1.3),但**后一半不成立**,现跑两条可修入口:

```
a) shots-import 整表重导 → 唯一数=2,renamedIds 如实回报
b) 逃生舱自己也能修(state-get → 把第二行改个 id → state-put --force)→ ["sh_dup","sh_fixed"]
```

存量重复有入口可修,故**本槽不做存量静默迁移**(它会改动已落库数据的寻址键,
用户按老 id 记的脚本会当场失配——W229 §9.1 已判过一次,本槽复核后维持)。

## 四、钉测试:两条路的判据成对

新增一条单元用例(`commands` 套件,紧挨着 W226 那条 `shots-import` 用例):
**`CLI state-put 逃生舱:整树原样落库(同 id 两镜照落两行),三处契约明写唯一性归调用方`**。
判据分两层:

- **行为层**:在 `loadCli` 沙箱里换掉 `api` 收下递出去的整树——
  `JSON.stringify(整树)` 与文件逐字节相同(含 `lastReview.perShot[].shotId` 仍是 `dup`)、
  `rev` 原样透传、同 id 两行原样两行;缺 `--force` 抛 exit 2 且**一次往返都不发**。
- **声明层**:`cli.js` / `README.md` / `docs/AI助手接入指南.md` 三处各要有那句锚点,
  且每一处锚点的 ±300 字符内要点名 `shots-import`;另把**对照面**钉上——
  `shots-import` 那道闸的判据(`taken.has(s.id)` → `renamedIds`)得还在。

另加真链路两套:

- `tests/cli.smoke.js` **+4 条**(真 server + 真 CLI,同一份"同 id 两行"两条路并排跑):
  导入档 `renamedIds:1` 且落库两个不同 id;`state-put` 缺 `--force` exit 2;
  `--force` 后照落两行同 id;落库后 `shot-set` 改的永远是首行。
- `tests/integration.js` **+1 条**(HTTP 直打):`{rev,changes}` 灌同 id 三行 → 200,读回三行原样。
