## 二、先量现网(改测之前,同一副夹具喂现取树)

夹具:一集一行分镜 `s1`(已出片),桩下到 `fetch` 那一层(`GET /api/state` 回一份拷贝,其余路由一律 500 并把路由名带出来)。逐条点名 `没这镜`:

| 入口 | 现取 exit | 现取错话 | 现取往返清单 |
| --- | --- | --- | --- |
| `shot-set` | **4** | `镜头不存在:没这镜` | `GET /api/state` |
| `shot-confirm` | **4** | 同上 | `GET /api/state` |
| `gen-shot-image` | **4** | 同上 | `GET /api/state` |
| `gen-shot-video` | **4** | 同上 | `GET /api/state` |
| `review-frames` | **4** | 同上 | `GET /api/state` |
| `review-note` | **4** | 同上 | `GET /api/state` |

同族对照(同一棵树上真跑出来的码,不读源码字面):`项目不存在` **4**、`分集不存在` **4**、`主体不存在` **4**;参数错那一族 `shot-set` 缺 `--patch` 仍是 **2**。

即:退出码这一格**实现本来就对**,缺的只是判据——`CliError('镜头不存在:' + sid, 4)` 这个 `4` 写成 `1`、或整句改走 `need(…)` 出 `2`,现取树上**一条都不红**(读它的那两条批量用例走的是宽判 `/镜头不存在/`,只认错话)。而 exit code 是 Agent 分流的唯一依据(4 是「点名的东西不在」,与 2 参数错、5 服务端错各归各):码一漂,调用方就把「这一镜不在表里」当成自己参数写错或服务端故障,重试与报错都走错分支。

另量到一格、**本槽有意不判**:`findShot` 只认 `x.id === sid`,`shot-confirm p1 ep1 1` 现取报 `镜头不存在:1`(不认镜号),而 `exec` 那一侧的 `execCtx` 是「镜头 id 或镜头号」两认。两侧有意不同形,W317 起明令不代补,故本条判据里一句不提按名 / 按号——加一句「不认镜号」等于代定那个分位。

## 三、加的那一条(`tests/unit.js`,`commands` 套件,+1)

紧挨 W317 那条主体侧同形用例落笔,四档:

1. **六条按 id 点名单镜的入口逐条同形**:必须抛 / 错话点名用户给的那个串 / `exit === 4` / 往返清单恰是 `GET /api/state`。第四问量的是同一件事的另一半——**取行在取图、取片、抽帧之前**,点错镜时一分钱的上游都不许下发;把 `findShot` 挪到 `genImage` / `genShotVideo` 之后,退出码仍是 4 而钱已经花掉,只有往返清单读得出来。
2. **库里那一行逐字段未动**(点错镜的一趟不许顺手改表)。
3. **同一档**:`项目不存在` / `分集不存在` / `主体不存在` 现跑也须是 4——这一格读的是同一棵树上真跑出来的码,哪天有人把这一族分叉成两个码,先红在这里。
4. **参数错那一族仍是 2**:缺 `--patch` 出 2 且错话带 `--patch`。没有这一格,把 4 与 2 并成一个码时第 1 档只需跟着改数字就能过。
