## 1. 病灶:两个数字七个周期没有断言,一对同名用例打掉了取证工具

本槽治的是两件被连续两份核验报告点名、但都还没人接的事。

### 1.1 `integration` 与 `cli.smoke` 的数字在对账之外

W23 立文档数字对账契约时,把这两个数**明确留在外面**,理由写在 `w23-readme-count-assert.md` §5:

> 未纳入对账的是 `integration.js` / `e2e.js` / `cli.smoke.js` 三个套件的断言数——
> 它们的用例不是静态数组,静态实计会得到假值。

这条判断在当时是对的,但它此后成了一个七个周期没关的洞。`w63-cycle6-audit.md` 与
`w96-cycle7-audit.md` 各自实测过同一件事:把 README 的 `integration` 数改错、把 `cli.smoke` 数改错,
**单测全绿**。周期 7 那份报告把它写成本轮"最尖锐的一处对照":同一个洞一个字没堵,
而周期 6 有 3/14 支掉进去、周期 7 是 0/17——**数字这一轮全对,靠的是人守,不是断言**。

本槽在基线上复现了两次(变异 1、2,见第 4 节):`126 → 105`、`97 → 64`,两次都 **461/461 全绿**。

### 1.2 `w84` 与 `w87` 留下的一对同名用例

基线上跑 461 条用例,只有 **460 个不同的用例名**。重名那条是

```
contract · 注册表全仓持有者名单:每条 def 的字面持有者恰好只有 js/prompts.js(谁在别处抄第二份即红)
```

`w84` 与 `w87` **各自独立**把"逐槽各写一份的持有者名单"改写成了"按注册表现取的一条",
两条名字撞了;W90 按并集解法把两侧都留下(取并集本身没错——它不能替两个槽判断哪一份该弃)。
`w87-role-editor-prompt.md` §210 当时其实已经写下"注意 W84 那条与本槽同名同形,合并时只留一条",
但那是一句散文,合的时候没有任何东西会拦。

**它的害处不在这条冗余用例,在取证方法上。** 本目录从 W21 起一直在用「用例名集合双向比对证明没删测」,
`w96` 实测这套工具在 `w85 → w90` 这一步会得到**新增 9 条**,而真实增量是 **10 条**——
集合口径把重名那条吃掉了。也就是说:**只要仓里存在一对重名,"删了一条真用例"就可能被"少数出一条重名"抵消掉,
而那正是这件工具唯一要证明的事。**

## 2. 落地 A:两个套件的用例数进 `contract` 对账

新增一条用例,接在既有那条「单元测试用例数由 `SUITES` 套件表求和」之后,**既有五条一条不删**。

### 2.1 取数口径:按套件自己数用例的那个口径静态点数

两个套件都要起真实服务子进程(`integration.js` spawn `server.js` + HTTP,`cli.smoke.js` spawn 临时 server + 逐条跑 `cli.js`),
单测里跑不动,所以不能"跑一遍取实测"。**但也不必**——两个套件登记用例的方式都是同一个形状:

| 套件 | 登记形态 | 收尾那句总数 |
|---|---|---|
| `tests/integration.js` | 每条用例一行 `report(name, cond, detail)`,`report` 自己 `PASS++/FAIL++` | `` `\n===== ${PASS}/${PASS + FAIL} PASS, ${FAIL} FAIL =====` `` |
| `tests/cli.smoke.js` | 每条用例一行 `report(name, ok, detail)`,`report` 自己 `results.push(...)` | `(results.length - failed.length) + '/' + results.length` |

所以**行首 `report(` 的行数,就是套件末尾那句总数的口径**。断言按这个数去核 README,
而不是另立一套"数 `assert` 调用"之类的第二口径。

对账的是**用例总数**,不是通过数:`cli.smoke` 那 2 项失败(`未登录 whoami → exit 3`、
`llm --json mock 链路`)与 `master` 逐字同名、已连续七个周期挂在同一位置,与本槽无关,
也不影响总数这个数。

### 2.2 三层守住"静态点数就是实跑总数"

W23 那句"静态实计会得到假值"的成立条件很具体:**`report` 落在循环或回调里,一行会跑出多条。**
本槽不去论证这件事不会发生,而是把它写成断言:

1. **每条 `report(...)` 必须独立成行**——全文件 `report(` 的出现次数(减去那一处 `function report(`)
   必须恰好等于行首 `report(` 的行数。塞进 `forEach`/`map`/三元/表达式里,这一条当场红(变异 5 实测)。
2. **末尾那句总数必须由套件自己的计数器算出**,不许手写数字——两个套件各按自己那句的写法钉住正则。
3. **README 那句话删不掉**——沿用 `assertDocNum`:一处都找不到该数字表述同样算红(变异 3 实测)。

这三层的净效果是**失败关闭**:哪怕将来有人真把 `report` 放进循环,静态数会小于实跑数,
而 README 上写的是实跑数,第 1 条先红——不会出现"静态数假、README 也跟着假、两边对上了"的静默通过。

### 2.3 `tests/e2e.js` 为什么不一起收进来——这不是偷懒,是这条判据真的不成立

顺手实测了 `e2e.js`:README 写 **63 项断言**,而行首 `report(` 只有 **56** 行,全文件 `report(` 出现 58 次。
差额来自它按 tab 列表循环那一处:

```
for (const t of TABS) { … report('项目tab·' + t, …); … }
```

**W23 那句"静态实计会得到假值"在 `e2e.js` 上是字面成立的**,而在 `integration.js` / `cli.smoke.js` 上不成立——
这个区别此前只是没人分开量过。第 2.2 节第 1 条断言正是这个区别的机器可查版本:
`e2e.js` 若照同样口径接进来,那一条会立刻红并点名它。**故本槽只收那两个真能对账的,
`e2e.js` 的 63 如实留在对账之外**;要收它得先把那个循环里的用例改成逐条登记,超出本槽范围。
另按目录纪律,`node tests/e2e.js` 只在用户明确要求时跑,本槽没跑,故这个 63 本槽也**没有独立实测过**,
不写成"已核实"。

## 3. 落地 B:改一条重名 + 用例名全局唯一

### 3.1 改的是哪一条

**只改用例名,判据一个字未动,两条用例都留着。** 改的是 `w84` 那一份(现落在 `tests/unit.js` 第 5550 行,
紧跟在「镜头「按指令改」人设(源级)」之后,注册表条数下限写 `>= 20`):

| | 改前 | 改后 |
|---|---|---|
| 名 | `注册表全仓持有者名单:每条 def 的字面持有者恰好只有 js/prompts.js(谁在别处抄第二份即红)` | `注册表全仓持有者名单(镜头「按指令改」段的一份,与主体段那条同判据):每条 def 的字面持有者恰好只有 js/prompts.js(谁在别处抄第二份即红)` |
| 判据 | 26/20 条 `def` 逐条全仓扫 + 条数下限 + 同 `def` 键组点名音色推荐那一对 | **逐字不变** |

`w87` 那一份(第 5005 行,紧跟「主体「按指令改」人设(源级)」,下限写 `>= 26`)**名字与判据都不动**。

选这一侧改、并且把"与主体段那条同判据"写进名里,是因为两条现在确实是同判据的两份:
名字要能回答"为什么这里有两条",否则下一个人读到两条同形断言只会再纠结一次该不该删一条。
**不改判据、不删条**——这一对冗余该不该合成一条是收编面的事(两条的下限分别钉着 20 与 26 两个时点),
本槽只治重名。

### 3.2 新增的唯一性断言

```
用例名集合大小 === 用例条数(取自 SUITES 全表)
「套件 · 用例名」标签同样逐条唯一(不许靠套件前缀去重)
```

第二条是因为取证时打印的是 `套件 · 用例名`:跨套件同名一样会把集合口径糊住,
所以两层都钉。重名时报错点名是哪几条撞了,不是只给一个数字。

**这条断言只拦重名,不许拿它当删测的理由**:它和「用例名集合双向比对」是配套的两件——
前者保证后者的口径不被吃掉,谁把一条用例改名去躲问题,后者那一向照旧报"这个名字消失了"。

| 4. `tests/integration.js` 真加一行 `report(...)`(不改 README) | 红:`实测 127,文档 126` |
| 5. 把一行 `report(...)` 改写成 `[1,2].forEach(i => report(...))` | 红:`每条用例须是独立一行的 report(...) 调用:期望 125,实际 126` |

变异 5 是本槽最想接住的那个场景:**它红的不是数字,是"静态点数不再代表实跑条数"这件事本身**——
即 W23 当年顾虑的那种假值,现在报得出来。
