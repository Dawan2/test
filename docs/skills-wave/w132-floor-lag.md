# W132 · 棘轮下限「该抬没抬」补机器判据:FLOOR 与 live 的差额从无界钉成不超过 3 格

> 槽位范围:`tests/unit.js` 的 `contract` 套件新增 1 条用例 + 抬 2 个既有下限字面,`README.md` 同步两处数字,
> `docs/skills-wave/README.md` 份数与索引行,本记账件。
> **零产品代码改动**(`js/`、`server.js`、`cli.js`、`mcp.js`、`billing.js` 一行未改),不动发布门口径、不新增计费动作、**不删任何用例**。
> 基线 `cursor/w129-integration-1481` head `2f6880c`(开工现取核实相符),本槽不做任何合并。

## 1. 病灶:棘轮只拦"往下走",拦不住"停在原地"

`tests/unit.js` 的 `contract` 套件里有四个 `FLOOR` 字面:三套件用例数那条表里的
单元 / 集成 / CLI 冒烟三格,加上记账件份数那条的一格。四格的判据都是同一个形状:

```
assert(live >= floor, …)
```

这个方向拦得住"少一条用例"。拦不住的是**下限自己落在后面**:

- **加了用例不抬 FLOOR**:`w128` 一槽加了 6 条单测,抬了记账件那格(142 → 143),
  单元那格留在 480 而 live 已是 486。**全绿,一条不报**——`w129-integration-log.md` 第 4.2 / 5.7 节量出并如实登记了这一处。
- **把 FLOOR 字面改小而一条用例都没删**:同理全绿。下限从 486 调回 480,`live >= floor` 照样成立。

两种改法的后果是同一个:**下限守的水位低于实况**。差额里的那几条用例删起来只剩"文档数字对账"一道守卫,
而 W121 立这层棘轮的全部理由,恰恰是"文档数字与实测两边一起改小时相等判据仍然成立"。
下限一旦落后 N 格,棘轮在这 N 条上就等于不存在——**它没坏,只是保护的水位不是今天这个水位**。

W105 当年把它写成 `>=` 而不是 `==` 有明写的理由(`==` 会让每加一条用例都当场红,等于再造一个要人工同步的数),
代价就是这一路至今**零机器判据、只靠人记得**;W129 交接第 2 条把它挂了出来,本槽收它。

## 2. 落地:钉的不是"下限等于实况",是「差额有上限」

新增一条用例,接在三套件棘轮那条之后,**既有四条断言一字未改**(只按各自写明的规矩抬了两个数字,见 2.4):

```
const SLACK = 3;
…
assert(live[label] - floor <= SLACK, label + ':下限 ' + floor + ' 落后实测 ' + live[label] + ' 共 ' + … );
```

四格逐格判,报错点名是哪一格、落后几格。**判据不取 `live === floor`**:那正是 W105 拒过的那条路——
每加一条用例都必须同轮改这个字面,棘轮就变成第二个要人工同步的数,而且是"改小一处即静默"的那种数。
这里换的是判据类别(W129 交接第 2 条点名的两条路之一):**差额本身进对账,只不过对的是上限而不是等号**。

这么钉之后,差额有了一个可以说出口的含义:**它就是"能被静默删掉的用例条数"上限**。
今天这个数无界(单元那格实测松过 6 格),本条把它钉成 3。

### 2.1 为什么两种病灶归到同一条判据

「加了测不抬下限」与「把下限改小」在源码里是两个动作,在实况上是同一个状态:`live - floor` 变大。
判据取的是状态而不是动作,故两条路都红在同一句上,报错文案里也把两条一起写明
(「加了用例/记账件就把那个 FLOOR 字面抬到当轮实况,把它改小同样红在这里」)。
这与本套件"一条用例一个失败含义"的惯例不冲突:这里的失败含义只有一个——**下限守的水位低于实况**。

### 2.2 上限为什么是 3

3 是**允许被静默删掉的条数**,不是随手取的宽限:

- 本目录的槽单轮增量常见 1–3 条(本槽 1 条),故**常规加测槽照旧不必动那些字面**——
  这正是不写 `==` 换来的东西,若上限取 0 就退化成 W105 拒过的严格相等。
- 连着几槽都不抬、或一槽加 4 条以上不抬,当场红。`w128` 那次松 6 格,若当时有本条则合入前就红。
- 差额越大,棘轮失效的面越大;3 条是"删掉之后评审还看得出来"与"每轮都得改字面"之间的取值,
  它是**一个字面**,要调只改这一处,而调它就得在同轮记账件里说明理由——与四个 `FLOOR` 自己的规矩一致。

### 2.3 四个 FLOOR 字面现取自本文件源码

判据不重抄一份下限数字(抄一份就是再造一个会漂的数),而是从 `tests/unit.js` 自己的源码里把四个字面读出来:
三套件那张表按 `['套件名', 数字,` 的行形取三格,记账件那条按 `const FLOOR = 数字;` 取一格,
**取不到即红**(`assertEq(floors.length, 3, …)` 与 `assertEq(ledger.length, 1, …)`)。
这一层是有意加的:把 `FLOOR` 改名、挪窝、或整条判据搬走时,本条不会静静退化成恒真句,而是报"取数口径失效"。
live 那半各按各自套件的既有口径现算(`SUITES` 求和 / 行首 `report(` 行数 / 目录里的 `wNN-*.md` 份数),
与被它盯着的那两条用例取同一个口径,不另立第二种算法。

### 2.4 顺带抬的两个字面

按各自条目写明的规矩抬,只改数字、其余判据一字未动:

| 下限 | 抬档 | 依据 |
|---|---|---|
| 三套件棘轮里的 `unit` FLOOR | `486` → **`487`** | 「新增用例时把下限抬到当轮实况」,对应本槽这一条用例 |
| 记账件份数 FLOOR | `144` → **`145`** | 「新开一槽记账时把下限抬到当轮实况」,对应本记账件这一份 |

集成与 CLI 冒烟两格实测就是对的(130 / 102),一个数字没改。抬完四格差额**全为 0**。

## 6. 交接

1. **差额 ≤ 3 意味着 3 条以内的静默放松仍然存在**:把下限调小 2 格、或加 2 条用例不抬,本条不报。
   这是不写 `==` 的直接代价,写在这里而不是藏着——要再收紧只需把 `SLACK` 改小,
   但改到 0 就等于 W105 拒过的严格相等,得先答"每加一条用例多改一处字面"值不值。
2. **本条盯的是四个 `FLOOR`,不盯别的下限**:以后再立新的棘轮字面,得同轮把它接进这条的取数口
   (三套件那张表加一行会自动被认到,别处新写的 `const FLOOR = N;` 也会被那条单条断言的计数当成"多出来一处"而红——
   这是有意的:新下限要么进这两处形态之一,要么同轮改本条)。
3. **`tests/e2e.js` 仍在下限与对账之外**(那处 tab 循环让行首点数不等于实跑条数),本槽未扩。
4. **判据只覆盖条数,不覆盖判据强度**:把一条用例的断言体掏空成 `assert(true)`,四格数字全不变,本条不报。
   这一条与 W121 交接第 1 条同源,仍开着。
5. **W129 交接第 2 条到此可以划掉一半**:"下限变松是静默的"不再成立(超过 3 格即红),
   但"下限与 live 严格同步"仍不是机器判据,而是记账纪律。
