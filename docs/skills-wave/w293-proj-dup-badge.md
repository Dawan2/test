> 起点 `origin/cursor/w292-integration-a523` 尖 **`501fe37ab449d72a77b4f7fe55f4f9cd6fc1e0c8`**
> (`git fetch` 后现取,`checkout -b` 完 `rev-parse HEAD` 核过,与交接自称的 `501fe37` 逐字节相同)。

## 一、收的是哪一条

W291/W292 残留,原话:

> 发现存量重复仍得先走到分集工作区 / 主体库那一页。项目详情面与分集列表上没有对应的角标。

W283/W285/W287/W289/W291 五槽把去重这条链从规则到卡片小标铺完了,但**每一处露出点都在"走进去之后"**:
主体库那一页的页头、分集工作区那一行集级顶栏、以及那两页各自的卡片小标。
项目详情面是每条进来的路都要过的那一屏(路由 `#/project/<pid>` 与各处重渲都落在它上面),
而它此刻**一枚角标都没有**——整树导入/恢复与逃生舱 `state-put` 写进来的重复 id,在这一屏上与干净项目
长得一模一样;用户要发现自己在多付钱,只剩"先点进某一页"这一条路。

本槽只补那一格:**项目详情面各报一个数,点过去落到能收拾它的那一页。**

## 二、挂点(动手前量的那一遍)

明令「量清:项目详情模板挂在哪几个入口(独立路由 vs 嵌入),少挂就有一条进来看不见」。量的结论是
**模板只有一份,故挂一处一条路不漏**——与 W291 那张"五档各挂哪一处"的表形状相反,那边是五种渲法、
这边是同一份渲法的八条入口:

| 进来的路 | 现取 | 走的是哪份模板 |
|---|---|---|
| 路由 `#/project/<pid>` | `js/app.js:130`(`pd` 那一支) | `Views.projectDetail` |
| 上传剧本 → 稍后分集 / 主体确认完 / 生成分集完 | `js/proj-upload.js` 三处 | 同一份(直调重渲) |
| 新建分集完 | `js/episodes.js` 一处 | 同上 |
| LLM 分集落库完 | `js/episode-util.js` 一处 | 同上 |
| AI 策划 / 剧本译制落库完 | `js/proj-planner.js` 两处 | 同上 |

`Views.projectDetail` 全树**定义 1 处、调用 8 处**(`js/app.js` 那一处就是路由那一支,其余七处是上表后四行),
八条入口一律渲同一份模板。故"少挂一处就有一条进来看不见"在这一层不成立;真会漏的是**另一个维度**:
项目页有八个 tab,角标挂进某个 tab 的**内容体**里就只有那一个 tab 看得见。
量出来的挂点因此是**tab 行那一条**(八个 tab 共用它,与 W287 挂集级顶栏同形),
判据逐 tab 真渲一遍(M2 现跑正是这一格)。

调用面按源级钉的是**哪几个文件在调它**(现取 `app.js` / `episode-util.js` / `episodes.js` /
`proj-planner.js` / `proj-upload.js` 五个),而不是调了几次——多一处直调重渲不必多挂一处角标,
真长出第二份项目详情模板时那条判据先红。

嵌进「主体」tab 的主体库那一页(`Views.roles(host, pid, true)`)照旧自己扫自己那一份、
渲自己的页头入口与逐位小标——本槽一个字没动它。

## 三、报什么数、点到哪儿

tab 行上两枚(现网 `tag yellow` 同形,只在真有重复时露出来):

```
🧹 主体 id 重复 2 位        🧹 镜头 id 重复 3 行(2 集)
```

分集列表上,撞车那几集的卡片各挂一枚(干净那一集一枚不挂):

```
第一集  分镜 4 镜  镜头组 未分组  🧹 id 重复 2 行
第二集  分镜 2 镜  镜头组 未分组
第三集  分镜 2 镜  镜头组 未分组  🧹 id 重复 1 行
```

四件分寸定在这三枚上:

| 分寸 | 取的口径 | 不取那一种会怎样 |
|---|---|---|
| **报的是"要改几位 / 几行"** | `plan.length`(首位、首行不算) | 改报"共几处撞车"就与那两页入口上的数对不上——而用户是先在这一屏读到数、再点进去核计划的(M6 现跑) |
| **镜头那枚合计报 + 摊在几集上** | 全项目 `Σ plan.length` 与撞车的集数 | 只报总行数的话,"去哪一集收拾"仍得自己一集一集翻 |
| **点过去落到能收拾它的那一页** | 主体 → 「主体」tab;镜头一集 → 那一集工作区,多集 → 「分集」列表并清掉搜索词与页码 | 多集时跳某一集是猜(M7);回列表却不清搜索词,可能整屏被过滤光、那几枚卡片角标一枚也看不见(M8) |
| **单位词各按自己那一侧** | 主体数"位"、分镜数"行" | 照抄对面那个字即红(M4);项目页不是新造一套词,是把那两页的词原样带上来 |

悬停那两句说明各报三件事:撞了几位/几行共用同一个 id、代价(按 id 只取得到首位/首行,而批量补图与
批量生成逐位/逐行计费)、去哪儿收拾(点名「🧹 主体 id 去重」/「🧹 镜头 id 去重」那道预览 + 确认闸)。
只报警不给活路等于没说——这一句与两条 CLI 命令、两页入口的措辞同一套分寸。

## 四、数从哪来:只读两侧现成那一份

明令「扫描只读现成 `Domain.dupIdScan` / `dupIdMarks` / 已有 `dedupeShotScan`/`dedupeScan`,
禁止再抄一份规则」。落地形状是一条直链,一处扫描喂两个消费方:

```
js/episodes.js  dupIdBadges(p)              ← 整页恰 1 处(源级钉着这个 1)
  RoleOps.dedupeScan(p.subjects)  .plan.length   → seats:主体库要改几位
  SB.dedupeShotScan(ep.shots)     .plan.length   → 逐集要改几行(撞车的集才进表)
       ↓  const dup = dupIdBadges(p)  在 render 里恰 1 次
       ├─ tab 行那两枚角标(八个 tab 共用)
       └─ renderEpisodes(shown, eps, pages, dup) → 分集卡片那几枚(逐集行数从 dup 现取,不再扫)
```

规则(首次出现留原 id、后面每处撞车各发一个新 id)在 `Domain.dupIdScan` 一份没动;
两侧那份扫描(`js/roles.js` 的 `dedupeScan`、`js/storyboard.js` 的 `dedupeShotScan`)也一字没动
——它们各自注入自己那一端的发号器(`Store.uid('sj')`/`Store.uid('sh')`)与单位词,
项目页这一屏**现取它们**,于是这一屏报的数与那两页入口上那个数天然同一个。

**为什么不在 episodes.js 里直调 `Domain.dupIdScan`:** 那就得在这一屏再注入一遍发号器
(而这一屏一个 id 都不发)、再挑一遍单位词。抄一份到这里行为可以完全一样(M9 现跑,行为面逐字节等价),
而两份计算迟早对同一份脏数据给出两套数——那时这一屏报的"有 2 位要改"与用户点进去看到的计划对不上,
"发现存量重复"这件事本身就不可信了。

`Domain.dupIdMarks` 本槽**没有消费**:它出的是"这一位/这一行是第几处"的逐位次表,
而项目页这一屏渲不出主体位与分镜行(它渲的是项目、tab 与分集卡片),没有可挂位次的对象。
挂到分集卡片上是另一件事(逐行落点,见 §八残留 1、明令点名下一槽)。
