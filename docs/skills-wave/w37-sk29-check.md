# W37 · SK-29 交付契约门校验面落地(上游定稿契约判成结论)

基线 `cursor/w34-integration-07a0`(head `0e79638`,含 W30/W31/W33/W32 四支收敛)。
本槽只落 SK-29 的**校验半**,不含合并、不动发布门、不动交付打包、不动计费。

## 1. 起点:SK-29 在基线上仍是 pending

动工前先按纪律核对短名单实况,而不是照着计划表开工:

```js
{
  id: 'film.deliverContract', sk: 'SK-29', name: '交付契约门', stage: 'film', wave: 'W4',
  kinds: ['check'], pending: ['check'], cmds: ['episode.compose', 'episode.produce'], gaps: ['G-10', 'S-07'],
  note: '复用既有发布门与问题清单口径;方法论门挂成可选门默认 warn,既有 fail/warn 口径不动',
}
```

`pending: ['check']` 且 `checks` 为空,`cmds` 里也没有 `episode.preflight`——这一条确实还没有出口。
落地后去掉 `pending`、登记 `checks: ['film.upstreamFinalContract']`、补登 `episode.preflight` 消费点,
`gaps: ['G-10', 'S-07']` **两条都保留**(下面第 6 节逐条说明各清到哪一步)。

顺手核对了并行槽的边界:W35 的 SK-24、W36 的 infra 记账都不落在 `film` 面,本槽不碰那些条目。

## 2. 判定输入:上游定稿契约那件事,在基线上还不是可判定的

`S-07` 记的原话是「交付契约优先级无显式判定:上游定稿目前是**注入给模型的文本约束**,不是可判定的门」。
基线上这件事有两处载体,都不产出结论:

| 载体 | 形态 | 为什么不是可判定的结论 |
|---|---|---|
| `js/agent.js` 的 `upstreamFinal(p, boardKey)` | 把上游已定稿板块拼成「★ 上游已定稿(权威约束,不得偏离)」注入板块 Agent 系统提示词 | 是给模型看的文本约束。约束成不成立、有没有被绕过,系统自己不知道 |
| `js/episodes.js` 板块阶段下拉的软闸门 | 改成「待审核/已定稿」那一刻,上游有未定稿板块时弹一条 `U.toast` 提醒 | 一次性 toast,浏览器独有、不落库、不进任何回执;关掉页面就没了,CLI/服务端拿不到 |

所以本面的判定输入就取这件事本身的两份实况:

- **契约链的阶段**:`p.boards[板块名].stage`(`未开始`/`进行中`/`待审核`/`已定稿`),与上面两处载体读的是同一个持久化字段、同一批字面值。
- **契约背书的产物**:`Domain.workflow(p, online).steps` 里同键步骤的 `done`/`status`/`blockers`。

判两向,共三个码:

| 码 | 判据 | 这一向在说什么 |
|---|---|---|
| `final-out-of-order` | 已定稿板块的主线上游还有未定稿板块 | **契约优先级倒置**:注入给下游的「上游已定稿」缺环——本板块的定稿,背书的是一份尚未定稿的上游 |
| `audit-out-of-order` | 待审核板块的主线上游还有未定稿板块 | 同一条优先级口径的较轻一档:上游还会变,本板块的审核结论可能返工 |
| `final-unbacked` | 已定稿板块对应的主线步骤实况未 `done` | **定稿无产物背书**:契约签了,但它背书的那一步在产物上站不住 |

三条补充口径:

- **上游有多个未定稿时只报最靠前那个**(整条链的第一个缺环),不逐个重复报同一件事。
- **待审核板块不判产物背书**。审核还没过、产物不成立是常态,不是契约冲突;只有「已定稿」才是本面要求兑现的那份承诺。
- **一个板块都没登记过阶段的项目不产出结论**。没在用看板不等于有缺陷,无判定输入即不冒充结论
  (与 SK-20 的「取不到集序即不判」、SK-28 的「时间轴未成形即不判」同纪律)。
- `final-unbacked` 的 `name` 取该步**首条阻塞项文案**,没有阻塞项时留空只给状态词——不编一句阻塞文案。

## 3. 单源:板块词表与就绪判定一句都不在校验层重写

这一面最容易做成第二份真相:板块名是七个中文串、"这一步好没好"又是一整套推导,照抄一份最省事。
两处都改成现取:

```js
const chain = STAGES.map(x => ({ step: x.key, board: x.name, stage: boardStageOf(p, x.name) }));
…
const steps = Domain.workflow(p, !!(ctx || {}).online).steps;
```

- **板块名与链序取 `STAGES` 主线七步表**。七步的 `name` 逐字就是看板那七个板块的键
  (`剧本,主体,分集,分镜,生成,审片,成片`),链序就是主线步序。看板改名或改序时源级+行为断言先红,
  校验层因此不必也不得另存一份板块词表。
- **产物实况取 `Domain.workflow` 的同键步骤**。与流程条、分集状态、发布门 G1 走同一份推导,
  `online` 维度也随 `Domain` 走(在线态下离线模拟产物不算出片,离线态算)——校验层不写第二份就绪判定。

这与 SK-18 的级差取 `WfCore.sizeGap`、SK-22 的判旧取 `Domain.shotVideoStale`、SK-28 的切段取
`Domain.subtitleSegs` 是同一条纪律。源级断言把它钉住:`js/skills.js` 里必须出现
`STAGES.map(x => ({ step: x.key, board: x.name` 与 `Domain.workflow(p,`,且不得出现任何支线板块名字面量。

## 4. 判定范围窄于看板软闸门,这一点如实写进条目 note

链只取主线七步,于是本面判不到两类东西,`note` 里明写而不含糊:

- **看板的支线板块**:`AGENT_BOARDS` 实为「导演 + 主线七步」八项,支线只有`导演`定调一个
  (`制片` 是 `Domain.workflow` 的支线步与项目 tab,不是看板板块——这一句一开始写错成"制片/导演两个",
  由核对 `AGENT_BOARDS` 实况纠回,单独一个提交)。
- **`Domain.workflow` 的四个支线步**:`prod` / `director` / `shell` / `clips`,同样不在主线契约链上。

看板那条 toast 按看板全序提醒(含导演板块),范围比本面宽一档;本面换来的是**可判定、两端拿得到、
不随页面关闭消失**,并且多判了 toast 完全没有的那一向(`final-unbacked` 的产物背书)。
支线板块清单由断言钉在实况上:看板加板块时先红,提醒同步 `note` 那句话,否则 note 会静默失真。

## 6. 两条缺口各清到哪一步

- **`S-07` 由本面承接,但条目仍保留该编号**。缺口原话说的是"上游定稿只是注入给模型的文本约束,
  不是可判定的门";本面把它变成了两端拿得到的 `warn` 结论——**可判定这一半清了**,
  "门"那一半(要不要拦)属 `G-10`。保留编号与 SK-12/13 保留 `S-03`、SK-22 保留 `S-05` 同口径。
- **`G-10` 不清账**。方法论门要不要挂成默认 `warn` 的可选门,是产品口径问题,未定之前门禁一个字不动;
  另外"定稿的内容对不对、契约本身该怎么写"属语义判断,仍归 LLM 审片,同待 `G-10`。

记账诚实位那条断言随之改了判据:SK-29 的校验面已落地,再写 `pending: ['check']` 反而是**假记账**。
所以不再拿 `pending` 快照当判据,改钉三条真实约束——条目仍记 `G-10`、`js/release.js` 对 `Skills` 零引用、
G2 与 `overall` 计数口径逐字未动。

  不进问题中心即不可能改门禁状态。
- **不拦交付动作**:`js/produce.js` 与 `js/sb-io.js` 对 `Skills` 零引用——合成与导出打包行为不变。

## 10. 剩余与未纳入

- **未接问题中心**。接进去要决定归哪一档危险级、跟看板那条 toast 怎么去重(同一件事两处提醒),
  是独立一轮的事;本槽按"只报不拦、先接一个消费点"的最小边界收口。
- **未接审片路径**。审片报告的 `checks` 现在按镜挂,而本面是**项目级**判定(判的是板块契约链,不是某一镜),
  挂进镜级报告没有落点;要接得先决定项目级结论在报告里怎么呈现。
- **未判定稿内容本身**。"这份定稿写得对不对"是语义判断,归 LLM 审片(`G-10`)。
- **未判"交付版本落后于当前版本"**。`p.__ver` 由 `continuity.js` 每次保存都自增,
  拿它做"已交付版本不是当前版本"的契约会恒命中,噪音大于信息,故不落这一码。
- **看板软闸门未改**。那条 toast 保持原样(它的范围更宽,含导演板块),本面不去替它收窄或改写。
- `node tests/e2e.js` 按仓库纪律未跑(需用户明确要求)。本槽不含合并、不含 PR。
