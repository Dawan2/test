# W183 · 摘掉 `release.dirty` 转发:Bus 的 50 格事件留痕不再被对折

> 分支 `cursor/w183-bus-recent-dirty-36dc`,基线 `origin/cursor/w179-integration-3a6e @ 7cae7c8`。
> 产品面只改 `js/release.js` 一处(删 10 行转发、留 5 行注释),`js/bus.js` 一个字节未动。

## 1. 结果一句话

`js/release.js` 底部那段通配订阅——收到主线事件就再 `Bus.emit('release.dirty', …)`「触发角标重算」——
**转出去的那条没有任何一个源事件顶不了的订阅者**:角标重算的三处通配订阅
(`js/episodes.js` 项目页三角标 / `js/issues-ui.js` 问题弹窗与角标 / `js/workbench.js` 制作台三分区)
**都不按事件名过滤,且都带防抖**,源事件那一轮就已经重算过,转发件只是把同一轮防抖重置一遍。

重绘一次不多,净效果全落在 `Bus` 的 50 格事件留痕上:**一条主线事件占两格**。
`Bus.recent(12, pid)` 是 Agent 按需查询里 `t === 'events'` 那一路的取数口
(`js/agent-ops.js`,即用户问"最近发生了什么"时助手照着念的那份),于是**能回看的轮数当场对折**。

本槽不发这条转发件。live 实测(第 2 节):50 轮主线事件下,能回看的轮数 **25 → 50**,
`recent(12, pid)` 里的真事件 **6 → 12**,而**三处重绘一次不少**(第 2.3 节)。

数字 live:`unit` 554 → **556**(`release` 子套件 34 → **36**:一条按新实况翻面重写成三条)、
`contract` **125** 未动、`integration` **143/143**、`cli.smoke` **105/107**(那两条与 `master` 同名的失败照旧)。
记账件份数 192 → **193**(含本文),单元 `FLOOR` 554 → **556**、记账件 `FLOOR` 192 → **193**、
主 `README.md` 明写数一并按 live 抬。`TOPIC_FLOOR` 与 `GUARD_TOPICS` 十七条一条未动。

## 2. 停工位现取核实(在 W179 基线 live 上量,不抄别处的记账件)

任务口径给了三条否定条件:**没有转发 / 转发有独特订阅者 / 50 格对折不成立**——任一成立即停工。
三条逐条现取,**都不成立**,故停工位成立。

取证手段是一支临时探针:`vm` 沙箱按 `index.html` 的顺序加载**真** `js/bus.js`、`js/release.js`、
`js/issues.js`、`js/issues-ui.js`、`js/workbench.js`,不桩 `Bus`(既有 `issues` 套件那条用同名假 `Bus`
数防抖轮次,那份桩不带 50 格留痕,量不出本槽这件事)。同一支探针在基线与本槽 tip 上各跑一遍。

### 2.1 转发还在

基线 `7cae7c8`,`js/release.js:547–556`:

```js
try {
  if (window.Bus) Bus.on('*', (ev) => {
    if (!ev || !ev.name) return;
    const nm = String(ev.name);
    if (nm.startsWith('shots.') || nm.startsWith('compose.') || nm.startsWith('review.') || nm.startsWith('episode.') || nm === 'plan.step') {
      Bus.emit('release.dirty', { src: nm, p: ev.p, ep: ev.ep, brief: ev.brief });
    }
  });
} catch (_) {}
```

### 2.2 它没有独特订阅者

全树按 `Bus.on('release.dirty'` / `Bus.emit('release.dirty'` 现扫:

| 文件 | `on` | `emit` |
|---|---|---|
| `js/release.js` | 0 | 1 |
| `tests/unit.js` | 2 | 0 |

`js/` 侧**零订阅者**;`tests/unit.js` 那两处是 W149 那条用例自己挂上去数条数的桩,不是产品消费点。
收得到它的只有三处 `'*'` 通配订阅,而它们收源事件时**执行的是同一段回调**——
对它们而言转发件与源事件不可区分,故不是"独特订阅者"。

### 2.3 50 格对折成立,而重绘一次不少

**留痕面**(连发 50 条主线事件,`brief` 逐轮编号,`p.id` 同为 `p1`):

| | 基线 `7cae7c8` | 本槽 tip |
|---|---|---|
| `recent(50)` 总条数 | 50 | 50 |
| └ 其中真事件 / `release.dirty` | **25 / 25** | **50 / 0** |
| 50 格覆盖到的主线轮数 | **25 轮** | **50 轮** |
| 回看得到的最早一轮 | **第 25 轮** | **第 0 轮** |
| `recent(12, 'p1')` 里真事件 / 转发件 | **6 / 6** | **12 / 0** |

`recent(n, pid)` 是**先按 pid 过滤已经截断过的 50 格、再取后 n 条**,故 pid 过滤救不回被挤掉的轮次:
上表最后一行就是 `js/agent-ops.js:730` 那一口实际会拿到的东西。

**扇出面**(一条 `shots.batchDone`,数各通配回调被叫几次):

| 通配订阅者 | 基线 | 本槽 tip |
|---|---|---|
| `js/release.js` | 2 | —(不再订) |
| `js/issues-ui.js` | 2 | **1** |
| `js/workbench.js` | 2 | **1** |

每个回调被叫两次:源事件一次、转发件一次。转发是在 `release.js` 的回调里**同步** emit 的,
故它对注册在前的 `issues-ui` 是一次重入、对注册在后的 `workbench` 是抢在源事件那一次之前到达——
两种都只是又走了一遍 `clearTimeout` + `setTimeout`。

**重绘面**(真跑 `issues-ui` 的角标写入与 `workbench` 的 `Release.collect`,等防抖全部落地后数轮次):

| | 基线 | 本槽 tip |
|---|---|---|
| 一条主线事件 → `Issues.collect` | 2 | **2** |
| 一条主线事件 → `Release.collect`(发布门) | 1 | **1** |
| 连发五条 → `Issues.collect` | 2 | **2** |
| 连发五条 → `Release.collect` | 1 | **1** |

`Issues.collect` 那个 2 不是重复:一次来自 `issues-ui` 自己那轮防抖(弹窗与角标共享同一次快照),
另一次来自 `workbench.paintIssues`——两个消费面各算各的,与转发件在不在无关。

**四个数在基线与本槽 tip 上逐个相等**,即任务问的第 2 问答案是:
摘掉转发,角标 / 成片门 / Issues **一次必要重画都不少**。成因是三处订阅都带防抖
(`issues-ui` 150ms、`episodes` 300ms、`workbench` 400ms),转发件与源事件同一轮就被并掉了。

### 2.4 一处如实登记的口径

`js/episodes.js` 的角标订阅**没进这支探针**:它的 `badgeCtx` 只在 `Views.projectDetail` 的 `render()`
里赋值,要把它驱动起来得铺一整套项目页 DOM,而全仓至今对 `js/episodes.js` 只有源级断言、从不执行它。
它那段回调与另两处同形(`Bus.on('*')` → `clearTimeout` → `setTimeout` 300ms → 重画三角标),
本槽按**源级**钉住它仍在(第 3 节第三条判据),没有拿它的重绘轮次充数。

## 3. 改了什么

### 3.1 产品

`js/release.js`:删掉第 2.1 节那 10 行,留 5 行注释写明角标重算的驱动源在别处、以及这条为什么不该再发。
文件头 `依赖` 那行的 `window.Bus` 保留并注明用途——**它仍在用**:`stampRelease` 落定时发 `release.stamped`
(`js/release.js:255`),那是一条真事件,不在本槽射程内。

三处通配订阅一行未动:本槽不改它们"不按名过滤"这件事(那会连 `agent.chat` 之类也一并不再触发重算,
是另一件事、另一种取舍),只让不该发的那条不发。

`js/bus.js` 一个字节未动——「订阅者隔离、回调不冒泡、`emit` 定名 payload 顶不掉」三条契约原样。
G1/G4 门槛、`GUARD_TOPICS`、`staleShotSplit`、`Skills.gaps()` 键集一律未碰。

### 3.2 判据:一条翻面重写成三条

W149 立的那条(`Bus 通配订阅 · 一条主线事件只转一次 release.dirty`)钉的是"转发件形态正确";
转发件本身没了之后它整条失效。按新实况拆成三条,**坏哪一格报哪一格**:

| 判据 | 钉的是 | 形态 |
|---|---|---|
| 留痕面:`Bus 事件留痕不被转发件对折` | 连发 50 条主线事件后 `recent(50)` 零 `release.dirty`、覆盖 50 轮、最早回看得到第 0 轮、`recent(12, pid)` 是 12 条真事件 | 运行期,真 `bus.js` + 真 `release.js` |
| 重绘面:`摘掉转发不少一次重绘` | 一条事件各重算一轮、连发五条仍防抖合并成一轮 | 运行期,真加载两个通配订阅者 |
| 源级面:`角标重算的驱动源是通配订阅本身` | 全树零 `release.dirty` 发出点与订阅点、`js/release.js` 可执行行零 `Bus.on('*')`;**反面**钉住三处通配订阅仍在 | 源级,注释整段抹掉后再扫 |

源级那条的反面是有意的:摘掉转发之后,"源事件驱动重算"这件事就完全压在那三处通配订阅上,
谁把它摘了,谁得自己接上重算——那时红的是这一条,而不是等到用户发现角标不动。

判据有意**不钉** `release.dirty` 这个名字永不复用:它要回来只需先有一个源事件顶不了的订阅者
(比如某处只想在门禁真需要二次重算时被叫醒),报错句里写的就是这个条件。

## 6. 本槽没做的事

- **不改 `js/bus.js`**:订阅者隔离、回调不冒泡、`emit` 定名那三条契约是另一槽的,一个字节没动。
- **不给三处通配订阅加事件名过滤**。那能省下"非主线事件也重算一轮角标"(如 `agent.chat`、
  `continuity.*` 一族),但它**一格留痕都省不下来**——留痕是 `emit` 那头记的,与谁订阅无关;
  且那是在改三个消费面的重绘口径,与本槽这条"不该发的别发"不是同一件事。如实登记为未做。
- **不动 G1/G4 门槛、`GUARD_TOPICS`、`staleShotSplit`,`Skills.gaps()` 键一个没拆。**
- **不碰 `release.stamped`**(`js/release.js:255`):那是打版本落定的真事件,同样零订阅者、同样占一格留痕,
  但它不是转发件——"零订阅者的真事件要不要发"是另一个问题,判据在哪一侧都还没想清楚,本槽不顺手收。
- **不合入、不开 PR、不跑 `tests/e2e.js`。**

## 7. 残留与欠账

1. **`js/episodes.js` 那处通配订阅至今没有行为面判据**(第 2.4 节)。全仓对它只有源级断言,
   它的 `badgeCtx` 要靠一整套项目页 DOM 才驱动得起来。故"项目页三角标真的会随主线事件重画"
   这件事,今天只有 e2e 那一侧和人眼看得见;本槽新增的源级那条只钉住"它还订着 `'*'`",
   钉不住它订完之后做了什么。
2. **重绘面那条数的是"轮次",不是"画对了没有"。** 它用的是计数桩(`Release.collect` 换成计数器、
   角标 `innerHTML` 的 setter 计数),证明得了防抖没塌、驱动源还在,证明不了那一轮画出来的内容是对的。
3. **`Bus` 的 50 格上限本身仍是个写死的数,且没有"回看得到多久"这种口径的判据。**
   本槽这条留痕面用例把 `HIST_MAX` 与"能回看几轮"绑在了一起(M5 因此红),但那是副作用不是本意:
   哪天真要调这个上限,得同轮改本条那两个字面。
4. **`release.stamped` 与 `continuity.*` 一族同样是零订阅者却占留痕格的事件**(现扫:`continuity.js` 9 处发出点、
   `release.js` 1 处),本槽一条没动。它们与 `release.dirty` 的差别在于**它们是真事件不是转发件**——
   一条主线动作对应一格留痕是留痕该干的活,而转发件是同一件事占两格。这条界线是人划的,没有判据管它。
5. **本槽在自己这条分支上,`master` 与集成线上那段转发照旧在。** 不合入、不开 PR。
