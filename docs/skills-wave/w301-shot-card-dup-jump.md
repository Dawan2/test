# W301 分镜卡片小标补跳转:点后续那几行的小标定位到留原 id 的第 1 行

> 起点 `origin/cursor/w300-integration-06c6`,`git fetch` 后现取尖 `d1933301662499e61baf3bef71b8a30c636c62c7`
> (交接自称 `d193330`,`checkout -b` 后 `rev-parse` 逐字符核过)。功能支 `cursor/w301-shot-dupjump-70c4`。

## 一、收的是哪一条

W299 残留第 1 条(W300 §七原样保留),原话:

> **分镜卡片那枚小标还不能跳。** 主体侧收了「跳到第 1 位」,镜头侧同形的那一条(「跳到第 1 行」)
> 明令点名下一槽。`Domain.dupIdKeepOrder` 收下 `dedupeShotScan` 换过单位词那份结果派生出来的位次表照样读得动
> ……而镜头侧的落点比主体侧多量一件事——分镜卡片在四视图 + 剪辑台五档里各有各的渲法,
> "切到哪一档才看得见第 1 行"得像 W287/W291 那样先量一遍,不能照抄主体侧这条切 tab 的写法。

W291 把「是哪几行撞了」标了出来,而标出来之后用户的下一句是**「第 1 行长什么样」**——
按 id 取镜落到的就是那一行(它是"引用会落到哪一行"的答案),而卡片上看得见的只有画面、提示词与出片状态,
撞的那个 id 一个像素都不显。本槽只补那一格:**后续那几行的小标点得动,点它滚到并高亮留原 id 的第 1 行那张卡。**

去重写库那一路(顶栏入口、预览、确认闸)一个字没碰;`Domain.dupIdKeepOrder` 与 `Domain.dupCopy` 一行未改。

## 二、动手前先量:五档里哪几档渲得出分镜行,「跳」在每一档怎么落到那一行

明令要量的两件事,现取源码逐档核过(`Store.state.settings.epViewMode` 五档,行为面另有五档各真渲一遍):

| 档 | 中栏渲的是什么 | 有没有分镜行 / 小标 | 落点怎么落 |
|---|---|---|---|
| `shots` 分镜视频 | `SBViews.centerHTML` → 逐镜 `shotThumbHTML` 缩略图卡(时间轴横排 / 数列式竖排两种布局都 `ep.shots.map`) | 有(W291 挂点之一) | 同一条缩略图带里滚到那张卡 + 高亮 |
| `cut` 剪辑台 | `SBViews.cutHTML` → 同一个 `shotThumbHTML`(卡与卡之间多一枚转场槽) | 有(与上一档共用那一处挂点) | 同上,同一条带里 |
| `groups` 镜头组 | `ShotGroups.renderInto` → 组卡片 + 底下那条**分镜时间线**(`ep.shots.map` 逐行) | 有(W291 挂点之二) | 同一条时间线里滚到那一行 + 高亮 |
| `board` 分镜脚本 | `SB.scriptBoardHTML` 渲场次与节拍 | **无**(一行分镜都不渲,故一枚小标都没有) | 不适用 |
| `bb` 节拍板 | `BeatBoard.render` 渲五段节拍 | **无**(同上) | 不适用 |

量出来的两个结论,本槽的形状全压在上面:

1. **落点永远就在同一档里,不必切视图。** 三档渲的都是**整张分镜表**(`ep.shots` 全表逐行,没有任何过滤),
   故"第 1 行"必然与被点的那一行同屏——这与主体侧那条**相反**:主体库按分类 tab 过滤,第 1 位可能在别的 tab 下、
   本 tab 上压根渲不出来,故那一条要先切 tab 重渲再定位并 toast 说一句。**镜头侧照抄那套写法就是多走一步**
   (还得回答"切到哪一档"这个本不存在的问题)。本槽这一跳因此不切视图、不换选中镜、也不多说一句话。
2. **绑定要按挂点分两处。** 缩略图卡那两档共用中栏那条带,一处绑得住(`js/storyboard.js`,渲完那一下);
   镜头组那条时间线在自己的容器里、且**每次内部重渲(改组名/换分组/自动分组)都重挂一遍**,
   故那一处绑在 `ShotGroups.renderInto` 的 `renderPanel` 里。少绑一档的后果是**那一档上小标照旧渲得出来、点了没有任何反应**
   ——判据里那三档逐档真点一遍,就是为这一格(变异 M5/M6 各摘掉一处,当场红)。

## 三、跳转长什么样

小标外观没动(仍是 W291 那枚 `tag yellow`,位次与那句说明逐字未改),后续那几行的那一枚多了三样东西:
落点序号 `data-dupjump`、指针光标,以及那句说明尾巴上多的一句:

```
🧹 id 重复 第 2/2 行     ← 点它:滚到第 1 行那张卡并短暂高亮
🧹 id 重复 第 1/2 行     ← 它自己就是落点,不挂跳转
```

悬停那句说明现取同一份模板(`Domain.dupCopy`,一个字没改),只在挂了跳转的那几枚后面缀上一句:

```
……收拾存量走顶栏「🧹 镜头 id 去重」(先看计划,确认才改)。点这枚小标定位到第 1 行那张卡(就在这一档里,不换视图也不换选中镜),纯跳转不改任何字段。
```

点下去发生的事只有一档:那张卡短暂高亮(`outline` + `boxShadow`,2.2s 后自动褪)并滚到屏中
(`block:'center'` + `inline:'center'` —— 缩略图带是横排、时间线是竖排,两个方向都要)。

三件分寸定在这条跳转上:

| 分寸 | 取的口径 | 不取那一种会怎样 |
|---|---|---|
| **只跳第 1 行** | 后续那几行一律指向留原 id 那一行 | 挨着跳"下一行"的话,跳到的是另一行要改 id 的,而用户问的是"引用会落到哪一行" |
| **第 1 行自己不挂跳转** | `keep === row` 时那一枚一个属性都不多 | 跳到自己身上是一句废话,而挂上之后 W291 那条判据当场红(那一枚的标记形状被改了) |
| **落点按全表实位认(`data-row`)** | 卡片挂 `data-row="${ep.shots.indexOf(s)}"`,跳转按它取 | 按镜头 id 认的话取到的永远是**文档里最靠前那一张**:那是拿 DOM 的先后再判一遍"谁是首行",与位次表那一套序各是各的(今天两者恰好同解,而"恰好"不是判据) |

夹具上的实况(五行 `dup / solo / dup / two / two`,两组各撞两行):

```
第 1/2 行(不挂)  无标  第 2/2 行→0  第 1/2 行(不挂)  第 2/2 行→3
shots / cut / groups 三档各点两枚:落点分别是第 1 行与第 4 行那张卡,视图不换、选中镜不换、零 toast
```

## 九、这一槽可复用的两件事

- **同形的一条交互往另一侧搬时,先量"另一侧的容器长什么样",别先照抄写法。** 主体侧那条跳转的三步里有一步
  (先切 tab 再定位)是**主体库按分类 tab 过滤**才需要的;镜头侧三档渲的都是整张表,那一步不但多余,
  还会引出"切到哪一档"这个本不存在的问题。量的成本是读五档的渲染入口(§二那张表),收益是少写一段错的交互。
- **"少挂一处"这种缺口,行为面判据要按挂点逐档真驱动一遍。** 源级数"绑了几处"只答得出数字,
  答不出"哪一档点了没反应";本槽三档各真渲、各真点两下,M5/M6 摘掉任一处绑定时报的就是那一档的
  `chip(...).onclick is not a function` —— 一眼读得出是哪一档漏了。
