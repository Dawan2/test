| # | 改法 | 基线 `7cae7c8` 全套 |
|---|---|---|
| M1 | 子集位退回旧一行(`pend = pend.filter(s => ids.has(s.id))`) | **红 1**:`contract` 那条,报「`cli.js` 的子集过滤须现取 `Domain.shotVideoStale`」 |

## 2. 冒烟确实没覆盖这一条

`tests/cli.smoke.js` 里 `episode.generateVideos` 只出现一次,是零成本那一路:

```
r = cli('exec', 'episode.generateVideos', '--pid', pid, '--epid', ep2); // 未确认镜 → blocked,零生成零计费
```

整份冒烟对 `--args '{"shotIds":[…]}'` 零调用,对"过期 done 镜"零夹具——
它是**有意**不碰生成链路的(文件头写明"不触发生图/生视频等真实计费调用"),
而"显式子集含过期镜会不会真下发"恰恰只在下发那一刻才看得见。
所以这一格在冒烟上不是漏了,是那个套件的射程之外;**本槽也没往里加**(见第 5 节)。

停工位成立。

## 3. 补的是行为面:让 `cli.js` 自己那一行真跑一遍

### 3.1 沙箱 `loadCli()`

`cli.js` 是脚本不是模块:没有 `module.exports`,末尾自调 `main()`。要在单测层真跑它的 `EXEC`,
沙箱做三件事,其余一字不改:

- **只掐掉末尾那一行入口**(`src.replace(/\nmain\(\);\s*$/, '\n')`),掐不到当场 `assert` 报错——
  入口哪天挪窝,红的是这一句,而不是让沙箱静默把命令行主流程也跑起来;
- **`EXEC` 是 `const`**,不落在全局对象上,故在同一 context 里再求一次值取出来
  (`vm.runInContext('EXEC', sb)`);
- **`require` 用 `Module.createRequire(<仓库根>/cli.js)`**:`cli.js` 里那些 `require('./js/*.js')`
  得按仓库根解析,按 `tests/` 解析会全部落空。

`stateGet` / `withProject` / `genShotVideo` / `genImage` 是函数声明(挂在全局对象上),夹具按需换成桩。
**换掉的只有服务端往返与真实生成**:子集过滤、判旧、确认闸、终稿锁仍是 `cli.js` 自己那一份,
`Domain` 是真的(经真 `require` 进来,不是桩)。引擎桩记下每次真收到的镜头 id,用例数的是**引擎实收**,
不是回执里的数字——回执那个 `total` 在"一镜也没跑"时照样印 `ok: true`,正是 W176 当初逮到的那种形态。

### 3.2 两条用例,分工不合并

| 用例 | 钉的是 |
|---|---|
| `CLI exec generateVideos:显式子集里的过期 done 镜真进引擎参数,点名的鲜镜进不来(不带子集的整集批量照旧不碰过期镜)` | 开口的**三个方向**:过期镜进得来、点名的鲜镜进不来(每镜都真扣费)、开口只开在显式子集这一路 |
| `CLI exec generateVideos:终稿锁仍拦在子集之外(定稿的过期镜不重跑,定稿产物一个字节没动)` | W176 留下的那个**有意缺口**:`counts.stale` 照数定稿的过期镜、子集位不碰它、回执按真跑的镜数报 |

两条都先 `assertEq(episodeState().counts.stale, …)` 与 `Domain` 对一次账:
夹具日后被调、或判旧口径变了,先红在这一句上,而不是让下面几句悄悄变成恒真。

第一条用例里"整集批量"那半是本槽额外摊出来的一个方向。W176 在浏览器那一端钉了"进得来 / 进不来"两向,
**第三向("这个口只开在显式子集这一路")两端都没有用例**——把整集批量那一路也开成放过期镜过,
用户没点名的已出片镜会被顺手重抽,每镜真扣费,而 W176 那三条行为面与源级那条全绿(见第 4 节 M5)。

**M5 是净增覆盖里最值得单记的一格**:源级那条按 `episode.generateVideos` 的实现段切片,

## 5. 为什么没往冒烟里加

任务口径允许加一条不并行的 smoke,前提是证明它失败形态稳定且不与并行冲突。本槽**没加**,理由三条:

1. **要真下发才看得见**。这一格的判据是"引擎实收了哪几镜",在冒烟里意味着真跑一次生视频——
   那正是 `cli.smoke.js` 文件头明写不做的事(真实计费调用归 `tests/live-gen.js`)。
   退而求其次只看回执 `total`,又恰好是 W176 逮到的那个"一镜没跑也印 `ok`"的形态,钉不住。
2. **`cli.smoke` 那 2 项既有失败与本格无关但会混淆读数**。它此刻是 105/107,新增一条后分母变 108,
   而那两条失败的成因(`whoami` 退出码、`llm` mock)与本格毫无关系;把一条需要真生成的用例摆进去,
   失败形态会随上游与限流窗口漂移,读数就不再是"这道判据红没红"。
3. **单测层这一格已经钉住了,而且更严**。冒烟看得见的最多是回执,单测层数的是引擎实收。

故按任务口径的默认优先级只加 `unit` 行为面。`tests/cli.smoke.js` 本槽**一个字节没改**,
它仍是 107 条、105 通过、失败仍是那两条。
