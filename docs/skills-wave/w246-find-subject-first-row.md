## 一、先 live:写回到底落在哪一行

沙箱直接 `runInContext` 真 `cli.js` 本体(只掐掉末尾 `main()` 入口),换掉的只有服务端往返与生成引擎;
落库面一律读 **clone 语义的 disk 夹具**——`stateGet` 每次现取一份拷贝,只有 `withProject` 真提交的补丁才落盘。
这一条是本槽的取证前提:编排层只在自己手里那份快照上改一改也会"看起来落库了",共享同一个对象的夹具量不出真假。

夹具:主体库 `dup(A-首位)` / `solo(B-不重复)` / `dup(C-第二位)` / `dup(D-第三位)` 四位、三位同 id,全都缺参考图
(与 W242 §1.4 那一格同一份夹具,便于两槽的数字对得上)。

### 1.1 主体侧:点名一档与整库一档都中招

| 档 | 引擎实收 | 回执 | 落库 | 到手图 |
|---|---|---|---|---|
| 点名 `["dup"]` | 3 次 | `ok:true total:3 ok:3 failed:[]` | `A-首位:g3.png` / 其余三位无图 | **1 位** |
| 整库(不点名) | 4 次 | `total:4 ok:4` | `A-首位:g4.png`、`B-不重复:g2.png`、C/D 无图 | **2 位** |

`A-首位` 那一格是被 `g1 → g2 → g3` 连写三遍的结果:三笔钱买到的是同一位主体的第三张图,
前两张连同那两笔钱一起没了,而回执一个字的失败都没报。

### 1.2 这不是一次性的,是每轮复发的漏

同一份库连跑三轮整库补图(每轮都是"补缺图的那几位"):

```
基线 cli.js   第 1 轮:扣 4 笔,回执 total:4 ok:4,库里有图 2/4
              第 2 轮:扣 2 笔,回执 total:2 ok:2,库里有图 2/4
              第 3 轮:扣 2 笔,回执 total:2 ok:2,库里有图 2/4
              三轮共扣 8 笔,库存永远停在 2/4
```

C、D 两位每一轮都被重新判成"缺图"、每一轮都真扣一笔、每一轮的图又都写去了首位。
**这个漏没有收敛点**:跑到第 N 轮仍是 2/4,回执仍是 `ok` 全绿。
用户能看到的唯一异常是主体页上那两位一直没图,而他刚刚"成功"跑了 N 遍。

### 1.3 停工条件:不成立

交接给的停工条件是「若现跑已按这一轮选中的那一行写回,只记账」。现跑逐档反过来:
点名档 3 笔换 1 位、整库档 4 笔换 2 位、连跑三轮 8 笔仍是 2/4。故不停工,改写回。

### 1.4 `findSubject` / `findShot` 是否同形:**同形**

交接点名要核的这一格,现跑量了镜头那一侧同一份形状(同 id 三行 `dup`/`solo`/`dup`/`dup`,全都待生成):

```
镜头点名 ["dup"]  引擎实收 3 次,回执 total:3 ok:3 failed:[],出片 1/4 行
整集连跑三轮      4 笔 → 2 笔 → 2 笔,共 8 笔视频钱,出片行数永远停在 2/4
```

病灶逐字同形:`cli.js` 的 `episode.generateVideos` 每轮 `findShot(epLive, s.id)` 取的也是
`(ep.shots || []).find(x => x.id === sid)` 的首行。**本槽按交接明令没碰它**(§五 1 交出去)。

浏览器那一端两侧都不是这个形态:`js/commands.js` 的 `for (const s of todo)` 把**循环里拿到的那个对象**
直接交给 `EpisodeUtil.genSubjectImage(p, s, …)` / `SBGen.batchGenVideos`,没有第二次寻址,三位各得一张。
两端的差异来自 CLI 有 `withProject` 这一道"重取最新状态再打补丁"的往返,而浏览器没有。

### 1.5 单条命令那一路不算这一格

`hujing subject-image <pid> dup --gen` 现跑落在首位、扣一笔、到手一张——
点名一个 id 而库里有多位时**取首位是这条命令的既有语义**(用户点名的就是一个,只扣了一笔,没有"多花的钱"),
本槽一个字没动它。这一格与批量那一档的区别是"扣了几笔",不是"取的第几位"。

## 二、改了什么(产品码一处,`cli.js` +11 −1)

### 2.1 `nthSubject(proj, sid, nth)`:紧跟 `findSubject` 之后

```
const nthSubject = (proj, sid, nth) => {
  const rows = (proj.subjects || []).filter(x => x.id === sid);
  return rows.length ? (rows[nth] || rows[0]) : findSubject(proj, sid);
};
```

同 id 一位都没有时**委托回 `findSubject`**:按名引用那一路(`subject-image <pid> 林晚` 这种)照旧走原来那一份,
连"主体不存在"的 exit 4 也仍由它抛,本槽不另造第二个错误出口。
`rows[nth] || rows[0]` 是并发改表(这一趟跑到一半别处删了一位)时的兜底:退回原行为,不静默丢产物、不抛异常中止整趟。

### 2.2 调用点:序数在**快照全表**上数,不在待跑清单上数

```
const nthOf = new Map();
const seenIds = Object.create(null);
(p.subjects || []).forEach(s => { const n = seenIds[s.id] || 0; seenIds[s.id] = n + 1; nthOf.set(s, n); });
…
const sj = nthSubject(projLive, s.id, nthOf.get(s) || 0);
```

`nthOf` 按对象身份记(`todo` 里的元素就是 `p.subjects` 里的那几个对象),不按 id 记——同 id 那几位的序数各不相同。

**为什么必须在全表上数**:待跑清单是过滤过的。首位已有图被 `!s.image` 跳过时,
在 `todo` 上数出来的序数是 `0,1`,写回落到全表的第 0、1 位——**首位那张已有的图被覆盖、末位仍补不上**。
这一档单独钉了一条用例(§三 ③),变异 2 现跑正是这个形状。

### 2.3 没碰的

选人闸 `todo = (p.subjects || []).filter(s => ids ? ids.has(s.id) : !s.image)` 逐字未动;
`Domain.dupSubjectRowsNote` 与它的调用点未动(那句话说的是"多花了几位的钱",与"钱买到了什么"是两件事,
**两件都成立时它照旧说得对**:三位真跑三位,只是此前三份产物落在一位身上);
`Domain.dupRowsNote` 的算术未动(W245 的地);`findSubject` 本体未动;`findShot` 未动;
`state-put` 仍只有 `need(f.force)` 一道闸;`Skills.gaps()` 仍 20 键;
`js/` 与 `server.js` / `mcp.js` **零 diff**——本槽只动 `cli.js`、`tests/unit.js`、`README.md` 与本目录。

### 3.1 变异五手,逐手红在自己那一句

| # | 怎么改坏 | 结果 |
|---|---|---|
| 1 | 退回基线(`findSubject(projLive, s.id)`) | 红 **1**:本条 ①(`实际:A-首位:g3.png / 其余无图,期望 3,实际 1`) |

| 3 | `nthSubject` 恒回 `rows[0]`(序数白算) | 红 **1**:本条 ①(与变异 1 同一句——寻址退化到同一个形状) |
| 4 | 序数错位一格(`nth + 1`) | 红 **1**:本条 ③(首位被覆盖、第二位无图、第三位拿到图) |
| 5 | 选人闸改成按 id 只跑一位(拿"每位都写对"给它开路) | 红 **2**:W242 那条(`CLI 那端选人闸同样按位筛,三位照跑`)+ 本条 ①的前提句 |

两处现跑出来的方法性的东西,原样记下:

- **变异 1 与变异 3 红得逐字相同,这是对的。** 「重取时不带序数」与「带了序数但不用」是同一个 bug 的两种写法,
  报错句相同不算判据分不开——它们该被同一句话拦住。真正要分开的是变异 2 与变异 4
  (序数**算错**的两种),它们红在另一条档上,报错句里印的是落库全貌,一眼读得出错位方向。
- **变异 5 只红在行为面,`contract` 那条源级判据没接住。** 那条判的是骨架里
  `todo = ` 那**一行**上不许出现 `new Set`/`findIndex`/`indexOf`;把去重拆成两行
  (`const seenPick = new Set();` 单独一行,`todo = ` 那行只留 `!seenPick.has(s.id)`)就绕过了它,
  五条源级断言一条不红。接住它的是 W242 那条行为面用例(引擎实收 `1` 而不是 `3`)。
  **源级判据按行取样时,把同一件事拆成两行就是它的固有盲区**;本槽有意不去改那条判据(W242 的地,
  而且行为面已经接住了),原样登记——哪天要收紧,收法是把取样单位从"行"换成"`todo` 那条语句所在的块"。

1. **镜头那一侧是同一个 bug,live 量出来了,按交接明令一个字没改——这是本槽交出去的最重的一格。**

   注意冲突面:那一段紧挨着 `Domain.dupRowsNote` 的调用点(W245 的地),同轮并进时按"两侧各在同一段落改动"处理。
