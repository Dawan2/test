## 二、动手前量的那两遍(明令逐条)

### 2.1 卡片上还能挂哪:卡上没有空位,故只给脏项目多长一行;真会漏的是另外三条路

`.proj-card` 现取 `minmax(260px,1fr)` 网格,`.proj-body` 里四格都占着:

| 卡上现有的格 | 现取 | 还能不能挂 |
|---|---|---|
| `.proj-name` | 项目名(`display:flex`,右侧无余量) | 不能:挂上去会与长剧名抢一行 |
| `.proj-desc` | 简介,**定高 34px `overflow:hidden`** | 不能:多一枚就把简介顶掉一行 |
| 日期那一行 | `📅 创建时间` + 右侧「🏭 一键跑批」tag(仅跑批项目有) | 半个位:跑批项目上那个 tag 正占着右侧 |
| 集数那一行 | `N 集 · N 主体` + 右侧「删除」按钮 | 不能:删除按钮是这张卡上唯一的破坏性动作,不与角标挤 |

量出来的结论是**卡上没有现成空位**,故落地形状是:**只有撞车项目才在日期那一行下多长一行**
(`row wrap`,两枚各占一格、窄卡上自然折行),干净项目的卡片一个像素都不动——
角标本来就只在真有重复时才该露出来,这一行因此不是"占了个位置",是"脏了才长出来"。

真会漏的不是卡上位置,而是**卡片这一层压根渲不出来的三条路**(明令点名的筛选/分页/空状态):

| 进来的路 | 现取 | 只挂卡片会怎样 |
|---|---|---|
| 搜索词筛掉 | `list = all.filter(p => p.name.includes(search))` | 撞车项目被筛掉,整屏一枚角标看不见 |
| 翻页翻过去 | `PER = 10`,`shown = list.slice(...)` | 撞车项目在第 2 页,第 1 页一枚也看不见 |
| 搜索筛空(空状态) | `shown.length === 0` 那一支渲的是「没有匹配…」,**整个卡片区不渲** | 卡片区连同角标一起没了 |
| 一个项目都没有 | `all.length === 0` 那一支渲空状态 | 无所谓(没有项目就没有脏项目) |

故挂点量出来是**两处**:卡片一处(说得出"是哪个项目、脏几位/几行"),
**页头一处**(说得出"整屏之外还有几个")。页头那一枚有意插在
「一个项目都没有 / 搜索筛空 / 正常列表」三条分支**之外**,三条路都看得见它
——挂进卡片区就随卡片一起被筛没(M3 现跑正是这一手)。

### 2.2 全量项目扫两棵树的开销:树本来就在内存里,扫它比一次 `Store.save()` 便宜

明令「量清列表是否已有 `p.subjects`/`ep.shots` 在内存;若没有,不要为角标去逐项目打网」。现取:

- `Store.myProjects()` = `this.state.projects.filter(p => p.userId === u.id)`,回的**就是 `Store.state.projects`
  上那几个对象本身**(与 `Store.getProject(id)` 回的是同一批引用),`subjects` 与 `episodes[].shots` 全在;
- 整棵树由 `Store.pullState()` 一次 `GET /api/state` 拉齐,列表这一屏不存在"只拉了摘要"这一档;
- 故**扫的是内存树**,本槽一处网都没打(判据里拿计数版 `fetch` 桩钉着:渲这一路 `__fetches` 恒空)。

开销现跑(`node /tmp` 下的一次性基准,只读 `js/domain.js` 那份 `dupIdScan`,不进仓库):

| 规模 | 镜头数 | 全量扫两棵树 | 同一棵树 `JSON.stringify`(即 `Store.save()` 那一下) |
|---|---|---|---|
| 轻(10 项目 × 8 集 × 40 镜) | 3,200 | **0.59 ms** | 1.70 ms |
| 中(30 项目 × 12 集 × 60 镜) | 21,600 | **3.52 ms** | 11.56 ms |
| 重(100 项目 × 30 集 × 100 镜) | 300,000 | **31.64 ms** | 198.97 ms |

扫描是 `O(全树 id 数)` 一遍线性(`Domain.dupIdScan` 一个 `Map` + 一个 `Set`,发号器只在真撞车时才叫),
三档下都是同一棵树 `JSON.stringify` 的 **1/3 到 1/6**——而后者是每次写库都要付的钱。
故「值不值」的答案是:**值,且不必为它加缓存**。

同轮如实记下这一下的代价落在哪:搜索框 `oninput` 每敲一个字重渲一次,这一遍扫描跟着重跑
(中档 3.5 ms、重档 32 ms)。有意不加跨渲染缓存——缓存要跟着删项目、跟着别处写 id 失效,
那是拿一处陈旧风险换几毫秒;量到的数不支持这笔交易(§八残留 2 登记为没做的量)。

卡片上(撞车项目才有,现网 `tag yellow` 同形,与项目详情面 tab 行那两枚**逐字相同的串**):

```
        3 集 · 4 主体                              删除
```

```
🔍 搜索项目名称        🧹 2 个项目有重复 id        ＋ 新建项目
```

四件分寸:

| 分寸 | 取的口径 | 不取那一种会怎样 |

四处已经在用的同一条路),本槽没造新机制;进分集工作区那一路直接落 `#/project/<pid>/episode/<epid>`。

而批量补图逐位计费、批量生成逐行计费)、去哪儿收拾(点名「🧹 主体 id 去重」/「🧹 镜头 id 去重」
那道预览 + 确认闸)。页头那句另多报一件:这个数按全量项目算、逐个点名是哪几个项目各脏几位/几行

## 四、数从哪来:第三次同读,而这一屏一个字都不再抄

明令「扫描只读现成 `dupIdScan` / `dedupeScan` / `dedupeShotScan`,禁止再抄规则」。落地是一条直链:

```
js/domain.js    Domain.dupIdScan          ← 规则一份(首位/首行留原 id、后面每处撞车各发新 id)
js/roles.js     RoleOps.dedupeScan        ← 注入 Store.uid('sj') 与单位词「位」
js/storyboard.js SB.dedupeShotScan        ← 注入 Store.uid('sh') 与单位词「行」
js/episodes.js  dupIdBadges(p)            ← 把两侧那两份合成 {seats, rows, eps}(整页恰 1 处扫描)
                window.EpisodeOps = { dupIdBadges }   ← 本槽新增的透出,恰 1 处
js/projects.js  EpisodeOps.dupIdBadges(p) ← 本槽:整屏恰 1 处,页头那一枚与卡片那几枚同读它
```

`js/projects.js` 里 `Domain.dupIdScan(` / `dedupeScan(` / `dedupeShotScan(` / `dupIdMarks(` /
`keepOrder` / `new Map(` / `new Set(` **各 0 处**(源级钉着这几个 0):这一屏不认识去重规则,
也不再数一遍谁是首位/首行。卡片那一两枚由 `dupCardTags(p, d)` 渲,它只挑单位词与那句说明,
**自己一次都不扫**(数由调用方把那一份传进来)。

**为什么不在 projects.js 里直调两侧扫描:** 那就得在这一屏再挑一遍单位词、再合并一遍逐集行数,
而项目详情面已经把这件事做成 `dupIdBadges` 了。抄一份到这里行为可以完全一样(M5/M6 现跑,
行为面逐字节等价),而三份计算迟早对同一份脏数据给出三套数——那时列表上说"这个项目 2 位要改"、
点进去详情面说别的数,用户先信哪一个都不对。

`Domain.dupIdMarks` 本槽照旧**零消费**:这一屏渲不出主体位与分镜行,没有可挂位次的对象。
