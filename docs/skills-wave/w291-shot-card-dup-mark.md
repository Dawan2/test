# W291 分镜卡片补同 id 重复标记:撞车的每一行报出「第几行 / 共几行」

> 起点 `origin/cursor/w290-integration-2ade` 尖 `4f7e552`(`checkout -b` 后 `rev-parse` 现取核过,
> 与交接自称逐字节相同)。功能支 `cursor/w291-shot-dupid-573a`。

## 一、收的是哪一条

W289/W290 残留第 1 条,原话:

> 分镜卡片还没有同 id 重复标记。形状不能照抄:单位词是「行」,而卡片在四视图 + 剪辑台五档里各有各的渲法,
> 「挂在哪一处才五档都看得见」得像 W287 挂顶栏那样先量一遍;好处是 `Domain.dupIdMarks` 收下
> `dedupeShotScan` 换过单位词那份结果照样读得动,本槽判据已把这一格喂过,要加的只有展示那一层。

W287 给分镜面补了去重入口、把「要改几行」写在集级顶栏那个按钮上;W289 给主体库卡片补了逐位小标。
镜头侧的卡片这一格还空着:分镜表按 `ep.shots` 逐行渲,同 id 那几行在卡片上与几个不同镜头
**长得一模一样**——画面、提示词、出片状态、审分各是各的,撞的只是那个**看不见的 id**。
于是读到「🧹 镜头 id 去重(2)」的人,想知道是哪几行,只有点开弹窗看计划(那一屏按行号点名,
而卡片上那个镜号与它对不对得上得自己数)或者自己去猜。

本槽只补那一格:**撞车的每一行在自己那张分镜卡片上挂一枚小标,报出「第几行 / 共几行」。**

## 二、五档挂点(动手前量的那一遍)

明令「五档(board/shots/cut/bb/groups)各挂哪一处才看得见;少挂就有一档进来看不见」。
量的口径只有一句:**这一档渲不渲得出「一行 = 一个镜头」的东西**。

| 视图档 | 中栏渲的是什么 | 渲得出分镜行? | 挂点 |
|---|---|---|---|
| `board` 分镜脚本 | 场次与节拍(`js/sb-board.js`,`ep.shots` 只被它**写**、不逐行渲) | 否 | 挂不上——这一档上看得见的仍是顶栏那条入口 |
| `shots` 分镜视频 | 缩略图条/竖列,逐镜一张卡(`shotThumbHTML`) | 是 | `js/sb-views.js` 那张缩略图卡 |
| `cut` 剪辑台 | 播放器 + 带转场槽的时间轴,**共用同一张 `shotThumbHTML`** | 是 | 同上一处(一处挂住两档) |
| `bb` 节拍板 | 五段节拍(`js/beatboard.js`,`ep.beats`) | 否 | 挂不上——同 `board` |
| `groups` 镜头组 | 组卡 + **一条逐镜的分镜时间线**(`data-tlshot` 那一行) | 是 | `js/shotgroups.js` 那条时间线 |

**结论:渲得出分镜行的是三档,挂点是两处**(`shots` 与 `cut` 共用一处)。两处一挂,三档都看得见;
少挂 `js/shotgroups.js` 那一处,从「镜头组」tab 进来的人就一枚小标都看不见(M3 现跑正是这一格,红 1)。

`board` / `bb` 两档没有分镜行可挂,故那两档上「页面级发现重复」这件事仍全靠顶栏那条入口
——它挂在四视图与剪辑台共用的那一行集级顶栏上,五档一处不漏(W287 已量过)。
这两档「确实没有分镜行」不是靠人眼看住的:判据里另有一句按源级钉着
(`js/sb-board.js` / `js/beatboard.js` 里 `ep.shots.map(` 现取各 0 处),哪天那两档长出逐行渲染,
本槽这条先红,提醒同轮把标记挂上去。

## 三、标记长什么样

现网 `tag yellow` 同形的一枚小标,挂在卡片镜号名字那一行下面:

```
🧹 id 重复 第 2/3 行
```

悬停那句说明(`title`)现取同一份标记,报四件事:

```
本集分镜表里共 3 行镜头共用 id「dup」:这是其中第 2 行,去重时这一行改发新 id,画面与提示词一个字不动。
按 id 取镜的地方只找得到第 1 行,而批量生成按行逐行跑、逐行计费;
收拾存量走顶栏「🧹 镜头 id 去重」(先看计划,确认才改)。
```

留原 id 那一行报的是另一句去向:

```
本集分镜表里共 3 行镜头共用 id「dup」:这是其中第 1 行,这一行留原 id。……
```

三件分寸就在这枚小标上定住:

| 分寸 | 取的口径 | 不取那一种会怎样 |
|---|---|---|
| **留原 id 那一行也标** | 撞了 id 的**每一行**都挂,含第 1 行 | 只标「要改的那几行」的话,「按 id 取镜会落到哪一行」就读不出来——而那正是这枚小标最有用的一句(M6 现跑,红 2) |
| **共几行按全表算** | `ep.shots` 整表口径 | 按视图里当下渲出来那几行数的话,同一行在不同档下会报出不同的总数 |
| **顶栏那个数与卡片那几枚不是同一个数** | 顶栏数**要改几行**(首行不算),卡片标**撞了 id 的每一行** | 强行凑成同一个数就得挑一边说谎:顶栏改成 3 会与「确认后改 2 行」对不上,卡片漏掉首行就丢了上面那一格 |

夹具上这三格的实况(四行镜头 `dup / solo / dup / dup`):

```
顶栏                🧹 镜头 id 去重(2)
分镜视频 / 剪辑台     A-首行 第 1/3 行   B-不重复 (无标)   C-第二行 第 2/3 行   D-第三行 第 3/3 行
镜头组时间线          #1 第 1/3 行   #2 (无标)   #3 第 2/3 行   #4 第 3/3 行
分镜脚本 / 节拍板      (无分镜行可挂;顶栏那条入口照旧在)
```

单位词是「行」,不是主体侧那个「位」——分镜表里没有"位"。这一层就是换单位词那一层
(派生只给 `nth`/`total` 三格数字,单位词不进派生),照抄主体侧那个字即红(M4 现跑,红 2)。

## 四、位次从哪来:整页只扫一遍分镜表

明令「位次只从 `Domain.dupIdMarks(scan)` 派生,禁止页面再扫/再数;扫描仍只读现成
`dedupeShotScan` / `Domain.dupIdScan`」。落地形状是一条直链,一处扫描喂两个消费方:

```
js/storyboard.js  Views.episode
  dupScan  = dedupeShotScan(ep.shots)        ← 整页恰 1 次(源级钉着这个 1)
  dupRows  = dupScan.plan.length             → 顶栏那个数:要改几行
  dupMarks = Domain.dupIdMarks(dupScan)      → 逐行位次:{ 行号: { id, nth, total } }
      ├─ SBViews.centerHTML / cutHTML → shotThumbHTML → dupRowTag
      └─ ShotGroups.renderInto              → SBViews.dupRowTag
```

`Domain.dupIdMarks` 是 W289 下沉的那一步派生,本槽一个字没改:它收下 `dupIdScan` 的结果,
按「首行算第 1、计划里第 k 条算第 k+1」推逐行位次。W289 判据已把**换过单位词**那份结果
(镜头侧 `dedupeShotScan` 把 `n` 换成 `rows`)喂过一遍,故本槽这一端直接读得动、
`js/domain.js` 一行未动、`Domain.dupIdScan` 的同读处照旧 4 处(一处没加)。

**为什么不让卡片这一层自己数一遍:** 位次与「改哪一行、留哪一行」是**同一套序**。
两份数法一漂,卡片上标的「第 2 行」就与预览里改的那一行对不上——而用户是把这两处
**一起读**的(先看卡片认出是哪几张,再点开弹窗核计划)。M5/M8 两手证明了这一格:
一手让页面为小标再扫一遍表、一手把位次算法抄一份到页面上,两手**行为面逐字节等价**、
渲出来的小标一个像素不差,只有源级那两句接得住。

**取标记按全表实位:** 缩略图卡那一端写 `(ep.shots || []).indexOf(s)`、镜头组那一端写
`ep.shots.indexOf(s)`,取的都是「这一行在整张分镜表里排第几」。拿视图里那张表的局部下标取
就会错位(M2 现跑,红 1)。
