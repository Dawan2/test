# W266 集成记账:W265 审片汇总面按行取报告并进集成线

一条槽并进同一条集成线,一次真 `--no-ff`。本文只记集成面的读数与判断,槽自身的病灶/改法/变异见 `w265-batch-review-summary-row.md`(同目录)。

**本槽是集成线上第三条「快进形」**(前两条是 W262、W264),而且是三条里**退化得最彻底的一条**:对侧的 `merge-base` 现取不只等于我方尖的树,而是**等于我方尖那个提交本身**——`B` 与 `P1` 是同一个 SHA,不是两个碰巧同树的提交。于是 git 在这次 merge 里**一次合并动作都没做**:合完的树与 `P2` 逐字节相同,`P1 → M` 的 numstat 与 `B → P2` 的 numstat 逐行相同。`--no-ff` 在这里买到的只有「历史上留下一个能指名道姓的合入点」。

W262 §三 立下、W264 §三 照办的那条规矩在本槽第三次照办——**树比对这类证据整体归零,「有没有丢东西」改由变异 + live 实测承载**。

## 三、`git diff 我方 对侧` 在本槽量出空,而这句话是恒真的

## 九、这一槽学到的

1. **快进形有程度之分,而最退化的那一档连"必要条件"都给不出**。W262 是发现、W264 是照办,本槽是第一次遇到 `B` 与 `P1` **提交级相等**:此时 `tree(M) == tree(P2)` 在拓扑上不可能不成立,树面证据从"信息量小"降到"恒真"。判断一条快进形能读出多少,要先分清 `B == P1` 是**同树**还是**同提交**——前者 git 还做了选择,后者连选择都没有。

2. **变异要能把一句语义拆成两半单独破坏**。M1/M2 打的都是行寻址,任一手都会连带弄坏"打开哪一份";只有 M3 让行寻址完好而只错报告来源,才证明「打开本批那一份」是一条**独立**判据。合入时真正会丢的往往是复合语义里的某一半(另一半还在,读起来像全都在),故变异手数要按语义的**可分性**设计,不是按代码行数。

3. **`+2` 与 `680 → 682` 是两种不同强度的证据**。数字相等有两处判据自动算(反事实① 红 2 即证),而"没删测"只有名集多重集比对量得出来——本槽全套读数里,`零缺失` 是唯一一条既非恒真、又不被文档数字判据覆盖的。
