# W120 · 把 `report(...)` 静态点数的另一半钉住:不许包进循环或迭代回调

> 槽位范围:只动 `tests/unit.js` 的 `contract` 套件(新增 1 条断言 + 2 个模块级工具函数)、`README.md` 里两处措辞与数字,以及本记账件加索引行、明写份数与下限棘轮。
> **零产品代码改动**(`js/`、`server.js`、`cli.js`、`mcp.js`、`billing.js` 一行未改),**零测试文件改动**(`tests/integration.js` 与 `tests/cli.smoke.js` 一个字未动),不动发布门口径、不新增计费动作、**不删任何用例**、不放宽任何既有断言。
> 基线 `cursor/w117-integration-8b2d` head `15a03ca`(**不合 W113、不合 W119**)。

## 1. 先把 W113 那条阻塞核验成真

W113 周期 8 核验报告的阻塞表第 4 条(报告 6.3 节)说:W102 那条契约只封住单行形态,多行 `forEach` 包住一条 `report(` 时行数与调用数都不变而实跑 +1,**而用例源码里那句注释声称这一路会红,实测只对单行成立**。

本槽在自己的基线上把它重跑了一遍,逐个数都对上了。

先看 W102 那条契约的钉法。`tests/integration.js` 与 `tests/cli.smoke.js` 都要起真实服务子进程、单测里跑不动,故它按套件源码静态点数:数行首 `^[ \t]*report\(` 的行数,拿它跟 README 的数字比。这个口径成立的前提是"静态行数 = 实跑条数",而那条前提由同一个用例里的一句断言守着——`calls === lines`,即"`report(` 的调用总数必须等于它独立成行的行数"。注释写的是「把 report 塞进循环或回调里,一行会跑出多条」。

**这句话对单行写法成立,对多行写法不成立。** 单行 `[1, 2].forEach(() => { report(...); });` 的行首不再是 `report(`,行数少 1 而调用数不变,`calls === lines` 当场对不上;可把同一句拆成三行——`forEach` 开头一行、`report(` 仍独立成行、`});` 一行——**行首点数、调用数、名字面数、不同名数一个都不变**。

实测(基线 head `15a03ca`,把 `tests/integration.js` 第 140 行那条 `注册成功` 用 `['a', 'b'].forEach(_v => { … });` 包成三行):

| 口径 | 变异前 | 变异后 |
|---|---|---|
| 行首 `report(` 行数(W102 对账用的那个数) | 130 | **130** |
| `report(` 调用数(`calls === lines` 那一层) | 130 | **130** |
| 就地写死的名字面数(W114 那条第 1 层) | 130 | **130** |
| 不同名数(W114 那条第 3 层) | 130 | **130** |
| `node tests/integration.js` **实跑条数** | 130 | **131** |
| `node tests/unit.js contract` | 全绿 | **全绿** |

四个静态口径全部纹丝不动,实跑多出一条,README 停在 130,单测一条不红。W113 记的是对的。

顺带说明这个洞为什么值得单开一槽而不是顺手把注释改准:**这两个套件恰恰是"单测里跑不动、只能静态点数"的那两个**,静态数是它们唯一的对账凭据;凭据与实况脱钩的路径只要还开着,W102/W114 那一整串断言钉住的就只是"README 与一个可以造假的数一致"。

## 2. 落地:换判据,不是补正则

W113 给了两条路:一条是让静态数不再是唯一判据(读回套件最近一次运行结果、或让套件把条数写进可读文件再对账),另一条是"若要留在纯静态,至少把判据从『行首 `report(`』收紧成『该行所在语句块不在任何循环/回调体内』"。

本槽走第二条。第一条要在单测里落地就得引入一份跨进程的运行结果文件——那份文件本身成了新的可造假凭据(谁把它改了单测一样绿),而且它在 CI 顺序上依赖两个套件先跑过,单测就不再自足了。第二条是纯静态、自足、零新增文件。

### 2.1 判据:按括号配对还原外层块链

在 `contract` 套件里新增一条,接在既有那条「集成测试与 CLI 冒烟用例数由各自套件源码实计」之后,**既有九条一条不删、一条不改**。上一条钉的是"每条 report 独立成行",这一条钉的是"这一行外面套着什么",两个判据分开钉才拦得住多行包法。

做法是逐字符配对括号,取每条 `report(` 出现时栈上所有未闭合开括号所在行的**行首至该括号那段原文**(下称"块头"),链上任一块头命中循环或迭代回调即红:

- 迭代回调:`.forEach(` / `.map(` / `.filter(` / `.some(` / `.every(` / `.find(` / `.findIndex(` / `.flatMap(` / `.reduce(` / `.reduceRight(` / `.sort(`
- 循环:`for (` / `while (` / `do {`

合规写法在两个套件里只有两种形状——`async function main() {` 与就地开的裸 `{ }` 分节块;实测 232 条 `report(` 的块链全部只由这两种构成,**零误报**。

### 2.2 为什么不按缩进推块链

最省事的写法是"从 `report(` 那行往上找第一条缩进更浅的行,那就是它的块头"。两个套件缩进齐整,这么写当轮也是绿的、也能拦住 1 节那条变异。**但它拦不住把包裹层写成同缩进的版本**:

```
  for (const _v of ['a', 'b']) {
  report('注册成功', …);
  }
```

`report(` 缩进 2、`for (` 缩进也是 2,按缩进往上找会直接跳过它、一路找到 `async function main() {` 而判绿。一条只在代码排版整齐时才成立的判据,防的是手滑防不住绕。故判据取真括号配对,与缩进无关(实测见 3 节变异 2)。

### 2.3 抹码:注释/字符串/正则里的括号不能算

要配对括号就得先把非代码里的括号排除掉。`tests/integration.js` 里正则字面有 194 处、模板串 11 处,`/^分镜闭环回流·.+:出 \d+ 镜约 \d+ 秒;缺提示词 \d+ 镜;未挂主体 \d+ 镜$/` 这种带 `(`/`{` 的字面直接进配对会把整个栈带偏。

`blankNonCode` 把行注释、块注释、单双引号串、模板串(按 `${}` 插值深度找收尾,插值里再嵌反引号也不会认错)、正则字面**整段抹成等长空白**,换行与字符偏移原样保留——抹完只剩代码骨架,而块头仍能按原偏移从原文里切回来(报错信息里给的是可读的原句)。正则与除号的界线按前一个有意义字符/关键词判(`(`/`,`/`=`/`return`/`typeof`/`of` 这一类之后的 `/` 才当正则开头)。

**最要紧的一处设计**是它对自己失准的处理。这类手写扫描的通病是"没看懂就少配一对括号",而少配的后果恰好是块链变短、变短就更容易判绿——**失准方向与放行方向一致,静默即假绿**。故本条把配平做成硬判据:提前收到闭括号(栈已空)当场报错,文件扫完栈不为空同样报错,报错文案直接写明"抹码扫描失准,本断言不可信"。实测三个套件加 `tests/unit.js` 自己,大括号与小括号净配平都是 0,过程中栈也没负过。

## 3. 变异验证(四条,逐条实测)

| 变异 | 结果 |
|---|---|
| 1. 把 `tests/integration.js` 第 140 行 `注册成功` 用**多行 `forEach`** 包起来(`report(` 仍独立成行,缩进照常) | **红 1 条**:`集成测试:report(...) 不得写在循环/迭代回调体内…:实际 "tests/integration.js:141 外层「['a', 'b'].forEach(」 / tests/integration.js:141 外层「['a', 'b'].forEach(_v => {」"` |
| 2. 同一条改成**不缩进**的多行 `for (const _v of […]) { … }` | **红 1 条**:`…实际 "tests/integration.js:141 外层「for (const _v of ['a', 'b']) {」"` |
| 3. 变异 1 之下,**除本条外的所有断言** | **全绿**(99/100,只红本条)——W102 的 `calls === lines`、W114 的名唯一三层、README 三处数字对账全部没反应 |
| 4. 变异 1 之下实跑 `node tests/integration.js` | **131/131**,而静态四个口径仍是 130 |

变异 3 是本条落地的正取证:它把 1 节那张表换了个说法再证一遍——**这条洞除了本条断言之外没有第二个守卫**,不是"顺手加固",是补唯一的那一层。变异 2 是 2.2 节那个设计选择的取证:按缩进推块链的写法在这一条上会判绿。

变异 1 的报错同时点出块链上两层(`forEach(` 那个小括号与箭头函数那个大括号),这是有意的——两层都是真实的包裹层,只报一层反而让人以为改掉箭头函数写法就能过。

**这条断言只拦包裹写法,不许拿它当删测或改判据的理由**:被拦住时正解是把循环体拆成逐条独立的 `report(...)` 登记(每条各有自己的名字,W114 那条名唯一同时管着),不是把用例删掉,更不是把断言的词表改窄。

## 6. 交接

1. **W113 阻塞表第 4 条(报告 6.3 节)可判为闭合,但只闭合"多行包裹"这一路**。同节末尾还挂着一条同类残留——**变异 7:真删一条 `report(` 且 README 同步改小,全绿**,因为三个用例数一条棘轮都没有(记账件份数那条有 `FLOOR`)。本槽有意不顺手做它:那是"用例数只增不减"的产品口径问题,与本条"静态数代不代表实跑数"不是同一件事,合在一槽里做会让两条断言的失败含义混在一起。要做的话照 `FLOOR` 那条的形状写即可。
2. **词表是判据的一部分,新增迭代方法要跟着补**。本条认的是那 11 个数组迭代方法加三种循环。将来若有人用 `for await (` 或自定义的 `times(n, cb)` 之类包裹,词表点不到——但那两种在两个套件里都还没出现过,现在就把词表扩到"任何带回调的调用"会连 `assert` 这类正常嵌套一起误伤。撞到时按同形补词,不要改成"块链上不许有任何函数体"。
3. **`blankNonCode` 与 `reportBlockHeads` 是模块级工具,后来者可以直接用**。前者是这个仓里第一份"按 JS 词法抹非代码段"的工具(此前的静态断言全是单行正则),要写"某段代码在什么结构里"这类判据时不必再从正则起步;用它时请把配平自检一并保留,那不是可选的健壮性装饰,是这类扫描失准与放行同向时唯一的报警。
4. **两个套件的合规形状现在只有两种**(`async function main() {` 与裸 `{ }` 分节块)。这不是本条钉住的东西——本条只禁循环,没有正向枚举允许的块型。若哪天想把它收成白名单,先想清楚 `try {` / `if (` 这类要不要放行(现在都放行,而它们确实不会让一行跑出多条)。
