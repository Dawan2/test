## 四、加的那一条(`commands` 套件,三档)

名:`CLI gen-episode 补底图那一步同样落到本轮那一行:同 id 多行各补各的底图,不许几张全写在首行身上`。

夹具沿用 W305 那份形状——同一集四行、`dup` 占第 1/3/4 行、`solo` 占第 2 行,四行都 `confirm:true`、
`video.status='none'`,**有意一行都不给 `image`**(这一趟得先补底图)。落库面读 clone 语义的 disk 夹具
(`cliDisk`:只有 `withProject` 真提交的补丁才落到 disk 上,编排层在自己手里那份快照上改一改
也会看起来「落库了」)。生图桩两件事一起带:**序号**保证每张各不相同,**收到的提示词原样带进 url**
——只看「有没有图」量不出 C 那一手,提示词进了 url 才分得开「写回哪一行」与「提示词取哪一行」。

1. **四行都缺底图的正常一趟**:四笔生图钱**四行**到手图、四张各不相同,且**每一行手里那张的 url 里
   带的是它自己那一行的提示词**;`ok/landed` 仍 `4/4`。
2. **首行本来就有底图**:生图引擎只收到三次,**首行那张 `old.png` 一个字不许被改写**
   (按 id 取首行时它第一个被第二行那张盖掉),连同原有那行共四行到手图。
3. **`exec episode.generateVideos` 对照**:走的是同一段补图逻辑,前两句同形各判一次,
   末一句要求两条批量路径**逐行落到同一个结果上**(哪一行拿到哪张图逐行相同)。

第 ③ 档是本槽唯一一处越出 `CMD['gen-episode']` 的地方:B 那一手与 A 是同一个窟窿的另一份,
夹具与断言原样够用,只收一半会留下一条明知故犯的漏网。
