# W181 · `js/release.js` 底部 `Bus.on('*')` 那处空 `catch`:停工位不成立(零产品代码改动)

一句话结论:**停工位不成立**。那处 `catch (_) {}` 吞的不是产品错误,而是「`window.Bus` 在场而 `Bus.on` 不是函数」这一条
**成品页走不到的模块降级路径**;订阅回调自己的异常压根走不到它(那是 `js/bus.js` `emit` 的订阅者隔离在管,属总线既有契约);
G4–G6 / 下载 / 审片回流上量不出任何一格「失败被吃掉、用户看到成功」;headless 的 `js/release-core.js` 没有同一张网。
更要紧的是反方向:**摘掉它,同一形态下 `window.Release` 当场是 `undefined`——十项门、打包、发布留痕一并没有**。
故本槽按停工纪律**一行产品代码不改**,把 live 举证与覆盖面判据落进 `tests/unit.js`(+5 条),
让"它只兜注册、它改不了任何一门、它的入口在成品页不存在"这三句话此后由判据接着,而不是靠下一个人再读一遍代码。

**基线**:`cursor/w174-integration-7f3d` 的 `b1f5fd6`。W172–W180 各支一律未取(含在飞的 `w179` 合入员)。

## 1. 病灶陈述与它的实际形状

那段代码(基线原样,本槽一字未动):

```js
/* ---------- Bus 事件订阅:主线任务变动时刷新交付门角标 ---------- */
try {
  if (window.Bus) Bus.on('*', (ev) => {
    if (!ev || !ev.name) return;
    const nm = String(ev.name);
    if (nm.startsWith('shots.') || nm.startsWith('compose.') || nm.startsWith('review.')
      || nm.startsWith('episode.') || nm === 'plan.step') {
      Bus.emit('release.dirty', { src: nm, p: ev.p, ep: ev.ep, brief: ev.brief });
    }
  });
} catch (_) {}
```

`try` 块顶层**只有一句**:注册。回调那一坨是**稍后由 `Bus.emit` 调起的**,那时这段 `try` 早已执行完,
异常落不到这个 `catch` 里。W149 当年写下过这个判断但没落判据,本槽把它连同另外四面一起钉住(第 4 节)。

## 2. Live 举证(基线 `b1f5fd6` 现跑,数字全部实测)

### 2.1 它吞的是什么:注册面,不是回调面

| 探针 | 实测 |
|---|---|
| `bus.js` 在场时 `release.js` 调 `Bus.on` 的次数 / 其中抛错次数 | **1 / 0**(`Bus.on` 是全函数:校验入参、回退订句柄,不抛)|
| 让转发出去的回调真抛错,异常反弹回 `Bus.emit` 调用方(管线)了吗 | **否**——被 `js/bus.js` 第 30 行 `set.forEach(fn => { try { fn(ev); } catch (e) {} })` 隔离 |
| 那处 `catch` 参与了上面这条吗 | **没有**。它在模块加载期执行一次就结束了 |
| 唯一走得到它的形态 | `window.Bus` 为真 **而** `Bus.on` 不是函数,即 `bus.js` 没加载或被桩顶掉 |

所以第一问的答案是:**吞的是"模块没加载"那一路**,不是"订阅回调里的真实异常"。
后者由总线自己隔离——那是 `js/bus.js` 顶注释第 4 行写死的契约(「订阅者异常隔离(不阻断管线)」),
不是本处偷偷吞的,也不该由本处翻案。

### 2.2 那个形态在成品页存不存在

| 探针 | 实测 |
|---|---|
| 全树给 `window.Bus` 赋值的文件 | **只有 `bus.js` 一处** |
| 那句赋值的形状 | `window.Bus = { on, off, emit, recent };`——IIFE 末尾**一次性整体挂**,没有"先挂对象再逐个补方法"的中间态 |
| `index.html` 里 `bus.js` / `release.js` 的位次(共 69 个 script) | **1 / 41** |

`bus.js` 加载失败时 `window.Bus` 是 `undefined`,前面那句 `if (window.Bus)` 直接短路,`catch` 仍然走不到。
要走到它,得同时满足"Bus 这个名字有值"和"它缺 `on`"——**成品页里没有任何一条路径能造出这个中间态**,只有测试桩能。

### 2.3 摘掉它会怎样(反方向的实测)

| 手法 | 同一形态(`Bus` 在场缺 `on`)下的实测 |
|---|---|
| 基线原样 | 整支照常加载,`window.Release` 十个出口全在,`collect()` 照出 10 门 |
| 把 `try { … } catch (_) {}` 摘成裸块 | `TypeError: Bus.on is not a function`,**`window.Release` 是 `undefined`** |

它兜住之后省下来的不是"一次角标没重算",是**整支模块的导出**。
拿十项门 + 打包 + 发布留痕去换一个走不到的形态上的日志,不是收益。

### 2.4 G4–G6 / 下载 / 审片回流:有没有「失败被吃掉、用户看到成功」

| 面 | 实测 |
|---|---|
| `Domain.episodeState` 抛错 + 那处 `catch` 真被触发 | G4/G5/G6 三门 `warn`,`info` 是 `校验异常:Domain 崩了`;`overall=warn`,**没有任何一门印「0 镜 → 通过」** |
| 同一夹具在"总线正常"与"catch 真被触发"两种形态下的门禁结论 | **逐字相同**:`fail/3/2/4/5` + 十门 `code:status:info` 串一模一样 |
| `downloadReleaseZip` 落地失败(`Blob` 不可用) | 如实 `throw`「交付包已打好,但浏览器下载没能落地:…」,**成功 toast 0 条** |
| 审片回流(`review.*` 事件) | 只作为**源事件名**参与转发判断;回流本身走 `WfCore.memFeedback/memWrite`,不经这段 |

G4–G6 的「判不出来就说判不出来」是 W145 落的,下载那条如实失败是 W162 落的,两处都已有判据在守;
本槽复核它们在**那处 `catch` 真被触发**这一形态下同样成立,并把这个"逐字相同"钉成新判据。

### 2.5 headless 有没有同一张空网

| 探针 | 实测 |
|---|---|
| `js/release-core.js` 空 `catch` 数 | **0** |
| 它提到 `Bus` 的次数 | **0**(环境差异一律经参数注入,模块内不碰 window)|
| 缺 `Domain` 注入 | G1 与 G4/G5/G6 **`fail`**,`info` 点名「缺 Domain 注入」 |
| `Domain` 自己抛错 | 四门 **`warn`**,`info` 带原始错因,`overall` 不放行打版本 |

**没有同一张网。** headless 那半的两条降级路径都是显式的、带原因串的,且 fail/warn 分得清"漏注入"与"上游崩了"。

### 2.6 顺带量到的一件事(**不属本槽,登记交接**)

W149 留的三条"无害"理由里第三条是「`release.dirty` 全树零订阅者」。**今天它只对一半**:

| 探针 | 实测 |
|---|---|
| `release.dirty` 的**命名**订阅者 | **0**(与 W149 同) |
| **通配**订阅者(`Bus.on('*')`,收得到 `release.dirty`) | **4 家**:`episodes.js` / `issues-ui.js` / `release.js` / `workbench.js` |
| 一条 `shots.batchDone` 触发下游通配回调的次数(三家各算) | **6**(源事件 3 次 + 转发件 3 次) |
| 一条主线事件占 50 格事件留痕的格数 | **2**(源事件 1 + 转发件 1) |
| 连发 40 条主线事件后,50 格里真主线事件剩几条 | **25**(另 25 格是转发件) |

也就是说:`episodes.js` 的通配回调**不按事件名过滤**、每次都重画 `Release.badgeHTML(p)`,
`release.dirty` 想触发的那次角标重算**在源事件那一轮就已经做过了**;转发件带来的只是一次防抖计时器重置,
代价是 Agent 的「最近发生了什么」实际窗口对折。这是**转发那段**的事,不是 `catch` 的事,
且摘掉转发是行为改动——按停工纪律不在本槽做,数字登记在第 6 节交接。

## 3. 判定:停工位不成立

任务给的停工判据是三条并列:「只包 `Bus.on` 注册本身」「回调错误仍会冒泡」「没有用户可见的假成功」。
逐条对实测:

1. **只包注册本身** —— 成立(第 1 节源级形状 + 2.1 探针)。
2. **回调错误仍会冒泡** —— **字面不成立**:回调错误不冒泡,它被 `js/bus.js` `emit` 的隔离 `catch` 吃掉。
   但吃掉它的**不是本处**,而是总线自 `js/bus.js` 第一版就写在顶注释里的既有契约(「订阅者异常隔离(不阻断管线)」),
   四家通配订阅者共用同一份隔离。要翻这条得改的是 `js/bus.js` 的分发契约、影响的是全部订阅方,
   **那是另一个槽的题目,不是"release.js 的空 catch"这个停工位**。本槽把边界钉成判据(第 4 节 T2),不越界改它。
3. **没有用户可见的假成功** —— 成立(2.4:三面各查一遍,一格都没有)。

三条里两条直接成立、第三条的"不冒泡"另有其主且已有明文契约,**加上 2.3 那条反方向实测(摘掉它反而丢掉整支模块导出)**,
结论是:**这不是"空 catch 吞产品错误",不修根因,不改行为,产品代码一行未动。**

## 4. 落地:5 条判据(零产品代码)

全落在 `tests/unit.js` 的 `release` 套件,紧挨 W149 那条之后。
`loadRelease()` 加一个可选参数 `bus`(缺省不装总线 = 既有全部用例逐字不变;`'real'` 装真 `js/bus.js`;
`'no-on'` 装一个缺 `on` 的 `Bus`——那是这处 `catch` 唯一走得到的形态)。

| # | 判据 | 钉住的是 |
|---|---|---|
| T1 | **那处 `catch` 只兜注册这一下** | 源级:`js/release.js` 恰有 1 处空 `catch`(多一处 / 少这一处都红在同句),它兜的 `try` 块**顶层恰 1 句**(剥注释后按括号深度数分号)且那句是 `if (window.Bus) Bus.on('*'`;行为:`'real'` 下 `Bus.on` 是全函数(走不到 `catch`),`'no-on'` 下整支照常导出、七个出口全在、`collect()` 照出 10 门 |
| T2 | **兜不兜住,G1–G10 逐字不变;回调异常归总线** | `'real'` 与 `'no-on'` 两形态下 `overall/fails/warns/blockers/score` + 十门 `code:status:info` 串**逐字相同**(夹具须真摊到 pass 与 fail 两侧,另有一句自检守着);前一个订阅者抛错不阻断后一个、不反弹回 `emit` 侧;并钉住那句隔离**写在 `js/bus.js` 里**(挪走就同轮改这条) |
| T3 | **那个形态在成品页不存在** | `window.Bus` 全树只由 `bus.js` 一处赋值 + 那句是一次性整体挂 + `index.html` 里 `bus` 位次早于 `release`;通配订阅方名单按名点住(4 家);同样收通配的 `issues-ui.js`/`workbench.js` 在同一形态下**本就当场 `TypeError`**(它们没有这处 `catch`)——这个形态一旦为真,塌的不止 release 那一支 |
| T4 | **headless 没有同一张网** | `js/release-core.js` 空 `catch` 数 0、`Bus` 出现次数 0、每个 `catch (e)` 都带出 `e.message`;行为面 Domain 抛错时 G1/G4 记 `warn` 带原始错因且不放行 |
| T5 | **转发件的全部代价** | 一条主线事件占 2 格留痕(`release.dirty,shots.batchDone`);连发 40 条后 50 格里真事件 25 条、转发件 25 条 |

另把 W149 那条用例里已经过期的一句消息改准:
`'release.dirty 至今零订阅者'` → `'release.dirty 至今零**命名**订阅者(通配那几家收得到,见下一条按名点到)'`。
断言本身(`assertEq(subs.join(','), '')`)一个字没动,只是它说的理由今天要按 2.6 的实况说。

## 6. 没碰的面 / 交接

**产品代码 `js/` 一个文件都没进 diff。** 逐条点名不碰的:

- **不碰 G4 门槛**,不动 `staleShotSplit` / `shotIds` / `GUARD_TOPICS` / W180 的 G1 `script` 口径(各是别人的槽)。
- **不碰 `js/release.js` 任何一行**(那处 `catch` 与它兜着的转发段原样)。
- **不碰 `js/bus.js`**:`emit` 的订阅者隔离是总线契约、四家通配订阅者共用,翻它是另一个槽(第 3 节第 2 条)。
- **不碰 `js/release-core.js`**、不动 `gaps()` 的键、不改任何门禁判据与 `overall` 计数口径。
- **不给 `release.dirty` 加订阅者,也不摘掉转发**(2.6 是行为改动,按停工纪律不在本槽做)。

留给下一槽的两件,都带着本槽实测的数:

1. **`release.dirty` 这条转发今天是净负债**(2.6):它想触发的角标重算,`episodes.js` 的通配回调在源事件那一轮**已经做过**
   (那个回调不按事件名过滤、每次都重画 `Release.badgeHTML(p)`),而它每条主线事件多占 1 格 50 格留痕,
   把 Agent 的「最近发生了什么」窗口对折(连发 40 条只剩 25 条真事件)。
   摘掉它是行为改动,得连着 W149 那条用例与本槽 T5 一起重算——**T5 就是为这一刻立的**:
   谁动转发,那两个 25 当场红,必须同轮把新实况写进去。
2. **四家通配订阅者的守卫写法不齐**(2.3 / T3):`release.js` 有 `catch`,`episodes.js` 的 `bindBadgeBus` 只在被调用时才判,
   而 `issues-ui.js` / `workbench.js` 在模块顶层直接 `bindBus()`、缺 `on` 时整支当场 `TypeError`。
   今天这不构成缺陷(那个形态成品页走不到,T3 钉着),但**哪天 `window.Bus` 多出第二个赋值点,它就从"走不到"变成"走得到"**——
   T3 的第一句断言(只此一处赋值)就是那个警报器。
