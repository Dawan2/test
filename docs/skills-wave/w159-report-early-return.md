## 1. 病灶:W141 交接第 1 条点名的那一路,今天仍是零判据

`integration.js` 与 `cli.smoke.js` 跑不进单测(都要起真实服务子进程),README 里它们的用例数是**静态点数**——
数行首的 `report(` 有几行。围着这个口径的判据到 W141 已经六层:

| 判据 | 落自 | 防的方向 |
|---|---|---|
| 行首点数 == 调用数 == README 明写数 | W102 | 静态 < 实跑 |
| 契约段自报条数 == `SUITES.contract` 长度 | W126 | 文档自数 |
| 块链上不许有循环/迭代回调 | W120 | 静态 < 实跑 |

W141 那条是反方向的第一条,而它自己的交接第 1 条写明只覆盖"块链看得见"的那一路,**另一路仍开着**:
登记点在 `main` 里、前面有一处提前 `return`/`throw`,后面那些 `report` 照样一条不跑,而它们的块链上一层条件块都没有。

本槽在基线 `31d7aeb` 上把这一路量了出来。复现只要在两条登记点之间插一句:


- 静态四个口径(行首点数 / 调用数 / 名字面数 / 不同名数)**一个不变**,仍是 141;
- 后面 138 条登记点的**块链仍然只有 `async function main() {`**,四条块链判据(W120/W124 两条/W141)逐层点不到;
- 施加这条变异后,**除本槽这一条外单测一条不红**(现跑逐条复核:行首点数、四条块链判据、下限棘轮全绿);
- 而 `MV_SKIP_REST=1 node tests/integration.js` 现跑只出 **3 条 PASS**,末尾那句 `===== N/N =====` 总数**根本不打印**,
  **退出码仍是 0**——README 写着 141,套件一声不吭地少跑 138 条。

这比 W141 那一路更糟的一点是**它连"跑完打印了一个总数"都没有**:那种漏法至少还留下一个可与 README 比对的实跑数,
这一种把总数那行一起跳过了,今天没有任何一处看得见。

## 2. 落地:不看块链,改看 `main` 自己那一层的控制流

新增一条用例接在 W141 那条之后,**既有七层一字未改**(只按各自写明的规矩抬了两个数字,见 2.4)。

判据换了类别:**块链判据回答的是"这条登记被什么包着",本条问的是"跑到这条登记之前会不会先走人"**,
往块链上再叠一层解决不了——早退语句根本不在任何一条登记点的块链上。

新增模块级工具 `mainOwnFlow(rel)`:在 `blankNonCode` 抹完的骨架上定位 `main` 的函数体,逐字符走到它的收尾花括号,
途中把**嵌套函数体**(箭头体 / `function` 体 / 具名方法体)里的东西一概略过,返回 `main` **直属**的
退出点(`return` / `throw` / `process.exit(`)与登记点(`report(`),各带行号、字符偏移与源码原句。

### 2.1 三种退出形式各有各的位置口径

| 形式 | 口径 | 理由 |
|---|---|---|
| `return` | **一律不许** | 唯一一种**静默**收场:后半截不跑、末尾总数不打印、退出码仍是 0 |
| `process.exit(` | 只许在**最后一条**登记点之后 | `process.exit(0)` 摆在就绪前置里同样是静默归零,故卡得比 `throw` 严一格 |
| `throw` | 不许夹在**第一条与最后一条**登记点之间 | 走 `main().catch` → `FAIL++` / `exit 1`,大声;两个套件今天的就绪等待失败正是这么写的 |

两个套件今天的合法形状恰好各在两头,一处不用改:
`integration.js:136` 的 `if (!up) throw new Error('服务 30s 未就绪')` 在第一条登记点之前、
`cli.smoke.js:54` 的注册失败 `throw` 同样在前置里、`cli.smoke.js:492` 那句按 FAIL 数的 `process.exit` 在最后一条之后。

这么切之后**静默截断那一路整条封死**,漏在外面的只剩"前置里 `throw`"这一种——它退出码非 0,当场看得出来,
不是本目录这一串判据在防的"文档与实跑长期不等而全绿"。

### 2.2 本条**不禁一切 early return**

判据只认 `main` 直属的那一层。套件里的 helper 与回调(`req` 的 Promise 体、`donePid`、`putMeta`、`api`、
各处 `forEach` 回调)里的 `return` 归它们自己——那些 `return` 只是从 helper 返回,不会让 `main` 少跑一条登记,
本条一处不碰。第 3 节变异 5 是这一点的正取证:在 `main` 里就地写一个带两处 `return` 的箭头 helper 再调用,**全绿**。

### 2.3 "是不是函数体"的判定有意保守

`mainOwnFlow` 认函数体的写法与 W124 那条禁 helper 的判据同形(箭头体 / `function` 体 / 具名方法体,控制结构按关键词表排除),
但**它在本条里的作用是反的**:W124 用它找"不该出现的包裹层",本条用它找"该跳过的地盘"。
故认错的两个方向后果不对称——

- 认不出某种函数体 → 它里面的 `return` 被算成 `main` 的 → **多报一条,当场红**;
- 把普通块(`if (…) {`、裸 `{`)误当函数体 → 里面真正的早退被跳过 → **静默放行**。

判据因此取保守侧:**认不出来就当普通块**。两个套件里 `main` 直属的裸 `{ }` 分节块有十余处,
变异 8 就是把早退塞进其中一处,照样红。

### 2.4 顺带抬的两个字面

按各自条目写明的规矩抬,只改数字、其余判据一字未动:

| 下限 | 抬档 | 依据 |
|---|---|---|
| 三套件棘轮里的 `unit` FLOOR | `520` → **`521`** | 「新增用例时把下限抬到当轮实况」,对应本槽这一条用例 |
| 记账件份数 FLOOR | `166` → **`167`** | 「新开一槽记账时把下限抬到当轮实况」,对应本记账件这一份 |

集成与 CLI 冒烟两格实测就是对的(141 / 107),一个数字没改。抬完四格差额**全为 0**。

## 6. 交接

1. **W141 交接第 1 条到此闭合**,闭合方式与它给的处置一致(换判据类别),但落点比它建议的那条窄:
   它写的是"把实跑总数落成产物再对账",本槽没走这条——那份产物本身会变成新的可造假凭据(谁改了单测一样绿),
   而且它让单测在 CI 顺序上依赖两个套件先跑过,单测就不再自足(W120 §2 当年否掉第一条路的理由同此)。
   本条是纯静态、自足、零新增文件的。
2. **仍开着的只剩"就绪前置里 `throw`"这一种**:在第一条登记点之前 `throw`,整跑归零而本条放行。
   它不静默——`integration` 走 `main().catch` 打印异常且 `process.exit(1)`,`cli.smoke` 同形——
   故不属于本目录这一串判据在防的"文档与实跑长期不等而全绿"那一类。要连它一起收,只能把就绪等待改成
   "失败也先把 N 条登记补齐再退出",那是改被测套件的形状,本槽不做。
3. **`mainOwnFlow` 是模块级工具,后来者可以直接用**:要写"某段代码在 `main` 自己那一层还是在嵌套函数里"
   这类判据时不必再从正则起步。用它时请把 2.3 那个保守侧记住——**认不出函数体只会多报,认错成函数体才会开洞**,
   收严它的函数体词表是安全的,放宽不是。
4. **它认的 `main` 是名字**(`(?:async )?function main() {`)。两个套件今天的主流程都叫 `main` 且都是零参数函数;
   哪天改成别的名字或改成箭头赋值,`mainOwnFlow` 会当场报"找不到 main() 主流程入口"而不是静默判绿——
   这一句是有意留的硬报错,不许改成 `if (!m) return`。
5. **`tests/e2e.js` 仍在对账、下限与本条之外**(它按 tab 列表循环登记,行首点数本就不等于实跑条数),本槽未扩。
