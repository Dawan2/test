## 4. 冲突怎么解(逐处)

二十九处冲突全是并集型或"取更新的一侧",没有一处需要择一丢弃对侧的实质内容。解法一律是**先用 `git diff --word-diff=porcelain <merge-base> <branch> -- <file>` 把该分支对这个文件的全部增量列出来,再逐条补进基线全文**,而不是凭冲突块里看到的那点内容判断——冲突块只是分支增量的一部分,另一部分在同一次合并里已自动合并成功。

长行 README 沿用 W29/W34 那条路子:

```
# 1) 冲突块一律先取 HEAD 侧(基线是三路里的超集,冲突块内它一侧最全)
# 2) 再把对侧的增量逐句折回去 —— 增量清单来自上面那条 word-diff
# 3) 终态逐条 grep 复核 word-diff 清单里的每一句都在位
```

这不是 `git checkout --ours <file>`。区别在第 2、3 步:`--ours` 整份取会**静默丢掉**对侧那一整行里的全部新句子;本槽对三条分支的长行增量逐条折回并逐条 `grep` 复核在位(`w35` 12 条、`w36` 2 条、`w37` 9 条,全部命中)。

### 4.2 `tests/unit.js`(第 1 步):`wfCore()` 取值点断言两侧各收了一半

第 1 步最值得记的一处,因为两侧**不是并集关系而是各自更严一半**:

- HEAD(基线,`w33` 改过)侧:把断言从"出现次数恰好 1"放宽成"至少 1 次",理由写在注释里(用到它的校验项会越来越多);同时**加严**了一条——整个 factory 体内不得出现顶层 `const x = wfCore()` 绑定(原先只查第一条 `CHECKS[` 之前那一段)。
- `w35` 侧:把断言**加严**成精确取值点清单 `normalizeCut,sizeGap`,并要求每一处 `wfCore()` 都即时取值、不留裸解析;但它那一侧没有 HEAD 加的整体绑定判据。

**取两侧的严格并集**:保留 `w35` 的精确清单与"不留裸解析",清单按合并后实况抬成三项 `CAMERA_MOVES,normalizeCut,sizeGap`(`sizeGap` 是 SK-18、`CAMERA_MOVES` 是 `w33` 的 SK-20、`normalizeCut` 是 `w35` 的 SK-24),再保留 HEAD 那条整体不得顶层绑定的判据。实测三处都是即时属性取值、无一处顶层绑定,两条判据同时成立。

> **口径**:两侧对同一条断言"各放宽一半、各加严一半"时,不要按"取更新的一侧"办——那会静默丢掉另一侧加严的那半。逐条对比两侧**判据的强弱**,取严格并集;取完要回头验一遍并集在合并后的实况上确实成立(本处的清单从两项抬到三项就是这一步验出来的)。

### 5.2 判据换钉类:三处"剩余 `pending` 快照"互相打脸

这是本槽唯一一类需要**换判据**而不是换期望值的,值得逐条记:

三条分支各自都往 `skills` 套件里写了一处"SK-29 的 `check` 面仍 `pending`"式的断言,用意都是"别因为我这一面落地就把发布门方法论门记成已闭合":

**解法取 `w37` 的口径,不是各自改期望值**:`w37` 在自己那一步就写明了理由——"这里不再拿 `pending` 快照当判据(那一面已落地,写 `pending` 反而是假记账),改钉真实约束:条目仍记 `G-10` + `js/release.js` 对 `Skills` 零引用 + G2/`overall` 计数口径逐字未动"。本槽照这条口径统一了另两处:
