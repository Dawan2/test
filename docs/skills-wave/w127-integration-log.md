## 4. 逐处怎么解

### 4.1 契约段那句散文:同一句话、两种口径,取对侧口径 + 保留我方散文

这是本槽唯一一处**不能靠"现取 live"解掉**的冲突,也是本文第 1 节列的第一件事。

两侧改的都是「文档数字对账契约」那段开头那半句:

- **我方(W125,旧口径)**:`node tests/unit.js contract` **十三条**断言把它们钉在实测值上
  ——数的是"这段里做数字对账的那几条",十三这个数是逐条点着实跑清单数出来的,**零机器判据**。
- **对侧(W126,新口径)**:`node tests/unit.js contract` **套件(实测 102 条断言,含下面这些数字对账在内的全部契约用例;这个条数本身也进对账,现取 `SUITES.contract` 实计,套件加减用例而这句话没跟着改即红)**
  ——数的是整套件实跑条数,有断言接着。

**判据不是"谁的数对",而是"哪一种口径有机器边界"。** 旧口径的问题 `w126` 自己写清了:
"哪几条算数字对账"没有机器边界,按名字前缀圈会漏掉段里点名却不带前缀的三条(循环禁令 / 三套件棘轮 / 单元名唯一),
为它们改名等于给"按名成集双向比对证明没删测"那件取证工具制造一次全仓改名;按首尾标记注释圈则把病灶换个地方漂。
新口径读得出、判得动。**故取对侧口径。**

但对侧那句话是在**看不见 W124 两条新断言**的前提下改写的(2.2),它保留的是叉点那版的段中散文。
我方那段里描述 helper 禁令与 `for await` 禁令的文字**与口径无关、是独立内容**,不能随口径一起被顶掉。
故这一处的解法是**两侧各取一半**:

- 句首那半句(自报条数 + 口径说明)整段取对侧;
- 段中从「块链禁循环只封得住"循环"那一路」到「这两个套件的用例名也各自唯一」之间那段,**一个字不删地取我方**,嵌回原位。

合并后那句里的**数不取两侧任一值**(十三 / 102),现取 live:**104**。
`104 = 基线 contract 103 + w126 那一条`,现跑对过(5.1)。

**用例表那一处**(3 节末记的"该冲突而没冲突"):四条 `report(...)`/条数相关断言现在同段并存——
W120 循环禁令、W121 三套件下限、W124 helper 禁令与 `for await` 禁令、W126 契约段条数。
**四条都留、不并条**,理由沿用 W123/W125 两槽写下的同一条:失败含义不同,报错文案不许合成一句。
本槽实测这四条的分工确实分开(5.6 的六条变异)。
