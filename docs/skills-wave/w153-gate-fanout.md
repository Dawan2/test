# W153 · 门槛码的扇出成契约:`Domain.gateBlockers` 新增一档时,漏投的消费方要被点名

**范围**:`js/domain.js`(阻塞码收进登记表 `GATE`,新增 `D.gateCodes()` 枚举面)+
`js/plans.js`(新增 `GATE_SKIP` 白名单与 `Plans.gateSkips()`)+ `tests/unit.js`(contract +1)+
`README.md` 与本目录 `README.md` 同步。
**基线**:`cursor/w148-integration-9f3a`(`3bbaac1`,开工现取核实相符,自测 509/509)。
**不做**:不发明新的门槛码(四码原样)、不改任何一条门槛判据与阻塞项形状、不改危险级取值、
**不让任何一道发布门去看 `p.script`**(G1–G10 一字未改)、不改 `Issues.GATES` 与 `TODO_OF` 的既有行为、
不新增计费动作/命令/端点、不从 `Skills.gaps()` 摘任何键、不合并其它并行槽。

## 1. 病灶:一向已钉、反向向零

前置门槛派生 `Domain.gateBlockers` 现在有**三个消费方**,取法各不相同:

| 消费方 | 怎么取 | 表外的码 |
|---|---|---|
| 流程条 `Domain.workflow` | `gateOf('script'/'subjects'/'eps')` 按 **step** 分组 | 该 step 没人取就画不出来 |
| 问题中心 `Issues.collect` | `GATES[g.code]` 按 **码** 查投影表 | `if (!t) return;` 静默丢弃 |
| 计划层 `Plans.fromWorkflow` | `TODO_OF` 各取材器读 `gates['码']` | 没人读就不出计划步 |

W138 与 W147 钉的都是**同一向**:「消费方用的码必须是派生会回的码」(码名分裂即红)。
反向那向——**派生新增一档而某个消费方没跟上**——一条断言都接不住,而且它是静默的:
那一态在该面上凭空消失(问题中心一条问题都收不出、计划层弹「当前主线无待推进事项」),
用户看到的与"这项没问题"一模一样。W147 交接第 1 条已经预告过这一格,并写明"真要点名得同轮加一句"。

**基线实测**(`3bbaac1` 独立 worktree,给 `gateBlockers` 加一档 `eps-no-content`,两个消费方都不跟):

```js
if (!eps.length) out.push({ step: 'eps', code: 'no-eps', label: '未建分集' });
else if (eps.some(e => !(e.content || '').trim())) out.push({ step: 'eps', code: 'eps-no-content', label: '有分集缺剧本正文' });
```

→ `node tests/unit.js` **509/509 全绿**。这一档不是"派生回不出来才没红"——同一份基线上现跑
(带空正文分集的项目,Node 直调):派生回 `eps-no-content`,**流程条画得出来**(它沿用 `eps` 这一步,
`gateOf('eps')` 原样带出),**问题中心的项目级条目是空的**(`GATES` 查不到即 `return`),
计划层同样一步不出。两个消费面确实把这一档丢了,而全仓无一条断言点得到——正是本槽要补的那一格。

W138 那条"两侧码集双向相等"看着像已经钉了反向,其实钉不住:它的 `seen` 是**五个夹具摊出来的码**,
再与写死的四码字面比对——新增的码只要没被那五个夹具触发就进不了 `seen`,包含关系两向都照样成立。
判据的枚举面必须来自**派生自己**,不能来自夹具。

## 2. 落法:登记表当枚举面 + 逐码打桩看实际产出

### 2.1 派生侧:码收进登记表,枚举面由表来报

```js
const GATE = { script: 'no-script', subjects: 'no-subjects', noImage: 'subjects-no-image', eps: 'no-eps' };
D.gateCodes = () => Object.keys(GATE).map(k => GATE[k]);
```

`gateBlockers` 的四行改用 `code: GATE.script` 这样出码,**函数体不再出现码字面**。
这样"加一档"这件事没有旁路:进表就进 `gateCodes()`,契约用例当轮点得到;
想绕开表直接写 `code: '新码'` 则撞上"函数体零码字面"那条源级断言。

有意**没有**改成源码扫描函数体取码(那是判据去猜实现),也没有把 `gateCodes()` 写成第二份手抄清单
(那正是本槽要消灭的那类分裂)。四个码在 `js/domain.js` 里仍**各只一处字面**,
W138 立的 `前置门槛码单源` 那条契约用例本槽全程绿、一字未改。

### 2.2 消费侧:接不住的码要写下理由

```js
const GATE_SKIP = {
  'no-script': '整本剧本靠上传/粘贴入库,没有能替用户写剧本的命令;它在场时提取主体与剧本拆集两步一律不出(前置守卫写在上面两个取材器里)',
};
```

`no-script` 是唯一一个**不占计划步**的门槛码,理由不是"忘了",而是计划层根本没有可执行命令能代办
(与 `TODO_OF` 里 `episode.understanding: null` / `episode.preflight: null` 是同一纪律:
不投是写下来的决定,理由跟着落在源码里)。`Plans.gateSkips()` 把它报出来给契约用例查。

问题中心那边**不设免投白名单**:它是断点的唯一清单面(CLI `hujing issues` 与 MCP 同读这份投影),
每一码都得看得见,故契约里它是硬要求。

### 2.3 判据侧:逐码打桩,不靠夹具

契约用例把 `Domain.gateBlockers` 打桩成"只回该码"(项目对象一字不改),再看两个消费方的实际产出:

| 消费方 | 桩下应产出 | 漏投时的报错 |
|---|---|---|
| `Issues.collect` | 恰一条项目级条目,`kind` 与 `label` 原样取派生;`Issues.gates()` 里也在册 | 「门槛码 X 没登记进问题中心的门槛投影表,collect 静默丢弃它」 |
| `Plans.fromWorkflow` | 至少一步计划步 | 「门槛码 X 在计划层既没有取材器接住、也没在 `Plans.gateSkips()` 登记不投的理由」 |

打桩而不是造夹具,是因为**新增的码本来就没有夹具**——夹具是人写的,人漏投的时候多半也想不到写它。
桩把"该码出现时会怎样"这件事变成可枚举的,与码是不是真能被现实项目触发无关。

## 3. 加测(+1)

| # | 套件 · 用例 | 钉住什么 |
|---|---|---|
| 1 | `contract · 门槛码扇出:Domain.gateCodes() 逐码在问题中心与计划层都有投影(漏投即红)` | 六层:①`gateBlockers` 函数体零码字面(绕开登记表的码进不了枚举面);②`gateCodes()` 取表给副本;③真派生在四个夹具上不回表外码;④派生的 `step` 与流程条 `gateOf` 取的步同集;⑤逐码打桩:问题中心投得出条目且 `gates()` 在册、码集不许溢出枚举面;⑥逐码打桩:计划层出得了步,或在 `Plans.gateSkips()` 有理由(理由长度也判,白名单不是许愿池),另加源级一条钉住取材器读的码都在枚举面里 |

第 ④ 层是顺带补的**第三个消费方**:流程条按 `step` 取,新增一档若带了新 `step`(如 `graph`),
`workflow` 里没有对应的 `gateOf('graph')`,它的阻塞项一条都画不出来——与按码那两处同一个病。
判据不是"必须有哪几步",而是**派生给得出的 step 集合与 `gateOf` 取的 step 集合相等**。

## 6. 边界

- **不发明门槛码**:四码(`no-script`/`no-subjects`/`subjects-no-image`/`no-eps`)原样,判据、文案、
  `count` 列、那处 `else if` 互斥全部逐字未改;`gateBlockers` 的产出**逐字节相同**
  (`GATE.script` 求值就是原来那个字面)。
- **不动发布门**:G1–G10 判据与 `fail/warn` 计数一字未改,没让任何一道门去读 `p.script`。
- **不动既有投影行为**:`Issues.GATES` 四行、危险级取值(缺图中危、其余低危)、`TODO_OF` 各取材器的
  判定与文案全部原样;新增的只有一张白名单表和两个只读投影函数,产品路径上没有新调用点。
- **不摘 `gaps`**:`Skills.gaps()` 仍 20 键,短名单 `note` 一字未动——本槽收的是既有消费面之间的
  扇出契约,不对应任何一条缺口编号的"落地",没有键可摘。
- **不合并其它槽**:基线是 W148 集成线 head,本槽只加自己这两条分支提交。

## 7. 交接

1. **给 `gateBlockers` 加一档现在有明确流程**:把码加进 `js/domain.js` 的 `GATE` 表 → 契约用例当轮红两次
   (问题中心、计划层各一次)→ 分别在 `Issues.GATES` 加一行(危险级/落点/一行说明)、在 `TODO_OF`
   接一个取材器**或**在 `Plans.GATE_SKIP` 写下不投的理由;若这一档带新 `step`,还要在 `Domain.workflow`
   里给那一步接 `gateOf`。三处都跟上了才绿。
2. **`Plans.gateSkips()` 现在只有 `no-script` 一条**。它不是"永久豁免":哪天计划层有了能代办整本剧本
   入库的命令(如"从各集正文回填整本原文",W147 交接第 2 条提过),就该把这条理由删掉改成取材器——
   删不掉时白名单那条断言会反过来红(登记了理由却真出得了步)。
3. **问题中心那侧有意没有白名单机制**。它是断点的唯一清单面,"某一档故意不给用户看见"这种需求
   一旦真的出现,要先想清楚 CLI/MCP 同读这份投影的后果,再决定是加机制还是改那一档该不该存在。
4. **本槽只覆盖项目级门槛码的扇出**。分集级阻塞项(`Domain.episodeState` 的 `blockers`)有它自己的
   一组消费方(问题中心逐集分支、`flow-tpl` 的 `gaps`、计划层集级取材器),扇出契约同样没钉——
   形状与本槽不同(那边是逐集循环里的分支而不是查表),要收得先看 `episodeState` 的 blockers
   能不能也收成一张可枚举的登记表,与本槽是两件事。
