## 1. 停工位:先在基线 live 举证「三档空跑末堆恒 0」

W202 残留第 4 条记的是:`emptySubjectImageNote` 末一堆「N 位没能说清原因」是安全阀,
**真实调用点上恒为 0,行为面无人覆盖,只有源级读得出来**。先把这句话本身跑一遍。

沙箱 `loadCommands()`(浏览器命令层)与 `loadCli()`(headless 那一端)各真跑一次
`subject.generateImage`,三档如交接所列(无主体 / 全有图 / 点名不在库),末堆从回执 `note` 上正则取数:

```
浏览器  ① 无主体      ok=true total=0  note="项目还没有主体,一位也没跑"                     末堆=0
        ② 全有图      ok=true total=0  note="没有待补图的主体,一位也没跑:2 位已有参考图"    末堆=0
        ③ 点名不在库  ok=true total=0  note="点名的 2 位主体一位也没跑:2 位不在主体库"       末堆=0
CLI     ①②③ 与浏览器逐字相同(两端同读一份派生)                                          末堆=0
```

三档成立。纯函数面上末堆造得出非零也现跑过——库里还有缺图主体却说没得跑(整集那一路)、
点名的主体就在库里却说没跑(点名那一路),两种形状分别报 `1 位没能说清原因`。
两者在命令层够不着的原因同一条:两端 `todo` 的筛法与派生的分堆筛法互为反面
(整集路 `!s.image` 对 `s.image`、点名路 `ids.has(s.id)` 对 `ids.includes(s.id)`),
只要有一位归得进末堆,`todo` 就非空,压根不到空跑早退那一行。

## 2. 但「恒为 0」不成立:非数组 `subjectIds` 是真进得来的形状

停工位第 2 问要的是「能否造出末堆 > 0 的夹具,若能造出而命令层不走 note 才算恒 0 成立」。
造得出,而且**命令层照走 note**——走的还是错的那一档。

两端选人闸都写成 `Array.isArray(args.subjectIds) && args.subjectIds.length`
(`js/commands.js` 第 229 行、`cli.js` 第 1290 行),而派生里那一句是 `picked && picked.length`。
非数组的 `subjectIds` 于是被两边读成两件事:命令当"没点名"整集跑,回执当"点名了"逐个数。

这个形状不是臆造的:`CMD.exec` 的 `--args` 是 `JSON.parse` 原样进来的,不按类型整形
(`cli.js` 第 1426 行),MCP `hujing_exec` 的 `args` 同样原样 `JSON.stringify` 转手。
只有助手自动发令那条路会经 `WfCore.sanitizeCmdArgs` 把非数组丢掉——人手那三条口子都没有这一层。
把一个 id 直接写成字符串(`--args '{"subjectIds":"sj_nv"}'`)是最顺手的写法。

基线 live(全部主体都有图,故两端都走空跑早退):

```
--args '{"subjectIds":"sj1"}'            普通库(5 位,id 都是多字符)
  命令实际:整集路,引擎实收 0 位
  回执    :"点名的 5 位主体一位也没跑:5 位不在主体库"   ← 用户只写了 1 个 id,回执说他点了 5 位
--args '{"subjectIds":"sj1"}'            库里恰有单字符 id(s / j / 1,都有图)
  回执    :"点名的 3 位主体一位也没跑:3 位没能说清原因"  ← 末堆 = 3,「恒为 0」当场不成立
--args '{"subjectIds":{"0":"sj1","length":1}}'
  new Set(picked) 抛 "object is not iterable",一次 ok 空跑被 metered 接住塌成 fail
```

字符串被 `[...new Set('sj1')]` 按**字符**拆成了 `['s','j','1']`——「点名的 N 位」里的 N
是字符数,不是用户点的位数;库里的 id 恰好是单字符时这些字符全都命中,`gone = 0`,
剩下的整堆落进安全阀。这不是安全阀失灵,恰恰是它按设计露了头:归不了堆的位数没被抹平,
所以这条漏报才有地方看得见。

## 3. 改了什么:派生的点名判据与两端选人闸同形

`js/domain.js` 一处:

```js
-    if (picked && picked.length) {
+    if (Array.isArray(picked) && picked.length) {
```

注释同轮补上理由(为什么必须与选人闸逐字同形、字符串与类数组各会出什么事)。
改的是**回执怎么分档**,选人逻辑一个字没动——不为了让阀门非零去动选人,
也不把安全阀从派生里删掉装绿。改完两端四档逐字对齐:

```
浏览器/CLI  --args '{"subjectIds":"sj1"}'              note="没有待补图的主体,一位也没跑:3 位已有参考图"  末堆=0
浏览器/CLI  --args '{"subjectIds":{"0":"sj1",...}}'    同上(不再抛)                                        末堆=0
浏览器/CLI  --args '{"subjectIds":["sj1"]}'            note="点名的 1 位主体一位也没跑:1 位不在主体库"      末堆=0
```

`cli.js`、`js/commands.js` 零 diff:两端本来就同读一份派生,修在派生上两端一起好。

## 4. 补的行为面:`commands` +1 条

停工位第 3 问要的两半都钉进同一条用例
(`subject.generateImage 空跑回执的末堆安全阀:纯函数造得出非零,两端真实入口一律 0(含非数组 subjectIds)`):

1. **纯函数面造非零,逐字红在期望句**:整集路 `没有待补图的主体,一位也没跑:1 位已有参考图、1 位没能说清原因`、
   点名路 `点名的 1 位主体一位也没跑:1 位没能说清原因`,两句用 `assertEq` 整句对——
   把 `say(..., '没能说清原因')` 任一行摘掉即红,措辞改了也红。
2. **同一份夹具交给命令层是真跑得到的一位**:`total === 1`、`note === undefined`。
   这一步是"末堆在真实入口上够不着"的正面理由,而不是靠"跑不出来"推断——
   选人闸哪天漏了人(空跑早退真被触发、安全阀真响),红的是这一句,不会让回执替漏跑打掩护。
3. **两端真实入口逐档末堆必须 0**:五档(无主体 / 全有图 / 点名不在库 / 点名给了字符串 / 点名给了类数组)
   × 两端(`Commands.execute` 与 `EXEC['subject.generateImage'].run`),
   每档都判 `ok === true`(拼句抛异常会在这里塌成 fail)、`total === 0`、引擎实收 0 次、
   `note` 整句相等、末堆 `=== 0`。

有意不加源级判词:两端选人闸与派生分档是否同形,靠"字符串那两档回执必须是整集路那句"从行为上量,
不再添一条读源码的正则。`cli.smoke` 一条没加(分母仍 109)。

## 7. 交还与残留

- **末堆能不能非零**:纯函数面能(两种形状),真实入口上修完之后**不能**。
  修之前能——非数组 `subjectIds` 那条路上末堆真的报出过非零(库里有单字符 id 时),
  故 W202 残留第 4 条那句"真实调用点上恒为 0"在基线上是**不成立的**,本槽把它变成成立的。
- **补的是函数面还是命令面**:两面一条用例里都补了,重心在命令面
  ——纯函数那两句是为了给"命令层为什么够不着"提供正面理由,不是单独的派生测。
- **`emptyBatchNote` 那一侧同形的口子没碰**:镜头侧 `js/commands.js` 与 `cli.js` 的 `shotIds`
  选人闸同样是 `Array.isArray(...)`,而 `emptyBatchNote` 里也是 `picked && picked.length`,
  同一条漏报在镜头侧成立(交接明令不动镜头侧,故本槽一个字没改,如实留在这里)。
  要收的话判据与本槽逐字同形,行为面照抄第 4 节三点即可。
- **`say()` 的负数没兜底**:库里出现同 id 的两位主体时 `gone` 会算成负数,
  回执报出 `-1 位不在主体库`。这一档在两端命令上够不着(同 id 有一位命中 `todo` 就非空),
  纯函数面上现跑得出来,登记在此不动。
