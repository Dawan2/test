# W289 主体库卡片补同 id 重复标记:撞车的每一位报出「第几位 / 共几位」

> 起点 `origin/cursor/w288-integration-4291` 尖 `f9a6bfa`(`checkout -b` 后 `rev-parse` 现取核过,
> 与交接自称逐字节相同)。功能支 `cursor/w289-dupcard-7c31`。

## 一、收的是哪一条

W285/W286 残留,原话:

> 卡片本身没有重复标记,页面级发现仍靠页头那个总数。

W285 给主体库补了去重入口、W287 给分镜面补了同形的一条,两槽都把「要改几位/几行」写在页头那个按钮上。
但那个数只回答**「有几处要改」**,不回答**「是哪几张卡撞了」**——卡片按 `p.subjects` 逐条渲染,
同 id 那几位在卡片上与几个不同主体长得一模一样:名字、类型、参考图、音色、定稿位各是各的,
撞的只是那个**看不见的 id**。于是读到「🧹 主体 id 去重(2)」的人,想知道是哪几位,只有两条路:
点开弹窗看计划(那一屏按序号点名「第 3 位「C-…」」,而卡片上没有序号可对),或者自己去猜。

本槽只补那一格:**撞车的每一位在自己那张卡的名字旁挂一枚小标,报出「第几位 / 共几位」。**

## 二、标记长什么样

现网 `tag yellow` 同形的一枚小标(与去重弹窗里点名重复 id 的那一枚同色同形),挂在卡片名字那一行、
排在「✓ 已定稿」左边(两枚共存,那一行加了 `wrap`,230px 窄卡上换行不挤):

```
🧹 id 重复 第 2/3 位
```

悬停那句说明(`title`)现取同一份标记,报四件事:

```
主体库里共 3 位主体共用 id「dup」(可能分散在不同分类下,本页只看得见其中几位):
这是其中第 2 位,去重时这一位改发新 id,名字与设定一个字不动。
按 id 取主体只找得到第 1 位,而批量补图按位逐位跑、逐位计费;
收拾存量走页头「🧹 主体 id 去重」(先看计划,确认才改)。
```

三件分寸就在这枚小标上定住:

| 分寸 | 取的口径 | 不取那一种会怎样 |
|---|---|---|
| **留原 id 那一位也标** | 撞了 id 的**每一位**都挂,含第 1 位 | 只标「要改的那几位」的话,「引用会落到哪一位」就读不出来——而那正是用户最想知道的一句 |
| **共几位按全库算** | `p.subjects` 整表口径 | 按本分类 tab 数的话,同 id 那几位分散在角色/场景/道具下时,两个 tab 各报一个数(场景那一位会标成「第 1/1 位」) |
| **页头那个数与卡片那几枚不是同一个数** | 页头数**要改几位**(首位不算),卡片标**撞了 id 的每一位** | 强行凑成同一个数就得挑一边说谎:页头改成 3 会与「确认后改 2 位」对不上,卡片漏掉首位就丢了上面那一格 |

夹具上这三格的实况(五位主体 `dup/solo/dup/dup(场景)/lone(场景)`):

```
页头            🧹 主体 id 去重(2)
角色 tab        A-首位 第 1/3 位   B-不重复 (无标)   C-第二位 第 2/3 位
场景 tab        D-场景那一位 第 3/3 位              E-只此一位 (无标)
```

## 三、位次从哪来:只读 `Domain.dupIdScan` 的结果,页面不扫第二遍

明令「去重规则仍只读 `Domain.dupIdScan`,禁止页面再抄一份扫描」。而扫描给出来的是**整组口径**:

```
duplicates: [{ id, n, keepOrder }]        哪个 id、几处撞车、哪一处留原 id
plan:       [{ order, from, to }]         首处之外每一处改成什么
```

卡片要的是**逐处口径**「这一张是第几处、共几处」。这中间那一步派生本槽下沉 `Domain.dupIdMarks`:

```
D.dupIdMarks(scan) → { 序号: { id, nth, total } }
```

推法只有一句:计划里 `from` 是这个 id 的那几条**恰是首处之外的后续处、按序号升序排**,
故首处算第 1、计划里第 k 条算第 k+1,共几处 = 1 + 那几条。

**为什么收在派生里、不让页面自己数一遍:** 位次与「改哪一处、留哪一处」是**同一套序**。
两份数法一漂,卡片上标的「第 2 位」就与预览里改的那一位对不上——而用户是把这两处**一起读**的
(先看卡片认出是哪几张,再点开弹窗核计划)。M4/M5 两手证明了这一格:两种改法**行为面逐字节等价**,
只有源级那两句接得住。

**为什么不读 `duplicates` 上的处数字段:** 那个字段名由两端各自换成自己的单位词——
主体侧 `dedupeScan` 把 `n` 换成 `seats`、镜头侧 `dedupeShotScan` 换成 `rows`。
读它这一层就得认识两个名字;从计划现推则两侧同一份代码都读得动
(判据里把换过单位词的那份结果也喂了一遍,M6 就是读 `d.n` 那一手,当场红 2)。
单位词照旧留给调用方在展示那一层换上——「位」这个字只出现在 `js/roles.js` 的模板里。

## 八、残留

按「产品上还差什么」排,一条不多写:

1. **分镜卡片还没有同 id 重复标记。** 明令点名下一槽。形状不能照抄本槽:分镜侧的单位词是「行」,

   「挂在哪一处才五档都看得见」得像 W287 挂顶栏那样先量一遍;`Domain.dupIdMarks` 收下
   `dedupeShotScan` 换过单位词那份结果照样读得动(本槽判据已把这一格喂过),要加的只有展示那一层。
2. **`cli.js` 的 `shots-dedupe` 注释里点名 `Domain.reviseTargets` 的那半句仍不准**(W287 残留第 1 条原样在)。
   明令不碰,继续记账点名。
3. **发现存量重复仍得先走到主体库那一页。** 项目详情面与项目卡片上没有对应的角标,
   页头那个按钮与本槽这几枚小标都只在主体库(独立页与项目详情嵌入版)渲出来;
   整树导入/恢复那几条路照旧能写进重复 id(明令不给入口加闸),这仍是**存量**出口。
4. **小标只报位次,不报"这一位与哪一位撞了"的跳转。** 用户读到「第 2/3 位」之后想看第 1 位长什么样,
   仍得自己在同一 tab(或别的 tab)里翻——跨分类那一位尤其翻不到,小标那句说明只提了一句
   「可能分散在不同分类下」。要收得给小标挂上按序号定位的跳转(与分集页 `__roleFocus` 那条路同形)。
5. **主体侧与镜头侧的展示文案仍各写一份**(W287 残留第 5 条原样在)。本槽又添了一句
   (卡片小标那句说明),要合并成一份模板得先把单位词与引用面交代那一段参数化。
