## 1. 一句话结论

**周期 8 是七个周期里第一个"什么产品功能都几乎没加、把三个洞堵上"的周期:
提示词注册表整轮只从 40 键推到 41 键(净 +1),`CHECKS` / 面表 / `gaps()` / `KB` / `playbooks` / `pending` 七个数一个没动,

变异实测逐条转红——这是"核验报告开药方 → 某个槽照方抓药"这条路径七个周期以来第一次真的走通。
代价是治理动作本身长出了新的失误面:功能槽基线纪律在周期 7 做到 13/13 之后,本周期出现两次落在功能槽 head 上,
其中一次(W110)因此整条跳过了一个集成波次;而 `tests/unit.js` 刚补上的用例名唯一性断言,
在 `tests/integration.js` 上还没有对应的一条,那里此刻就有一对同名。****

先说堵上的三个洞,三条都是本槽变异实测出来的,不采信任何一份记账件的自述:

1. **W102 那条**把 `README` 的 `integration`(130)与 `cli.smoke`(102)两个数字接进现算对账。
   周期 6 与周期 7 两份报告各实测过一次"改错全绿",本槽把同一路变异重跑,**这次两次都红**。
   它选的口径不是实跑(两套件都要起真实服务子进程,单测里跑不动),而是**按套件源码里 `report(...)` 的独立行数静态点数**,
   再配一条「每条用例须是独立一行的 `report(...)` 调用」把静态数与实跑数钉在一起。**这条钉法有一处漏,见 6.3。**

   与目录实况、索引表行数三方对齐,外加一条 `FLOOR = 127` 的只增不减棘轮。
   周期 7 那路"文件与索引行一起删就全绿"的变异,**本槽重跑当场红**;把明写份数也改小仍红。
   **要静默删掉一份记账件,现在得同时改四处**,其中第四处在 `tests/unit.js` 的 `FLOOR` 字面上。
3. **G-13 的 A / C / D 三张名单本周期全部归零**,余量只剩判据外的 `js/api.js` 两处层内兜底缺省(`'你是专业助手。'`),

### 6.3 W102 那条契约的确切边界:本槽把它量了出来

W102 选的口径是**静态点数**:数 `tests/integration.js` / `tests/cli.smoke.js` 里 `^[ \t]*report\(` 的行数,
拿它和 README 的数字比。这个口径成立的前提是"静态行数 = 实跑条数",而那条前提由同一个用例里的一句断言守着:

```
assertEq(calls, lines, label + ':每条用例须是独立一行的 report(...) 调用(嵌进表达式或回调里静态点数就代表不了实跑条数)')
```

**这句注释里写的防线,本槽实测只对单行形态成立。**

- **变异 6**(单行 `[1,2].forEach(() => { report(...) });`):行首不再是 `report(`,行数少 1、调用数不变 → **当场红** ✅
- **变异 19**(把同一句拆成三行,`forEach` 开头一行、`report(` 仍独立成行、`});` 一行):
  **行数不变、调用数不变 → 断言全绿**;而 `node tests/integration.js` 实跑从 **130 变 131**。
  README 仍写 130,**静态数与文档数一致、与实跑数差 1,单测 471/471 全绿。**

**所以这条契约的准确说法是**:它把"README 数字与套件源码脱钩"这个洞堵上了
(改数字会红、删测不改数字会红、手写总数会红),
**但"套件源码与实跑条数脱钩"这一层只封住了单行写法**;多行包裹是同一个洞的另一个入口,
而这两个套件恰恰是**单测里跑不动、只能静态点数**的那两个。

**同一类的残留还有一条(变异 7)**:真删一条 `report(` 并把 README 同步改小,全绿。
这与 `unit` 那条同形(`unit` 的数也是从套件表现算的),
**区别是记账件份数那条有 `FLOOR` 棘轮,而三个用例数一条棘轮都没有。**
