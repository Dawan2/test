## 二、这套 Skill 的组织方式(机制,比清单更有参考价值)

- **Skill = 一份 Markdown**:写清楚"一个环节该怎么做 / 什么能做什么不能做 / 质量标准在哪里",Agent 读文件即可执行该环节。安装形态是 `.agents/skills/<name>/SKILL.md`(Codex)或 `.claude/skills/<name>/`(Claude Code)。
- **分层**:内容创作类按功能分 12 层(选题→创作→下载→配音→数字人→编辑→字幕→视觉→图文→调度质检→动效→商业诊断),另有编码开发类。
- **调度器 Skill**:每条长链有一个"总控"Skill 负责串联下游(`ra-video-wash-pipeline` 管前期、`ra-video-production-director` 管制作期),用户一句话触发,中间不逐步下指令。
- **交接稿契约**:前期链产出一份"交接稿",其 frontmatter(比例/时长/声音/字幕风格)是**硬契约**,下游 Skill 的默认值不得覆盖;`status` 字段承载整条生产线状态。
- **硬门(gate)**:多处设置"不通过就停"的卡点——付费生成前必须有用户确认过的试听音频;字幕 QC 未过不算交付;最终质检(画幅/分辨率/音视频流/抽帧)全过才允许归档。
- **状态即目录**:项目文件夹在「待制作 / 制作中 / 已制作」之间移动,兼作多机互斥锁(防两台机器重复制作)。
- **人工只留 3 个决策点**:确认校对稿、确认试听音频、挑封面(作者自述每条视频约 5 分钟人工)。
- **隐私区**:下载源视频、逐字稿等中间件存 `.internal/`,不进成稿、不进归档、不进公开文档。

## 七、与本平台的相关性汇总(仅供筛选,未决定落地)

按相关性从高到低,可进入后续讨论的**机制类**要点:

1. **制作总导演 + 交接稿硬契约**(`ra-video-production-director`):上游契约字段优先于下游默认值、状态目录兼互斥锁、质检全过才允许归档。与本平台 `domain.js` 单源 / `release.js` 发布门 / 任务幂等键三处同构,是对"主线贯通"最直接的参照。
2. **一句话触发的长链调度**(`ra-video-wash-pipeline`):对应本平台 Commands 统一命令层 + Plans 持久计划,可对照其"人工只留 3 个决策点"的收敛程度。
3. **字幕时间戳必须来自真实音频 + 结构化 QC 产物**(`ra-audio-to-subtitles`):可直接作为纪律与审片维度候选。
4. **渲染 manifest + 禁止静默降级**(`tts-skill`):与本平台"失败如实报错并退费、不用占位冒充"一致,manifest(参考文件哈希+参数+fallback 标记)可作为可追溯凭据的样板。
5. **付费动作前置确认门 + 输入变更使确认失效**(`heygen-digital-avatar`):与本平台 `Tasks.run` 计费纪律互补。
6. **发布后复盘回写上游**(`ra-复盘`):本平台主线双向流动目前缺的最后一段闭环。
7. **去 AI 味硬禁清单**(`ra-人话`)与 **AI 痕迹检出**(`dbs-ai-check`)配对:可接入本平台提示词单源与文本质量门。
8. **风格注册表 + 多候选出图**(`skill-cover`)与**排版脚本 + 图形每次重绘的两层分工**(`rn-cover-skill`):对应本平台影调风格双轴与"模板+生成"混合出图。
9. **量化质量门**:Anti-PPT 门(`rn-motion-director`)、全帧门(`rn-replica-qc`)、口播剪辑量化参数(`ra-local-talking-head-cut`),可作为审片标准的量化取向参照。
10. **会话状态存档/续读**(`dbs-save` / `dbs-restore`)与**模糊需求规整为可执行说明书**(`dbs-good-question`):与本平台 Plans 跨会话落库、continuity 快照、导演助手目标规整同类。

低相关性(本平台形态不涉及):外部平台视频下载、公众号提取、数字人形象本身、SaaS/黑白文字动效风格、dbs 商业与个人成长诊断工具的大部分。
