## 2. 宿主长什么样

"校验宿主"不是新模块,而是**把剧本正文接进已有的校验型扩展点**,让 `Skills.check('script', …)` 这条早就存在却一直空转的调用路径真正有东西可跑:

```
剧本正文(ep.content / p.script)
        ↓  Skills.check('script', {p, ep, s}, ctx)      ← 早已存在的分发口,本轮之前 script 步恒回空数组
  CHECKS['script.*'](obj) → {pass, level, hits}          ← 本轮新增的三条实现
        ↓
  episode.preflight.result.checks(浏览器 Commands / CLI exec 同一份)
  Issues.collect() 的 script-craft 低危条目(浏览器可见)
```

**文本源**:有分集上下文取 `ep.content`,没有就取 `p.script`——拆集前只有一份整本剧本时同样判得动,剧本步本来就是这三条的作用面。
**判定基面**:一律先去空白(`replace(/\s+/g,'')`),位置 `at` 与字数用同一口径,换行缩进不影响结论。
**判定下限**:去空白正文短于 30 字视为无判定输入,直接回 `info` + 空命中——不拿"通过"冒充"没判"(缺剧本本身是问题中心的高危项,不在这里重复报)。

## 3. 三条校验项判据

### SK-07 `script.openingHookAnchor` — 开篇钩子锚定

判据出自 `KB` 条目「钩子六型」的最后一句:**前 3 秒必须冲突锚定,直接进冲突,背景后面补**。

| 命中码 | 判据 | 级别 |
|---|---|---|
| `late-hook` | 开篇窗口(去空白前 120 字)内没有冲突锚点,正文后面才有;`hits` 带全文首个信号词与它的位置 | `warn` |
| `no-hook-anchor` | 全文都找不到冲突锚点(通常是梗概/设定稿,不是可拍剧本) | `warn` |

- **锚点**= 出现引号台词(六型示例无一例外从台词或动作瞬间起手),**或**命中冲突信号词表。词表按六型各取其字面可判定的信号(身份反转/误会揭穿/致命危机/情感极限/秘密曝光/打脸预备)。
- 窗口取 120 字是按约 4.5 字/秒的口播量折算的开篇十余秒——比"3 秒"宽,**宁可漏判也不误报**:这是提醒不是门禁。
- 两个命中码互斥,一次最多一条 hit;`hits` 另带开篇 24 字摘要供展示层直接显示。

### SK-08 `script.faceslapStepOrder` — 打脸四步完备性

判据出自 `KB` 条目「打脸四步」:**羞辱 → 隐忍 → 反击 → 释放,四步缺一不可**。每步一组字面信号词,取其在正文中的首现位置。

| 命中码 | 判据 | 级别 |
|---|---|---|
| `missing-step` | 该步一个信号词都没命中;`hits` 带步名 | `warn` |
| `step-out-of-order` | 该步首现早于**前一已命中步**;`hits` 带步名与基准步名 | `warn` |

- **命中步数不足两步就不判**:不是每集都该有打脸段落,拿"没写打脸"当缺陷报是纯噪音。两步以上才认定"这是一段打脸戏,可以谈完备性"。
- **各步词表只收该步独有的字面**:跨步通用词(如"当众""跪下"这类既能出现在羞辱也能出现在释放的钩子用语)一律不收——一个词同时属于两步,会把步序判成假倒置。词表调整过一轮正是为此。
- 篇幅配比(羞辱约 40%、反击约 30%、释放约 30%)与爽点强度递进**不判**:字面信号定不出段落边界,配比要靠语义分段,属审片维度(`G-10`)。

### SK-09 `script.dialogueLineLength` — 台词单句长度

判据出自 `KB` 条目「对话铁律」:**单句 ≤30 字**。

| 命中码 | 判据 | 级别 |
|---|---|---|
| `long-line` | 单句去空白字数超阈值;`hits` 带载体(`script`/`shot`)、镜号或正文位置、实际字数与句首摘要 | `warn` |

- **两处载体一份实现**:剧本正文的引号台词(中英文引号通用),与分镜表的 `s.dialogue`。SK-09 的 `covers` 本就是 `script` + `shots`,判据只此一份。
- **阈值现取 KB 条目正文**:从「对话铁律」里解析 `单句≤30字` 的数字,校验层不写第二份;条目改写导致字面失配时,契约测试里那条 `assert(/单句≤30字/.test(KB.section('对话铁律')))` 先红。
- 一段台词先按中文句读(`。!?;…——`)切句再逐句判长:一段三句的对白不会因为总字数被误判。
- 铁律的其余分句(潜台词代替直白、禁说明文式台词、长独白全剧 ≤3 处)**不判**:前两条是语义判断,第三条要全剧口径,分集级判定会偏严。

## 4. 消费点与"只报不拦"

**就绪检查(双端)**:`js/commands.js` 与 `cli.js` 的 `episode.preflight` 各加一句,结论按主线步序拼接:

```
result.checks = Skills.check('script', {p, ep}) ++ Skills.check('subjects', {p, ep})
              = [钩子锚定, 打脸四步, 台词长度, 引用完备性, 跨镜一致性]
```

`episode.preflight` 仍是 `risk: 'read'` / `meter: false` 的零计费命令,`ok`/`status` 仍只由 `Domain.episodeState` 决定,校验结论只搭在 `result.checks` 上——与 SK-12 那轮定下的口径逐字一致(单测按源码断言两端都没有把结论并进 `Domain` 推导结果)。

**问题中心(低危)**:`js/issues.js` 新增 `{kind:'script-craft', sev:'low'}`,明细把命中码翻成中文并带定位(打脸步名 / 台词摘要 / 镜号),处置走导航自查(不挂命令,点它不会发起任何生成)。

这条 push 放在**未拆镜等早退分支之前**——原有逐集循环里"没剧本""没分镜""分镜过期"三种情况会 `return` 掉后续判定,而剧本刚写完还没拆镜时,正是这三条最该被看见的时候。放在缺剧本判定之后则是必要的:没有正文就没有判定输入。

选低危同 SK-13:发布门 G2 只数高/中危(`js/release.js` 本轮一行未动),**低危不改任何存量项目的门禁状态**。
