# W141 · 静态点数的反方向补判据:`report(...)` 不许坐在会跳过的条件块里

> 槽位范围:`tests/unit.js` 的 `contract` 套件新增 1 条用例 + 抬 2 个既有下限字面,`README.md` 同步两处数字与契约段一句,
> `docs/skills-wave/README.md` 份数与索引行,本记账件。
> **零产品代码改动**(`js/`、`server.js`、`cli.js`、`mcp.js`、`billing.js` 一行未改),不动发布门口径、不新增计费动作、**不删任何用例**。

## 1. 病灶:五层测试契约全在守「静态 < 实跑」,反方向一条没有

`integration.js` 与 `cli.smoke.js` 这两个套件跑不进单测(都要起真实服务子进程),故 README 里它们的用例数是**静态点数**——
数行首的 `report(` 有几行。围着这个口径已经有五层判据:

| 层 | 判据 | 防的是 |
|---|---|---|
| L1 | 行首点数 == 调用数 == README 明写数 | 数字写错、登记嵌进表达式 |
| L2 | 契约段自报条数 == `SUITES.contract` 长度 | 那段散文自己的数漂 |
| L3 | 块链上不许有循环/迭代回调 | 换行包进 `forEach` 体 |
| L4 | 块链上不许有 `main` 以外的函数体 + `report` 须是裸表达式语句 | 包进 helper 复用 |
| L5 | 三套件下限棘轮 + 下限与 live 的差额上限 | 真删测、把文档一并改小 |

五层封的方向是同一个:**一处静态登记点跑出多条**,即 静态 < 实跑。反方向——**静态 > 实跑**——一条判据都没有。
周期 9 的独立核验件(`w130-cycle9-audit.md` 洞二)把它量了出来,本槽收它。

复现只要把一条 `report(...)` **原样搬进带花括号的条件块**:

```
if (process.env.MV_EXTRA_CHECK) {
  report('充值后余额正确', wallet.balance >= 100, '实际 ' + wallet.balance);
}
```

行首点数、调用数、用例名字面数、不同名数**四个静态口径一个不变**,块头既不是循环也不是函数体
(L4 的函数体判据按 `CTRL` 词表把 `if (…) {` 有意排除了——不排除的话所有控制结构都会被当成函数体误报,那个排除本身是对的),
于是五层全绿;而这条分支不成立时**实跑就少一条**,README 对的是套件末尾自报的实跑数。

本槽在基线 `42b2798` 上现跑复核了这一处:施加上面这条变异后 `node tests/unit.js` **492/492 全绿**,
而 `node tests/integration.js` 实跑 **129/129**、README 写着 **130**。
这是本目录里 README 数字与实跑数**可以长期不等而全绿**的那一路。

同一条改成**同一行前缀写法**(`if (cond) report(…);`)反倒 L1/L4/L5 三层同时红(第 3 节变异 2 实测),
故漏在外面的只有"带花括号"这一种形状——判据缺的是块写法这一路,不是整个条件分支这件事。

## 2. 落地:判据不是"禁止 `if`",是「块链只许无条件块」

新增一条用例接在 L4 的 `for await` 那条之后,**既有五层一字未改**(只按各自写明的规矩抬了两个数字,见 2.4):

```
const isMain = h => /^(?:async\s+)?function\s+main\s*\(\s*\)\s*\{$/.test(h.trim());
const OWNED = /=>\s*\{$|(?:^|[^\w$])(?:function|for|while|do)(?![\w$])/;
…
if (!/\{$/.test(h) || h === '{' || isMain(h)) return;
if (OWNED.test(h.replace(/'[^']*'|"[^"]*"/g, "''"))) return;
bad.push(…);
```

块链仍由既有的 `reportBlockHeads` 还原(抹码 → 括号配对 → 取每个未闭合开括号所在行的块头),本槽没有另立第二种扫描。

### 2.1 为什么立白名单而不是列 `if`/`switch`/`try` 词表

L4 的第二条(`for await`)已经把这一课上过:**按词表匹配字面这类判据的固有面是"词表列举得再全,写法比词表多"**。
条件块这一路比循环更宽——`if` / `else` / `switch`-`case` / `try`-`catch`-`finally` 都是分支,以后还会有新写法。
故本条反过来立**白名单**:登记点的块链上只许出现"进了 `main` 就一定执行"的块——

- `async function main() {`:套件唯一的入口函数体;
- 就地开的裸 `{`:两个套件用来分节的那种块,进了必执行。

其余一律红。`switch` / `try` 这两种本槽从没写进任何词表,变异 5 / 变异 6 照样各红一条(第 3 节),
这正是白名单相对词表的差别:**新写法默认落在红的一侧**。

这条**不是"禁止一切 `if`"**:判据只看那条 `report(...)` 的块链,两个套件里其余的合法分支
(`report` 自己的 `if (cond) PASS++`、`if (data) r.write(data)`、清理与就绪等待里的那些)一处也不碰。

### 2.2 归口:哪些形状留给上面三条报

块头写着 `for` / `while` / `do` / `function`、或以 `=> {` 收尾的,是 L3 与 L4 的辖区,本条**不重复报**:
它们报的是"一条登记跑出多条"(静态 < 实跑),本条报的是"这条登记可能一条都不跑"(静态 > 实跑),
两个失败含义不合并——这与本套件"一条用例一个失败含义"的惯例一致,也是任务点名要保的分工。

归口有意做得**窄**:漏归口只是多红一条(块头确实不是无条件块),归口过宽才会开洞。
`{` 之外的层(调用/数组的括号)同样跳过——那说明登记点落进了表达式,归 L4 的"裸表达式语句"那一点管;
不跳过的话多行 `forEach` 会连坐三条(第一版实测:`[1].forEach(` 这个**括号头**被本条点到,而它的箭头体已经归口了)。

### 2.3 归口判词先抹掉块头里的字符串字面量

`OWNED` 认的是 `for`/`while`/`do`/`function` 这几个词,而块头里的**字符串字面量**照样含这些字:
`if (process.env.MV_MODE === 'do-it') { … }` 里的 `do-it` 会让归口误判成"这是循环,归上面报",而上面那几条判据一个也点不到它——
洞就这么开回来。故归口判词前先把块头里的 `'…'`/`"…"` 抹成空串。

这一步是**实测出来的**、不是预防性的:拆掉这行后同一条变异 `107/108` 全绿(只剩本槽未落地的份数那条),装回去当场红(第 3 节变异 7)。
顺带量到的一处基线实况:同形的 `'for-real'` 字符串会让 L4 的 `for await` 那条误报一句(它的 `FOR_KW` 同样读到了字符串里的 `for`),
`'function'` 会让 L4 的函数体判据误报一句——**既有词表判据自己也在读字符串**,本槽不动它们(那是它们各自的判据面),只把本条的归口口径钉死。

### 2.4 顺带抬的两个字面

按各自条目写明的规矩抬,只改数字、其余判据一字未动:

| 下限 | 抬档 | 依据 |
|---|---|---|
| 三套件棘轮里的 `unit` FLOOR | `492` → **`493`** | 「新增用例时把下限抬到当轮实况」,对应本槽这一条用例 |
| 记账件份数 FLOOR | `149` → **`150`** | 「新开一槽记账时把下限抬到当轮实况」,对应本记账件这一份 |

集成与 CLI 冒烟两格实测就是对的(130 / 102),一个数字没改。抬完四格差额**全为 0**。

## 6. 交接

1. **本条只覆盖"块链"看得见的那一路**。看不见的那一路仍开着:登记点在 `main` 里但**前面有一处提前 `return`/`throw`**,
   块链上一层条件块都没有而后面那些 `report` 照样一条不跑。这一路上 L1 与本条都点不到,今天只有"套件跑完自己打印总数"这件事看得见,
   而没人把那个总数与 README 对起来——**要接得住得换判据类别**(比如把实跑总数落成产物再对账),往块链判据上再叠一层没用。
2. **CLI 冒烟那 2 项与 `master` 同名的失败照旧不影响对账**(对的是用例总数不是通过数),这一点本槽没有改动。
3. **白名单认的"裸 `{`"没有语义判据**:它认的是块头恰好只有一个 `{`。要是以后有人写 `{ // 只在某某情况下跑` 这种带条件语义的分节块,
   本条照旧放行——判据看的是语法形状,不是注释里的意图。
4. **归口那份 `OWNED` 与 L3/L4 的词表是两份**(本条只需要"这形状归别人报"这一点,不需要复刻它们的判据),
   故 L3/L4 收严词表时本条不必跟着改;反过来,若哪天把 L3 或 L4 整条撤掉,归口就会变成真洞——撤那两条时得同轮回看本条。
5. **`tests/e2e.js` 仍在对账、下限与本条之外**(它按 tab 列表循环登记,行首点数本就不等于实跑条数),本槽未扩。
