## 1. 收之前先量:同一道钳位此刻写在几处

`w136-sk25-owe-guard.md` 第 5 节把这一面记成"两端各按自己的缺省值跑",实测比记账多一处——**是三处**:

| 处 | 原字面 | 谁在读 |
|---|---|---|
| `cli.js` `EXEC['episode.produce']` | `Math.max(1, Math.min(5, +args.maxRetry \|\| 2))` | CLI 整集分轮的轮次上限 |
| `js/produce.js` `autoSmartReview` | `Math.max(1, Math.min(5, ep.sbConfig.maxRetry \|\| 2))` | 浏览器逐镜重试的次数上限 |
| `js/commands.js` `episode.produce` | `Math.max(1, Math.min(5, args.maxRetry \|\| ep.sbConfig.maxRetry \|\| 2))` | 命令层入参合流后写回 `ep.sbConfig` |

另有三处写着同一个区间/缺省但不是钳位:`js/storyboard.js` 参数配置面板的 `[1, 2, 3, 4, 5]` 与 `(c.maxRetry || 2)`、
同文件 `defaultSBConfig` 的 `maxRetry: 2`、`js/produce.js` 跑批模板的 `maxRetry: 2`。
`js/cmd-registry.js` 的参数描述 `审片不达标重试上限 1-5(默认 2)` 是给人读的那一份口径,`cli.js` 的注释还写着
「与注册表口径一致」——**靠注释维持一致**正是这一面被记成欠账的原因。

## 2. 收进哪一层

选 `js/domain.js` 而不是 `js/wf-core.js`,判据与 W131 收 `reviseTargets` 时同一条:这是**领域推导**不是提示词装配,
`wf-core` 那一份是"怎么问模型",`domain` 那一份是"这一集现在该怎么走"。而且同一份 `domain.js` 里
已经有修订闭环的另一个阈值 `D.REVIEW_MIN = 7`(达标线)与重抽面 `D.reviseTargets`——
收敛次数放在它们旁边,修订闭环的三个口径(判谁不达标 / 该重抽哪几镜 / 还能重来几轮)在同一处读得全。

```js
D.REVISE_RETRY_MIN = 1;
D.REVISE_RETRY_MAX = 5;
D.REVISE_RETRY_DEFAULT = 2;
D.reviseRetryLimit = function () {      // 候选值按优先级依次给,第一个能读成非零数的胜出
  for (let i = 0; i < arguments.length; i++) {
    const n = +arguments[i];
    if (!Number.isFinite(n) || n === 0) continue;
    return Math.max(D.REVISE_RETRY_MIN, Math.min(D.REVISE_RETRY_MAX, Math.floor(n)));
  }
  return D.REVISE_RETRY_DEFAULT;
};
D.reviseRetryOptions = function () { … };  // 1..5,参数面板的次数选项由区间派生
```

**变参而不是固定两个入参**,是因为三个消费点的候选链不一样长:CLI 只有命令入参、浏览器闭环只有分集配置、
命令层是"入参优先于分集配置"。写成 `reviseRetryLimit(args.maxRetry, ep.sbConfig.maxRetry)` 之后,
"谁先谁后"这件事在调用处一眼看得见,而"读不出来算什么"只在 domain 一处定义。

**上下限的理由写进注释**,不只写数字:上限存在是因为每一轮都真扣费(重生成 `COST.video` + 复审 `COST.review`),
不设限即无限扣费;下限 1 是"至少给一次改正机会",**0 轮等于关掉修订闭环,那由 `smartReview` 开关表达**——
这句是本槽新定的口径,此前 `|| 2` 只是把 0 当成"没填",没人写过为什么 0 不是一个合法轮次。

四个消费点改成现取,`js/cmd-registry.js` 的描述文字**有意不改成模板串**:那份注册表此刻零依赖
(UMD factory 不收任何模块),为一句描述给它挂上 `domain` 依赖会动到几个沙箱的加载顺序。
改成由用例对账——描述里的区间与缺省必须与 `Domain` 那三个常量逐字对得上(见第 4 节 M10)。

## 3. 逐值同值,只有一处有意不同

新老两种算法在所有能想到的输入上逐值比对(`node -e` 现跑),**只有小数不同**:

| 输入 | 老(三处各自的 `Math.max(1, Math.min(5, x \|\| 2))`) | 新 | |
|---|---|---|---|
| `undefined` / `null` / `''` / `0` / `'abc'` / `[]` | 2 | 2 | 同 |
| `1` / `3` / `5` / `'3'` / `true` | 1 / 3 / 5 / 3 / 1 | 同 | 同 |
| `9` / `-2` / `0.5` | 5 / 1 / 1 | 同 | 同 |
| **`2.7`** | **2.7** | **2** | **有意改** |

小数截整不是顺手做的整洁,是**修掉一个能让质量闸门放行的形态**。`js/produce.js` 的重试循环是

```js
for (let attempt = 0; attempt <= maxRetry && !pass; attempt++) {
  …
  else if (attempt < maxRetry) { retryCnt++; …重抽… }
  else { manualCnt++; }        // 转人工只在 attempt === maxRetry 那一轮走得到
}
```

`maxRetry = 1.9` 时循环在 `attempt = 2` 处结束,`attempt < maxRetry` 在 0 与 1 两轮都成立,
**`else` 那一支一次都没进**——该镜既没达标也没进 `manual` 计数。而命令层的质量闸门判的正是
`rv.result.manual > 0`,拿到 0 就放行合成。轮次截整后这一路不复存在(用例
`autoSmartReview:小数轮次截整后超限仍如实转人工` 钉的就是它,去掉 `Math.floor` 当场红)。

小数从哪来:`js/wf-core.js` 的 `sanitizeCmdArgs` 对 `type: 'number'` 只做 `+v` 不取整,
`--args '{"maxRetry":1.9}'` 与 MCP 透传都送得进来;命令层此刻会先钳一道再落库,
但 `autoSmartReview` 读的是 `ep.sbConfig`,旧数据与直接改配置那两条路绕得过命令层。

## 4. 护栏怎么改:两向翻面,不是删

W136 那条护栏的**后半是反向断言**——它逐处对照源码钉住"点名的余量此刻确实还在",
其中收敛面那四句(`cli.js`/`js/produce.js` 各有一道就地钳位、`domain.js`/`wf-core.js` 按名字与按形状两向零命中)
在本槽落地后必然红。W136 第 7 节把这种红写明了是设计意图:「要删的是仍欠段里那句已经不成立的话,不是断言」。
照办:**断言的方向翻过来,一条不少**。

| | W136(两面都欠) | 本槽(收敛面已落地) |
|---|---|---|
| 前半·已落地那半 | 只钉"不许把 `reviseTargets`/`reviseSubset` 挤进仍欠段" | 另加**正向**要求:已落地那半须点名 `收敛次数` + `Domain.reviseRetryLimit`(名词 + 源码标识符成对,与 W136 同规格) |
| 前半·仍欠段 | 须含 `收敛次数`+`maxRetry`、`autoSmartReview`+`逐镜` 两组 | 只剩形态那一组;`reviseRetryLimit` 进了"不许挤回仍欠段"的名单 |
| 后半·收敛面 | 两端各有钳位、双端单源层零命中 | 反过来:`domain.js` 里那道钳位**只此一处**、四个消费点各自 `Math.min(5,` 与 `maxRetry \|\| 数字` 都归零且都现取 `Domain.*`;注册表描述与三个常量对账 |
| 后半·形态面 | 循环嵌套方向 + 浏览器不引 `revise*` 派生 | **一字未改**(那一面仍欠;只把"不引派生"的正则写实成 `reviseTargets\|reviseShotIds\|WfCore.reviseSubset`,免得与新加的 `reviseRetryLimit` 撞名) |

另加一条 UI 子集判据:跑批模板只放低三档 `[1, 2, 3]`(**本槽有意不动这个 UI**),
判据不是"必须等于全区间",而是**档位须落在登记区间内且给得出缺省档**——UI 可以取子集,不可以越界,
也不许把缺省值挪到取不到的地方。

## 6. `G-03` 此刻还欠什么

只剩一面,SK-25 的 `note` 原话:**两端闭环形态不同构**——浏览器 `autoSmartReview` 把重试嵌在逐镜循环里
(一镜连着重抽到达标为止),CLI `episode.produce` 是整集低分子集重抽一轮再复审(集外循环)。
**同一份次数口径在两端数的不是同一件事**:浏览器数的是"这一镜重抽了几次",CLI 数的是"整集重来了几轮"。

本槽因此只统一了**取值**,没统一**语义**——这不是遗漏,是边界:要让两端数同一件事,得先定
① 浏览器进度面板改成分轮之后逐镜进度怎么显示(现在是一镜一行、重抽次数写在行内),
② 逐镜计费节奏改成整集子集重抽后,中途中止的退费与预估怎么对齐。两条都是产品口径,不在本槽范围
(与 `w131-g03-shotids.md` 第 7 节、`w136-sk25-owe-guard.md` 第 5 节的交接同调)。

`Skills.gaps()` 的 `G-03` 键**不摘**、关联索引仍是 `review.stage` 与 `review.reviseLoop` 两条——
目录口径是落地一面不摘键。
