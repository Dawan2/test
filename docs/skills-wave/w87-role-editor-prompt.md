## 3. 这一条为什么带变量,以及变量为什么不做成三条键

收编前的 system 半是模板串,类别就地插值:

```js
const kindWord = { character: '角色', scene: '场景', prop: '道具' }[s.kind] || s.kind;
system: `你是短剧${kindWord}设定师。…`
```

三条路可走,取第三条:

| 方案 | 为什么不取 / 取 |
|---|---|
| 三条键(`persona.editCharSystem` 等) | 三句话只差两个字,角色是同一个(主体设定师),产物落点也同一个(`s.prompt`)——按 W76/W77 立的"合成的前提是角色同一"判据,这里恰恰是同一个角色,分三键等于让用户改一句话要改三遍 |
| 一条键、类别写死 | 缺省就变了(道具那次会拿到"角色设定师"),违反"缺省逐字节不变" |
| **一条键 + `{kind}` 变量** | 缺省逐字节不变(取值口填),用户改一次三类主体一起跟随,而类别仍由代码现取——用户改不到也不必改 |

注册表本来就有 `fill(key, vars, ov)` 与条目上的 `vars` 字段(此前只有 `sb.reviewUser` 那条评审指令在用),本槽是**人设类键里第一条带变量的**。`vars: ['{kind}']` 不是装饰:`Prompts.list()` 把它透给「全局默认值 → 核心提示词 skill」页,用户改写时看得见这一条里有个占位符不能删。这一点由一条断言钉住(变异 11 转红)。

## 4. 为什么是独立键,不与分镜那侧的同形入口合成

任务明写「独立键,不要与 `gen.editSystem` 合成」。`gen.editSystem` 是 W84 那条分支上给 `js/sb-views.js` 镜头「按指令改」开的键——**本槽基线(W80 tip)里它不存在**,`js/sb-views.js` 那处仍是内联字面。所以本槽落地的形态是:开一条自己的键,并且**即使将来两侧都收编也不合并**。判据不是"任务这么说",是两步的角色与产物落点都不同:

| 步骤 | 角色 | 产物落到哪 | 下游 |
|---|---|---|---|
| 主体编辑页「按指令改」 | 短剧{角色/场景/道具}设定师 | `s.prompt`(主体的设定提示词) | `genMainImage` 重出**主体参考图** |
| 分镜侧「按指令改」 | 短剧分镜改图专家 | 镜头的画面提示词 | 重出**镜头素材** |

两句话的措辞也不同(一句讲"保留与指令无关的外形/风格要素",一句讲"保留原提示词中与指令无关的画面要素与风格约定")——**没有同字面就谈不上复用**。合成一条的代价很具体:用户为了让主体改图更保守而改一次缺省,连镜头改图的缺省一起改掉了。

同理也不并进只隔一条的 `persona.promptSystem`(八维度重写文生图提示词):那一步的角色是"文生图提示词专家",输入是八维度人设表、产物是整条立绘提示词;这一步是拿着一句自然语言指令去**改**一条既有提示词。两条 `def` 不同字面,有断言正反两向钉住(第 6 节)。

也不做 `WfCore` 派生函数:该步只要这一句人设,不接方法论块、不接 `Skills.block`,与 `und.system`/`graph.system` 同形直接从注册表取。

## 5. 契约半不开放:这一刀切在哪

注册表条目里只有"人设句 + 改写纪律"那一句。切下去留在 user 半的是这些:

```js
messages: [{ role: 'user', content: `主体:${s.name}(${kindWord})\n项目风格:${p.style || ''}\n当前设定提示词:${s.prompt || '(空,请据名称与指令撰写)'}\n\n修改指令:${inst}\n\n返回 {"prompt":"改写后的完整设定提示词"}` }],
```

刀切在"讲给模型听的行为要求"与"消费侧的解析契约"之间:`{"prompt":…}` 这个字段名是回填口径(`if (!out || !out.prompt) throw new Error('LLM 返回为空')` → `[data-f=newprompt].value = String(out.prompt)`),用户改一个字这一步就恒报"LLM 返回为空",而这一步是先扣了 `llm.optimize` 的。主体名/项目风格/当前设定提示词那几行同理是取数口,不是可调的口吻。

**"半不开放"是有意的,不是漏收**:开放的那半(人设 + 改写纪律)恰恰是用户最想调的——"不超过120字"想放宽、"保留与指令无关的外形要素"想收严,现在改得到了;改不到的那半改坏了只会让这一步整轮失败。由一条断言钉住注册表里不得出现 `"prompt":"改写后的完整设定提示词"` 这个字面。

## 6. 缺省逐字节不变靠哪几层钉住

1. **注册表层**:`Prompts.get('persona.editSystem')` 与"把类别换成 `{kind}` 的那一句"直接比对;并要求这句 `def` 在 `Prompts.list()` 里**恰好命中一条**(反向撞车转红,变异 8)。
2. **行为面(沙箱真跑)**:三类主体各真跑一遍,从 `API.chatJSON` 的请求体上截获 `system`,与收编前 `${kindWord}` 插值出来的三句逐字节比对;并断言三句**互不相同**(变量没填进去就红,变异 5/6)。真跑还顺带证了这一步真的跑完了:回包按原口径解析回填、点「应用」后 `s.prompt` 变成改写结果、`genMainImage` 收到的就是它。
3. **消费层(源级)**:`system: Prompts.fill('persona.editSystem', { kind: kindWord }),` 必须与该步 user 半锚点 `返回 {"prompt":"改写后的完整设定提示词"}` 在 600 字符内配对——键挪到别的步骤上、或这一步被改走别的键、或退回内联都当场红(变异 2、6、10);`js/role-editor.js` 的 `system: '你是` / `` system: `你是 `` 计数归零。
4. **全仓持有者名单**:见下一节。
5. **不冒充双端**:这条链路没有服务端/CLI 对端(`/api/wf/*` 里没有主体改图端点),断言正向要求 `server.js`/`cli.js` 不出现该步的 user 半锚点。收编解决的是**可覆盖**,不是可 headless——与 W51 三条多轮键、W71 四条剧本键同口径,记账里如实这么写。

`Prompts.fill` 对未覆盖键先取 `def` 再替换 `{kind}`,覆盖表为空对象/`undefined` 同样落 `def`,故没改过提示词的用户看到的 system 半与本槽之前逐字节一样。编辑页其余模块(四模式预览/配音/八维度/资产/定稿/场景画板)一行未碰。

## 7. 全仓持有者名单:从逐槽各写一份改成按注册表现取

W69/W71/W76/W77 各写了一份"这一句只剩注册表一份"的名单(扫 `server.js`/`cli.js`/`mcp.js`/`index.html` + `js/*.js`,持有者必须恰好是 `js/prompts.js`)。收到第 26 条时逐槽再抄一份已经不划算——**新收的键不会自动进名单**,漏写一次就留一个洞。本槽把它更新成一条**按注册表现取**的:

```js
const list = Prompts.list();
list.forEach(it => assertEq(files.filter(rel => src[rel].includes(it.def)).join(','), 'js/prompts.js',
  it.key + ' 的 def 字面持有者应恰好只有 js/prompts.js(别处抄第二份即红)'));
```

现取的好处是覆盖面跟着注册表走:26 条一条不漏,下一槽新收的键**自动进名单**,不必再新写一条同形断言。既有那四份逐槽写的名单**一条不删**——它们钉的是"那一步的取值口",与本条的覆盖面互补(变异 2 只红逐槽那侧的配对,变异 7 只红全仓名单)。

两处收严:

- **反查另一向不能照搬"全部 def 互不相同"**。注册表里 `voice.recommendSystem` 与 `voice.recommendBatchSystem` 两条 `def` 逐字节相同,是 W73 明写的口径(键位是持久化面,合成一条再拆回来会废掉用户已写的覆盖)。所以反查写成"同 `def` 的键集合恰好是那一对",再多一对同字面就是合并漏了或抄错了 `def`(变异 8 转红)。
- **本条 `def` 带变量,`includes(def)` 扫不到填好的整句**。所以源级那条另按"变量之后那段不变量"(`设定师。按用户指令改写文生图设定提示词:…不超过120字。`)再扫一遍全仓——谁把填好的整句抄回源码里同样红(变异 7 转红,变异 1 也因此在两条用例上红)。
