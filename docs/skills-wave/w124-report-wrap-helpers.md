## 1. 要收的是哪两路

W122 那份集成记账件在验收 W120 的循环禁令时,现测出两条判据仍走得通的边界并如实交接(集成槽不新立口径故当时都不改判据)。本槽把这两条各做成一条断言。

两条边界的共同形状是 W113 周期 8 报告阻塞 4 的形状:**一处静态 `report(...)` 登记点跑出多条,而四个静态口径一个不变**——行首 `^[ \t]*report\(` 行数、`report(` 调用总数、就地写死的名字面数、不同名数,全部纹丝不动;README 对的是套件自报的实跑数,两边一起失真还是全绿。

### 1.1 helper 包装

把一条 `report(...)` 包进箭头函数 helper,再从两处调用:

```
  const emitDup = (cond, detail) =>
    report('注册成功', cond, detail);
  emitDup(reg.status === 200 && reg.data && reg.data.token, reg.msg);
  emitDup(reg.status === 200, reg.msg);
```

`report(` 仍独立成行、名字仍是就地写死的字面、两个 `emitDup(` 调用点行首都不是 `report(` 故不进任何静态口径。W120 那条按块链判循环:这里块链上那层是箭头函数,循环词表(11 个数组迭代方法 + `for (`/`while (`/`do {`)一个字都点不到。

**更要紧的是这个写法连块链都不留痕**:`const emitDup = (…) =>` 后面直接换行接 `report(…);`,没有花括号,故 `report(` 出现那一刻栈上除了 `async function main() {` 一个多余的括号都没有——按"块链上有什么"这一类判据,再怎么扩词表都看不见它。

基线实测(`tests/integration.js` 第 140 行那条 `注册成功`):

| 口径 | 变异前 | 变异后 |
|---|---|---|
| 行首 `report(` 行数 | 130 | **130** |
| `report(` 调用数 | 130 | **130** |
| 就地写死的名字面数 | 130 | **130** |
| 块链上的循环层数 | 0 | **0** |
| `node tests/integration.js` **实跑条数** | 130 | **131** |

### 1.2 `for await (`

```
  for await (const _v of [1, 2]) {
    report('注册成功', …);
  }
```

块头是 `for await (const _v of [1, 2]) {`,里面明明白白写着 `for`,而 W120 的词表正则要求 `for` 与 `(` 相邻(`(?:^|[^\w$])(?:for|while)\s*\(`),中间隔一个 `await` 就匹配不上。同样静态 130 / 实跑 131。

W120 的交接第 2 条给的处置是"按同形补词,不要改成块链上不许有任何函数体";W122 的现测结论相反——**这不是漏收一种语法糖,是按词表匹配块头字面这类判据的固有面:词表列举得再全,写法比词表多**。本槽取后者:换判据类别,不往词表里塞词。

## 2. 落地:两条断言,失败含义分开

新条接在 W120 那条循环禁令之后,**既有十条一条不删、一条不改**(循环禁令那条一个字未动)。两条各自成条而不并进旧条,是因为它们说的不是同一句话:

- 旧条说的是"这一行外面套着循环";
- 新条一说的是"这一行被包进了一个可以被调用多次的函数";
- 新条二说的是"旧条那份词表点不到这个 `for`"。

三条合成一条的话,断言红了只知道"有问题",不知道该拆循环、拆 helper 还是补判据。

### 2.1 新条一:不许包进函数 helper(分两点报错)

一处静态登记点跑出多条,来路只有两种——**循环**与**函数复用**。前者归旧条,后者归本条。本条不数词表,只认"函数体"这一类结构,分两点报:

1. **带花括号的 helper**:块链上出现 `main` 以外的函数体块头。判定看块头是不是以 `{` 收尾且这个 `{` 开的是函数体——箭头体(`=> {`)、`function` 体,或 `名字(参数) {` 这类具名函数/对象方法体;控制结构 `if (…) {` / `for (…) {` / `catch (e) {` 形状与第三种相同,按关键词表排除(`if`/`for`/`while`/`switch`/`catch`/`do`/`else`/`try`/`finally`/`with`/`await`)。`async function main() {` 单独放行。
2. **不带花括号的箭头 helper**:1.1 那个形状块链上一层不多,只有"`report(...)` 不是裸表达式语句"这一点看得出来。故给 `reportBlockHeads` 多返回一个 `pre`——该次调用往前到最近一处语句边界(`;` / `{` / `}`)之间的**抹码后**原文,这一段除空白外有任何东西就算红。

`pre` 取的是 `blankNonCode` 抹完的骨架而不是原文,故注释与字符串里的 `;`/`{` 不会被当成语句边界、也不会被当成"前面还有代码"。

这一点顺带还拦住 `const r = report(…)`、`return report(…)`、`if (x) report(…)` 这类写法。前两种是把登记点当表达式用(值可以被再消费),第三种是"这一条可能不跑"——都同样让静态点数代表不了实跑条数。

**关键词表里那个 `await` 是有意加的**:`for await (const v of arr) {` 也长成 `名字(参数) {` 的样子(`await` 恰好落在名字位),不排除的话它会同时红在本条上,与新条二的失败含义混在一起。排除之后两条各红各的(见 3 节变异 1/2)。

### 2.2 新条二:不许落在 `for` 与 `(` 不相邻的迭代体内

判据是"块头里有 `for` 关键字(`(?:^|[^\w$])for(?![\w$])`),但不是旧条那个紧邻形状(`(?:^|[^\w$])for\s*\(`)"。凡 `for` 引出的块,要么被旧条点到,要么红在这一条上,中间不留缝——将来再冒出别的 `for` 变体(比如换行写成 `for\n(`),不必改任何词表。

### 2.3 与旧条的重叠是有意的

`.forEach(v => { … })` 这类**迭代回调**同时是循环、也是函数体,故它会同时红在旧条与新条一上(3 节变异 3 实测)。这不是重复造轮子:

- 旧条不覆盖新条一(箭头 helper 不是循环);
- 新条一不覆盖旧条(`for (const v of arr) { … }` 是循环但不是函数体);

两条各封一半、交集处双报,比把交集切掉再互相依赖要稳——切掉交集就得让一条断言去引用另一条的词表,那份词表一改两条一起漂。

## 6. 交接

1. **W122 交接的那两条边界到此闭合,闭合方式与 W120 的交接建议相反**。W120 第 2 条写的是"按同形补词,不要改成块链上不许有任何函数体";本槽两条恰恰都是换判据类别——一条真的禁了 `main` 以外的函数体,一条把 `for` 的判定从"词表点得到的形状"翻成"点不到就算红"。写在这里不是要推翻那条交接,而是把两次的判断依据摆齐:**词表在写法可枚举时够用,而 JS 的包裹写法不可枚举**,W122 的两条现测就是这句话的证据。后来者若再遇到同类,先问"这一路是不是还有第三种写法",再决定补词还是换判据。
2. **仍然走得通的一路:非循环的一次性回调**。`p.then(() => { report(…); })` 这种在新条一下会红(它是函数体),但 `await (async () => { report(…); })()` 同样会红——而它只跑一次,是**误报**。两个套件里现在一处都没有,故本槽不为它开豁免口子(开了就等于给"包一层匿名函数"重新放行)。真撞上时正解是把那条 `report(...)` 挪到函数外面,不是放宽判据。
3. **`reportBlockHeads` 现在给三样东西:`line` / `heads` / `pre`**。写"某条调用落在什么结构里"这类静态判据时,块链看得见带括号的包裹层,`pre` 看得见不带括号的那半,两个一起用才盖得全。用它时请把 `blankNonCode` 的配平自检一并保留——这类手写扫描失准的方向与放行方向一致,静默即假绿。
4. **三个用例数仍然一条棘轮都没有**。W113 周期 8 报告阻塞 4 同节末尾那条残留(真删一条 `report(` 且 README 同步改小,全绿)本槽同样有意不顺手做:那是"用例数只增不减"的产品口径问题,与本槽"静态数代不代表实跑数"不是同一件事,合在一槽里做会让断言的失败含义混在一起。远端 `w121-suite-count-ratchet-*` 看题目正是冲它去的。
5. **块头判定读的是原文不是抹码后的骨架**(与旧条一致)。故块头那一行里若出现写在注释或字符串里的 `for`、`=>`,理论上会误报。两个套件里现在的块头只有 `async function main() {` 与裸 `{` 两种,没有可撞的面;要改成读抹码后的骨架,得让 `reportBlockHeads` 连块头也返回两份(报错信息仍要用原文,否则读不出是哪一句),本槽不为一个尚未发生的形状先改接口。
