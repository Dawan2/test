## 4. 逐处怎么解

### 4.1 两条新用例:都留,不并条

`tests/unit.js` 契约段那一块冲突里,我方是 W120 的循环禁令、对侧是 W121 的三套件下限,
两条各占一个 `{ name, fn }` 条目,`git` 把它们看成同一位置的两种写法。**判据是两条都留**,理由由被合入支自己写明:
下限那条报的是"用例被删了",循环禁令那条报的是"登记形态被破坏、静态点数代表不了实跑条数",
**两种病灶的处置完全不同,合成一条会让报错文案必须同时描述两件事**。
本槽照它交待的分条落地,两条的实现与注释一字未改,合并后 `contract` 99 → **101**。

主 `README.md` 那一块同源:我方那段描述循环禁令、对侧那段描述三套件下限,
取法是把对侧那一句原样插在我方段落的对应位置(接在「三处一起改小则红在下限上。」之后、「中文数字与阿拉伯数字同一口径」之前),
两段措辞都不改写。同段句首那个「`contract` N 条断言」两侧各自把九改成十,合入后是 **十一**(见 4.3)。

### 4.2 明写份数与记账件 `FLOOR`:两侧都不对,取合入后 live

W105 立的这层判据有三份记录要同时对上:目录实况、`docs/skills-wave/README.md` 明写的份数、索引表行数。
两侧各自从 `w117` 那时的 132 起算,加自己这条线上的记账件:

```
我方(W119 + W122 走完):132 + w113 + w119 + w120 + w122 = 136
对侧(W121):            132 + w121                      = 133
合入后目录实况:        132 + w113 + w119 + w120 + w121 + w122 = 137
```

**冲突块里两侧给的都不是答案**(与上一槽 4.1 逐字同形,这已是第四次)。取 137,`tests/unit.js` 的 `FLOOR` 同步取 137,
合并提交自身即绿(`contract` 101/101)。本文与本文那行索引落地后目录是 **138**,明写份数与 `FLOOR` 一并抬到 **138**。
分两个提交落地,**每个提交自己都是绿的**:

- `b60223f` 合并提交:补两侧索引行的并集 + 明写份数与 `FLOOR` 一并取 **137**;
- 本文落地后 **138**。

**下限写成 `>=` 而不是 `==`** 的理由见 `w105-index-completeness.md` §2.1,
本槽照它交待的做法(「新开一槽记账时把下限抬到当轮实况」)把棘轮往上推。
「最新一份收敛记录」那个指针同步改成本文,`w122` 挪进"更早的分叉登记"那串的队首。

### 5.7 那两条边界:多一层下限也没关死,本槽重测不改判据
