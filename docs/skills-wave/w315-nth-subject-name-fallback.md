## 二、先量现网实现,再动笔

`cli.js` 那三行现取(一个字没动):

```js
const findSubject = (proj, sid) => {
  const s = (proj.subjects || []).find(x => x.id === sid || x.name === sid); // 兼容按名引用
  if (!s) throw new CliError('主体不存在:' + sid, 4);
  return s;
};
const nthSubject = (proj, sid, nth) => {
  const rows = (proj.subjects || []).filter(x => x.id === sid);
  return rows.length ? (rows[nth] || rows[0]) : findSubject(proj, sid);
};
```

三条现取事实,写用例之前逐条量过:

1. **兜底分两处**:`rows[nth] || rows[0]` 是序数越界那一处(同 id 还有位,只是序数指不到);
   `: findSubject(proj, sid)` 是同 id 一位不剩那一处,而它委托过去的 `findSubject` 认的是 **id 或名字**两种。
   故这一处委托本身又分两半——名字也对不上时抛 `主体不存在`(exit 4),名字对得上时**真把那一位取回来**。
2. **树上只有报错那一半有判据**:`commands · subject.generateImage 同 id 多位…` 第 ⑤ 档的 `gone2`
   把同 id 那几位整个删掉,名字随位一起没了,走的是抛错那一路。取到人的那一半现取**零判据**。
3. **调用点唯一**:`nthSubject` 在 `cli.js` 只有 `EXEC['subject.generateImage']` 每轮重取那一处
   (`nthSubject(projLive, s.id, nthOf.get(s) || 0)`),故行为面判据只能从这条命令上取,不另造第二个入口。

**实现已对,故本槽一个字不改它**:`nth` 语义未动、按 id 仍按序数取、`findSubject` 的按名兜底未动、
两处兜底一处没剥。本槽**只加测**。

### 2.1 缺的那一半在真实操作里长什么样

按名兜底能被走到,要的是「库里没有 `id === sid` 的位、却有一位名字正是 `sid`」。
这不是造出来的形状,它就是**并发改表里改的是 id 不是人**那一种:
这一趟跑到一半,别处把同 id 那几位重新发了一遍 id(`subjects-dedupe --apply` 与整表重导都这么改),
人还在库里、名字一个字没变,而本轮按 id 数出来的位一个不剩。
既有那一档删的是**位**(人没了,该报错);本槽这一档改的是 **id**(人还在,该取到)。
两档形状相邻、结论相反,判据得各占一条。

## 三、加的那一条:三档,落 `commands` 套件

用例名:`subject.generateImage 并发改的是 id 不是人:同 id 一位不剩时按名兜底真取到那一位(不止是报错那一半)`,
插在既有那条 `subject.generateImage 同 id 多位…` 之后(两档形状相邻,读的人接着往下看)。
夹具四位、三位同 id `林晚`,末位的**名字**正是那个 id 字面(按名兜底认的就是它);
落库面照旧读 clone 语义的 disk 夹具(`cliDisk`),序数表按快照全表数,一律沿用既有那条的形状。

| 档 | 改表时机 | 钉的是 |
|---|---|---|
| ① | **末轮**开跑前重发 id(名字与已到手的图留着) | 序数 2 越界 + 同 id 一位不剩,按名字仍够得着那一位:`failed` 空、四位逐位对图串等于 `林晚·少年\|g1 , B-不重复\|无图 , 林晚·青年\|g2 , 林晚\|g3`、`landed` 3、缺省提示词按取到那一位自己的名字拼(含 `林晚` 不含 `少年`) |
| ② | **首轮**开跑前重发 id | 序数没越界(`nth=0`)同样走按名那一路——它认名字、不认第几位,三轮认的是同一位:图只落在名字对得上的那一位身上,`ok/landed` = **3/1**(`ok` 照数三次引擎调用,那三笔钱都真花了;`landed` 如实报只落到 1 位) |
| ③ | 末轮开跑前重发 id **且连名字一起改** | 对照面:这才是真找不到人——`failed` 1、错话仍是 `主体不存在`、一位都没被顶替着写图 |

③ 是①②那两句绿的量尺:**没有它,"退回库里第一位"这种认错人的改法照样能让①绿**(见 §四 M2)。
①里 `late.subs.map(s => s.id)` 先钉一句前提(改完 id 后库里一个 `id === '林晚'` 的位都不剩),
免得哪天夹具失手、按 id 那一路其实还通着,而①绿得莫名其妙。

判据一律取**落库那一整串**而不是回执那一格:回执报的是解析到的那一位的名字,
它说不出产物写在了谁身上(W313 §八 那一课,M2 那一手正是这个形状)。

## 八、这一槽可复用的一件事

**一句委托能被「就地抄一份同样的错话」换掉而全树不红,说明判据钉的是错话、不是那条委托。**
`nthSubject` 那句 `: findSubject(proj, sid)` 一直有一条用例读它,读的却只是它抛出来的那句 `主体不存在`——
而那句话谁都抄得出来。把委托换成就地抛(M1),用户可见的错话一字不差、判据一条不红,
真正没了的是**委托带过来的另一条路**(按名认人)。
故给「委托型兜底」立判据时,得先问它委托过去的那一头**有几种收场**:
每一种收场各要一条能红的用例,只钉报错那一种,等于只钉住了其中一半,而另一半连它自己被删了都不知道。

**相邻两档形状越像,越得把「量尺」那一档一起写进来。**
①(改 id、人还在 → 该取到)与③(连名字一起改 → 该报错)只差一个字段,
少了③,「退回库里第一位」这种认错人的改法照样能让①绿(M2 在起点树上就只红另一句)。
对照档不是凑数的第三格,它是新判据能不能说「绿是因为认对了人」的全部依据。
