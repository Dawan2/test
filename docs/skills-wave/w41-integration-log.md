## 4. 冲突怎么解(逐处)

十一处冲突全是并集型或"取信息量为全集的一侧再折回对侧真增量",没有一处需要择一丢弃对侧的实质内容。

两份 README 的长行问题本槽三步都撞上了(`w37`/`w39`/`w40` 各改了同一段数千字的单行,行级三方合并对它们完全无能为力)。沿用 W29/W34 那条路子:

```
# 1) 冲突块先取信息量为全集的那一侧(注意:不一定是 HEAD 侧,要逐块判)
# 2) 再把对侧的真增量逐句折回 —— 增量清单来自 word-diff
```

本槽把第 1 步的措辞改了:W34 写的是"一律先取 HEAD 侧(基线是三路里的超集)",本槽**这条不总成立**——第 6 步 `w40` 那一侧虽然整体更旧,但它含 HEAD 侧没有的两处增量;而第 3 步 `w37` 那一侧只有一句比 HEAD 新。所以取侧要按块判、按 `word-diff` 的增删两向都看,不能默认基线是超集。

> **口径**:长行 README 冲突不要 `git checkout --ours <file>` 整份取(W16 第 5.1 节那个坑),也不要默认"基线侧是超集"。做法是对每一块跑一次 `word-diff`,把 `[-删-]` 与 `{+增+}` 两向都读完,再决定哪一侧打底、哪几句折回;最后逐条 `grep` 复核终态在位。

本槽消解冲突标记用的是一次性小脚本(按块指定"取哪侧 / 并集 / 并集后排序"),再用 `StrReplace` 逐句折回——不是 `checkout --ours`,区别在第 2 步:`--ours` 会**静默丢掉**对侧那一整行里的全部新句子。
