### 4.1 M1:明令点名要核的那一格

明令要核的是"`uploadFileUrl` 在、闸不在 `uploadFile` 里"。M1 把落库口那句委托换回起点的写法
——**P1 上这句本来就长这样,81/81 全绿**;M 上当场**红 1**。
这一格读出来的是:**净新增看守面恰是"落库口必须走带闸的那个取 url 口"这一件事**,
而它在起点树上完全无人看守(起点树就是缺口本身,还全绿)。

### 4.2 M2/M3/M4 各 +1:闸内三层各守各的

同一道闸拆得开三层,三手各红 1、互不顶替:

- **M2(码)**:`exit 5` 是"错在服务端那一侧"这一族。改成 2 就变成"你参数写错了",
  Agent 按码分流时会去劝用户改命令行,而实际该做的是重试或报障。
- **M3(`trim`)**:`'   '` 落库看起来像有图,渲染时是一张裂图——比空串更难查。
  摘掉 `trim` 只有那一格会红,说明四档里"纯空白"那一档是**单独**被钉住的,不是被空串那格顺带罩住的。
- **M4(错话)**:改成不点名的 `'上传失败'` 即红。这一格值钱在于它证明判据读的是
  **`/未回文件地址/` 这句具体的话**,而不是宽判"抛了就行"——`{code:0}` 那一档原本抛的是 `TypeError`,
  宽判读法下它和本槽的 `CliError` 长得一样。

### 4.3 M6–M8:服务端那一半,本槽独有

W319 在 `tests/integration.js` 加的三条钉的不是客户端,而是**服务端产不产得出那种反常回执**。
这一层前十一条槽都没有,得拿 `server.js` 的改法去撬:

- **M6(成功分支不发 `url`)**:P1 **红 2**、M **红 3**。P1 那 2 条红是既有用例(它们要拿 url 去下载/比对),
  净新增恰 **1** 条——就是"成功回执带非空 `url`"那一条。
- **M7 / M8(两个拒收分支各改成 2xx 空回执)**:**P1 两手都 152/152 全绿**,M 各红 1。
  **这是本槽最值钱的两格。** 它逐字印证了 W319 写在那三条判据上方的那句注释——
  「只判成功面的话,把某个拒收分支改成 200 空回执照旧全绿」:在起点树上,
  把「不支持的文件类型」或「缺文件数据」从 `fail(res, 400, …)` 改成 `ok(res, {})`,
  **整个集成套件一声不吭**;而那正是客户端那道闸挡的形态——服务端一旦漏出 2xx 空回执,
  用户原有的图就被空串顶掉。两面各站一条之后,这道闸才说得清定位:
  **服务端那三条说明反常不该发生,客户端那一条说明反常发生了也不许把用户的东西弄丢。**

## 八、这一槽可复用的一件事

**对侧动了产品码的快进形槽,变异台得往"这道闸挡的那一侧"也伸一手,否则读到的只有闸自己。**

前十一条快进形槽的对侧都是只加测,变异台的手全落在客户端产品码上就够了。
本槽对侧加的三条集成判据钉的却是**服务端产不产得出那种反常回执**——
这一层拿客户端的改法一手都撬不动,非得去改 `server.js`。
而撬下去的读数是本槽最值钱的两格:**M7 / M8 把两个拒收分支各改成 2xx 空回执,
起点树 152/152 一声不吭**,合完各红 1。

这两格说明的是一件容易被跳过的事:**一道"纯防御"的闸,光在客户端立判据是读不出价值的**——
读的人下一句必然是"服务端又产不出这形态,那这闸有用吗"。
只有把服务端那一侧的契约也钉住,并且**证明在钉住之前那条契约可以被静静改掉**,
两条判据合起来才说得清定位:**一条说明反常不该发生,另一条说明反常发生了也不许把用户的东西弄丢。**
合入方要核的不是"对侧加了几条",而是**这两侧是不是都真的站住了**——
而那只能靠在两棵树上各改一次服务端来读。
