# W299 主体库卡片小标补跳转:点小标定位到「留原 id 的那一位」

> 起点 `origin/cursor/w298-integration-59d3` 尖 `808b56d`(`checkout -b` 后 `rev-parse` 现取核过,
> 与交接自称逐字节相同)。功能支 `cursor/w299-dupjump-a914`。

## 一、收的是哪一条

W289 残留第 4 条,原话:

> **小标只报位次,不报"这一位与哪一位撞了"的跳转。** 用户读到「第 2/3 位」之后想看第 1 位长什么样,
> 仍得自己在同一 tab(或别的 tab)里翻——跨分类那一位尤其翻不到,小标那句说明只提了一句
> 「可能分散在不同分类下」。要收得给小标挂上按序号定位的跳转(与分集页 `__roleFocus` 那条路同形)。

W289 把「是哪几张卡撞了」标了出来,而标出来之后用户的下一句是**「第 1 位长什么样」**——
按 id 取主体落到的就是那一位(它是"引用会落到哪一位"的答案),而卡片上看得见的只有名字与设定,
撞的那个 id 一个像素都不显。于是读到「第 2/3 位」的人要看第 1 位,只有两条路:
在本 tab 上一张张比对(而卡片上没有序号,比不出来),或者点开去重弹窗读那一屏计划里的「第 1 位「A-…」」
再回卡片上按名字找。同 id 那几位分散在不同分类 tab 下时,连这两条路都断了——那一位在别的 tab 上,
小标那句说明也只提了一句「可能分散在不同分类下」。

本槽只补那一格:**后续那几位的小标点得动,点它定位到留原 id 的第 1 位那张卡;那一位在别的分类 tab 下时先切 tab 再定位。**

## 二、跳转长什么样

小标外观一个像素没动(仍是现网 `tag yellow` 那一枚,W289 的位次与那句说明逐字未改),
后续那几位的那一枚多了三样东西:落点序号 `data-dupjump`、指针光标,以及那句说明尾巴上多的一句:

```
🧹 id 重复 第 2/3 位     ← 点它:滚到第 1 位那张卡并短暂高亮
🧹 id 重复 第 1/3 位     ← 它自己就是落点,不挂跳转
```

悬停那句说明现取同一份模板(`Domain.dupCopy`,一个字没改),只在挂了跳转的那几枚后面缀上一句:

```
……收拾存量走页头「🧹 主体 id 去重」(先看计划,确认才改)。点这枚小标定位到第 1 位那张卡(在别的分类下就先切过去),纯跳转不改任何字段。
```

点下去发生的事分两档:

| 第 1 位在哪 | 点了之后 |
|---|---|
| 同一个分类 tab | 直接定位:那张卡短暂高亮(`outline` + `boxShadow`,2.2s 后自动褪)并滚到屏中,tab 不换、不多说一句话 |
| 别的分类 tab | 先把 tab 切过去重渲一遍,再定位到那张卡,并 toast 一句「第 1 位「A-…」在「场景」分类下,已切过去」 |

三件分寸定在这条跳转上:

| 分寸 | 取的口径 | 不取那一种会怎样 |
|---|---|---|
| **只跳第 1 位** | 后续那几位一律指向留原 id 那一位 | 挨着跳"下一位"的话,跳到的是另一位要改 id 的,而用户问的是"引用会落到哪一位" |
| **第 1 位自己不挂跳转** | `keep === seat` 时那一枚一个属性都不多 | 跳到自己身上是一句废话,而挂上之后 W289 那条判据当场红(那一枚的标记形状被改了) |
| **跨分类先切 tab 再定位** | `target.kind !== tab` 时先换 tab 重渲 | 不切的话本 tab 上压根渲不出那张卡,点了没有任何反应——而"跨分类那一位翻不到"正是这条跳转要收的那一格 |

夹具上这两档的实况(六位主体 `dup(场景)/solo/dup/dup/two/two`,默认角色 tab):

```
角色 tab   B-不重复(无标)  C-第二位 第 2/3 位→0  D-第三位 第 3/3 位→0  E-同分类首位 第 1/2 位(不挂)  F-同分类第二位 第 2/2 位→4
点 F 那枚   tab 不换,定位到 E(同分类)
点 C 那枚   切到场景 tab,定位到 A-场景那一位(它那一枚报的正是「第 1/3 位」)
```

## 三、落点从哪来:`Domain.dupIdKeepOrder`,页面不翻第二遍

W289 已经把位次收在 `Domain.dupIdMarks`,回的是**按序号取的一张表** `{序号: {id, nth, total}}`。
这张表答得出「这一处是第几处」,答不出**「第 1 处在哪一格」**——而跳转要的正是后者。
中间那一步本槽下沉 `Domain.dupIdKeepOrder`:

```
D.dupIdKeepOrder(marks, id) → 本组第 1 处那个序号(表里没有即 -1)
```

推法只有一句:同一份表上,`id` 相同且 `nth === 1` 的那一格就是留原 id 那一处,按序号升序取第一个。

**为什么收在派生里、不让页面自己翻一遍:** 位次、改名计划与落点是**同一套序**。
页面自己翻出来的落点今天与 `keepOrder` 逐组相同(M4 实测行为逐字节等价),而两份计算迟早对同一份
脏数据给出两套序,那时卡片上跳过去的就不是预览里留下的那一位——**而用户点这一下正是为了看"引用会落到哪一位"**。
判据里另钉了一句:回的必须是**数字**序号。表的键是字符串,原样带出去时调用方拿它与自己那个下标严格比就永远不等,
第 1 位那一枚会跟着挂上"跳自己"的跳转(M6 就是这一手,当场红 3)。

**为什么不把落点塞进 `dupIdMarks` 那一格:** 那张表现在只出 `id/nth/total` 三格,单位词与展示口径都不在这一层,
多一格 `keep` 就得让两侧(位/行)都跟着认识它,而分镜侧那条跳转是下一槽的活;
按 `(表, id)` 现取一句反而两侧同一份代码都读得动。

2. **`cli.js` 的 `shots-dedupe` 注释里点名 `Domain.reviseTargets` 的那半句仍不准**(W287 残留第 1 条原样在)。
   明令不碰,继续记账点名。
3. **发现存量重复仍得先走到主体库那一页。** 项目详情面与项目列表那几枚角标点过来是"到主体库这一页",
   落点仍是整页(页头那个入口),不是撞车那张卡;整树导入/恢复那几条路照旧能写进重复 id
   (明令不给入口加闸),这仍是**存量**出口。
4. **跳转只有"去第 1 位"一个方向。** 站在第 1 位那张卡上,看不到"还有哪几位撞了我这个 id"——
   它那一枚小标一个跳转都不挂(挂上就是跳自己)。要收得让第 1 位那一枚指向后续那几位(不止一位时还要挑一个或列出来),
   而那是另一种形状的交互(一对多),不是本槽这条一对一的定位。
5. **切过 tab 之后回不去。** 跨分类那一跳把整屏卡片换了一批,toast 说了切到哪一类,
   而"切回刚才那一类、回到刚才那张卡"没有路,只能自己点回原来那个 tab 再找。
6. **主体侧与镜头侧的展示文案仍各写一份**(W287 残留第 5 条原样在)。本槽又添了一句
   (小标那句"点得动",在 `js/roles.js` 展示那一层),镜头侧下一槽多半要添同构的一句;
   要合并成一份模板得先把"点了做什么"这一段与单位词一起参数化。
