# W190 · 问题中心过期镜条目补一句分报(`count` 一个数不改、照旧不挂 cmd)

一句话结论:**停工位半成立**——W177/W186 记的两条里,「没有可点的空跑出口」这一条 live 实测**成立**(这条不挂 `cmd`,
按钮走的是导航分支,只改 `location.hash`,一次命令都不发),而「基线文案已足够」这一条**不成立**:
混堆时明细对**全部**过期镜统一说「建议重生成」,而其中定稿的那几镜批量重生成一律锁着 `!s.final` 跑不到。
故按任务给的中间那档处置——**只补 `staleSplitNote` 同类说明**,`count` 仍是过期镜总数,发射条件与危险级一个都不动。

**`count` 有没有改:没有。** 它照旧是 `c.stale`(含定稿过期镜),与门槛那一侧的 `counts.stale` 同一个数。

**基线**:`cursor/w185-integration-9b22` 的 `fb58034`。W183–W189 各支一律未取(不 cherry-pick w186/w187)。

## 1. 停工位陈述

W177 落 G4 分报时把问题中心这条留在原地,W186 复看后记下两句:

1. `js/issues.js` 的 `stale-shots` **不挂 `cmd`**,它报的是计数,不是"按下去就给你办"的下发承诺;
2. 若要给它补分报,**得先定 `count` 跟不跟着分**——W186 当时的判断是「它与 G2 高中危计数同源」。

任务给的禁令也正卡在这里:**不许为了分报把 `count` 改成不含定稿过期镜**(那会放宽 G2)。
所以第一件事不是改代码,是在基线上把这三问量出来。

## 2. Live 举证(基线 `fb58034` 现跑,数字全部实测)

夹具:一集四镜,`sh0` 鲜镜、`sh1`/`sh3` 可重跑的过期镜、`sh2` **定稿**过期镜——即任务点名的「可重跑 + 定稿过期」混堆。

### 2.1 混堆时这条长什么样

| 探针 | 实测 |
|---|---|
| `Domain.staleShotSplit` | `{all:[sh1,sh2,sh3], rerun:[sh1,sh3], locked:[sh2]}` |
| `Domain.episodeState().counts.stale` | **3** |
| 条目 `count` | **3**(= 总数,含定稿那镜) |
| 条目 `label` | `「第一集」3 镜素材已更新(过期)` |
| 条目 `detail` | `镜头 2、3、4 生成后输入有变化,建议重生成` |
| 条目 `sev` / `cmd` / `goto` | `mid` / **无** / `#/project/p1/episode/ep1` |
| 同一分堆下 `Domain.staleSplitNote(2, 1)` 会说什么 | `(可重跑 2 镜;另 1 镜已定稿,批量重生成不覆盖定稿产物,需先解锁终稿)` |

**这就是缺口所在**:三镜混在一句「建议重生成」里,而 `镜头 3`(即 `sh2`)是解锁终稿之前谁也重生成不了的。
G4 已经在回执上把这句话说出来了,问题中心这条没有。

### 2.2 点它会不会被领去空跑

| 探针 | 实测 |
|---|---|
| `it.cmd` | `undefined` |
| `js/issues-ui.js` `fixIssue` 走哪一支 | `if (it.cmd)` 短路 → 落 `if (it.goto)`:只 `location.hash = it.goto` |
| 弹窗渲染出的按钮 | 普通「→ 去处理」(`data-igoto`),不是命令类那颗 `▶ 重生成`(`data-ifx`) |
| 点它发出的命令数 / 扣费 | **0 / 0** |

**不会。** 问题中心这条没有可点的空跑出口——W177/W186 记的这半是准的。
所以本槽**不给它挂 `cmd`**:挂上去才会造出「按下去只跑得到 `rerun` 那半、而条目报的是总数」的空跑口。

### 2.3 G2 到底数的是什么

这是 W186 那句「`count` 与 G2 高中危计数同源」要被推翻的一格。`js/release.js` 的 G2 是:

```js
const unresolved = list.filter(x => x.sev === 'high' || x.sev === 'mid');
const high = unresolved.filter(x => x.sev === 'high').length;
const mid = unresolved.length - high;
```

| 探针 | 实测 |
|---|---|
| 本夹具全清单 | `stale-shots/mid/count=3` \| `review-stale/mid/count=1` \| `shot-stable-lexicon/low/count=4` |
| G2 读到的高危 / 中危 | **0 / 2**(数的是**条目数**) |
| 若 G2 数的是 `count` 之和 | 4 ≠ 2 —— **两者不同源** |
| 把 `stale-shots.count` 改成 `rerun` 数(3 → 2)后 G2 | **0 / 2,与改前完全一致** |

**`count` 不进 G2。** W186 那句判断在 live 上不准:G2 数的是条目在不在、危险级是哪档,`count` 只是给人看的数。

那什么才真会放宽 G2?**发射条件**。第二个夹具(一集一镜、该镜定稿且过期,`rerun=0`):

| 探针 | 实测 |
|---|---|
| 基线:条目在不在 / 该集高中危条目数 | **在** / **2** |
| 反事实:改成按 `rerun` 数发射条目 | 这条**凭空消失** / 降为 **1** |

即:改 `count` 放不宽 G2,**改发射条件才会**。本槽两个都不改,只在 `detail` 尾巴上接一句。

## 3. 判定与处置

任务给的三档,逐条对实测:

- 「基线文案已足够 **且** 没有可点的空跑出口 → 停工位不成立,停」:后半成立(2.2),**前半不成立**(2.1)——
  混堆时那句「建议重生成」对定稿那几镜是假的,而两端批量重生成锁 `!s.final` 这件事 `js/commands.js` 里
  全量路径(`filter(s => !s.final && !Store.shotVideoReady(s))`)与显式子集路径(`filter(s => !s.final && ids.has(s.id) && …)`)**都锁**。
- 「只缺一句说明、`count` 仍是总数 → 可以只补 `staleSplitNote` 同类说明」:**这一档成立,按它办。**
- 「不许为了分报把 `count` 改成不含定稿过期镜」:遵守,且 2.3 顺带量出这条禁令拦的其实是**发射条件**那一手,
  改 `count` 本身放不宽 G2——两手都不做,并各配一条判据(第 5 节 M2/M3)。

## 4. 落地(`js/issues.js` 一处,产品面单文件)

`if (c.stale)` 那一段改成三件事:

1. 判旧改**现取 `Domain.staleShotSplit`**,镜号由分堆的 `all` 反查——原先那行 `filter(s => Domain.shotVideoStale(…))`
   等于在本层再跑一遍判旧,补分报若照旧留着它,同一段里就会有两处各自判旧的入口;现在**只此一处**。
2. `detail` 尾巴接 `Domain.staleSplitNote(sp.rerun.length, sp.locked.length)`——与发布门 G4 **同一句**,
   本层不自己拼(各拼一版的话,同一个项目在问题中心与交付检查上会读到两种说法)。
3. `count` / `label` / `sev` / 发射条件 / 不挂 `cmd`:**一个字没动**。

两堆不分家时 `staleSplitNote` 回空串,故没有定稿过期镜的项目上明细**逐字与基线相同**。
