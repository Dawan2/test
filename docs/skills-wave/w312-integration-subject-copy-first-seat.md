## 八、这一槽可复用的两件事

**一、"删一半会响、删干净不响"是快进形合入的固有形状,别把前者当成后者的证据。**
本槽 M-DEL 那一手只删掉合进来的那条用例、把棘轮与文档数字留在原地,当场**红 2**;
而 M-REV 把整槽(用例 + 两处 `FLOOR` + 两处文档数字 + 索引行 + 记账件文件)一起退回,
**719/719 全绿**——三方份数自洽地一起变小、棘轮 `>=` 照旧成立,树上一条不响。
同一刻 `git diff M P2` 也是空集。
所以看到"删掉它会红"时要先分清删的是哪一半:
**判据面的棘轮守的是"别只删测不改数",守不住"整槽一起消失"。**
唯一能分开"整槽还在"与"整槽没了"的,仍是锚点台产出面那 18 条在 P1 上不命中、在 M 上条条命中。

**二、锚点选在"新槽与邻居共用的词汇"上,产出面会自己给自己作假证。**
本槽产出面挑的 21 条锚点里有 **3 条在 P1 上同样命中**——
`A-首位` / `C-第二位` / `D-第三位` 这三个夹具名是 W311 照隔壁 `subjects-dedupe` 那条抄的,
它们点的是"这一片用例"而不是"这一条用例"。
判别力要按 **18** 读而不是 21。
这与树上 `GUARD_TOPICS` 那层「宽锚按选择性现算(单锚扫到全套件 5% 以上即算泛)」是同一课,
只是这一次发生在**合入槽自己临时搭的脚手架上**——脚手架没有那层选择性判据护着,
故锚点台每一条都得在 P1 上先量一次"它到底命不命中",
**不能因为它是新用例里的字面就默认它在旧树上找不到。**
