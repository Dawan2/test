### 4.1 `README.md` 那条长行:掩数字比对证成"两侧改的是两件事"

两侧都改了第 611 行(`node tests/unit.js` 那条 16000 余字符的长行),两侧长度差 160 字符。
**先掩数字再逐字符比对**,读出来的是两件互不相干的事:

- `P1` vs `B`:`sed 's/[0-9]\+/#/g'` 后 `cmp` 逐字节相同 → 我方**只改了数字**;
  逐个数字位比对,82 个数里只有第 0 个从 `633` 变 `643`,其余 81 个一个没动。
- `P2` vs `B`:掩数字后**不相同** → 对侧改的是散文。用 `difflib` 求 opcode,
  全部落在 `equal` + **单个 `insert`** 上(位置 2923,长度 160 字符),
  插进去的是「**人手命令两道闸**:generate 侧提示词白名单不点名它…execStep 侧照旧落 blocked
  零下发,两侧判据都只认注册表 `manual` 那一位」那一段。

故这一行的并集是**确定的**:取对侧那句散文 + 我方那个数字,再把数字按 live 定。
收完当场回验 `union == P2` 成立(证明散文一个字没漏)、`单元测试(643 项断言` 在位
(证明数字那一侧没被吃掉)。**没有走"整句取我方"这条路**——那会把对侧那 160 字散文丢掉,
而这一行恰恰是 README 里唯一写着"两道闸"的地方。

两侧在 `README.md` 里另各有一行改动,不在同一行故 git 自动合上,合完逐行回验:
