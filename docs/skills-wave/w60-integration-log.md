## 5. 折回对侧文本:内容对不等于字节对

两处折回(4.1 的那一句、4.2 的 W56 段)都是**把对侧的散文抄进以 `ours` 为底的长行**。抄完通读看不出问题,
按首尾锚点切段逐字节比对时两处都失配,失配点同一类:

```
docs README 记账诚实位 W56 段 | theirs 517 字 / 本槽 517 字
  首个不同在第 157 字:theirs="\"剧本分析助手\"从剧本里认人)…" 本槽="“剧本分析助手”从剧本里认人)…"
README 核心提示词 bullet W56 句 | theirs 156 字 / 本槽 156 字
  首个不同在第 129 字:theirs="\"剧本分析助手把人物落进主体库\"…" 本槽="“剧本分析助手把人物落进主体库”…"
```

**字数相同、语义相同、渲染后几乎一样**:作者原文用的是半角 `""`,折回时被抄成全角 `“”`。
这一类既没有断言兜底(散文不进任何断言),也不会在 `git diff` 里显眼(整行都在变),
更不会被通读捞出来。改回半角后两段均 `逐字节相同`。

留给后面的槽的做法:**折回对侧散文后,按首尾锚点从两侧各切一段做 `===` 比对**,不要靠眼睛。
同理适用于 4.2 的索引行——那一行也做了同样的比对(`cmp` 与 `theirs` 逐字节相同)。
