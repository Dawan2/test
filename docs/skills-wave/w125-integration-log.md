## 4. 逐处怎么解

### 4.1 三条新用例:都留,不并条,而且新条要排在循环禁令之后

`tests/unit.js` 契约段那一块冲突里,我方是 W121 的三套件下限、对侧是 W124 的两条(helper 禁令 + `for await` 禁令)。
**判据是三条都留**,理由由两侧各自写明且互不冲突:

| 用例 | 报的是什么病灶 |
|---|---|
| W120 循环禁令(基线已带) | `report(...)` 套在循环/迭代回调里 |
| W124 条一 helper 禁令 | `report(...)` 被包成可复用的函数(块链上的函数体,或前面还有代码的非裸语句) |
| W124 条二 `for await` | `for` 引出的块而词表点不到的那个形状 |
| W121 三套件下限 | 用例被删了 |

四条的失败含义两两不同,合成一条会让报错文案必须同时描述几件事。

**排序不是随便定的**:`w124` 两条的注释都以「上一条按块链禁循环……」起头,
故新条必须紧跟在循环禁令之后,W121 那条下限仍排在用例名唯一那条之前(与基线上的相对位置一致)。
按这个序落地后,四条用例的注释里所有"上一条 / 上面两条"这类指代**逐条现读为真**。
合并后 `contract` 101 → **103**。

主 `README.md` 那一块同源:对侧在「……循环体就算红」之后插了两句(「块链禁循环只封得住『循环』那一路」起头的那段),
我方在同段末尾有一句「三个套件的用例数同样只增不减」。取法是把对侧那两句原样插在我方段落的对应位置、
我方那一句原样留在末尾,两段措辞都不改写。
