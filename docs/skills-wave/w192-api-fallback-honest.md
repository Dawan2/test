## 1. 结果一句话

周期账上挂在 G-13 名下的「`js/api.js` 的回退属未决产品口径」这个停工位,按 live 举证**部分成立**:

- **不成立的那半(占大头)**:登录后端后真实上游一旦失败,`chat` / `chatJSON` / `chatJSONRobust`
  **逐条如实抛错**,一处占位冒充都没有;超时重放按 `operationId` 幂等不重复扣费;
  服务端 `jsonMode` 内部修复失败后以 502 + 已退费返回,客户端不再重试也不再修复。
  这一半**一个字没改**,离线 PH 占位原样保留。
- **成立的那半(一处)**:`listModels` 在**七个失败分支**上都写着 `if (cachedRaw) return cachedRaw`,
  只要浏览器 localStorage 里还留着模型缓存,失败就被静默换成一次"成功的拉取"。
  用户直接看得见:后端 500 / 上游 key 无效 / **压根没登录**时,「⚡ 测试连接」照渲绿色
  **「✓ 连接成功,共 N 个可用模型」**;「↻ 刷新模型列表」照 toast「已刷新,共 N 个模型」而实际一个字没刷。
  更硬的一格是那行回退**排在 401 分支之前**——登录过期时 `U.authExpired()` 不触发,
  本地恰好有缓存的用户既不掉线也不重登,与无缓存用户的行为当场分叉。

另有一处**纸面上的假成功**一并收:设置页顶端与计费说明写着
「未配置或**连接失败**时,所有 AI 功能自动回退到本地模拟/启发式实现」「失败自动回退本地实现」,
而实况恰恰相反(在线失败如实报错并退费)。文案是用户判断"失败会怎样"的唯一依据,与实况反向即等于承诺了一次假成功。

## 2. 先把 G-13 名下这个"回退"是什么说清楚

任务口径把停工位描述成「上游失败则换另一条路径 / 静默成功 / 占位」。
但**仓库账本上 G-13 记的那个 `js/api.js` 的"回退",不是这一类**——
`js/skills.js` 里 SK-10 / SK-11 的「仍欠」段与 `tests/unit.js` 两条判据点的都是同一件事:

> `js/api.js` 的 `chatJSON` / `chatJSONRobust` 在**调用方不给 `system` 时垫的那句
> 「你是专业助手。」**,它不在提示词注册表里、用户覆盖不到,故 G-13 缺口未闭合。

那是**提示词人设的缺省兜底**,与"上游失败换路径"是两回事。两条判据(`|| '你是专业助手。')` 恰 2 处、
全仓人设字面持有者名单里的 `js/api.js:2`)都**原样留着,本槽一个字没碰**——
收编它属于 G-13 本身的落地面,不在本停工位射程内,且任务明令不拆 `gaps()` 键。

本文判的是任务口径里那个**失败回退**面。两者同在 `js/api.js`、同被叫作"回退",本节先把它们分开,
免得后续把"人设缺省进注册表"与"失败不许冒充成功"记成同一笔账。

### 3.3 「用户能看到的假成功」可复现路径

只有一条,复现步骤:

1. 任意时刻成功拉过一次模型列表(localStorage 落下 `mv_hujing_models_cache`);
2. 退出登录 / 或让后端返回 500 / 或让上游 key 失效;
3. 进「个人中心 → API 设置」点「⚡ 测试连接」。

基线渲染:`<span class="tag green">✓ 连接成功,共 3 个可用模型</span>`。
修复后渲染:`<span class="tag red">✕ 未登录后端,无法获取模型列表</span>`(或对应的真实故障文案)。

## 4. 改了什么,以及为什么删掉它不伤离线

删掉 `listModels` 七个失败分支上的 `if (cachedRaw) return cachedRaw`,只留 TTL 内的正常缓存命中。

**这一手不伤离线可用性,原因是下拉表本来就不靠 `listModels`**:

```
getTextModels() → this._modelIds || this._loadCachedIds() || Object.keys(RECOMMENDED)
```

它自己按三级取,`listModels` 抛不抛错与它无关;后台预热那次调用本来就 `.catch(() => {})`。
换句话说,那处缓存回退**唯一服务的调用方,恰恰是两个"明确要一次现拉结果"的入口**——
`testConnection()` 与「↻ 刷新模型列表」,而这两个正是绝不能撒谎的。live 复核:
修复后拉取失败时 `_modelIds` 仍是 `null`(失败结果不写进内存态)、`getTextModels` 照给 `stale-a,stale-b`,
未登录且无缓存时照给内置三条推荐。**离线 PH 占位一处没删。**

直连分支的四处一并收:它与代理分支是同一个函数里同一个惯用法,
留一半会让「测试连接」的假成功只要切一下单选按钮就照旧复现,那条 tripwire 也就写不成"永不假成功"。
这四处**不涉及模型路由表**(`RECOMMENDED` / `MODELS` / `CONFIG.llmModel` 链一个字没动)。

文案两处按实况改写,README 同口径同轮改。

### 5.3 变异复核(逐条真跑,不是推演)

| # | 变异 | 结果 |

| M1 | 把代理分支那四处 `if (cachedRaw) return cachedRaw` 原样恢复 | **红 3**:「拉取失败一律抛错」点名 `实际返回 ["stale-a","stale-b","stale-c"]`、「401 不被缓存吞掉」、「缓存只在 TTL 内命中」 |
