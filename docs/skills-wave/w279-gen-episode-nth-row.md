## 一、改的是哪一格

`CMD['gen-episode']` 每轮回最新树上取本轮那一行,取法从 `findShot`(按 id 取首行)换成 `nthShot`(按序数取同 id 第几行),与 `exec episode.generateVideos` 那一处逐句同形:

```
const nthOf = new Map();
const seenIds = Object.create(null);
(ep.shots || []).forEach(s => { const n = seenIds[s.id] || 0; seenIds[s.id] = n + 1; nthOf.set(s, n); });
…
const sLive = nthShot(epLive, s.id, nthOf.get(s) || 0);
```

三件事按明令逐条对齐,一处都没另起炉灶:

- **复用 `nthShot`,不另抄一份对位**。`cli.js` 里那个 `nthShot(ep, sid, nth)` 是 W248 立的,两处兜底(序数越界 `rows[nth] || rows[0]`、同 id 一行不剩时委托回 `findShot` 抛「镜头不存在」的 exit 4)本槽一个字没动,直接当第七个调用点用。全树 `findShot` 由 **17** 处降到 **15**(调用点 −1、注释里那句自述 −1),`nthShot` 由 **6** 升到 **8**(调用点 +1、新注释里点名 +1),`nthSubject` **3** 处未动。
- **序数在快照全表 `ep.shots` 上数,不在待跑清单 `todo` 上数**。`gen-episode` 自己带断点续跑(`s.video.status === 'done'` 的行被筛出待跑清单),首行已出片时在 `todo` 上数出来的序数是 `0,1`——写回会落到全表第 0、1 行,**首行那段已有的片被覆盖、末行仍补不上**。这与 W248 在 `exec` 那一处踩过的坑逐字同形,判据单独钉了一档(§三 ②)。
- **座位表按对象身份记**(`Map` 的键是行对象,不是 id 也不是下标),在 `todo` 筛出来之前照全表走一遍。

`landed` 的算法一个字没改:座位键仍是 `id + '#' + 它在当轮那棵最新树的同 id 那几行里排第几`,仍在本轮真成功之后才进集合,仍由 `seats.size` 现算而不是抄 `result.ok`,空跑那一路仍 `landed: 0`,岔开那句话仍单源 `Domain.landedNote(ok, landed, '行')`。

## 二、`landed` 那一档判据同轮改的是什么口径

换完之后,**表没被别处改过时 `landed` 恒等于 `ok`**——这正是 W277 §残留 2 预告的那件事。W277 那一条的第一档钉的是「同 id 三行的一趟 `ok:4 / landed:2`,`note` 说清共位」,前提没了。

按明令改成**与现网两条批量命令一致的口径**——`exec episode.generateVideos` 与 `exec subject.generateImage` 那一条 `landed` 判据(`tests/unit.js` `commands` 套件 3904 行那条)现取就是这么分档的,本槽逐条照它搬:

| | 那两条批量命令现取的档 | `gen-episode` 本槽改成 |
|---|---|---|
| 正常一趟 | `ok` 与 `landed` 相等,`note` 一句不加 | 同(①档:`4/4`,`note` 为 `undefined`) |
| 岔开怎么造出来 | `withProject` 桩在末轮开跑前删掉末行 → 序数越界退回首行 → 两轮共位 | 同(③档:`ok:4 / landed:3`) |
| `ok` 的口径 | 引擎调用成功次数,不许改成 `failed` 来凑落库数 | 同(③档明写) |
| 空跑 | 恒带 `landed: 0` | 同(⑥档) |
| 座位键带 id | 三个各占一行的不同 id 不许缩成 `landed:1` | 同(⑤档) |
| 判词单源 | 与直调 `Domain.landedNote` 逐字节相等 | 同(③档,单位是「行」) |

**`landed` 字段本身一格没退**:它仍恒在回执上(含空跑那一路的 `0`),仍现算,仍在两数岔开时挂那句 `note`。变的只是**这个漏此后由谁触发**——从「同 id 多行这件事本身」变成「跑到一半别处改了表」,与那两条同源。共位覆盖仍不退费(那几次调用都真发生、真扣了钱),`ok` 一个字没动,计费面零 diff(`gen-episode` 的钱由服务端按每次上游调用记,浏览器侧计费仍一律走 `Tasks.run`)。

## 三、判据:条数未动,原地把那一条重写成六档

新形态落在同一条用例上(`commands` 套件,名字随行为改成「`CLI gen-episode` 同 id 多行:每一轮的片落到本轮那一行,回执的 `ok` 与 `landed` 各说一件事」),六档:

1. **同 id 三行 + 一行不重复的正常一趟**:四笔钱**四行**出片,且四段片各不相同(同一段写几遍等于只买到一段);`ok:4 / landed:4`,`landed` 等于**磁盘上真出片的行数**(现数,不抄回执),`note` 一句不加;`result.shots` 键数仍是 2(按 id 记本就收不住同 id 几行)。
2. **首行已出片被断点续跑跳过的一趟**:三笔钱补上三行、连同原有那行共四行出片,**首行那段 `old.mp4` 一个字不许被改写**,`3/3`。这一档钉的是「序数在全表上数」,只数待跑清单时它当场红。
3. **并发改表**(`withProject` 桩在末轮开跑前删掉末行):序数越界退回首行、两轮共位 → `ok:4 / landed:3`,`failed` 为空(不许让 `undefined.image` 把这一趟炸成失败),`note` 说清「4 次调用、3 行落库」且与直调 `Domain.landedNote(4, 3, '行')` 逐字节相等。
4. **同 id 一行不剩**:剩下那两轮如实进 `failed`,错误说法仍是 `findShot` 那句「镜头不存在」——不另造第二个出口。
5. **各占一行的不同 id**:`3/3`,`note` 一句不加(座位键不带 id 时这一档当场造出假话)。
6. **一镜也没跑**:确认闸拦下那一路带 `landed: 0`。

夹具沿用 W277 那个 `sb.CMD`(`loadCli()` 把命令原语表从 vm context 取出来那一行),落库面仍读 clone 语义的 disk 夹具,引擎桩按下发次序给各不相同的片(默认那份按 `s.id` 命名,同 id 三行会撞成同一个 url,量不出「四段各不相同」)。

## 八、残留

**销号一条:W277 §残留 2「`gen-episode` 的写回路径仍取首行」。** 本槽把它换成 `nthShot` 并把序数在全表上数,同轮改掉了那条 `landed` 判据的第一档口径——原话预告的两件事都做完了。

原样留着 / 新登记的:

1. **`gen-episode` 的「座位只在本轮真成功后才登记」仍无判据**(W278 §残留 9,本槽 §四 M6 复量:提前登记**红 0**)。收法是造一档「取行成功、`genShotVideo` 才失败」的夹具,两条 `exec` 批量那边同形的洞也一并在那里收。
2. **单发那七条出口没有 `landed`**(原样传 W277 §残留 1)。本槽只改取行,一条没碰。
3. **引擎事件 `shots.batchDone` 的 `ok` 同样读不出落库实况**(原样传 W277 §残留 3)。
4. **共位那一轮的钱没有退路**(原样传 W254/W277)。换成按序数取行之后,共位只在「跑到一半别处改了表」时才发生,频次比换之前低得多,但「共位算不算交付失败」这个产品问题一个字没定。
5. **`result.shots` 按 id 记,同 id 只剩一个键**(原样传 W277 §残留 5)。它是 `gen-episode` 对外的回执字段,改键是破坏性改动;判据仍正面钉住键数并写明「落库数只看 `landed`」。
6. **`landed` 这一族仍是零源级判据**(原样传 W278 §残留:全树关于 `landed` 的断言只在 `tests/unit.js` 两个用例里)。本槽没加这一层。
7. **`state-put` 不设闸**;**主体侧没有 `shots-dedupe` 同类命令**;**`loadCli()` 取出来的 `CMD` 表仍只有 `gen-episode` 一条被测到**(三条一并原样传 W277)。
8. **摘 `nthShot` 兜底这一手的红数从 2 变成 3**(§四 M4)。这不是漏,是本槽扩出来的判据面,但它同时意味着:往后拿这一手当「两支有没有接触」的量尺时,基准数得按 3 读,照抄 W255/W257/W259 那三份里的 2 会读成假的分家。
