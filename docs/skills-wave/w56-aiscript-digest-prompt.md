# W56 · 剧本摘要人物小传步的人设改经注册表(`extract.system` 的第二个取用口,不新开键)

> 基线 `cursor/w50-integration-dad5 @ 371c75e`,落地分支 `cursor/w56-aiscript-digest-prompt-e8c8`。未合并 W51–W55。
> 本槽做的是 W45 记账件第 4 节点名的那处遗留:`js/episode-util.js` 里与 `extract.system` **同字面**的最后一处内联人设。
> 不改发布门(`js/release.js` 一行未碰)、不新增计费动作(摘要四步仍走既有 `API.chatJSON` 口径,一分不多扣)、未删测(反转 1 条既有断言的方向,新增 2 条用例)。

## 1. 现场:注册表里已有这句话,可这一处读不到它

W45 把主体提取的人设句收进注册表新键 `extract.system`(`def = '你是专业的短剧剧本分析助手。'`),并把 `wf-core` 常量撤掉。但那一槽收的是**提取步**这条链路;同一句话在 `js/episode-util.js` 里还有第二处写死的全文——`aiScriptDigest`(剧本摘要全文通读)第五步「人物小传」:

```js
// 基线 js/episode-util.js:⑤ 人物小传
const bios = await API.chatJSON({
  model, system: '你是专业的短剧剧本分析助手。',   // 与 extract.system 的 def 逐字节相同,但读不到用户覆盖
  ...
```

后果与 W40/W42/W45 那三处同形:用户在「偏好学习 → 全局默认值 → 核心提示词 skill」把主体提取人设改成自己那套口径(例如"只认正式全称,别名一律并进 `aliases`"),**提取步跟随、摘要里的小传步不跟随**。而这两步的产物落进的是同一个 `p.subjects` 主体库(小传步只写文本 `description`、不生图),口径分叉直接体现在主体库里:同一部剧的人物条目一半按新口径命名、一半按旧口径。

W45 当时如实记了这一处并留了一条计数型断言当路障(见该记账件第 4 节):`js/wf-core.js` 与 `server.js` 一律不得出现该字面,而 `js/episode-util.js` 断言的是**出现次数恰好 1**——因为提取步收编后,文件里仍剩小传步那一份,写成"不得出现"会假红。本槽把那个 1 消掉,断言随之反转。

## 2. 结果一句话

**复用 `extract.system`,不新开键**:小传步的 `system` 改成 `Prompts.get('extract.system')`,只取人设句、不接方法论段。注册表条数不变(仍 11 条),`js/prompts.js` 一字未动,**缺省逐字节不变**(摘要四步的 `system` 与 `user` 全部原样),覆盖时提取步与小传步一并跟随。

```js
// js/episode-util.js:⑤ 人物小传(浏览器隐式读 Store.settings.promptOverrides,与同文件取 split.system 同写法)
system: Prompts.get('extract.system'),
```

判"是同一句话还是两句话"用的是这三条,三条同时成立才复用键:

1. **字面同**:内联那份与 `def` 逐字节相同,不是"意思差不多"的另一份措辞。
2. **角色同**:两步的人设都是"剧本分析助手"——从剧本文本里认人,不是策划、不是导演。摘要链路里另外三步(分块通读 / 汇总 / 集纲)写的是 `'你是资深短剧策划。'`,那是另一个角色,**本槽不动**(见第 6 节)。
3. **产物落点同**:两步都往 `p.subjects` 写 `kind: 'character'` 的主体条目,且都过同一道 `WfCore.isPlausibleName` 可信性校验拦台词碎片。用户改人设想改的正是这件事的口径,分给两个键等于让同一个主体库听两个人指挥。

反过来说,若这三条有一条不成立(例如它其实是"摘要人设"、措辞另写一份),按纪律该新开独立键而不是把两句话硬合成一句——本槽实测过这条岔路(变异 4):新开一个 `def` 与 `extract.system` 相同的第二键会当场转红 4 条(注册表键脱离 skill 索引、"注册表命中恰好一条"变 2、README 提示词条数失配),证明"同 `def` 开两个键"这条路本身就被既有契约堵住了。

## 3. 为什么取 `Prompts.get` 而不是装配口 `WfCore.extractSystem()`

提取步取的是装配口:`WfCore.extractSystem(ov) = Prompts.get('extract.system', ov) + KB.pick('主体参考')`——人设句之后按键整条接 KB「主体参考」五条方法论(W19 立的注入面)。小传步**不能**照抄这个取值口:

- 行为面:那段方法论正文 278 字,讲的是"参考图必须随请求同包发送 / 参考人物 ≤4 / 大头照+全身照不要三视图 / 多人物标注对应图片"——全是**生图与参考图组**的纪律。小传步不生图、不装参考图组,只出一句话文本小传,接上去等于给 LLM 塞一段与本步无关的约束,**且缺省输出立刻不再逐字节相同**(变异 2 实测:小传步 system 从 14 字变 292 字)。
- 口径面:这一处要的是"人设句这一件事的单一来源",而不是"提取步那整条提示词"。与 W18 的形态相同——`gen.promptSystem` 也有两个取用口,生成步经 `WfCore.genPromptSystem` 取"人设句 + 抽卡公式/军规",审片一键优化与 CLI 修订重抽经 `WfCore.optimizeSystem` **只取人设句**。本槽是同一条纪律的第三次应用,故不再为它包第四个装配函数(包一层的理由是"人设句之后还要按键接正文",小传步没有这个需要)。

因此本槽落成"一键两口":提取步经装配口取整条,小传步经 `Prompts.get` 只取人设句。两口的相对关系有一条源级断言钉住(小传步不得改取带方法论段的装配口)。

## 4. 「另一端」在哪:这一处没有服务端对端

W40/W42/W45 那三处都要求"两端都改取值口",因为拆集/汇总/提取三步都有 `/api/wf/*` 对端。**摘要这条链路只在浏览器**:`aiScriptDigest` 由 `js/episodes.js` 剧本页「✨ AI 生成卖点/梗概/集纲」按钮、`runDigestDock`(普通模式解析后台进度)与 `js/director.js` 精细模式追加内容三处调用,`server.js` 里没有对应端点(源级断言:`server.js` 不得出现小传步的 user 半字面 `提取其中的主要人物`)。

所以本槽的"零内联"是**单端**结论,而不是漏了一端:两端断言的位置换成了"这一处不许长出第二端"。这也意味着收编只解决了"可覆盖",没解决"可 headless"——摘要链路仍进不了 CLI/MCP,属 G-13 之外的另一题(见第 9 节)。

## 5. 缺省逐字节不变靠哪两层钉住

W45 的三层里"装配口层"在本槽不适用(小传步不经装配口),故是两层,且第一层从源级升成了**行为级**:

1. **行为层(新增)**:把 `js/episode-util.js` 装进 `vm` 沙箱真跑一遍 `aiScriptDigest`(`API.chatJSON` 原样截获每步的 `system`/`user`),断言四步 `system` 拼起来逐字节等于 `策划|策划|策划|分析助手`——收编前那四份字面。改 `def`、接上方法论段、退回内联后再改字面,都在这一条上转红。这也是 `aiScriptDigest` 的**第一条行为面断言**(此前它只有源级断言,四步提示词改坏了单测看不见)。
2. **源级层(反转)**:`js/episode-util.js` 里该人设句的全文出现次数从"恰好 1"变**0**,并要求出现 `Prompts.get('extract.system')`。W45 留的路障至此归零,谁把小传步退回内联,计数断言与取值口断言一起红。

另外两条钉的是"覆盖只换人设":写覆盖后跑同一条链路,四步 `system` 只有末步变、前三步的策划人设不受影响;四步的 `user` 半(含 `{"characters":[{"name":...,"bio":...}]}` 返回约定与分块正文)与缺省那次**逐字节相等**,且覆盖后 `p.subjects` 仍解析出人物条目——**解析/JSON 契约不开放覆盖**这件事由这两条一起证明。

## 6. 摘要链路另外三步为什么不动

分块通读 / 汇总 / 集纲三步的 `system` 都是 `'你是资深短剧策划。'`,与注册表里现有 11 条中任何一条的 `def` 都不同(`und.system` 是"资深短剧导演"、`split.system` 是"专业的短剧策划编辑",都不是这一句)。它们是"注册表之外的内联人设"这个大头里的三处,与导演阐述 / 光影总控 / 剧本围读 / 拉片分析 / 配音导演 / 节拍拆解 / 发行文案同类——收编与否是产品口径题(注册表条目多了「全局默认值」页会变长,而这些步没有服务端对端,进注册表只解决"可覆盖"),W45/W49 的交接第 2 条已把这一类登记在 G-13 名下。

本槽只收"同字面的重复",不顺手收"另一句话",判据就是第 2 节那三条:同一句话的两份拷贝是**单源问题**(必须收),另一句话进不进注册表是**覆盖面问题**(产品口径题)。三步的策划人设三份拷贝里若要收编,该走的是"新开一个 `digest.planSystem` 键、三步同键"那条路,与本槽不是同一件事。

## 7. 记账:`Skills` 未动,SK-03 的仍欠段一字不改
