## 1. 现场:注册表里已经有这句话,记账还写着"待收编"

W45 把主体提取的人设句收进注册表键 `extract.system`,装配口改成 `W.extractSystem = ov => Prompts.get('extract.system', ov) + KB.pick('主体参考')`,W56 又给这个键接上第二个取用口(剧本摘要人物小传步)。可 `js/skills.js` 的记账停在收编之前:

```js
// 基线 SK-11 subjects.refDiscipline
note: '注入面落在主体步系统人设 WfCore.extractSystem(…),本条拼块即该条目正文;人设句入注册表待 G-13。' + …
// 基线 SK-10 script.aiToneBan
note: … + '有没有人味、像不像这个人物说的话属语义面,待 G-10;人设句入注册表待 G-13',
```

两条都在说"这句人设还没进注册表、用户还改不到",而实况是它进表已有三槽、覆盖两个取用口都跟随。读记账的人(排期、验收、Agent 自省)会据此以为主体步的人设半还没落地。

SK-10 那句更失真一层:**它根本没有专属人设句**。SK-10 的注入面走的是板块方法论通道——条目正文 `文案AI味` 进 KB 单源(W27,S-02 清账),落点是 `js/agent.js` 的 `BOARD_KB.剧本` 按键整条注入。W27 记账件第 108 行当时就写明"本条的注入走板块方法论通道,尚未有专属人设句",但 `note` 里那句话一直挂着,读起来像"SK-10 有一句人设待收编"。

## 2. 这处旧账为什么能活到第六个周期:它没有任何断言兜住

W56 与 W60 登记这处不实时给的顾虑是"改 note 会连着动 `Skills.gaps()` 投影与单测期望串"。本槽先按纪律 grep(`extract.system`、`G-13`、SK-10/11 断言)再动手,查出来的实况与顾虑不同:

- 全仓**只有一条**断言提到这件事,而且提的是**断言语**不是被断言的值:`tests/unit.js` 那条 `assertEq(sk11.gaps.join(','), 'G-13', 'G-06 的校验半落地后本条只剩人设句入注册表那一项')`——比对的是 `gaps` 字段,说明串里那半句纯属注释。
- 两条 `note` 的正文**零断言覆盖**:只改两条 `note`(撤掉本槽新增用例与 `prompts` 登记后实测)单测照样 403/403 全绿。旧账不是被断言拦住才没改,是**没人钉它**,所以它能一路带过 W45→W56→W60。

这与 W36 那次的结论同形:「改记账会动投影」这条顾虑在实测下不成立。区别是 W36 动的是 `pending`(`gaps()` 只投影 `gaps` 字段、不看 `pending`),本槽动的是 `note`(投影里根本没有 `note`)。

## 3. 结果一句话

`note` 改成现况:人设句已在注册表;两条的「仍欠」段各自改指**真正还在的那一处**。`gaps` 字段一字未动,`Skills.gaps()` 的键与值逐字节不变。

```js
// SK-11:注入面两半都在单源之内,仍欠的换成本条另一登记键 tplImage 的取用点
'本条拼块即该条目正文;人设句已在注册表(extract.system,装配口收覆盖表参数),'
  + '故注入面两半——人设句与方法论正文——都在单源之内、用户都改得到。'
  + '仍欠 G-13 的是本条另一登记键 tplImage 的取用点:八维度重写文生图提示词那步的人设仍内联在 js/persona.js,'
  + '不在注册表也就覆盖不到(与其余模块内联提示词同批处置)。'
// SK-10:本条没有专属人设句,仍欠的是剧本模块那几处内联提示词
'本条注入走板块方法论通道、没有专属人设句,'
  + '仍欠 G-13 的是剧本模块几处内联提示词(解说体改写、导演阐述、光影总控、剧本围读)未进注册表——'
  + '那几步既取不到本条目正文,用户也覆盖不到'
```

另补一处登记:SK-11 加 `prompts: ['extract.system']`。它的注入落点就是那个键的装配口,而条目里此前只登记了 `kb` 与 `settings`——与 SK-17(`sb.system`)、SK-21(`gen.promptSystem`)同口径把落点键写上,记账才对得上"人设已在注册表"这句话,且引用键自检(`Skills.validate`)会替它守着键名。

## 4. 「仍欠」段的锚点怎么定:先查那处余量是否真的还在

纪律是"仍欠段只写真正还在的",所以两个锚点都先在源码里核过,再写进 `note`,并各配一条源级断言(收编了就转红,逼着同步改记账):

| 条目 | 新锚点 | 实况(本槽实测) |
|---|---|---|
| SK-11 | `settings.tplImage` 的取用点:`js/persona.js` 八维度重写文生图提示词那步 | 该步 `system: '你是文生图提示词专家。'` 仍是内联字面,同文件里没有 `Prompts.get(`;注册表 14 条里没有哪条的 `def` 是这句话 |
| SK-10 | 剧本模块四处内联人设:解说体改写、导演阐述、光影总控、剧本围读 | `js/episodes.js` 四处 `system: '你是资深短剧解说编剧…'` / `'你是资深短剧/漫剧导演…'` / `'你是影视摄影指导(DP)…'` / `'你是短剧导演组的剧本围读会…'` 仍是内联字面,注册表里都没有 |

选锚点的判据是"这一处属不属于本条目自己的登记面":SK-11 的两个登记键是 `kb: 主体参考` 与 `settings: tplImage`,前者的取用点(装配口)两半都已单源,后者的取用点(`js/persona.js:16` 读 `settings.tplImage` 拼提示词)那一步的人设仍内联——余量落在本条目自己的键上,不是替全仓背 G-13 的账。SK-10 同理:它的登记面是剧本板块的方法论通道,而剧本模块里真正读不到这条方法论、用户也改不到的就是那四步。

`settings.tplImage` 这个键**本身不算欠**:它在「偏好学习 → 全局默认值」有输入框,用户改得到,不落在 G-13 那句"用户不能在线改写"的伤害面里。所以 `note` 写的是它的**取用点那步的人设**仍内联,而不是"模板未进注册表"——后者会把一件用户已经能做的事记成缺口。

## 5. `gaps` 为什么一个不摘:G-13 没有闭合

`Skills.gaps()` 只投影 `gaps` 字段,而 G-13 在目录里(`w1-pipeline-skill-map.md` 第 106 行)治的是"大量模块内联提示词未进注册表",不是"SK-11 那一句"。本槽实测全仓仍有 21 处内联人设(`system: '你是…` 字面计数;`js/episodes.js` 五处、`js/persona.js` 三处、`js/sb-board.js` 两处、`js/episode-util.js` 三处策划人设、`js/beatboard.js`、`js/proj-shell.js`、`js/proj-upload.js`、`js/editors.js`、`js/gsettings.js`、`js/agent-ops.js`、`js/experts.js`、`js/sb-views.js`),缺口显然开着——按 W36 立的**关联索引口径**(落地一面不摘标记),两条的 `G-13` 标记原样保留。

于是本槽的投影结论是:**`gaps()` 的键数与每个键的值逐字节不变**(键数仍 20,`G-13` 仍是 `script.hookType,script.aiToneBan,subjects.refDiscipline,eps.structureStage,gen.videoTpl,film.rhythmInject` 六条)。W56/W60 顾虑的"改 note 会动投影"没有发生,顾虑的成因见第 2 节:被误当成期望值的其实是一句断言语。

反过来说,若哪天 G-13 真的清账(内联人设全部收编),摘标记是那一槽的事,判据是"全仓再无内联人设",不是"SK-11 这一句已经进表"——本槽不预支那个动作,也不因为"我这一半好了"就把标记摘掉。
