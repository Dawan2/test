   240|## 八、这一槽可复用的两件事

**「失败了库脏不脏」这句话,判据得落在"有没有发出那次写"上,不能只对库内容。**
本条 ① 起手只写了"库里两位逐字段未动",而**上传失败时库本来就不会被改**——
把整条命令改成 `try/catch` 吞错(M1)之后,库内容那一层照样绿:
吞掉的那一趟发出的 `PUT` 递的是**没改过的**那棵树,库确实一个字没变,
可用户到手的是一次"成功了但没有图"的回执。**脏与不脏只在那次写发出之后才谈得上**,
故写这类判据得把往返清单一起数进去——那一层同时接住了"不该写却写了"与"错被吞了"两种改法。

**退出码这类判据,桩的落点决定它量的是产品还是量的是夹具自己。**
   250|`exit 5` 是 `cli.js` 自己按 HTTP 状态推的一步。把桩打在 `api` 上,

桩下到 `fetch` 那一层之后,推错一格就红。凡是"码是产品算出来的"这类判据,
**桩得打在那一步算出来之前**,不然量的是夹具自己填的那个数。
