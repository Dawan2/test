## 4. 逐处怎么解

### 4.1 W96:零冲突,但要补一行索引 —— 以及被前一条 assert 挡住的那两处

**这次合并 `git` 全程干净**(`docs/skills-wave/w96-cycle7-audit.md` 是纯新增文件,1120 行插入、零冲突标记)。
合完立刻跑 unit:**461/463,红 2 条**,两条都指同一件事——文件在、索引行不在:

```
FAIL | contract · docs/skills-wave 索引与目录实况双向对齐 | 索引表应与目录里的记账件一一对应(…期望里有 w96-cycle7-audit.md,实际里没有)
FAIL | contract · docs/skills-wave 索引完备性 | 记账件 w96-cycle7-audit.md 在目录里但索引表没有它那一行(合入时漏登记,或只合到了漏掉索引行的那一版)
```

这是**有意的分工**,不是 W96 的疏漏:核验槽只提交报告、不登记目录索引行(W55 就是这么定的,
这一处有契约断言兜底、撤掉即红),索引行由集成槽在合入时补。所以本槽补上那一行,
按报告正文现读内容写(周期口径、13 次合并 13/13 取 head、W63 两条高危阻塞已闭合、
W72/W90 两次时点结论失真、全仓第一对同名用例、G-13 余量三张名单三个口径、G-10 连续五个周期零开工),
按槽号排在 `w95` 与 `w97` 之间。

**补完之后红的不是零条,而是换了一条 —— 这是本槽第一个值得记的发现。**

```
FAIL | contract · docs/skills-wave 索引完备性 | 目录内相对链接不许悬空:
      实际 "w96-cycle7-audit.md → x.md(文件不存在) / w96-cycle7-audit.md → x.md(文件不存在)"
```

成因:那条用例里有**两段 assert,一段正向一段反向**——

```js
waves.forEach(f => assert(rows.has(f), '记账件 ' + f + ' 在目录里但索引表没有它那一行…'));
// ↑ 这一条一抛,下面这一段就再也跑不到
all.forEach(f => { …[...body.matchAll(/\]\(\.\/([A-Za-z0-9._-]+\.md)\)/g)]… });
assertEq(missing.join(' / '), '', '目录内相对链接不许悬空');
```

而 W96 的报告正文里有两处在**讲这条判据本身**,写法是 `` `](./〈文件名〉.md)` ``(6.1 节表格里一处、6.2 节后面正文一处)。
那是示意占位,不是真链接;但反向那半按 `[A-Za-z0-9._-]+\.md` 扫全目录,认得出这个形状、认不出这是在举例。

**在 W96 自己的分支上这两处永远看不见**:它那条正向 assert 一直红着,反向那半从来没跑到过
(所以 W96 自测 451/453 是"红 2 条"而不是"红 3 条")。**补上索引行让正向那条转绿的同一刻,反向那半第一次可达。**

解法上有两个方向,取哪个不是风格问题:

- 放宽断言的正则(让它跳过示意写法)—— **不取**。那条断言是这个洞唯一的守卫,
  为了让一份文档的举例通过而给判据开口子,等于用掉守卫去换措辞。
- 改文档那两处的占位形状 —— **取这个**。判据字符集是 ASCII,占位改成 `](./〈文件名〉.md)`
  之后读者读到的意思一字不变(仍是"任何 `](./…md)` 形式的相对链接"),而它不再是一个可解析的链接。

改完 **463/463**。断言一个字未动,重跑变异确认它仍会咬:真的悬空链接照样红。

**同一个坑本槽自己又踩了一次,如实记下:** 本文第 4.1 节(即这一段)与它那行目录索引
在写"讲判据用的示意写法"时,照原样把 `](./x.md)` 又抄了三处进来,提交前一跑当场红 1 条、
点名 `README.md → x.md` 与 `w104-integration-log.md → x.md` 两处。
**即"知道这个判据长什么样"并不足以避开它——只要在文档里复述判据的形状,就会命中判据本身。**
按同一手法改成非 ASCII 占位后 465/465。这条断言的这一面因此在本槽被实测了三次(一次接住 W96、一次接住本文)。
