## 一、这一格具体错在哪

`order` 是落库字段,不是"这一镜此刻排在第几行"。分镜工作区偏偏是**最容易让它漂**的那一面:
右栏「插入一镜」只给新镜排号、拖动换序与删除各有自己的重排点,而弹窗是从缩略图上点开的,
于是同一镜在同一屏上报两个号:

| 面 | 本槽前报的号 | 同一屏上别处报的号 |
|---|---|---|
| 缩略图 / 时间轴概要格 | 镜头 3(早就按实位出) | — |
| 点这一镜开的「更多工具」页头 | 更多工具(镜头 1)(该行 `order` 自称 0) | 同一镜 |
| 「分镜提示词」/「历史提示词」/「按指令改」页头 | 镜头 1 | 同一镜 |
| 「引用资产」/「存为主体形态」/「存入资产库」页头 | 镜头1 | 同一镜 |
| 「历史版本」/「首帧海选」页头 | 镜头 1 | 同一镜 |
| 批量生成结果的失败清单行 | 镜头 10、镜头 1 | 该批第 2、3 镜 |
| 批量出片前的待确认清单行 | 镜头 6、10、1 | 第 1、2、3 镜 |

待确认清单行还多一层:它有**两份**(镜头确认闸一份、出片前置检查一份),只收一处就会出现
"同一批未确认镜在两块面上报不同的号"——比两块都报错更难查,故两份同轮改完。
