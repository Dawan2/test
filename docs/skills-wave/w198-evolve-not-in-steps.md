> 基线 `cursor/w193-integration-f315@d55cd7d`;本槽分支 `cursor/w198-evolve-not-in-steps-fb5a`。
> 产品面只动两个文件(`js/cmd-registry.js` +5 −2、`js/skills.js` +14),`gaps()` 一个键没摘、G-11 标记与文案一个字没动。

## 1. 结果一句话

**停工位成立**:`expert.evolve` 塞进 SK-25(审片修订闭环)或 SK-30(一键成片投影)的 `steps`,
基线 `unit` **586/586 全绿**——而这两本 playbook 与 SK-26 那本走的是同一个出口
(`Skills.playbooks()` → `mcp.js` 的 `hujing_playbook`),调用方照着步序一步步跑,
蒸馏就在主线跑完的路上自动发生,而它改写 `persona` 没有撤回口。

判据由此换类别:不再靠"某一条链逐字应该是那几步"顺带拦,而是把「这条命令是人手动作」
做成注册表事实(`js/cmd-registry.js` 的 `manual: true`),由 `Skills.validate` **逐条目递归扫 `steps`**。
**不实现自动蒸馏,不动 G-11**:`expert.evolve` 照旧在 SK-26 的 `cmds` 里、四端出口照旧、
`gaps()` 仍 20 键、SK-26 的 `note` 与 `gaps` 逐字未改。

   那句期望值就得同轮改,拦阻跟着让开。换句话说,那两本今天挡住这一手是**顺带**的,不是有人在守。
3. **B3 今天不会真跑起来**。`mcp.js` 的 `playbookView` 逐步只取 `{cmd, args, note}`、
   `js/flow-tpl.js` 与 `js/plans.js` 只读 `.cmd`,嵌套那一层谁也不读。
   本槽仍把它一并封住,理由是**成本是一行递归**,而"今天没人读"与"改不出自动蒸馏"不是同一句话——
   如实登记为**预防性**判据,不冒充成"堵住了一条真在跑的路"。

## 3. 落地

### 3.1 `js/cmd-registry.js`:`manual: true` 是这条口径的单一来源

`expert.evolve` 那条元数据加一位 `manual: true`,注释从「不进 SK-26 的 playbook 步序」
改成「不进任何 playbook 步序」并写明判据落点。**只加字段不改行为**:
`names()`/`usageOf()`/`byName` 与四端读法一字未动,`META` 仍 13 条。

字段而不是判据里写死命令名,理由是这件事本来就该由命令自己声明:
今天只有 `expert.evolve` 一条项目外的人手命令,明天再有第二条(比如任何"不可撤回地改写用户资产"的动作),
在注册表上标一位就自动受同一道判据管,不必回头改测试里的名字表。

### 3.2 `js/skills.js`:`validate()` 逐条目递归扫

判据落在 `validate(deps)` 里而不是单独一个导出——那里已经是"引用键自检"的归口
(命令名存在性、步骤参数在不在 `cmd.args` 都在同一段),契约测试与启动期自检同吃一份。

三个刻意选择:

- **逐条目扫,不只扫编排型**。非编排条目今天的 `steps` 投影不出来,可 `kinds`/`pending` 改一个字就投影得出来;
  只扫 `live(s, 'orchestrate')` 等于把"先写进去、下一槽再打开"留成一条路。
- **递归**,见 §2 的 B3。
- **`d.CmdRegistry` 缺位时跳过**。`js/skills.js` 的工厂签名是 `(KB, Domain, wfCore)`,本来就不认识命令注册表
  (加载期依赖只有 `KB` 与 `Domain` 两件双端纯模块,契约里有源级断言盯着,本槽一行没碰);
  故这一层与既有的"命令名存在性"同条件——注册表没传进来就答不了这道题。
  真正兜住它的是契约那条用例:它显式传 `CmdRegistry`,且自己就地做一次变异复核(§4)。

报文里带步骤路径(`步骤 2.1`)——嵌套那一层红了要看得出来红在哪一层。

## 4. 加测一条(`contract`,零新夹具)

`人手命令不许进任一条目的 steps:manual 单源 + 逐条目递归扫(SK-26 之外的 playbook 同样封死)`,
四段各钉一件事:

1. **`manual` 清单本身进对账**:`CmdRegistry.META.filter(m => m.manual)` 逐字应是 `expert.evolve`
   ——多一条少一条都要同轮交代产品口径,不许靠"把这一位摘掉"让判据静静变成空扫。
2. **禁令封的是编排面,不是命令本身**:仍须有条目把 `expert.evolve` 登记在 `cmds` 上
   ——**删掉这条人手出口不是满足禁令的办法**(那会把 W143 补出来的四端出口一起摘掉)。
3. **实况全扫**:`Skills.list()` 逐条目 + `Skills.playbooks()` 逐本投影,递归,一条人手命令都不许出现;
   `Skills.validate({ CmdRegistry })` 同时应无话可说。
4. **判据自己在用例里被变异五次**:SK-25 直插 / SK-30 直插 / 字符串拼接 / 嵌一层 `steps` /
   写在非编排条目(`core.memoryDual`)上,五种各要求 `validate` 当场点名该条目,`finally` 里逐个还原,
   末尾再核一次注册表干净。这一段是防"判据日后静静退化成恒真句"的那一层——
   §2 的读数是一次性的手工现跑,而这五条是每轮都跑的。

**冒烟一条没加**:这一格全在注册表与投影上,不下发命令、不碰服务端,`tests/cli.smoke.js` 一个字节没改
(分母仍 108)。`tests/integration.js` 同理未动。

## 7. 残留

1. **`expert.evolve` 仍是唯一一条 `manual`**,故这道判据今天只管一条命令。
   "还有哪些动作该标 `manual`"没有清单也没有判据——第 1 段对账钉的是"这一条别丢",
   不是"该标的都标了"(那需要先有产品口径说清什么叫不可撤回)。
2. **嵌套 `steps` 那一层是预防性的**(§2 第 3 点):今天没有消费方会执行它,
   故 M4/M7 证明的是判据接得住,不是证明堵住了一条真在跑的路。
3. **`js/plans.js` 的 `generate`(1 积分按用户目标 LLM 拆步)不受本判据管**:
   它拆的是用户自己那个目标、只受命令注册表钳制(`cmd` 必须已注册),
   故 LLM 可以拆出一步 `expert.evolve` 而 `Plans.runAll` 会执行它。
   这**不是本槽的射程**(它不是 playbook `steps`,且那条路上是用户自己提的目标),
   但"人手命令能不能进 LLM 拆出来的计划步"是同一族的产品口径题,如实登记在这里。
4. **G-11 原样开着**:自动蒸馏没有出口,蒸馏仍要人点「🧠 进化」或显式发一条 `expert.evolve`。
   本槽只把"不许自动"这条口径从一条判据(SK-26)扩成一道注册表级的闸,**没有往前也没有往后走一步**。
