> **一条产品缺口槽:改的是 `cli.js` 一处落库口 + `tests/unit.js` +1 条 + `tests/integration.js` +3 条。**

## 二、收的是哪一格

W317 §七 3(W318 §七 原话带下)那条:

> 上传回 200 却不带 `url` 时会把用户原有的图抹掉。`{code:0,data:{}}` 与 `{code:0,data:{url:''}}`
> 都会落库并把原图顶掉;`{code:0}` 抛 exit 为 undefined 的 TypeError。本仓 `server.js` 成功分支
> 只有 `ok(res,{url})`、失败全是非 2xx,本仓服务端产不出,但客户端仍应把「无 url」当失败、
> 不许用空串覆盖原图。

## 三、先普查:谁读 `upload` 回执的 `url`

全树点名(`POST '/api/upload'` 与 `uploadFile` 两个取数口现取共 6 处),按**读到的 url 会不会落库**分档:

| # | 位置(现取) | 读到的 url 去哪 | 本槽收不收 |
|---|---|---|---|
| 1 | `cli.js` `subject-image --file`(`sj.image = …`) | **写回库**(顶掉主体现有的图) | **收** |
| 2 | `cli.js` `CMD.upload`(`upload <本地文件>` 命令) | 原样回给调用方,不进库 | 不收 |
| 3 | `cli.js` `gen-image --image`(`extra.image`) | 当参考图下发上游,不进库 | 不收 |
| 4 | `cli.js` `gen-video --image`(`extra.image`) | 同上 | 不收 |
| 5 | `cli.js` `composeItems`(占位/截帧 dataURL 先传服务端) | 进 compose 入参(`if (!img) continue;`),不进库 | 不收 |
| 6 | `js/utils.js` `U.uploadData` / `U.readAndUpload`(浏览器端) | `readAndUpload` 现取回的是 `url || f.data` | 不收(见下) |

**只收第 1 处**:明令是「只收同形写回,不要一把梭改所有 upload」。另五处现取各自的实况:

- 2/3/4/5 都不落库,拿不到 url 时的后果各不相同(回执如实带回 `undefined`、少一张参考图、
  compose 少一段),**要不要一起收得先定各自的口径**,不在本槽范围内(记进 §七)。
- 6 是浏览器那一端,现取**已经不会用空串覆盖**:`U.uploadData` 回 `null`/空,
  `U.readAndUpload` 那一句 `url || f.data` 当场回退到本地 base64,调用方写回的是 dataURL 而不是空串。
  故那一端本槽一个字不动。

## 四、先量现网:四档收场逐格现取

同一副夹具(桩下到 `fetch` 那一层、`withProject`/`uploadFile`/`findSubject` 全走产品自己那一份)
喂起点 `13c54a7` 与本槽两棵树,读回执 / 库里那位的 `image` / `PUT` 发了几次:

| 上传端点回什么 | 起点 `13c54a7` 现取 | 本槽 |
|---|---|---|
| `{code:0,data:{url:'/uploads/img/new.png'}}` | 回执 `"/uploads/img/new.png"`,库里同,`PUT` 1 次 | **一字不变**(同前) |
| `{code:0,data:{}}` | 回执 `undefined`,**库里 `image` 这个键整个不在了**(原图丢),`PUT` **1 次** | 抛 `CliError` `exit=5`,库里仍是 `/uploads/img/old.png`,`PUT` **0 次** |
| `{code:0,data:{url:''}}` | 回执 `""`,**库里 `image` 成了空串**(原图丢),`PUT` **1 次** | 同上 |
| `{code:0}`(连 `data` 都没有) | 抛 `TypeError: Cannot read properties of undefined (reading 'url')`,**`exit=undefined`**,库未动 | 同上(错话与码都成形) |
| `{code:0,data:{url:'   '}}` | 回执 `"   "`,**库里 `image` 成了三个空格**(原图丢,渲染是一张裂图) | 同上 |

即缺口是三层叠着的:①空串/缺字段落库把原图顶掉;②那一趟报的是**成功**(回执里 `image` 是空的);
③`{code:0}` 那一档抛的是 `TypeError`、`exit` 为 `undefined`,调用方按码分流时落进"未知失败"。

`server.js` 那个端点现取复核:成功分支只有一句 `return ok(res, { url: … })`,
其余出口(缺文件数据 / 超单文件上限 / 超配额 / 类型不在白名单 / 上传锁冲突)**全是非 2xx 的 `fail(...)`**
——**本仓服务端一档都产不出来**。故这道闸是**纯防御**:挡的是中间层、别的实现,或往后改端点时踩上。

## 五、改的那一处(`cli.js`)

在 `uploadFile` 旁边新增一个**只给落库那一路用**的取 url 口,`subject-image --file` 换成走它:

```js
async function uploadFileUrl(file, flags) {
  const up = await uploadFile(file, flags);
  const url = up && typeof up.url === 'string' ? up.url.trim() : '';
  if (!url) throw new CliError('上传未回文件地址(服务端回执无 url):' + path.basename(path.resolve(file)), 5);
  return url;
}
```

三件事各有取舍,逐条记下:

1. **闸装在新口子上、不装进 `uploadFile`。** 装进 `uploadFile` 就是一把梭改了 §三 那 2–5 处
   (`upload` 命令从此不能如实回执、compose 那一路的收场也跟着变),而它们各自的口径未定。
   变异台 M5 现跑正是这一手:**两棵树都全绿**——那三处一条判据都没有,一把梭改了也没人吭声。
2. **`exit` 归 5**(与上传端点 5xx 同族):回执不成形错在服务端那一侧,不是用户参数写错(2),
   也不是"点名的东西不在"(4)。变异 M4 把它改成 2 当场红。
3. **`trim()` 收空白**:`'   '` 落库看着像有图、渲染时是一张裂图,与空串同档处置。

`sj.image` 那一行仍是**赋值写在 `await` 右侧**(W317 §三 量过的那副形状):`uploadFileUrl` 一抛错
整条 `fn` 就断在那儿,`withProject` 的 `deepDiff` 与 `PUT` 一步都没跑到,故不必另加回滚。

**计费面零 diff**:`/api/upload` 现取不在计费白名单里(`billing.js` 整份不含 `upload`),
这条命令也不走 `Tasks.run`,**没有已扣的钱要退**;真发起上游之后失败的退费仍由服务端那套五件套管着,本槽一处未动。

## 十、这一槽可复用的一件事

**「客户端要不要信上游的回执」这件事,判据得两侧各站一条,而闸只装在会落库的那一口上。**

本槽的缺口在客户端(拿空串顶掉原图),但**本仓服务端产不出**那种回执——
只在客户端加闸,读的人下一句必然是"那这闸有用吗";只在服务端钉契约,
换个中间层进来照旧抹图。两侧各站一条之后,这道闸的定位才说得清:**服务端契约那三条说明反常不该发生,
客户端那一条说明反常发生了也不许把用户的东西弄丢。**

而"装在哪一口"是同一件事的另一半:同一个回执被五处读,只有一处会落库。
一把梭装进 `uploadFile` 时**两棵树全绿**(M5)——正因为另外四处一条判据都没有,
一把梭改过去没人吭声,而它们各自的收场口径至今未定。
**一处根因、五处消费、只有一处有明确口径时,闸就该装在那一处,余下的记进残留而不是顺手一起改。**
