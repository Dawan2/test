## 2. 条目正文:为什么这么写

`KB.WR_AIVOICE` / 取用键「文案AI味」。正文自撰,六条,分两半:

| 条 | 内容 | 性质 |
|---|---|---|
| ① | 套话硬禁词 19 个,一律不写;情绪落到具体动作、具体物件、具体反应上 | **可逐字命中**(校验层 `ai-cliche`) |
| ② | 台词禁书面连接词 12 个;这些词写在叙述里正常,从人物嘴里说出来就是没落地的书面腔 | **可逐字命中**(校验层 `spoken-formal`,只判台词载体) |
| ③ | 修饰副词 11 个单个都正常,通篇每千字超过 10 处即堆砌 | **可按密度命中**(校验层 `adverb-flood`) |
| ④ | 句式忌整齐:不连排比、不每句同一节奏,长短句交错 | 只能人读,词法判不了 |
| ⑤ | 一句话只能是这个人物说得出口的话 | 同上(语义面,归 G-10) |
| ⑥ | 改稿先删后改:AI 味多半是形容词与解释性从句撑出来的 | 同上 |

写法上的两条自我约束:

- **前三条必须是可判定字面**。条目要同时供两个消费方使用:提示词要的是"可读纪律",校验层要的是"可判定字面"。把硬清单排在前三条并用 `「词/词/词」` 的固定形态写,两个要求在同一段正文里同时满足——这也是本轮敢让校验层去读条目正文的前提(W24 §7 曾按"两者措辞不必相同"的假设把这条留给后续,实际写下来发现前三条完全可以合一,合一后才真的只有一份)。
- **后三条不假装可判定**。句式、人物口吻、改稿纪律都写进条目(它们对提示词有用),但校验层**一个都不解析**——判定输入是语境不是词表,仍归 LLM 审片(G-10)。条目比校验项管得宽,是正常的;反过来才是冒充。

词表内容与 W24 完全一致,取舍口径(为什么不收 `仿佛`/`宛如`、为什么副词只按密度判、为什么词表内不留互为前缀的词)见 `w24-sk10-ai-voice.md` §2,本文不复述。

## 3. 校验层怎么取

```js
const AI_KB = String(KB.section('文案AI味') || '');
const aiWords = label => {
  const m = new RegExp(label + '[^「]*「([^」]+)」').exec(AI_KB);
  return m ? m[1].split('/').map(w => w.trim()).filter(Boolean) : [];
};
const AI_CLICHE   = aiWords('套话硬禁词');
const FORMAL_WORDS = aiWords('书面连接词');
const ADVERB_WORDS = aiWords('修饰副词');
const ADVERB_PER_K = +((AI_KB.match(/每千字超过(\d+)处/) || [])[1] || 0) || 10;
```

三处口径说明:

- **按标签定位,不按出现次序**。`[^「]*` 不跨 `「`,故标签与其后第一个列表必定成对;条目里插入新条、调整条序都不会让词表串位。
- **解析不出即回空数组**,不留兜底词表——留一份兜底词表就等于留了第二份硬编码,与本轮要做的事相反。解析失效时该码不产出命中(如实的"判不了"),并由契约断言先红(见 §5)。
- **密度上限保留 `|| 10` 的数字兜底**,与 SK-09 的 `DIALOGUE_MAX`(`|| 30`)同款:数字失配只会退回原阈值,不会把密度判据变成除零或恒真。
- `ADVERB_MIN`(判密度的最短正文 200 字)**不进条目**:它是"多短的段落不下断言"的实现下限,不是方法论纪律,写进条目反而是把实现细节塞进给人读的正文。

```js
剧本: ['反转五式', '人物体系', '剧本诊断', '文案AI味'],
```

选它的三条理由:

- **它是剧本步现成的装配口**。`boardKBBlock` 就位时按键整条注入本板块条目正文,与主体 / 分集 / 分镜三个板块同一套写法;不需要新造装配口,也不需要改任何提示词模板。

- **同一提示词内不重复注入**。剧本板块此前三条与本条无交集,`DIGESTS` 侧也没有同键摘要——本轮**没有**往 `DIGESTS.sys` 补摘要:`KB.block()` 是 ~500 字的全流程通识块,三域行已满,而 AI 味硬禁的价值在于那份可逐字对照的清单,压成一句话摘要既挤占上下文又丢掉清单本身。板块方法论块给的是完整口径,正是这条该走的通道。
