> 基线 `cursor/w72-integration-8d3f @ d2e7c43`(两条并行集成线收成一条之后的头部),落地分支 `cursor/w79-editors-prompt-153a`。

## 1. 收编的是哪一处

`Views.comic`(漫剧图片编辑器)的「AI 生成对白」按钮:给一段剧情简述,让模型吐 2-4 个画面气泡。收编前那条 `system` 是一整串写死的字面:

```js
// 基线 js/editors.js:人设句与解析契约写在同一个字符串里
const r = await API.chatJSON({
  system: '你是漫剧编剧。根据用户给的剧情简述,生成 2-4 个画面气泡,只返回 JSON 数组,格式:[{"type":"对白","text":"..."}],type 只能是 对白/旁白/内心,text 不超过 30 字。',
  messages: [{ role: 'user', content: '剧情:' + plot }],
  …
});
```

这处此前**没有任何断言**碰过:`tests/unit.js` 里一次都没有出现过 `editors`,`js/skills.js` 也没有条目引用它——所以它既不在注册表里(用户覆盖不到),也不在任何名单上(收编与否没人看得见)。第 5 节给它补的那张名单治的就是后一半。

## 2. 切在哪一刀:只收人设句,契约半留在装配口

沿用 W49 定下的口径——**能改坏的东西不该开成开关**。这一整串里只有开头七个字是措辞,其余是**解析契约**,判据就在紧邻的十几行里:

| 契约半的一句 | 谁在依赖它 |
|---|---|
| `只返回 JSON 数组,格式:[{"type":"对白","text":"..."}]` | `Array.isArray(r) ? r : (r.bubbles \|\| null)` 两种形状之外一律回退本地模板 |
| `type 只能是 对白/旁白/内心` | `TYPES.includes(o.type) ? o.type : '对白'` 归类,词表就是 `const TYPES` 那三项 |
| `生成 2-4 个画面气泡` | `arr.filter(o => o && o.text).slice(0, 4)` |

用户在「全局默认值 → 核心提示词 skill」把 `type` 词表改一个字,这一轮的气泡就会被整批归成「对白」;把 JSON 形状改掉则整轮解析不出气泡、静默落回本地模板文案。人设句不同:它只影响语气与角色定位,改了照样解析。所以这一刀切在「你是漫剧编剧。」与「根据用户给的剧情简述」之间,契约半原样留在 `js/editors.js`,只是从字符串里提成一个具名常量 `BUBBLE_CONTRACT`,好让断言现取它。

`text 不超过 30 字` 与代码里的 `String(o.text).slice(0, 60)` 并不等值(提示词说 30、钳位钳 60),这是收编前就有的既有落差,本槽**一字未动**——改它是行为变更,不是收编。故第 6 节的用例只钉住 type 词表两侧同集,不拿字数上限去对代码。

## 4. 键登在 SK-03 名下,但记账要写清它与那一条的差别

「`Prompts` 全部 key 必须被 skill 索引引用」是既有契约(漏登即红),而短名单锁死 30 条,所以新键只能挂在既有条目上。挂 SK-03 `core.personaCtx`——那是注册表全部人设键的索引宿主(此前 12 条全在它名下)。

但 SK-03 的题目是「生效人设经 ctx 过服务端」,而漫剧气泡这一步**不过那条 ctx 通道**:它不注入生效专家的方法论段、不召回协作记忆,只是人设句进了注册表而已。这个差别写进 `note` 的「仍欠」段,不含糊过去:

| 条目 | 改成什么 | 仍欠段新增 |
|---|---|---|
| SK-03 `core.personaCtx` | `prompts` 补 `comic.bubbleSystem`;已落地那半补记「漫剧编辑器 AI 生成对白步的人设句成键,装配口在 `js/editors.js` 就地拼(人设句 + 契约半),浏览器隐式读覆盖表、缺省逐字节不变」 | ①漫剧气泡那处与四处对话装配口**同口径**:返回 JSON 形状与 type 词表是解析判据,同样只收人设句不开放契约半;②该步**不过本条的 ctx 通道**(编辑器工具步不注入生效人设与协作记忆) |

`gaps` 一字未动:G-13 治的是全仓的内联人设面,收掉一处不等于闭合,按关联索引口径不摘标记——`Skills.gaps()['G-13']` 的键与值逐字节不变(既有用例逐字符钉着那六个 id)。SK-10/SK-11 那两条「仍欠」段点名的是剧本模块四处与 `js/persona.js` 那处,与本槽这处互不重叠,故两条一字未动。

## 5. 全仓持有者名单:让"收编了没有"这件事第一次看得见

W66 记过一句「G-13 治的是全仓 21 处内联人设」,但那只是散文里的一个数字——没有任何断言现取过它,所以增删一处内联人设,全仓照样全绿。本槽给它补上一张**普查表**,与本键的用例同住一条:

```js
// 判据:以「你是」开头的字符串字面,按文件逐个计数(仓库根 *.js + js/*.js)
const census = files.map(f => [f, (src.match(/['"`]你是/g) || []).length]).filter(x => x[1]);
assertEq(census.join(' '), 'js/agent-global.js:1 js/agent-ops.js:2 … js/prompts.js:14 … js/wf-core.js:1');
```

三类持有者**混在同一张表里如实计数**,不做名义上的排除:

- `js/prompts.js:14` —— 注册表 `def` 本身(单源;另一条断言钉住"这 14 处就是以「你是」开头的那些 `def`",注册表条数变了这张表也要跟着改);
- `js/experts-data.js:16` —— 预置专家人设库(另一份单源,`experts` 键已进索引);
- 其余 **31 处**(19 个文件里的 17 个)—— 注册表之外仍各写一份的,其中 `js/api.js` 两处是兜底缺省(`opt.system || '你是专业助手。'`)、`js/gsettings.js` 一处是输入框占位文案,剩下 28 处是模块级内联人设。前三样按字面判据都算命中,与其为它们写例外,不如**如实计进去并在注释里说明成分**——例外条款越多,名单越容易被绕过。

这 31 与 W66 散文里那句「全仓 21 处内联人设」**不是同一个口径**,故本槽不去改那句话、也不拿它当期望值:那是当时按模块人工盘点的数,本表是按字面机械普查的数(把兜底缺省、占位文案、`user` 半开头的人设句一并算了进来)。两者各自说得通,混用才会出错。

这张表的双向性是本槽真正想要的:新写一处内联人设 → 名单多一行(变异 7 实测);把别处收编了却不改名单 → 名单少一处(变异 9 实测)。`js/editors.js` 另有一条独立断言反向钉住它已不在名单上。

判据的边界也如实写在这里:它只认「以 `你是` 开头的字面」,不认 `const SYS = '你是…'` 之外的其它写法,也不认英文人设与「作为一名…」这类变体;`tests/` 目录本身不在普查范围内(用例里必然写得到人设字面)。它封的是"悄悄多一处/少一处没人知道",不是"任何形态的人设都跑不掉"。

## 8. 与并行分支的关系

- `js/prompts.js`:本槽在 `REG` 末位追加一条。若并行槽也加键,取**并集**;条目相对次序只影响「全局默认值」页展示顺序,无行为面。合入后**注册表条数与那张持有者名单里 `js/prompts.js` 那一行要一并重算**(两处各有一条断言先红)。
- `js/skills.js`:只动 SK-03 的 `prompts` 数组与 `note`。`prompts` 取并集;`note` 以**实况**为准折回——谁再收编一处,已落地那半与仍欠段要一起改,变异 6 会先红。
- `tests/unit.js`:新增一条独立用例,不改既有用例。那张持有者名单是**全仓**判据,任何并行槽新增或收编内联人设都会让它先红——这正是它的用途,合入时按实况重算即可,不要为了让它绿而放宽正则。
- `README.md` / `docs/skills-wave/README.md`:提示词条数按合入后 `Prompts.list().length` 实计、单测用例数按实跑重算。
