# W114 · 集成套件那一对同名用例:改一条名字 + 两个 report 套件的名唯一断言

> 槽位范围:只动 `tests/integration.js` 的**一条用例名**、`tests/unit.js` 的 `contract` 套件、`README.md` 里两处数字与措辞,以及本记账件加索引行与份数。
> **零产品代码改动**(`js/`、`server.js`、`cli.js`、`mcp.js` 一行未改),不动发布门口径、不新增计费动作、**不删任何用例**。
> 基线 `cursor/w112-integration-5d79` head `9b7d13b`(**不合 W113**)。

## 1. 病灶:130 条用例只有 129 个名字,而取证工具按名成集

`tests/integration.js` 里有一对逐字同名的用例名 `项目不存在 404`:

| 位置 | 所属段 | 判据 |
|---|---|---|
| 第 510 行 | 测试 22(G-04)剧本拆集 `/api/wf/split-episodes` | `sp7.status === 404`(`pid: 'ghost_pid'`) |
| 第 643 行 | 测试 24(G-12)发布留痕 `/api/wf/release` | `rl5.status === 404`(`pid: 'ghost_rel'`) |

两条各自钉的是不同端点的同一类行为,**都该留着**;撞的只是名字。

它的害处不在这条名字上,在**取证方法**上。本目录从 W21 起用「用例名成集双向比对证明没删测」当收敛槽的零吃测手段,而集合口径会把一对重名里的一条吃掉——**删掉一条真用例、同时有一对重名,两者互相抵消就看不出来**(`w96-cycle7-audit.md` 在 `unit` 上第一次点名这个盲区,`w85 → w90` 实测报"新增 9 条"而真实增量 10 条)。

这处集成侧的重名此后连着被两条集成线撞到,而且是**同一盲区的另一面**:

- `w109-integration-log.md`:零吃测脚本期望侧去重、live 侧不去重,`integration` 当场**凭空多报**一条 `项目不存在 404`;
- `w112-integration-log.md`:照 W109 记的判据主动复现了一次,同样成功——盲区从一次性观察变成两次可复现的实测。

两份记录都把它如实登记下来,但**都只治了比对脚本的口径,没治重名本身**:仓里那一对还在,下一个收敛槽照旧要在这里绊一次。W102 在 `unit` 侧治过完全同形的一对(`w84`/`w87` 那两条持有者名单断言),集成侧一直空着。

## 2. 落地 A:只改一条名字

**只改用例名,判据一个字未动,两条用例都留着。**

| | 改前 | 改后 |
|---|---|---|
| 名 | `项目不存在 404` | `wf/release 项目不存在 404` |
| 判据 | `rl5.status === 404` | **逐字不变** |

改的是**发布留痕**那一条(第 643 行),拆集那条(第 510 行)名字与判据都不动。

选这一侧、并且用端点前缀,是因为**同一份文件里本来就有这个形状的先例**:第 439 行的 `wf/extract-subjects 项目不存在 404` 就是按端点前缀写的。名字要能回答"两条同判据的断言各自钉的是哪一处",端点名正是这两条唯一的差别;换成"其二""(发布)"之类的编号或补语,下一个人读到还得回源码里认。改一条而不是两条,是因为拆集那条与它相邻的 `缺剧本原文 400` 等几条都是不带前缀的短名、成段一致,动它要连着改一段;而单改一条就足以把名集恢复成一一对应。

## 3. 落地 B:两个 report 套件的用例名各自唯一

在 `contract` 套件里新增一条,接在既有那条「集成测试与 CLI 冒烟用例数由各自套件源码实计」之后,**既有八条一条不删**。与 W102 那条 `unit` 唯一性同形:上一条钉的是"条数",这一条钉的是"不同名字数",**两个数分开钉才拦得住重名**。

判据三层,按套件逐个跑:

1. **每行的名字都取得到**——行首 `report(` 的行数,必须等于"行首 `report(` 后紧跟单引号字面"的条数。名字若是拼出来的(模板串、变量、`'a' + b`),静态取不到,后两条的名集口径当场失真,故这一层先钉。
2. **不许重名**——报错点名撞的是哪几条,不是只给一个数字。
3. **名集大小恰等于 `report(...)` 登记行数**——即"多重集与集合同大小",与上一条互为正反两向。

覆盖 `tests/integration.js` 与 `tests/cli.smoke.js` 两个套件:这两个是同一形状(每条用例独立一行 `report(...)`,末尾总数由套件自己的计数器算出,该形态本身由上一条用例钉住),而零吃测的名集比对三个套件都要用,`cli.smoke` 在基线上是 102 条 102 名、接进来当轮就是绿的,不接等于把同一个盲区留半边。`tests/e2e.js` **不在内**,理由与 W102 把它排除在数字对账外的一样:它有一处按 tab 列表循环的 `report`,行首点数根本不代表实跑条数,接进来第 1 层当场红;按目录纪律 `e2e.js` 也只在明确要求时才跑,本槽没跑。

**这条断言只拦重名,不许拿它当删测的理由**:它与「用例名成集双向比对」是配套的两件——前者保证后者的口径不被吃掉;谁把一条用例改名去躲问题,后者那一向照旧报"这个名字消失了"。

## 4. 变异验证(四条,逐条实测)

| 变异 | 结果 |
|---|---|
| 1. 把 2 节改过的名字改回 `项目不存在 404`(制造重名) | 红:`集成测试:用例名不许重名…:期望 "",实际 "项目不存在 404"` |
| 2. 把该条名字写成模板串 `` `wf/release 项目不存在 404` `` | 红:`集成测试:…用例名须是就地写死的单引号字面:期望 130,实际 129` |
| 3. 在 `cli.smoke.js` 里把 `未知命令 → exit 2` 改成与前一条同名 | 红:`CLI 冒烟:用例名不许重名…:实际 "缺参数 → exit 2"` |
| 4. 整行删掉那条 `report(...)` | 红:`集成测试用例数:README.md 与实测不符(实测 129,文档 130)` |

变异 4 如实记一笔:**红的是 W102 那条数字对账,不是本槽这条**——删一条后剩下 129 行 129 名,名集口径本来就自洽。这正是两条的分工:数字那条管"少没少",本条管"名集口径还代不代表条数"。本槽这条断言在基线上是红的(130 行 129 名),改完名字才转绿,这也是它自己的落地取证。
