## 一、这一槽的形状:快进形,而"diff 空集"一个字都不作证

现取(全部以 `rev-parse` 为准,不抄任何一侧的自称):

| 位 | SHA | 说明 |
| --- | --- | --- |
| P1(我方尖) | `353dce0b601f59b93a3085b2e771bd4f66786633` | `origin/cursor/w294-integration-9c41` |
| P2(对侧) | `6d42fd3d08b22cf45c6de7ab8a9af752eff2989e` | `origin/cursor/w295-projdupbadge-4720` |
| merge-base | `353dce0b601f59b93a3085b2e771bd4f66786633` | **恰等于 P1** |
| merge commit | `c5889c97c2bd03bcbddf2ee3d17db810215a630a` | 本槽支尖 `cursor/w296-integration-07c6` |

W295 自称"从 w294 尖 `353dce0` 起支、HEAD `6d42fd3`",两个数**现取都对得上**;
`merge-base --is-ancestor P1 P2` 成立,故这是一条**快进形**槽。仍按纪律走 `--no-ff`,留住并入点。

快进形的代价写在这里:`git diff M P2` **空集**、`tree(M) == tree(P2)`(两侧同为
`58425480caf851a79f3d7cfbfa31ca114c76d6f9`)——这两格**都不承载结论**。它们在"对侧的东西一件没丢"
与"对侧的东西压根没进来过"两种世界里长得一模一样,任何一条 `--ours`/`checkout <old> -- .` 的误合
在这两格上照样全绿。本槽的结论**全部压在变异台与 live 探针上**,两格空 diff 只当形状记录。

反过来,快进形自带一格别的槽没有的**正面证据**:本槽新写的 11 手变异,锚点逐条拿到 P1 上试,
**11 手全部失配**(P1 上取不到那些串)。锚点失配本身就是"这段代码在 P1 上不存在、是随 P2 进来的"
的直接证据——比 diff 空集硬,因为它咬的是**新代码在合并后确实在场**这一面。

## 八、这一槽可复用的两件事

1. **快进形槽的取证怎么摆。** `diff` 空集与 `tree` 相等两格一律**只当形状记录、不承载结论**;
   把结论压到变异台 + live 上,再把"**新变异的锚点在 P1 上全部失配**"这一格当**正面**证据用
   ——它咬的是"新代码合并后确实在场",而空 diff 咬不动这一面。
2. **给"三层账"设变异前先读它声明的守法方向。** 花名册 / 在册 / 销号台账那道护栏明写
   「在册多出花名册没有的号一条不红」,朝那一向打出来的绿是**设计内**的,不是漏网(M11 → M11b)。
   把瞄错方向那一手连同改正后那一手一起登记,比悄悄换掉它更有用。
