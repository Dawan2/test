### 4.2 报告正文那处 ASCII 占位链接:改形状,不放宽正则

`w113-cycle8-audit.md` 第 3.1 节在转述「W104 顺手修掉了 W96 报告里两处讲判据用的示意写法」时,
把当年那个 ASCII 占位**原样抄了进来**,包在一对反引号里。
补上索引行让第一条 assert 转绿的同一刻,同一个用例里排在它之后的反向那半第一次可达,当场红第四条:

```
FAIL | …索引完备性:每份 wNN-*.md 各有自己的索引行,散文点到的记账件不许悬空
     | 目录内相对链接不许悬空:期望 "",实际 "w113-cycle8-audit.md → x.md(文件不存在)"
```

两条路,与 W104 当年面对的是同一道选择题:

- 放宽断言的正则(让它跳过示意写法)—— **不取**。那条断言是这个洞唯一的守卫,
  为了让一份文档的举例通过而给判据开口子,等于用掉守卫去换措辞。**任务口径也明写不放宽。**
- 改文档那一处的占位形状 —— **取这个**。判据字符集是 ASCII,占位改成非 ASCII 的 `](./〈文件名〉.md)`
  之后读者读到的意思一字不变(仍是"任何这种形式的相对链接"),而它不再是一个可解析的链接。

改完 `contract` **99/99**。**断言一个字未动**,并做了正反两向变异复核:

```
$ perl -0pi -e 's/〈文件名〉/x/' docs/skills-wave/w113-cycle8-audit.md
$ node tests/unit.js contract
FAIL | …目录内相对链接不许悬空:… 实际 "w113-cycle8-audit.md → x.md(文件不存在)"
===== 98/99 PASS, 1 FAIL =====        ← 判据仍会咬,不是靠放宽换来的绿
$ (还原) node tests/unit.js contract   → 99/99
```

**这一处值得单独记一笔的理由,不是"又踩了一次 W104 的坑",而是它踩坑的方式。**
W104 结尾给的口径是「在本目录里描述这条判据时,占位一律用非 ASCII 文件名」。
`w113` 读过这条(它在同一段里点名了 W104 的那个提交),并据此声明
「**本文件因此全程用反引号写文件名,不写任何指向本目录的相对链接**——补上索引行后不会再冒出第四条红」。
**这句声明当时是假的,而它假在一个很具体的地方:它把"用反引号包起来"当成了等价的防护。**
判据跑在文件的纯文本上,反引号只是两个普通字符、不参与匹配,包与不包对正则毫无差别。
所以:**W104 那条口径要照字面执行——非 ASCII 的是"文件名本身",不是"周围的排版"**。
这条断言的这一面至此被实测了第四次(一次接住 W96、两次接住 W104 自己、这次接住一份**专门声明自己避开了它**的文档)。

那句结尾声明本槽**不改**:按 W38 的存档口径,记账件正文里的自述不随并入回改;
而改完占位之后,它那句预言的结论(「补上索引行后不会再冒出第四条红」)现在**反倒成立了**——
99/99 里没有第四条红。
