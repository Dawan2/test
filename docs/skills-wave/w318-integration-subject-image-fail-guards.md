### 4.1 M2:明令点名要核的那一格

明令写的是「吞 `withProject` 抛错应变红」,现取逐字相符:把

```js

换成 `try { … } catch (_e) { ret = undefined; }`(吞掉 `fn` 的抛错后照旧走 `deepDiff` 与 `PUT`),
**P1 上 722/722 一手都不红,M 上当场红 2**,两句各打在一条新用例上:

```

### 4.3 M-DEL 与 M-REV 连读:快进形合入的固有形状

**M-DEL**(只删两条新用例、两处棘轮 724 与两处文档数字 724 留在原地)当场**红 2**,两句各有分工:

```
contract · README 数字对账 …… 单元测试用例数:README.md 与实测不符(实测 722,文档 724)
contract · 三套件用例数只增不减 …… 单元测试用例数不得少于 724(实测 722)
```

**M-REV**(测 + `README.md` + 索引 + 记账件整槽一起退回)**722/722 全绿**,
同一刻 `git diff 1f039f7`(工作树与暂存两侧)**都是空集**——退回去的那棵树与 P1 逐字节相同。

**"删一半会响、删干净不响"就是快进形合入的固有形状**:棘轮守的是「别只删测不改数」,
守不住「整槽一起消失」。这也正是 §三 那三层非取不可的理由——它们判的**是那棵树,不是那次运行**。

### 4.4 M-IDX:索引行是并集里独立的一层

只摘掉索引表里 `w317` 那一行(文件仍在目录里)**红 4**,其中一句直接说出合入的失手形态:

```
记账件 w317-subject-image-fail-guards.md 在目录里但索引表没有它那一行(合入时漏登记,或只合到了漏掉索引行的那一版)
```

## 八、这一槽可复用的一件事

**变异台读的是"两棵树的红绿之差",而"P1 上全绿"这一半往往比"M 上变红"那一半更能说明问题。**
本槽 M4 是最干净的例子:把错话从 `'主体不存在:' + sid` 改成不点名的 `'主体不存在'`,
M 上红 1、**P1 上 722/722 全绿**。P1 并不是没有读过这句错话——它有好几条用例点着 `主体不存在`,
但读法是宽判(`/主体不存在/`),错话不点名它一样过。
**"这句话已经有人读了"和"这句话被钉住了"是两件事**,而这两件事的差,
只有把同一手改法在两棵树上各跑一遍才读得出来。单跑 M 那一列会把 M4 记成"新条守住了错话",
单跑 P1 那一列会把它记成"本来就没人管"——两句都不是真相,真相是那一格从宽判收成了逐字。
