## 2. 校验项判据

`CHECKS['subjects.crossShotConsistency'](obj, ctx)`,`obj` 收领域对象包 `{p, ep}`;返回 `{pass, level, hits}`,`Skills.check` 再包一层 `{id, skill, …}`。

先按镜把每个**解析得到的**引用摊平成记录 `{shotId, order, name(镜里写的原名), full(全称), image(该主体在本镜的取图), fed(本镜真正进了参考图组的那张)}`,再按主体 id 分组比对。

| 命中码 | 判据 | 级别 | 为什么是问题 |
|---|---|---|---|
| `ref-image-drift` | 该镜 `fed` 与基准镜不是同一张(权威图与形态图混用、形态之间切换) | `warn` | 同一角色在镜间换了参考,形象会漂 |
| `ref-lock-gap` | 别的镜锁得住,这镜 `fed` 为空;`reason=no-image` 该形态取不到真实图,`reason=over-cap` 有图却被参考图组上限挤出 | `warn` | 这几镜的该主体不进参考图组,模型自由发挥 |
| `alias-drift` | 同一主体**同一形态**跨镜被不同名字引用(改名后旧名残留、提取别名混用) | `warn` | 主体称呼在分镜表里不统一,后续改名/回填与人工核对都会漏 |

- **基准**取该主体跨镜出现最多的那张图/那个名字(并列取先出现者),`hits` 只标偏离基准的那几镜,`alias-drift` 另带 `base` 字段给出基准名供回填。
- **只在一镜出场的主体不判**:一致性是跨镜概念,单镜没有可比对象;镜级入口(`{p, s}`)与只有一镜的分集同理回 `info` + 空命中,**不拿"通过"冒充"没判"**。
- **形态不同不按名字漂移判**:多形态本就是换装设计,`alias-drift` 只在同一形态内部比原名;形态切换的后果由 `ref-image-drift` 从"喂到的图"这一层看得见,不在名字层重复扣帽子。
- **级别全 `warn`**:一致性是风险不是硬错(形态切换可能是有意的),`fail` 留给"必然拿不到参考"的完备性面。`pass = 命中为空`。
- 纯本地零 LLM 零计费、纯函数:同输入同结论,不改动传入的领域对象(单测逐条断言)。判据依据的方法论条目是 `KB.GC_MULTI` / `KB.GC_REFS`(条目 `kb` 面),正文不进本层。

### 与 SK-12 的分工(为什么不是同一条)

| 场景 | SK-12 完备性 | SK-13 一致性 |
|---|---|---|
| 镜里写了主体库没有的名字 | `unknown-subject` fail | 不报(解析不到就没有跨镜可比) |
| 主体全程无真实图 | 每镜 `no-ref-image` warn | 不报(没有"别的镜锁得住"的对照) |
| 权威图缺、只有某形态有图 | 裸名那镜 `no-ref-image` warn | 裸名那镜 `ref-lock-gap:no-image` warn(点明别的镜锁得住) |
| 一镜引用了 6 个有图主体 | 全部通过(主体都有图) | 第 6 个 `ref-lock-gap:over-cap`——**只有一致性面看得见的静默丢参考** |
| 改名后部分镜仍写旧名 | 全部通过(曾用名兜底解析得到) | 旧名那几镜 `alias-drift` |

## 3. 单源与消费点

**判定输入现取真实生成口径**:`Domain.shotRefImages(p, s).refImages` 就是生成请求里那组参考图(去重、按 `characters → scene → props` 顺序、`slice(0, 5)`)。校验项据此判"这镜到底锁没锁住这个主体",因此**参考图组上限造成的静默丢参考**第一次有了出口——这一类既不是缺图也不是错名,靠单镜视角看不出来。

**就绪检查:两端零改动**。`episode.preflight` 调的是 `Skills.check('subjects', {p, ep})`,按 stage 分发,SK-13 落地即自动多一条结论:

```
episode.preflight → { ok, status, result: { …Domain.episodeState, checks: [ 完备性结论, 一致性结论 ] } }
```

**问题中心:新增一条低危**。`js/issues.js` 在既有逐集循环末尾读同一份校验项结论,聚合为 `{kind:'subject-inconsistent', sev:'low', …}`,明细定位到镜号与主体名,处置走导航自查(不挂命令、不触发生成)。展示文案(命中码→中文)落在 issues 层,判据不写第二份。

选低危不是保守:发布门 G2 只数高/中危(`js/release.js` 原样不动),**低危不改任何存量项目的门禁状态**,这条提醒才能在浏览器里可见而不越过"只报不拦"。
