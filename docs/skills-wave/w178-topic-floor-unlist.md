# W178 · 护栏主题的销号非留痕不可:花名册逐号点名 + 下限只增不减

> 分支:`cursor/w178-topic-floor-unlist-3a7f`,基线 `cursor/w170-integration-98b2 @ c2acb4d`。
> 零产品代码:`js/` 与 `server.js`/`cli.js`/`mcp.js`/`billing.js` 一个字节都没进 diff。
> 本文只记这一槽自己做的事:把「撤掉一条护栏主题登记」从一个可改的数字换成逐号点名 + 显式闭合理由。
> 清单机制本身在 `w158-rename-vs-delete.md`,登记面上一次扩容与那两种改法的实测读数在 `w175-guard-enroll.md`;
> 本文不代述、不复写、不改它们正文里的任何时点读数。

## 1. 结果一句话

`GUARD_TOPICS` 的下限此前只是一个可改的数字,两种静默放松各实测**红 0**:把 `TOPIC_FLOOR` 改小而一条主题都不删,
以及连同下限一起把某条主题整段删掉(后者就是完整的销号动作)。本槽把「哪些编号登记过」从数字换成**花名册**——
逐号写在本文里、与源码分开——并给销号开了一个只能显式落笔的去处 `GUARD_TOPICS_CLOSED`:

| 层 | 判据 | 拦的是哪一路 |
|---|---|---|
| 花名册逐号点名 | 花名册上每个号此刻要么在册、要么在销号台账里 | 撤登记(下限动不动都一样红) |
| 下限只增不减 | `TOPIC_FLOOR` 不得低于花名册条数 | 把下限改小而一条主题都不删 |
| 销号须留痕 | 编号搬进销号台账并写下闭合理由;锚点原样搬过来;仍有承载用例时须写明接手编号 | 悄悄撤掉一道还在生效的护栏 |
| 第五格棘轮 | `TOPIC_FLOOR` 与「在册 + 销号」的差额不得超过 `SLACK` | 一槽加 4 条以上登记而下限停在旧水位 |

**合法增主题一条不红**:在册多出花名册没有的号是允许的,加主题照旧只改 `GUARD_TOPICS` 那张表。

`GUARD_TOPICS.length >= TOPIC_FLOOR`,`>=` 只拦"往下走"、拦不住"把标尺本身改短"。逐条复跑:

| # | 变异(基线 `c2acb4d`,单元 542/542) | 实测 |
|---|---|---|
| N1 | `TOPIC_FLOOR` 10 → 5,主题一条不删 | **红 0** |
| N2 | 在 N1 之上再删掉 5 条主题登记(连同下限一起销号) | **红 0** |
| N3 | 只删 5 条主题登记、下限不动 | **红 1**(下限那句) |

## 3. 怎么立的

### 3.1 花名册写在记账件里,不在源码里再抄一份

抄在 `tests/unit.js` 里的话,销号只要顺手把那一行也删掉就照旧无声——那不过是把一个数字换成一张同样可改的表。
记账件是**落笔即定**的记录:本文进了索引、进了份数三方对齐、进了记账件份数棘轮,删它或改它都另有三层判据在看。
故 `topicRoster()` 现取本文「花名册」那一节的表格首列,取空即红(判据不许静默退化成恒真句)。

### 3.2 销号台账要的四样

```
{ id, anchors: [原样搬过来], why: 这道护栏原本守什么, closed: 为什么可以不守了, by: 接手的主题编号 }
```

- `anchors` 原样搬过来,不是留个纪念:销号之后仍要判得出"这道护栏是真没了,还是还在跑而登记被撤了"。
  锚点此刻仍点得到承载用例、而 `by` 又空着时当场红——那正是"悄悄撤掉一道还在生效的护栏"这一路。
- `closed` 不许空、不许照抄 `why`:`why` 说的是它守什么,闭合理由要说的是**为什么可以不守了**,两句话不是一句。
- `by` 填了就必须指向在册编号:一道护栏并进另一条主题是合法去向,指向一个不存在的号不是。

落地时这张台账是**空的**——它在这儿是为了让销号有个只能显式落笔的去处。

### 3.3 第五格棘轮

花名册只覆盖登记进它的号。一槽新登记 6 条而下限停在旧水位时,那 6 条撤起来仍旧只有花名册这一层管不到的空当,
故把护栏主题这一格也收进既有的 `SLACK` 棘轮(此前四格:单元/集成/冒烟/记账件份数),
live 取的是**历史编号总数(在册 + 销号)**——销号不会让这个数掉下去,故销号不必回头改下限。

## 6. 残留与欠账

1. **花名册只覆盖写进它的号。** 本槽把在册十条与新立的一条都写了进去,往后新登记的主题若不追加,撤起来仍旧只有
   第五格棘轮那点差额保护(而棘轮允许落后 `SLACK` 格)。有意如此:追加是可选的,免得把"加一条主题"变成必须改两处。
2. **三处一起改仍旧蒙得过去。** 把主题登记、花名册那一行、下限字面三处同轮一起改小,本槽一条都不红——
   这与记账件份数那格"目录 + 索引行 + 明写份数三处一起改"是同一形态(`w158-rename-vs-delete.md` 一线记过)。
   本槽收的是"改一处"与"改两处"这两级,第三级留在这里如实登记。
3. **闭合理由的**内容**没有判据。** 判的是"有没有、够不够长、是不是照抄 `why`",写得对不对读不出来——
   与所有"要求写下理由"的护栏同形。
4. **`hosted` 那一档依赖锚点被原样搬进销号台账。** 销号时把锚点改窄改宽,"这道护栏还在不在"就判偏了;
   本槽只钉住锚点条数不少于 2,没钉"与撤走前逐字相同"(逐字相同要另存一份历史锚点,那是第二份要人工同步的记录)。
5. **本槽没碰的既有残留**:`w175-guard-enroll.md` §6 那几条(宽锚判定本 HEAD 仍无、`hosts` 仍是手填数、
   人设类源级用例仍不在清单里、判据够不着"把自己改松"这一路)原样交接;`w170-integration-log.md` 的残留同样一条没动。
