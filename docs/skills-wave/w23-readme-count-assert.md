# W23 · 文档数字对账契约(README 计数写错即红)

> 槽位范围:只动 README/`docs/skills-wave/README.md` 里的数字与 `tests/unit.js` 的 `contract` 套件。
> 不动 `js/`、不动发布门口径、不删既有用例。基线 `cursor/w21-integration-514d`。

## 1. 病灶

W20 周期 3 核验查实:README 架构框那句「校验型扩展点 CHECKS 已落地 X 条」在十条分支上写过
**三条 / 七条 / 九条**三种值(实测分别是 8 / 9 / 9),单元测试断言数同样长期与实跑脱节
(`master` 自称 163、实测 201,差 38;`w18` 自称 299、实测 300)。

根因不是谁不细心,而是**没有任何断言把文档数字绑到代码实况**:

- 这些数字要靠人手重算,而重算的时机(改完 CHECKS、加完用例)恰好是注意力最少的时候;
- 分支一分裂,同一句话在各支上各自演化,合并时 `checkout --ours` 之类的粗粒度动作会把
  某一侧算对的值原样覆盖掉,合完没人再复核;
- 数字错了不影响任何一条测试,所以错到下一次人工核验才被发现。

只要对账仍是人工动作,这类失真就会周期性复发。本槽把对账变成断言。

## 2. 落地:三口径 + 一条目录对齐,全在 `contract` 套件

`tests/unit.js` 的 `contract` 套件新增四条用例,全部**从代码实况反推数字**,再与文档比对。

### 2.1 取数一律现取,不在测试里手抄第二份

| 文档里的说法 | 实测来源 |
|---|---|
| 架构框「CHECKS 已落地 N 条」/ 摘要句「共 N 条 `Skills.CHECKS` 校验项」 | `Object.keys(Skills.CHECKS).length` |
| 就绪检查「现有 N 条——剧本面 …」 | 登记了 `episode.preflight` 消费点的已落地校验面的 `checks` 求和 |
| 「N 面 N 条」 | `Skills.preflightStages().length` + 上面那个求和 |
| 「N 项断言」 | `Object.values(SUITES).reduce((n, t) => n + t.length, 0)` |
| 单套件清单 `a\|b\|c` | `Object.keys(SUITES)`(README 与 `tests/unit.js` 文件头注释两处都查) |
| 短名单 N 条内部能力 | `Skills.list().length` |
| KB N 条方法论 / N 条目 | `Object.keys(KB.SECTIONS).length` |
| N 条注册表提示词 / N 条主线 LLM 提示词 | `Prompts.list().length` |
| N 条领域命令 | `CmdRegistry.names().length` |
| N 位专家 / N 专家 | `ExpertsData.EXPERTS.length` |

三个 CHECKS 口径**是分开取的**,不共用一个数:全部校验项数、就绪检查面数、就绪检查条数
在语义上本来就可能分叉(某条校验项不登记 `episode.preflight` 消费点时前两者就不相等),
合成一个数会让"面表少接一面"这类缺陷被数字对上掩盖过去。

### 2.2 判据形态

- **中文数字与阿拉伯数字同一口径**:`cnNum()` 把「九」「十二」折成整数,文档换写法不必改断言。
- **一处都找不到也算红**:`assertDocNum` 先断言至少命中一处——否则把那句话删掉/改写就能静默绕过对账。
- **命中几处就核对几处**:同一措辞在文档里出现多次(如「短名单 30 条内部能力」两份 README 各一处),
  逐处比对,不允许"改对一处漏一处"。
- **目录索引双向对齐**:`docs/skills-wave/` 下每份记账件都要有索引行,索引行也不得指向不存在的文件,
  且链接文字就是文件名(W20 记过一次「33 行索引 / 32 份文件」的悬挂索引,此后靠人工补)。

## 5. 边界

- **不放宽任何发布门**:本槽零 `js/` 改动,发布门 G1–G10 口径、计费动作、`blockers` 一律未动。
- **不删测**:只增四条用例,既有用例名集合逐条保留。
- 未纳入对账的是 `integration.js` / `e2e.js` / `cli.smoke.js` 三个套件的断言数——
  它们的用例不是静态数组,静态实计会得到假值;要对账须先把用例登记形态改成表驱动,超出本槽范围。
  当前实跑值:`integration 93/93`、`cli.smoke 62/64`(两条既有失败与本槽无关,未动)。
