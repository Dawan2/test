## 2. 两键而不是一键:判据是 `def` 字面

任务口径是「`def` 相同才可共用键,否则两键」。两处 `def` 逐字节比过——

- 策划那处:`你是资深短剧策划/编剧,擅长短剧节奏、悬念设计与人物塑造,回答务实具体、中文输出。`
- 译制那处:`你是资深短剧出海本土化译制专家,目标市场:{market}。…`(带四条本土化要求)

字面不同,角色(策划/编剧顾问 vs 出海本土化译制专家)与产物落点(`p.plannerChat` 对话流,满意可「应用为剧本」 vs 按分集标记拆开写回 `p.episodes` 各集正文)也都不同,故**两条独立键**。与既有 29 条逐条比过也都不同字面——离得最近的是 `digest.planSystem`(`你是资深短剧策划。`),它是剧本摘要链路一键三口的那条,与策划对话差的不是两个字而是整个后半句与角色面(它出小传/集纲文本、不进对话流)。

```js
/* 项目实验台两步人设:AI 策划对话的角色是策划/编剧顾问(诊断结构、设计钩子、发散创意),
 * 剧本译制的角色是出海本土化译制专家,两条 def 字面不同(角色与产物落点也不同),故两条独立键。
 * 只收措辞面:策划那步其后的「当前项目信息:」上下文由取值口现拼(项目实况不随覆盖变动);
 * 译制那步的分集标记契约留在取值口常量 TRANS_CONTRACT、不开放覆盖(改坏即整轮译制结果一集都写不回)。 */
{
  key: 'planner.chatSystem', name: 'AI 策划对话 · 系统人设', vars: [],
  def: '你是资深短剧策划/编剧,擅长短剧节奏、悬念设计与人物塑造,回答务实具体、中文输出。',
},
{
  key: 'trans.localizeSystem', name: '剧本译制 · 系统人设', vars: ['{market}', '{lang}'],
  def: `你是资深短剧出海本土化译制专家,目标市场:{market}。这不是直译而是本土化译制,要求:
1. 人名本地化:把中文人名替换为目标市场本土人名(如 陈默→Ethan 式),全文保持一致
2. 台词口语化、俚语化,符合目标市场受众表达习惯,使用{lang}
3. 文化梗替换:本土文化梗替换为目标市场受众能共鸣的梗
4. 保留分集结构与爽点节奏(钩子/反转/打脸点位置不变)`,
},
```

**键名**沿用注册表既有惯例(前缀取步名/领域而不是文件名,与 W71 不取 `episodes.*`、W82 不取 `proj-shell.*` 同理):

- `planner.chatSystem`:前缀 `planner` 对应这一步的数据落点 `p.plannerChat` 与入口名「AI 策划」;后缀取 `chatSystem` 而不是 `system`——`planner.system` 读起来像"策划这一整块的人设",而这一步是**多轮对话**(历史 20 条随 system 一起发),若策划面往后长出别的 LLM 步(如按诊断结论出改稿建议),`planner.chatSystem` 才留得下并列位置。同族先例 `persona.promptSystem` / `dist.copySystem`。
- `trans.localizeSystem`:前缀 `trans` 与这一步的计费动作 `llm.translate` 同词根;后缀取 `localizeSystem` 而不是 `system`,因为这一步的产品口径是「**本土化译制**而非直译」(弹窗提示与 system 半第一句都写着),若往后长出直译/字幕译制,`trans.localizeSystem` 与它并列得开。**不并到 `dist.*` 名下**:发行那一族的产物是投稿/投流文案(`p.shell.dist`),译制的产物是分集剧本正文,不是同一个板块。

**注册顺序按产品流程**:两条排在剧本板块四步(`narration`/`reading`/`concept`/`light`)之后、`dirset.system` 之前——项目实验台这两步都围着剧本正文做(诊断改写 / 出海译制),属剧本层工具,而导演设定是它之后的开拍前定调。三条断言钉住(紧接 `light.system`、译制紧接策划、两条都在 `dirset.system` 之前),免得后续槽随手插到别处静默改掉「全局默认值」页的排列。

## 3. 策划那步:收编面到「当前项目信息:」之前为止

这一步的 system 半是三段拼的,收编只收第一段:

| 段 | 处置 | 为什么 |
|---|---|---|
| 人设句 `你是资深短剧策划/编剧,…中文输出。` | **进注册表**,用户在「全局默认值」页改得到 | 措辞好坏属人设面,改坏只是"建议质量差一点" |
| `'当前项目信息:\n'` 段头 + `ctxOf()` | **留在取值口现拼**,不随覆盖变动 | `ctxOf()` 现取的是项目名称/风格影调/目标市场/剧本前 3000 字/分集列表——**项目实况**,做成覆盖面等于允许用户在提示词里存一份项目快照;段头与它是一体的(段头进覆盖面而正文不进,用户改掉段头就会得到一段没有标题的裸实况) |

改完是:

```js
{ role: 'system', content: Prompts.get('planner.chatSystem') + '当前项目信息:\n' + ctxOf() },
```

`js/prompts.js` 在 `index.html` 里排第 21 行、`js/proj-planner.js` 排第 36 行,取值口用的是浏览器已有的全局 `Prompts`,不新增加载项。

## 4. 译制那步:变量进 `vars`,契约半留在取值口

这一步比前几槽多两个细节。

**其一,两处插值**。`${tgt.name}`(目标市场名)与 `${tgt.lang}`(目标语言描述)取自模块内的 `TARGETS` 三档(欧美/东南亚/日韩),是**用户在弹窗里点选的运行期取值**,不是措辞。注册表本来就有变量面(`Prompts.fill` + `vars`,先例 `sb.reviewUser` 的 `{style}`/`{brief}`),所以按键登记成 `vars: ['{market}', '{lang}']`,取值口改用 `fill`:

```js
{ role: 'system', content: Prompts.fill('trans.localizeSystem', { market: tgt.name, lang: tgt.lang }) + TRANS_CONTRACT },
```

登记了变量还有一条正查:`def` 里必须真有那两个占位符(登记了却填不到,用户覆盖时看到 `vars` 说明里写着两个变量而写进去无效——一条断言逐个点名)。

**其二,契约半在 system 半里而不在 user 半**。原串第 5 条是:

```
5. 保留「第X集」分集标记,每集开头必须有,供程序按标记拆分
```

这一条不是措辞,而是**「应用译制结果」那步的解析判据**——`result.split(/(?=第\s*[0-9一二三四五六七八九十百]+\s*集|Episode\s+\d+|…)/i)` 靠它把整篇译稿切成各集正文写回;识别不到就是「未识别到分集标记,未应用」,那一轮 2 积分白花、一集都写不回,不是"效果差一点"。所以按 W79 收 `comic.bubbleSystem` 的同一形状,把它留成取值口常量:

```js
/* 译制人设的契约半:「第X集」分集标记就是下面「应用译制结果」按标记拆分的判据,故留在取值口不开放覆盖
 * (改坏即整轮译制结果一集都写不回);措辞与四条本土化要求走注册表键 trans.localizeSystem,用户在「全局默认值 → 核心提示词 skill」改得到 */
const TRANS_CONTRACT = '\n5. 保留「第X集」分集标记,每集开头必须有,供程序按标记拆分';
```

**「契约半不开放」是正查的**,而且两面都查:注册表里不得出现 `第X集` 与 `供程序按标记拆分`(反面),以及**契约与解析侧必须同集**——用例把源码里那条 split 正则现取出来在 `vm` 里求值,拿 `第1集…第2集…` 真切一遍应得 2 段(正面)。这一条防的是"契约文字还在、解析侧那一支被删了"这类单侧漂移:契约里承诺「第X集」而解析侧只认 `Episode N`,模型照做也照样写不回。

**第 1–4 条为什么在覆盖面里**:人名本地化 / 口语化俚语化 / 文化梗替换 / 保留爽点节奏是**译制方法论**,改一条只改译稿风格,不影响能不能写回。这与 W82 的分段表口径一致(方法论正文与人设句同属"改坏只是效果差一点"那一侧),差别只在这四条是本步自撰而不是 `KB` 条目,所以随 `def` 一起进注册表、不必留在取值口。

## 5. 两处取值口都留在弹窗里:模块顶层不预取

`TRANS_CONTRACT` 是纯字面常量、放哪都一样,但**两处 `Prompts.get/fill` 一律不能提到模块顶层**。这个文件是 IIFE 立即执行、在 `index.html` 加载期就跑完顶层的,顶层预取等于把覆盖表冻在页面加载那一刻——用户在「全局默认值」页改完提示词、不刷新页面就再开一次策划对话,拿到的还是旧值,而缺省与覆盖两条路径都"看起来是对的",这类退化没有任何行为面能捞出来。

所以断言分两层:全文 `Prompts.get|fill(` **恰好两处**(多一处即有人预取或抄了第二份),且第一处 `Prompts.` 出现在 `function openPlanner` 之后(顶层区零取值)。变异 8 实测:把 `const PLANNER_SYS = Prompts.get('planner.chatSystem')` 放到模块顶层,源级当场红。

`TRANS_CONTRACT` 本身也没放模块顶层,而是放在 `openLocalize` 里紧邻 `TARGETS`——与 W79 的 `BUBBLE_CONTRACT` 同位(契约常量贴着它服务的那一步,读的人不必翻文件找)。

## 6. 取值口只有浏览器一端

两步都是纯浏览器链路:`server.js` / `cli.js` / `mcp.js` 里没有对端(项目实验台不在 `/api/wf/*` 六个端点里,也不在领域命令注册表里)。所以与 W71/W82 同口径:

- 取值口各一处,浏览器隐式读 `Store.state.settings.promptOverrides`。
- 断言写成**不许长出第二端**:`server.js` / `cli.js` 里不得出现两步的 user 半锚点(`请对以下剧本进行本土化译制` / `当前项目信息:`)。
- 收编解决的是"**可覆盖**",不解决"可 headless"——如实写进 README、SK-03 的 `note` 与本件,不含糊成"这两步已双端单源"。

行为面**没有沙箱真跑那一层**:两个 handler 都挂在 `U.openModal` 的 `onMount` 闭包里(要真 DOM 与 `styleOf`/`localeOf`/`langOf` 等 `episodes.js` 闭包外的全局),与 W71/W82 同形。能钉的两件事——缺省逐字节 + 覆盖只换措辞面——落在注册表取值行为上,取值口落在哪一步由源级配对正则锚住(策划那处与该步计费动作 `billingAction: 'llm.agent'` 配对、译制那处与 user 半锚点 `请对以下剧本进行本土化译制` 配对),两条合起来覆盖的面与"真跑一遍截获 system"等价。
