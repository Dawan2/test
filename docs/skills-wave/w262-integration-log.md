## 三、`live == 对侧` 在本槽是套套逻辑,故判据换一类

W260 §二 那句「`P1 == B` 不是免检章,它是『整份取对侧即并集』这句话的成立条件」在本槽推到了极限:**整棵树上 `P1 == B`**,于是「整份取对侧即并集」对每一个文件都无条件成立,`M == P2` 是 git 的定义而不是一次核对的结果。

这里有个必须写下来的陷阱:**这一槽做完 `--no-ff`,拿 `git diff HEAD P2` 量出空、宣布「合入无丢失」,这句话是恒真的**。它在快进形里恒成立,在整份覆盖丢东西的情形里**同样**成立——因为「整份覆盖」正是快进形的合法形态,两者在树比对上无从分辨。W260 那种「四棵树两两不同」的形态里,`M` 与两侧都不同本身就是一条弱证据;本槽这条证据为 0。

故本槽把「有没有丢东西」的判据从**树比对**换成**变异 + live 实测**两条,理由是这两条在快进形里不退化:

1. **live 实测**能分辨「对侧自称的数字」与「合完真跑出来的数字」。快进形下前者理应等于后者,但**理应相等不等于实测相等**——若对侧自称的 676 是抄的、实跑其实是别的数,快进形一样藏得住,而树比对永远看不出来。
2. **变异**能分辨「代码在树里」与「代码真被判据咬着」。整份取对侧时,判据面是否跟着一起到位、两端调用是否都真接上,树比对说不出一个字。
