## 一、先 live:W244 登记的那一格是真的

W244 §交接第 5 条(以及 W242 §五第 5 条)读源码登记过这一格,本槽先把它现跑出来再动手。

### 1.1 纯函数面逐档现取(合完树上,改动之前)

```
Domain.dupRowsNote(['dup'],              3 行) → "…比点名数多花了 2 行的钱。"   ← 用户手打,对的
Domain.dupRowsNote(['dup','dup'],        2 行) → "…比点名数多花了 1 行的钱。"   ← 假话
Domain.dupRowsNote(['dup','dup','dup'],  3 行) → "…比点名数多花了 2 行的钱。"   ← 假话
```

第二、三行那两句就是 W242 §1.5 在主体侧量出来的同一句话,只是把「位」换成了「行」。

### 1.2 递这份清单的是谁:两处机器派生,都是每行各排一条

`js/release.js` 收门那一遍里,两门的一键处置各自派生一份 `fix.shotIds`:

| 门 | 派生 | 形状 |
|---|---|---|
| G6 失败镜 | `(ep.shots \|\| []).filter(s => s.video && s.video.status === 'failed').map(s => s.id)` | **每行各排一条**,同 id 两行即 `['dup','dup']` |
| G4 过期镜 | `sp.all`,即 `Domain.staleShotSplit` 的 `stale.map(s => s.id)` | 同形 |

两处都没有 `new Set`,也**不该有**——去重之后第二行就永远排不进处置,门也就永远过不了。
故「同 id 两行时点名清单里有两条」是**实况**,不是笔误。

### 1.3 真跑整条 G6 链(门禁 → `execFix` → 命令层 → `digest`),改动之前

夹具:一集两行,`id` 都是 `dup`,`video.status` 都是 `failed`。

```
G6 fix.shotIds = ["dup","dup"]              ← 机器派生:每行各排一条
execFix → 引擎实收 dup, dup                  ← 点了两条、真跑两行,一行都没多花
改前 note = "点名的 1 镜在分镜表里占着多行同 id(dup 2 行):…比点名数多花了 1 行的钱。
             要一个 id 只跑一行,先用 CLI shots-dedupe 收拾存量重复。"
digest 照播 ← 发布门自己的按钮在诬告自己,还顺带劝用户去 shots-dedupe 一把
```

**这句话在这一路上错得比主体侧那一格更难受**:它不只报了个假数,还点名了一条出口命令
——用户照着去 `shots-dedupe --apply`,两行里后一行的 id 就真被改掉了,而他本来一分钱没多花。

### 1.4 停工条件逐条核过

| 条件 | 现跑 | 判 |
|---|---|---|
| G6/G4 递来的已经是去重清单 | 两处 `map(s => s.id)` 都没去重,`fix.shotIds` 实测 `["dup","dup"]` | **不成立** |
| 这句话在机器派生那一路本来就不出现 | 现跑真播了,`digest` 一条 toast | **不成立** |
| 主体侧那一格没收干净、得连着改 | `dupSubjectRowsNote` 已是 `extra = list.length - picked.length` + `extra <= 0` 早退(W242 收的),一个字不用动 | **不成立** |

故不停工,改那一句算术。

## 二、改了什么(产品码一处,`js/domain.js` 三行 + 注释四行)

```
  const ids = [...new Set(picked)];                    只用来逐个报「哪个 id 占着几行」
  const dup = …filter(x => x.rows > 1);                这一段一个字没动
- const extra = dup.reduce((n, x) => n + x.rows - 1, 0);
- if (!dup.length) return '';
+ const extra = list.length - picked.length;           真跑的行数 − 点名的原始条数
+ if (!dup.length || extra <= 0) return '';
- return '点名的 ' + ids.length + ' 镜在分镜表里…'
+ return '点名的 ' + picked.length + ' 镜在分镜表里…'
```

三处得**一起改**,少改任何一处都接不住(见 §3.1 M2/M3/M4)。

改后逐档:

| 点名清单 | 真跑 | 改前 | 改后 |
|---|---|---|---|
| `['dup']`(用户手打) | 3 行 | 多花 2 行 | **多花 2 行**(未变) |
| `['dup']`(用户手打) | 2 行 | 多花 1 行 | **多花 1 行**(未变) |
| `['dup','dup']`(G6 派生) | 2 行 | 多花 1 行 ← 假话 | **一句不说** |
| `['dup','dup','dup']`(G6 派生) | 3 行 | 多花 2 行 ← 假话 | **一句不说** |
| `['dup','dup']` | 3 行 | 多花 2 行 | **多花 1 行** |

**用户手打那一路逐字未变**,这是本槽的边界:两个口径只在机器派生的清单上分道。

### 2.1 G4 那一路顺带也对了,而且是靠早退接住的

G4 的 `sp.all` 含定稿的过期镜,而命令层的选人闸锁着 `!s.final` 不碰它们。
同 id 三行过期、其中一行定稿时:点名清单 3 条、真跑 2 行,`extra = 2 − 3 = −1`,**早退一句不说**——
这是对的(跑得比点名的还少,没有任何多花)。`extra <= 0` 那道早退在这一路上不是冗余。

### 2.2 为什么两端调用点一个字不用改

`js/commands.js` 与 `cli.js` 递进来的都是 `(args.shotIds, 这一趟真下发的清单)`,
本槽换的只是派生内部的减法。`contract` 那条源级判据(两端须现取 `Domain.dupRowsNote`、
可执行行里不许出现这句话的字面)照旧管着,本槽没给它添也没给它减。

- **M5 是唯一同时红三个套件的一手,而第三条红在本槽新加的对照面上。**
  只钉「G6 那一路一句不说」的话,把 `extra` 整个减小一格同样能让那一路闭嘴——

  补一句话的判据里,**"该说时说了"与"不该说时没说"得各占一条**,只钉后者会被"干脆别说"骗过去。

  这一格本槽只登记不收(收它要把"按 id 收窄"的语义面判据补进去,是另一件事,见 §五第 4 条)。

## 五、交接

1. **两份 `dup*Note` 现在算术同形了。** 镜头 `dupRowsNote` 与主体 `dupSubjectRowsNote` 的
   「多花几个」都是 `真跑数 − 点名清单原始条数` + `<= 0` 早退,逐个 id 报「占着几个」都按去重后的 id。
   两份仍是**两份**(单位与出口不同:行/位、`shots-dedupe`/主体库人工),`contract` 那条反面判据
   仍钉着它们不许合并。哪天再开第三份(比如配音那一拍),算术照抄这一条,别再抄去重口径。
2. **多扣费这件事本身仍在,本槽收的仍是"说错话"那一半。** 用户手打点名一个 id 仍然跑几行扣几笔,
   那句话照旧会播、照旧指向 `shots-dedupe`。选人闸按行筛是对的(第二、三行各有各的内容),
   要改成按 id 只跑一行,得连着「重复行里的内容怎么办」一起判,别拿这句 note 当幌子。
3. **`cli.js` 的 `findShot(ep, sid)` 取 `.find` 首行,是主体侧 `findSubject` 那一格的镜头版,本槽一个字没碰**
   (交接明令留给平行槽)。形状逐字同形:`EXEC['episode.generateVideos']` 每轮
   `const sLive = findShot(epLive, s.id)`,同 id 三行时三轮全写在首行身上——
   **扣三笔视频钱、只有一行到手产物**,而回执报 `total:3 ok:3`。
   浏览器那一端不是这个形态(`SBGen.batchGenVideos` 直接拿循环里的那个对象)。
   收它要动寻址语义并同轮重判回执 `ok` 按几行报,不是文案能承担的。原样登记,谁接谁跑。
4. **§3.1 那条源级判据的盲区(M8)原样留着。** `contract` 里「待跑清单不许被按 id 收窄」
   扫的是 `pend = ` / `todo = ` **那一行**上的 `new Set`/`findIndex`/`indexOf(`,
   把去重状态挪到上一行的局部变量上即可绕过。它在镜头与主体两侧是同一份写法,故两侧同时有这个盲区。
   现在接住这类改法的是行为面用例(引擎实收几行)。要收这一格,得把判据从"某一行的字面"改成
   "选人那一段的语义"(比如拿造出来的重复表喂选人那一段真跑),那是判据层的活,不在本槽射程内。
5. **失败档带不带这句仍没单独判**(与 W239 §5.5、W242 §五第 8 条同):无论 `ok` 与否都挂 `result.note`,
   `digest` 在失败档播的是 `error.message`。有意留的余量。
6. **整集那一路(不点名)照旧不说这句。** 那一路 `total` 本来就是行数,没有"点 1 个跑 3 行"的错觉。
7. 冲突面提示:`js/domain.js` 只改 `D.dupRowsNote` 函数体三行 + 它上面注释块尾部四行,
   与 `dupSubjectRowsNote`(隔着 `emptySubjectImageNote`)不相邻;
   `tests/unit.js` 两处——`domain` 那条既有用例里替换了一句断言、`release` 在 W202 G4 回音那条之后
   与 W202 G9 回音那条之前插了一条完整用例;`README.md` 改一个数 + 同一长行里插一句散文。
