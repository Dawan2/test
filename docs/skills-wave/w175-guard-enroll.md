## 3. 怎么登记的

### 3.1 锚点一律取实况取数口,用例名一个字不参与

五条主题的锚点全部是**源码标识符**或**注册表/登记表取值口**,没有一条取用例名或用例里的散文:

```
review-min-literal     Domain.REVIEW_MIN(单源常量) + DEFAULT_MIN_SCORE(有意不收编的那份可配阈值)
review-gate-single     const reviewGate = (domain.js 里那唯一一处判据) + st.reviewGate(消费侧取值点)
project-script-single  Domain.projectScript(单源取数口) + splitCore(拆集命令体)
ep-blocker-fanout      Domain.epBlockerCodes()(码全集) + Issues.epSkips()(不投理由的登记面)
zip-placeholder-ban    PLACEHOLDER(占位字面) + ZipUtil.download(落地口)
```

故按新实况翻面重写、改名、挪套件都不会红——只要还在读同一份实况。

### 3.2 `hosts` 按实况填,一题多承载不禁

现取落点:

| 主题 | 落点数 | 落在哪 |
|---|---|---|
| `review-min-literal` | 1 | `domain · REVIEW_MIN 消费点零分叉(源级)` |
| `review-gate-single` | 1 | `contract · 分集级审片门槛单源` |
| `project-script-single` | **2** | `commands · splitEpisodes:切分输入现取 Domain.projectScript` + `contract · 拆集的切分输入单源` |
| `ep-blocker-fanout` | 1 | `contract · 分集阻塞码扇出` |
| `zip-placeholder-ban` | **2** | `release · downloadReleaseZip 源级` + `release · downloadReleaseZip 运行期` |

两条 `hosts: 2` 都是**真多一处承载**而不是锚点写泛顺带扫进来的:

- `project-script-single` 的两处各钉一面——命令层那条钉住"提取过主体的老项目走拆集仍如实 `blocked / no-script`",源级那条钉住"命令层与计划层同读 `Domain.projectScript` 这一份";
- `zip-placeholder-ban` 的两处也各钉一面——源级钉可执行行零占位字面与落地口名单,运行期把桩打在函数对象上(`const Z = ZipUtil; Z.download(...)` 这类别名写法源级够不着,W170 的 M10′ 实测过)。

处置因此是**抬 `hosts` 到实测条数并在 `why` 里写清分工**,不是收窄锚点——收窄会把真承载判丢,而那一处正是别人以为还有人顶着的地方。既有的 `plans-gate-read` 也是 `hosts: 2`,本槽照它的写法。

### 3.3 锚点扛不扛得住收严了的宽锚判定

清单登记侧另有一路收严:一个锚点单独就扫到全套件 5% 以上用例时,它点的不是这道护栏而是一片用例。
本 HEAD 上没有那一层,但锚点按它的口径挑,现取(总用例 543 条 → 上限 28 条):

| 主题 | 各锚点单独命中面 |
|---|---|
| `review-min-literal` | `Domain.REVIEW_MIN` **6** / `DEFAULT_MIN_SCORE` **1** |
| `review-gate-single` | `const reviewGate = ` **1** / `st.reviewGate` **2** |
| `project-script-single` | `Domain.projectScript` **3** / `splitCore` **4** |
| `ep-blocker-fanout` | `Domain.epBlockerCodes()` **1** / `Issues.epSkips()` **1** |
| `zip-placeholder-ban` | `PLACEHOLDER` **3** / `ZipUtil.download` **3** |

五条十个锚点,最宽的一个是 6 条,离上限 28 还差 22 格。既有十条主题的锚点同轮现取,最宽的是 `gaps-key-set` 那条的 `Skills.gaps()` **17 条**,同样在线内(本槽未动它)。故这五条登记在收严口径下**不会被判成宽锚**,合线时不必回头改。

顺带记一格:两条 `hosts: 2` 若被误判成"锚点过泛",处置方向恰好相反(收窄 vs 抬 `hosts`),而本槽实测它们的锚点条条都窄——即它们是"真多一处承载"那一路,不是"有人替它顶着"那一路。

## 4. 新加的那条判据

### 4.1 判词抽成函数,拿造出来的用例集喂它

`guardHostsOf(anchors)` 改成 `guardHostsOf(anchors, cases)`(不传就现取全套件),另抽 `guardCases()` 与:

```
guardSpread(topic, cases) → { kind: 'lost' | 'spread' | 'ok', line }
```

`lost` 是落点归零(这道护栏没了、无人接手),`spread` 是落点数与登记不符,两种 `line` 都以主题编号打头。
「护栏主题不许失联」那条改成按判词分桶报,报错句一字未改。

新用例 `contract · 护栏主题真删得出红` 做的事:对每条主题、每一处承载,从现取用例集里**按引用抽掉那一条**再喂 `guardSpread`,断言

- 判词不许是 `ok`(是 `ok` 就等于这道护栏删掉也没人吭声,与压根没登记同一个结果);
- 报错句必须**以主题编号打头**(只报"少了一条用例"就与三套件下限那一层同形,读报错分不出删的是哪道护栏)。

另带两句自检,不许本条静默退化成空转:

- 抽样口径自检:按引用抽掉一条后总数得真的少一条;
- 接线自检:失联那条必须真经 `guardSpread` 取判词——它若自己另写一遍循环,本条抽样证到的就不是它在跑的那份判据。

**为什么不真去删一条用例**:那要么改文件再跑全套(单测做不到、也不该在跑测时改仓库),要么把用例数写死(与"只增不减"的下限打架)。抽掉一条**用例源码快照**是同一件事在判词这一层的等价形态,而判词正是失联那条唯一读的东西。

### 4.2 覆盖面

本条对 `GUARD_TOPICS` **逐条**跑,不只跑本槽新登记的五条:15 条主题、共 **18 处**承载(三条 `hosts: 2` 各占两处),每一处各抽一次,18 次全部命中非 `ok` 且报错句以主题编号打头。故新登记与既有登记从此同一标准,后来者加主题时这一条自动接上。

## 6. 残留与欠账

1. **销号这一步仍没有机器判据。** 把 `TOPIC_FLOOR` 改小与删掉主题两步一起做(M6 + M7)是完整的销号动作,而"同轮写明理由"至今靠人读 diff——清单里那句纪律是写给人的,没有任何断言在读它。这与三套件下限那一格"改小下限而一条用例都没删"是同一形态(W129 记过),本槽照旧没收。
2. **本槽只加 1 条用例、1 份记账件,故两格棘轮都被"差 1"蒙过去。** 基线那两个父值(542 / 183)抄下来一条都不红。这不是本槽的洞,是 `SLACK = 3` 这个设计的既有面(W162 / W148 / W170 各压过一次线),如实登记。
3. **宽锚那一层本 HEAD 上还没有。** 本槽的锚点按 5% 那条线挑并逐个量过(3.3),但判据本身不在这条线上——把某条主题的锚点改宽而落点数恰好仍对得上时,此刻一条都不红(M10 只在落点数变了时才响)。
4. **`hosts` 仍是手填数。** 本槽两条 `hosts: 2` 是量出来填的,而"量了没有"这件事没有判据管:填错时落点数那条会当场红,但"填的时候有没有读过实况"读不出来。W166 残留 1 原样成立。
5. **人设类源级用例仍不在清单里**(2.2 末段),按收录口径有意不收,不算欠账;哪天要收得先想清楚"某个文件此刻零内联"这一类的锚点该怎么写才不撞上别人家的反向断言。
6. **新加那条判据够不着"把自己改松"这一路**(M11),与所有判据同形;它够得着的是"失联那条不再经判词"(M14)与"判词退化"(M12/M13)。
