## 一、这一格具体错在哪

`order` 是落库字段,不是"这一镜此刻排在第几行"(插镜不重排即两镜同号、删镜即跳号、拖动换序不跟着换、
同 id 多行两行可能记着同一个号)。W267 把整集那两块面收到实位之后,单镜这条路上还读着这个字段,
于是同一镜在同一条审片面上报两个号——比两处都报错更难查:

| 面 | 本槽前报的号 | 整集清单里报的号 |
|---|---|---|
| 整集报告清单第三行 | — | 镜头 3(W267 已收) |
| 点这一行开出的报告页头 | 视频 #1-1(该行 `order` 自称 0) | 同一份报告 |
| 这份报告导出的抬头与文件名 | 镜头:1 / `…_镜头1.txt` | 同一份报告 |
| 这一镜的审片记录列表标题 | 审片记录 · 镜头 1 | 同一镜 |
| 这一镜生成中时的拦截提示 | 镜头1 视频仍在生成中 | 同一镜 |

页头那一处还有一层内部不一致:集号 `epIdx` 早在 W263 就按行对位取(`Domain.rowIndexOf`),
一个 `视频 #N-M` 里左半按实位、右半按字段,两半取法本就分家。
